（预计落在 `app/web/time-calc.js`（新）、`app/web/work-calc.js`（新）、`app/web/dev.js`、

来源：`docs/需求清单.md` 第 8 节第 7 条（通用模块）里的「工时统计」。

## 1. 想解决什么

开发工作这一块现在有：项目、挂在项目上的待办、问题 / bug、进展。四个都回答「做了什么」，
**没有一个回答「花了多少时间」**。做了三件事、推进了两条，但没人知道那是两小时还是两天；
「这周我在哪个项目上投得最多」也看不出来 —— 只能凭感觉。

游戏娱乐那边已经有一整套现成的机制可以照：玩一次记一条（哪天、哪款、多久），
外加一个「开始计时 / 停止并记录」的秒表。工时就是同一件事，只是把「哪款游戏」换成
「哪个项目」。

## 2. 放在哪

**开发工作的子页**：`#dev/hours`，顶上和记账的「账目记录 / 债务欠款」一样一排子 Tab
（项目列表 / 工时统计），两个页面都能互相切；项目详情页保持原样（它自己有「← 返回项目列表」）。

为什么不放首页：首页是「今天要看的东西」，工时是回头看的账；而且它天然属于开发工作
（每条工时都挂在某个项目上）。

## 3. 数据：一条工时

新表 `data.workLogs`（顶层，和 `gameRecords` 一个待遇），一条长这样：

```jsonc
{
  "id": "w-1",
  "date": "2026-10-14",
  "projectId": "p1",
  "minutes": 150,
  "note": "把工时页的画完了",
  "tags": ["开发"],
  "createdAt": "2026-10-14T21:00:00.000Z"
}
```

`projectId` 可不填（见第 11 节），`minutes` 是时长（2 小时 30 分 = 150）。

几条口径：

- **时长只存分钟**：表单里是「数字 + 单位（分钟 / 小时）」两格，落盘前拧成 `minutes`
  （和游玩记录一个做法，数据里不留两个影子字段）。
- **图片不要**：一条工时给不出「值得存张图」的场景，也就省掉一个附件目录
  （少动三处白名单和设置页文案）。
- **不进归档**：工时是账不是待办，没有「归档」这一说；删了进回收站。

## 4. 共用零件：`app/web/time-calc.js`（新）

工时要用的一整套「时长」和「计时」函数，游戏那边**已经有了**（`game-calc.js` 里的
`DURATION_UNITS` / `toMinutes` / `shownDuration` / `hoursOf` / `hoursText` / `durationText` /
`elapsedMinutes` / `clockText` 八个）。搬到新的 `time-calc.js` 里，`game-calc.js` 那儿
留一行 `export { … } from "./time-calc.js";` —— `game.js`、`item-form.js`、
`tests\游戏计算.test.mjs` 一个字都不用改（和上一轮搬 `lastMonths` 一个做法）。

为什么值得单开一个文件：这两个模块共用的不是「时长换算」这一点，而是「**记一条有时长的
记录**」这件小事 —— 换算、显示、秒表都在里头。以后再有什么「学了多久 / 练了多久」，
直接接这个模块，不用再抄第三遍。

## 5. 纯逻辑：`app/web/work-calc.js`（新）

| 函数 | 干什么 |
| --- | --- |
| `normalizeWorkLog(row)` | 补齐一条工时的形状（老数据、手写的都认） |
| `workStatsOf(logs, today)` | 今日 / 本周（周一起）/ 本月 / 累计的分钟数 + 条数 + 天数 |
| `monthMinutesOf(logs, months)` | 按月汇总 + `ratio`（给柱状图，和 `gameMonthTrend` 一个形状） |
| `byProjectOf(logs, projects)` | 按项目汇总：项目名 + 分钟 + 条数 + `ratio` + 占比，按分钟降序 |
| `collapseRows(rows, top)` | 分布太长时只画前 N 名，剩下的收成「还有 N 个 · 合计多少」（返回 `{ shown, rest, restMinutes }`） |

口径（和游戏、首页那套一致，别的地方也算得到同一个数）：

- **本周从周一算起**（`game-calc.js` / `goal-calc.js` 里那套 `weekStartOf` 的算法）。
- **只算填了日期的**：没日期的既不算任何一段时间，也不进按月的图（只在「累计」里出现，
  `statsOf` 就是这个口径）。
- **项目找不到的记录不丢**：归到「（项目已删）」那一行；`projectId` 空的归到「没记项目」。
  两行都照 `byProjectOf` 排进去 —— 数据在，就不该在图里凭空消失。
- **删项目时工时跟着进回收站**（和待办 / 问题 / 进展一个待遇，`trashPlan` 里那句
  `type === "devProject"` 多收一张表）。回收站能整条捞回来，所以不怕误删。

## 6. 界面：`#dev/hours`

从上到下五块：

1. **计时条**：没在计时就一个「开始计时」；在计时就是一个跳着走的 `00:12:34` +
   「停止并记录」+「取消计时」。照游戏页那套（记在 `sessionStorage` 的
   `xiali-work-timer` 里，切到别的模块再回来还在计；每秒只刷那行字，不重画整页）。
   停止后**打开弹窗**、把算出来的分钟数填好让你确认（想改项目、补备注都在那儿）。
2. **四个数字格**：今日 / 本周 / 本月 / 累计（分钟 + 多少条 / 多少天）。
3. **近 6 个月柱状图**：复用上一轮做的 `chart-calc.js` 的 `trendChartHtml`，
   当月那根画实一点，没记录的月份是一根零高柱。
4. **按项目分布**：一行一个项目（横条铺整行背景、条长按第一名，复用 `barFillHtml`）
   + 时长 + 条数 + 占比。
5. **记录列表**：一行一条（日期、项目名、时长、备注、标签、编辑 / 删除），按日期倒序；
   空状态写一句「还没记过工时，上面点『开始计时』或者『记一笔工时』」。

头上有「＋ 记一笔工时」（`openItemDialog("workLog", …)`）。

## 7. 表单：`workLog` 类型

字段：日期（必填）、项目（下拉，选项是 `projects` 表，可不选）、时长（数字 + 单位）、
备注、标签。没有图片区。`create` 里 `projectId: ""`、`minutes: 0`、`tags: []`、`createdAt`。

「项目」那一格的选项走 `ctx.projects = [[id, 名称], …]`（和「学习对象」那格一个做法）。

## 8. 搜索

搜索池里加一条：`{ table: "workLogs", module: "dev", hash: "dev/hours", label: "工时", … }`，
匹配日期、备注、项目名（要回 `projects` 表里取，照粉丝快照取账号名那个写法）。
标签照样进池子（本来就是通用机制）。

## 9. 明确不做

- **不把工时挂到具体某条待办上**（「这条待办花了多久」是另一个设计：要动待办表、
  要在待办行上显示，牵一发动全身）。这一版工时只挂项目。
- 工时不进「今日计划」、不参与首页那几张卡（它是回头看的账，不是今天要做的事）。
- 按标签统计工时、工时导出 CSV、按时间段筛工时、番茄钟 / 休息提醒（纯本地做不了后台提醒）、
  按小时工资算钱 —— 都不要。
- 不归档：删了就是进回收站。

## 11. 需要拍板的几件事

1. **放开发工作的子页**（我按这个写）；备选是首页加一张「本周工时」的小卡。
2. **计时器全局只有一个**（在跑的时候别的入口就是「先停了它」），停止后弹窗确认再落一条
   （我按这个写，和游戏页一个体验）；备选是「停止就直接落一条」。
3. **删项目时工时跟着进回收站**（和进展一个口径）；备选是工时留下、项目名显示成
   「（项目已删）」。注意这两个不冲突：留下来的那部分（手工清掉 `projectId` 的）
   照样归到「（项目已删）」那一行。
4. **项目选填**（不填就归到「没记项目」）够不够？还是必须选一个项目？

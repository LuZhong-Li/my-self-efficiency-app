# 标签系统（一）：纯逻辑与数据地基 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把标签这件事的纯逻辑（切分、清洗、校验、颜色）和全站数据地基（每条记录一个
`tags` 数组、老数据补齐、搜索池认标签）立住；做完这一份，界面上还看不出变化，
但后面那份（录入 / 展示 / 搜索面板）要用的东西全在这儿了。

**Architecture:** `tag-calc.js` 只管标签字符串本身（无依赖、无 DOM）；「哪张表、
跳到哪里、结果长什么样」这件事已经归 `search-calc.js`，所以扫全站标签、按标签
捞记录也放那儿（它本来就管着 `SOURCE_SPECS`）；老数据补齐在服务端 `服务.py`
的 `migrate()` 里照 `imagePaths` 那套补，前端读标签一律走 `tagsOfRow()`，
服务端进程再旧也不会崩。

**Tech Stack:** 原生 ES 模块（无框架、无构建、零外链）；Python 标准库小服务；
测试用 Node（纯逻辑）+ Python（`tests/自检.py`，接口层）。

**Spec:** `docs/superpowers/specs/2026-10-11-标签系统-design.md`（动手前先读一遍）

## Global Constraints

- **零外链**：界面文件里不能出现任何 `http(s)://` 链接；`tests/自检.py` 的
  `check_no_external()` 会扫。
- **不装依赖**：Node 只用来跑 `tests\*.test.mjs`（本机 v24，直接 `node 文件名`，
  不要 `package.json`、不要 `node_modules`）。
- **上限只有一个定义**：单个标签 `TAG_MAX_CHARS = 24` 个字、一条记录
  `TAG_LIMIT = 8` 个，都写在 `tag-calc.js` 里，别处不许再写一遍数字。
- **读标签一律走 `tagsOfRow(row)`**：不要直接读 `row.tags`（老数据没有这个字段、
  手改数据可能写成别的形状）—— 这是前端那道兜底。
- **只补不改**：迁移只给「缺 `tags` 或它不是数组」的记录补空数组；
  已经是数组的原样留着，不清洗、不排序、不去重。
- **颜色不落盘**：`tagColor(name)` 算出 1..8，CSS 用 `--tag` 变量取色。
- **注释与提交信息用中文**，说清「为什么」。
- 每个任务结束：本任务对应的 `node tests\*.test.mjs` 与 `python tests\自检.py` 都要过。

**Interfaces:**
- Consumes: 无（这个文件不 import 任何东西）

  - `tagColor(name) -> 1..8`（同一个名字永远同一档）

新建 `app/web/tag-calc.js`：

```js
/* 标签的纯逻辑：标签就是记录上的一个字符串数组。
 * 设计见 docs/superpowers/specs/2026-10-11-标签系统-design.md。
 *
 * 这里只管标签自己那一层：一串文本怎么切成标签、怎么洗干净、颜色取哪一档。
 * 「哪张表、跳到哪里、跨模块怎么捞」在 search-calc.js（它本来就管着那张表清单）。
 * 不 import 任何东西，Node 里能直接跑单测。 */

/** 单个标签最多几个字（超了截断；输入框里另外给提示，见 tagInputError） */
export const TAG_MAX_CHARS = 24;

/** 一条记录最多贴几个标签 */
export const TAG_LIMIT = 8;

/** 调色板只有这几档（style.css 里 .chip.tag-chip[data-c="1"…8]） */
export const TAG_PALETTE = 8;

/** 分隔符：中英文逗号、顿号、分号、空格、换行都算 */
const SPLIT = /[,，、;；\s]+/;

/** 把输入框里那一串切开（还没洗：可能带空白、可能重复） */
export function parseTagInput(text) {
  const raw = String(text == null ? "" : text);
  return raw.split(SPLIT).filter(Boolean);
}

/**
 * 洗干净：丢掉非字符串与空白、每个截到 TAG_MAX_CHARS 个字、
 * 按「忽略大小写与首尾空白」去重（留第一次写下的那个写法）、最多留 TAG_LIMIT 个。
 * 数组或字符串都收（手改数据可能把数组写成字符串），别的类型当空。
 * 顺序不排：他自己写的顺序就是他心里的重次。
 */
export function normalizeTags(value) {
  const list = Array.isArray(value)
    ? value
    : typeof value === "string" ? parseTagInput(value) : [];
  const out = [];
  const seen = new Set();
  for (const item of list) {
    if (typeof item !== "string") continue;
    const name = item.trim().slice(0, TAG_MAX_CHARS);
    if (!name) continue;
    const key = name.toLowerCase();
    if (seen.has(key)) continue;
    seen.add(key);
    out.push(name);
    if (out.length >= TAG_LIMIT) break;
  }
  return out;
}

/** 一条记录上的标签 —— 读标签一律走这里，别直接读 row.tags（老数据没有这个字段） */
export function tagsOfRow(row) {
  return normalizeTags(row && typeof row === "object" ? row.tags : []);
}

/** 编辑时填回输入框：["工作","本周"] → "工作、本周" */
export function tagsText(list) {
  return normalizeTags(list).join("、");
}

/**
 * 行上最多画几个标签：够的话全画，多了就画前 max 个、剩下的收成 +N。
 * 抽出来单独放是因为「画 HTML」那半截在 ui.js（跑不进 Node），
 * 而「画几个、剩几个」这种算术值得单测。
 */
export function visibleTags(list, max = 3) {
  const tags = normalizeTags(list);
  const keep = Math.max(0, Math.floor(max));
  return { shown: tags.slice(0, keep), rest: Math.max(0, tags.length - keep) };
}

/**
 * 输入框里那一串有没有毛病（超量 / 单个太长）。
 * 页面上要当场告诉人，不能静默截断 —— 截断是数据层 normalizeTags 的事。
 */
export function tagInputError(text) {
  const parts = parseTagInput(text).map((s) => s.trim()).filter(Boolean);
  if (new Set(parts.map((s) => s.toLowerCase())).size > TAG_LIMIT) {
    return `最多 ${TAG_LIMIT} 个标签`;
  }
  if (parts.some((s) => s.length > TAG_MAX_CHARS)) {
    return `单个标签最多 ${TAG_MAX_CHARS} 个字`;
  }
  return "";
}

/** 名字 → 调色板第几档（1..TAG_PALETTE）。同一个名字永远同色，颜色不落盘。 */
export function tagColor(name) {
  const key = String(name == null ? "" : name).trim().toLowerCase();
  let hash = 0;
  for (let i = 0; i < key.length; i += 1) {
    hash = (hash * 31 + key.charCodeAt(i)) % 1000003;
  }
  return (hash % TAG_PALETTE) + 1;
}
```

④ 文件末尾加两个导出：

```js
/**
 * 全站有哪些标签、各用了多少次。
 * 只数没归档的 —— 和搜索池一个口径（归档了就是不希望它再冒出来），
 * 这样点一个标签至少能捞到一条，不会点出一片空。
 * 排序：用得多的在前，一样多按名字。标签不落盘，每次现算。
 */
export function allTags(data) {
  const count = new Map();
  const spelling = new Map();
  for (const item of buildSearchPool(data)) {
    if (item.archived) continue;
    for (const name of item.tags) {
      const key = name.toLowerCase();
      count.set(key, (count.get(key) || 0) + 1);
      if (!spelling.has(key)) spelling.set(key, name);
    }
  }
  return [...count.entries()]
    .map(([key, n]) => ({ name: spelling.get(key), count: n }))
    .sort((a, b) => b.count - a.count || (a.name < b.name ? -1 : 1));
}

/**
 * 按标签捞记录：结果形状和 searchAll 一模一样（module / hash / label / text），
 * 所以搜索面板那套「画卡片、点一下跳模块」的代码一行都不用改。
 * 正文给的是标签自己那个写法，不是拿用户敲的那份（大小写要跟记录一致）。
 */
export function searchByTag(data, tag, includeArchived = false) {
  const want = normalizeText(tag);
  if (!want) return [];
  const hits = [];
  for (const item of buildSearchPool(data)) {
    if (item.archived && !includeArchived) continue;
    const hit = item.tags.find((name) => normalizeText(name) === want);
    if (!hit) continue;
    // 关键词是在「贴了这个标签的这批」里再筛一道（不是二选一），所以面板上
    // 「标签 + 关键词」叠加时，看到的永远是这个标签里的命中。
    if (kw && !item.hay.includes(kw)) continue;
    hits.push({ module: item.module, hash: item.hash, label: item.label, text: hit });
  }
  return hits;
}
```

（`searchByTag` 的签名是 `(data, tag, includeArchived = false, query = "")`，
函数体开头加一句 `const kw = normalizeText(query);`。）

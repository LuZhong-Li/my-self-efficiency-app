# 小李 · 模块目标（健身 / 学习 / 饮食）设计

2026-10-07。本文说「模块目标是什么、存哪、怎么自动变成今日计划里的待办」，
不写实施步骤（实施步骤见 `docs/superpowers/plans/2026-10-07-模块目标.md`）。

## 0. 背景与这个版本的边界

现在三个模块只有「记录」，没有「目标」：

- 健身页能打卡、能记体重，但「我要练成什么样、一周练几次」没地方写；
- 学习页能记时长和心得，但「每天学两小时」这件事只在你脑子里；
- 饮食页能记三餐和喝水，但「一天 8 杯水」没有人盯着。

于是每个模块各加上一条**模块级目标**：写在模块里、能带周期和起止日期、
能按一句人话规则**自动往「今日计划」里生成待办**，并且能看进度。

**两个概念分开，别混：**

| | 模块目标 | 待办任务（tasks） |
| --- | --- | --- |
| 是什么 | 模块级配置，长期的 | 单次执行项，某天做完就完了 |
| 存哪 | `data.moduleGoals` | `data.tasks` |
| 谁产生 | 你自己在模块页设置 | 你手动加，或目标按规则自动生成 |
| 举例 | 「三个月减 8kg，每周力量 3 次」 | 「10-07 力量训练」（今天这条） |

**这个版本做：**

1. 三个模块页顶部一张「🎯 当前模块目标」卡片（健身 / 学习 / 饮食）
2. 新增 / 编辑目标共用一个弹窗（复用 `openDialog` 那套液态玻璃壳）
3. 进「今日计划」时按规则自动生成当天的待办，带只读的来源标签
4. 目标的进度统计（健身按次、学习 / 饮食按天）+ 一条进度条
5. 今日计划顶部一条目标摘要；一个模块支持多条目标（可选增强里的第 1 条）

**这个版本不做：** 目标归档与历史目标、目标提醒推送、进度图表、
把目标同步到首页卡片、目标之间的依赖关系。

## 1. 已定的决定（逐条有出处）

| 决定 | 选择 | 为什么 |
| --- | --- | --- |
| 存哪 | 顶层新增 `moduleGoals`，按模块 id 分桶，每桶一个数组 | 用户定稿要求「目标独立存储、和待办笔记分离」；用数组是为了支持一个模块多条目标（可选增强第 1 条），`moduleId` 也照定稿写在每条目标里 |
| 一个模块几条 | 多条 | 用户可选增强第 1 条；数组天然支持，多花不了几行代码，删除按钮也就有了明确含义 |
| 三个模块 | 健身 / 学习工作 / 饮食计划 | 定稿正文与界面设计两处都点了这三个；标题里的「记账」没有对应的进度口径（记账是流水，不是目标），这次不做 |
| 弹窗怎么复用 | `openItemDialog("moduleGoal")` | 定稿交互规范第 2 条点名要这个函数；于是往 `item-form.js` 加一个类型，弹窗底层一行没另写 |
| 目标存哪张表 | 不在普通表里，按桶存 | `item-dialog.js` 加两个小钩子：`persist`（怎么落盘）、`trashPlan`（怎么移出），其它类型一行没动 |
| `isActive` 和「自动生成」 | 两个开关分开 | 定稿字段说明里 `isActive` 管「关了就不生成」，交互规范里又要求一个「自动生成任务」开关；两个都要有，于是都留着，两个都开才会生成 |
| 自动生成的时机 | 进「今日计划」页面时 | 定稿第 3 节第 1 条 |
| 防重复生成 | `genKey`（目标 id + 日期 + 第几条规则）+ `goal.lastRun` | 前者挡同一批规则的重复；后者挡「今天已经对过表了」——你自己删掉的那条不会又被加回来 |
| 删目标 | 只删这条配置，待办一条不动 | 定稿第 5 节第 3 条（防止丢数据）；因为不进回收站，删除确认里把这件事写清楚 |
| 自动生成的待办能不能改 | 正文能改，来源标签只读 | 定稿第 3 节第 1 条；`sourceModule / goalId / genKey` 是数据字段，不在表单里，改正文不会把它们冲掉 |
| 进度口径 | 该目标生成过的待办里完成了多少 | 定稿第 3 节第 2 条（完成数 ÷ 计划数）；只数这条目标自己生成的，手动加的普通待办不掺进来 |
| 健身 / 学习 / 饮食的口径 | 健身「次」，学习 / 饮食「天」 | 定稿第 3 节第 2 条给了健身按次、学习按天；饮食同理按天 |
| 卡片放哪 | 各模块页最上面，日历之上 | 定稿第 6 节的页面布局示例 |
| 删除 / 编辑后 | 就地重画当前页 | 项目里所有模块都是这个路子（`bindFresh` + 重画） |

## 2. 数据结构（写进 `数据.json`）

```json
"moduleGoals": {
  "fitness": [
    {
      "id": "8f2c…",
      "moduleId": "fitness",
      "moduleName": "健身计划",
      "mainTarget": "3 个月减重 8kg，每周力量训练 3 次，有氧 2 次",
      "cycle": "月度",
      "startDate": "2026-10-07",
      "endDate": "2027-01-07",
      "dailyRule": "每周一、三、五力量训练；周二、四有氧",
      "remark": "训练后记录体重、感受",
      "isActive": true,
      "autoTask": true,
      "lastRun": "2026-10-07"
    }
  ],
  "study": [ /* … */ ],
  "diet": [ /* … */ ]
}
```

| 字段 | 说明 |
| --- | --- |
| `mainTarget` | 核心目标文本（弹窗里必填） |
| `cycle` | 每日 / 每周 / 月度 / 自定义起止日期 |
| `startDate` / `endDate` | 起止日期，可以只填一个（不填就是不限） |
| `dailyRule` | 自动生成待办的规则（重点！一句人话，见 §3） |
| `remark` | 备注 |
| `isActive` | 目标开关；关掉就不生成 |
| `autoTask` | 自动生成任务开关；关掉就只当备忘，不生成 |
| `lastRun` | 上一次对表的日期，防止同一天重复生成 / 删掉又补回来 |

自动生成的待办就是在 `tasks` 里多三个字段：

```json
{ "date": "2026-10-07", "text": "力量训练", "category": "运动", "belong": "goal",
  "sourceModule": "fitness", "goalId": "8f2c…", "genKey": "8f2c…@2026-10-07#0" }
```

## 3. 自动任务规则怎么解析（一句人话 → 待办）

规则是给**你**写的，不是给程序写的，所以按「分号 / 句号 / 换行」切开之后逐条认：

| 规则里写了 | 认成 | 生成在 |
| --- | --- | --- |
| `周一` `星期一` `礼拜天` `周1` | 星期几 | 那一天 |
| `每周一、三、五` / `每周一三五` / `周一和周三` | 一组星期几 | 那几天 |
| `每天` `每日` `天天` | 每天 | 每天都生成 |
| `每月 1 号` `每月十五号` | 每月几号 | 每个月那一天 |
| 什么都没写 | 按目标周期兜底：每日 → 每天；每周 → 开始日期那天起每周；月度 → 开始日期那个号 | — |

任务文字就是规则里**剩下的那半句**，顺手去掉「自动生成 / 到今日计划 / 待办」
这些连接词和 `【】` 标记（圆括号里的补充说明保留，那是有用信息）。

例子：

| 规则 | 周一 | 周三 | 周日 |
| --- | --- | --- | --- |
| `每周一、三、五力量训练；周二、四有氧` | 力量训练 | 力量训练 | — |
| `晚 7 点-9 点学习`（周期：每日） | 晚 7 点-9 点学习 | 同左 | 同左 |
| `每月 1 号交房租` | — | — | — |

## 4. 界面

### 4.1 模块页顶部（健身 / 学习 / 饮食）

```
🎯 当前模块目标                                    [共 2 个目标] [+ 新增目标]
3 个月减重 8kg，每周力量 3 次、有氧 2 次
[月度 · 2026-10-07 → 2027-01-07] [自动进今日计划]   已完成 3 / 12 健身 · 25%
自动生成：每周一、周三、周五 力量训练；每周二、周四 有氧
备注：训练后记录体重、感受
▓▓▓▓▓░░░░░░░░░░░░░░░░
编辑目标   查看目标进度   删除
[日历组件（原有，保留不动）]
```

点「查看目标进度」就地展开一小块：累计进度 + 本周完成 + 这条目标生成过的待办
（最多 8 条，勾选状态一眼看得见）。展开状态只记在内存里，切页面就收起来。

一条目标都没有时，卡片给一句空状态 + 「新增目标」按钮，不留空壳。

### 4.2 编辑目标弹窗（新类型 `moduleGoal`）

标题「设置模块目标 / 修改模块目标」，字段顺序：

1. 所属模块（**只读**的一行，自动填「健身计划 / 学习工作 / 饮食计划」）
2. 核心目标（多行，必填）
3. 目标周期（每日 / 每周 / 月度 / 自定义起止日期）
4. 开始日期、结束日期（并排，结束日期可不填）
5. 自动任务规则（多行）
6. 备注（多行）
7. 启用目标（开关）、自动生成任务（开关）—— 并排

底部按钮：删除（编辑时才有）| 取消 | 保存。样式、Esc、点遮罩关、回车保存、
Tab 绕圈全部沿用 `openDialog`；这个弹窗**没有图片区**（目标不需要截图），
所以 `item-dialog.js` 里加了「没有 `upload` 就不装配件区」这条。

### 4.3 今日计划

- 顶部一条目标摘要：`🎯 今天的模块目标：健身：力量训练 ｜ 学习：晚 7 点-9 点学习`
  （今天没有目标要做就整条不渲染）
- 自动生成的待办在行上多一个来源标签 `健身目标任务`（只读标记）；
  正文照样能编辑（还是那个「修改任务」弹窗）、能勾、能删

## 5. 和原有待办的分界

| | 项目里的待办（`belong: dev:<项目 id>`） | 目标自动生成的待办（`belong: goal`） |
| --- | --- | --- |
| 出现在今日计划吗 | 不会（原有逻辑不动） | 会 |
| 谁删 | 在开发工作页删 | 在今日计划里删 |
| 删了目标会怎样 | — | 待办留下，只是不再自动生成新的 |

## 6. 边界与空状态

| 情况 | 表现 |
| --- | --- |
| 一条目标都没有 | 卡片空状态 + 「新增目标」 |
| 目标关掉（`isActive: false`） | 卡片上打「已停用」标签，不再生成 |
| 只关「自动生成任务」 | 卡片上打「不自动生成」标签，目标还在，进度照算 |
| 规则没写时间词、周期是每日 | 每天都生成 |
| 规则没写时间词、周期是每周 / 月度、又没填开始日期 | 不生成（宁可不生成，也不瞎生成） |
| 今天不是这条目标的日子 | 一条都不生成，摘要里也不提它 |
| 同一天多次进今日计划 | 只生成一次；你删掉的那条不会被补回来 |
| 改了规则 | 第二天按新规则走（当天已经对过表了） |
| 手写了 `moduleGoals` 是个数组 | 读的时候按 `moduleId` 归成桶，一条都不丢 |
| 老数据没有 `moduleGoals` | 读出来自动补一个空对象 |

## 8. 写进文档的取舍要点

> 健身 / 学习 / 饮食三个模块各有**模块级目标**：周期、起止日期、一句自动任务规则。
> 目标开着「自动生成任务」时，进「今日计划」会按规则生成当天的待办（带只读的
> 来源标签，正文能改、状态独立记录）；目标卡片上能看到进度和本周完成情况。
> 项目里的待办仍然只属于项目，不会跑到今日计划里。
> 删目标只删配置，已经生成的待办一条不动。

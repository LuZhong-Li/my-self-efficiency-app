# 图片附件（记账 / bug 登记 / 笔记共用）设计（2026-10-07）

## 要解决的问题

记账记完就想不起来那笔钱到底花在哪儿了，「午饭 黄焖鸡」这种文字备注远不如一张
付款截图；开发工作里的 bug 也一样，报个错不贴一张截图，过两天自己都看不懂。

这次给「记一笔」和 bug 登记加上**可选的图片备注**，并且把它做成一套三个模块
（记账 / bug 登记 / 笔记）直接复用的零件。核心约束只有一条：

> **图片独立存在本地文件夹里，`数据.json` 只存相对路径。**

原因是主数据文件这个「一个文件最好备份、最好搬走」的定位：

- base64 塞进 JSON 会让文件膨胀三分之一以上，几千字节的账目文件转眼几兆；
- `数据.json` 现在还能直接打开看，塞满二进制就没人看得懂了；
- 图片坏没坏、丢没丢是文件的事，不该连累整份数据读不出来。

## 一、数据

### 1.1 记录上的新字段

```
finance.transactions[].imagePaths = ["attachments/finance/20261007_ab12cd34.jpg"]
issues[].imagePaths               = ["attachments/buglog/20261007_ef34ab56.png"]
```

- 一律是数组，可以多张；空数组 `[]`（没图片）和字段缺失都算「没图片」。
- 存的是**相对路径**，不带盘符、不带 `数据\` 前缀，所以数据目录整体搬到别的盘照旧能认。
- 老记录读出来时由 `服务.py` 的 `migrate()` 自动补一个 `imagePaths: []`，
  页面那边就不用到处判空。旧数据一个字段都不动。

### 1.2 新设置

```
settings.attachments = {
  "pruneOnDelete": false,   ← 彻底删掉一条记录时，要不要连图片一起删（默认保留）
  "maxEdge": 1920           ← 图片压缩档位：长边上限，0 = 原图不缩
}
```

认得出就用，认不出（手改坏了）退回默认值，见 `attachment-calc.js` 的
`normalizeAttachSettings()`。

### 1.3 文件放哪

```
数据/
  数据.json          主数据：只存路径
  attachments/       图片本身就放在这儿
    finance/         记账
    buglog/          bug 登记
    note/            笔记（组件已经支持，模块还没做）
```

**这里和最初那份需求文档有一处不同**：文档里写的是「程序根目录下建
`attachments/`」，实际放在**数据目录**下面（默认就是 `D:\小李\数据\attachments\`）。

这么定的三个理由：

1. `同步到小李.cmd` 和 `.gitignore` 本来就把 `数据\` 整个排除在外，
   图片放在里面不用再改这两处，也不会跟着代码同步到另一份去；
2. 备份逻辑现在是「复制整个 `数据` 目录」，图片自动跟着走，
   设了 `XIAOLI_DATA_DIR` 搬到别的盘时也是数据 + 图片一起搬；
3. 数据目录是「运行时的东西」，程序目录是「代码」，图片属于前者。

相对路径的写法（`attachments/finance/…`）和文档里一致，所以真要挪到程序根目录，
改的只是服务端 `ATTACH_DIR` 一个常量。

### 1.4 文件名规则

```
yyyyMMdd_随机串.扩展名      例：20261007_ab12cd34.jpg
```

- 日期让文件夹里按天挨着排，随机串（8 位十六进制）保证不撞名；
- 扩展名白名单只有 `png / jpg / webp`；
- **规则不只是好看**：服务端 `attach_parse()` 拿它当白名单用（见 §5.4）。

## 二、服务端（`app/服务.py`）

三个新东西，都只用标准库：

| 接口 | 干什么 |
| --- | --- |
| `GET /attachments/<模块>/<文件名>` | 把图片发给浏览器；路径先过白名单，`..` 一律 403 |
| `POST /api/attachment` | 收一张图（JSON + base64），落盘，返回该存进 JSON 的相对路径 |
| `POST /api/attachment-delete` | 删几张图；返回 `deleted / missing / refused` |

另加两处小改：`/api/health` 带上 `attachDir`、`attachCount`、`attachBytes`（设置页显示占用）；
`/api/open-folder` 多认一个 `attach`。

为什么用 JSON + base64 而不是 multipart：`cgi` 模块在 Python 3.13 已经删了，
为一两张图自己拆 multipart 不值当；一次只收一张，体积上限走现成的 `MAX_BODY`。
服务端另外卡一道 12MB（`ATTACH_MAX_BYTES`），防手写的请求塞垃圾进来。

## 三、前端：两个文件

### 3.1 `app/web/attachment-calc.js`（纯逻辑，能被 Node 直接单测）

三个模块共用，命名规则 / 压缩口径 / 路径校验只要错一处就是三处一起错，
所以全抽成不碰 DOM 的纯函数：

| 函数 | 作用 |
| --- | --- |
| `normalizeAttachSettings(raw)` | 设置读出来先规整；认不出退回默认 |
| `checkImageFile({type,size,name})` | 收不收这个文件（类型白名单 + 30MB 硬上限） |
| `fitEdge(w, h, maxEdge)` | 长边缩到档位，等比；0 或本来就小就原样 |
| `decideEncode({...})` | 这张图要不要重新画：缩尺寸？重新编码？输出什么格式？ |
| `uniqueName(date, rand, ext)` / `attachmentPath(module, file)` | 命名规则 |
| `parseAttachmentPath(path)` | 路径解析 + 白名单校验，不合法给 `null` |
| `rowPaths(row)` | 老数据的 `imagePaths` 安全读取（不是数组就当空） |
| `viewerStep(index, total, delta)` | 查看器翻页，到头绕回另一头 |

**压缩口径**（值得记住的三条）：

- 长边超档位 → 缩；单张超 1.5MB → 重新编码一次；两条都不占 → **原样存**，
  不动像素也不动格式（真截图一般是这种情况）；
- png / webp 尽量保持原格式（截图重新压成 jpg，字会糊）；
  png 重新画完还超 2MB 的话，再压一版 jpg 比一比，谁小用谁；
- 单张上限 10MB 卡在**压完之后**：12MB 的手机照片照样收，压完通常只剩几百 KB。
  挑进来就超过 30MB 的才直接拒（压起来又慢又吃内存，不如先自己处理一张）。

### 3.2 `app/web/attachment.js`（画和接事件）

对外的几个零件：

| 导出 | 谁用 |
| --- | --- |
| `createAttach({module, paths, files})` | 记账弹窗、bug 表单：攒住「已存下的路径 + 刚挑进来还没写盘的图」 |
| `mountAttach(host, state)` | 把附件区挂到一个空 div 上；同一个 host 再挂只是重画，事件不会叠两遍 |
| `thumbsHtml(paths)` | 只读的缩略图行，记账明细 / bug 行用；没有图就返回空串 |
| `uploadPending(state)` / `commitUploads(state, done)` | 保存时才真的写盘 |
| `deleteAttachments(paths)` / `purgeRowAttachments(row)` | 删文件；后者会看设置开关，并且跳过「还有别人在引用」的路径 |
| `openViewer(items, index)` | 全屏看图 |

缩略图的点击和「图片读不出来」是**全局代理**（挂一次，谁身上有 `.thumb` 就归它管），
因为缩略图散在弹窗、列表好几个地方，一个个绑太碎。

## 四、交互

### 4.1 「记一笔」弹窗

备注下面多一块附件区：`＋ 添加图片备注` 按钮（原生 `<input type="file" multiple>`，
`accept="image/png,image/jpeg,image/webp"`）+ 缩略图列表 + 一行小字说明。

- 缩略图右上角一个 ×，单独移除这一张，不关弹窗；
- 点缩略图开全屏查看，左右翻页、Esc 关；
- **点「保存」才真的写盘**，顺序是「先写图片 → 再存 JSON」；
- **点「取消」一个字节都不会落盘**：挑进来的图只在内存里（blob + 预览地址），
  关弹窗时把预览地址还回去，不会攒一堆没人认领的图片。

弹窗里图片多了会变高，所以 `.dlg` 顺带改成「中间那块自己滚，标题和按钮始终看得见」——
改之前加了附件区之后「保存」会被顶到窗口外面点不着（实测窗口 764px、弹窗 902px）。

### 4.2 记账列表

当日明细的每一行，备注下面铺一行小缩略图；**没有图片就什么都不渲染**，
不会留一块空白。点缩略图看大图（多张能翻页）。

### 4.3 bug 登记

同一套组件，只是 `module` 换成 `buglog`，图片存进 `attachments/buglog/`：

- 「添加问题」那一行下面多了附件区；挑好的图先存在模块变量里，中途重画不会丢；
- 问题的行内编辑里也能加图 / 单独移除；
- 列表行同样在标题下面显示缩略图。

### 4.4 设置页

「数据与设置 → 图片附件」：附件目录在哪、一共有多少张占多少地方、当前档位，
以及两个开关：**彻底删除记录时要不要连图片一起删**、**压缩档位**（1080P / 2K / 原图）。
另有一个「打开附件文件夹」。

## 五、边界与兜底

### 5.1 旧数据

没有 `imagePaths` 的历史记录读出来自动补 `[]`，页面不判空也不会报错；
`settings.attachments` 缺了补默认值。旧数据一个字段都不会丢。

### 5.2 图片丢了

路径还在、文件被手动删了 / 挪走了：缩略图变成虚线占位「图片丢失」，
全屏查看里显示「图片丢失」，条目本身照常显示、照常能编辑。靠 `img` 的
`error` 事件（捕获阶段）记下来，不弹错、不崩。

### 5.3 回收站联动

- 记录移进回收站：图片**一个都不动**（回收站里那条还认领着自己的图）；
- 回收站里「彻底删除」/「清空回收站」：看设置开关。开着就删文件，
  关着（默认）就留在文件夹里，误删了还能找回来；
- 删文件之前会先扫一遍整份数据，**还有别的记录（或回收站里的记录）在引用这张图就不删**，
  免得导入 / 还原出来的两份数据互相删图；
- 单独从一条记录上移除某张图，跟着同一个开关走。

### 5.4 外面递进来的路径不可信

`/api/attachment-delete` 和 `GET /attachments/...` 收到的字符串一律先过
`attach_parse()`：目录必须是 `attachments`、模块必须在白名单里、
文件名必须长成「8 位日期_字母数字.白名单扩展名」。
所以 `attachments/finance/../../数据.json` 这种一定过不了，返回 403。

### 5.5 写盘顺序

先写图片（`.tmp` → `os.replace`，和 `数据.json` 一个规矩），再整份替换
`数据.json`。中间有一张失败就把前面写进去的删掉再报错，不留半截。

## 六、备份与搬运

备份逻辑一行都不用改：图片在 `数据\` 下面，复制整个数据目录（或者 U 盘整体拷走）
就是数据 + 图片一起走。设 `XIAOLI_DATA_DIR` 换盘同理。

## 七、这一版做到哪

**做了（原文档的 P0）**：弹窗里的上传 / 多图预览 / 单图移除；本地附件文件夹 +
JSON 只存路径；全屏查看（多张能翻页）；旧数据兼容；记账列表显示缩略图；
bug 登记复用；设置页的两个开关。

**顺手做的**：设置页显示附件占用、打开附件文件夹；演示数据配两张假的小票截图。

**没做（原文档的 P1）**：拖拽上传、图上写字、批量导出、首页卡片上的图片小标记。

**原文档里的第三条设置项（自定义附件文件夹路径）也没做**——真要换地方，
现在是用 `XIAOLI_DATA_DIR` 把整个数据目录挪走，附件跟着走；
单独给附件换一个盘的收益不大，先放着。

  非法模块 / 非法格式 / `..` 穿越 / 非法文件名一律被拒 → 删除 →

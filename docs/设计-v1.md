### 2.1 前端约定（第 5 步起）

- 一个模块一个文件：`app/web/<模块>.js`，导出 `render<模块>(root)`；
  公共小零件（区块标题、标签、下拉选项）放在 `ui.js`。
- 地址用哈希路由：`#dev` 是项目列表，`#dev/<项目id>` 是项目详情，
  刷新后还能停在同一个项目里。
- **项目待办就存在 tasks 表里**：`belong` 写成 `dev:<项目id>`、`date` 留空。
  今日计划和首页只认 `date` 有值的任务，所以它们不会混进来（改这两处的
  筛选条件时要记得带上 `date` 非空判断）。
- 行内编辑：每个模块自己记一个「正在编辑谁」，改完 `touch(true)` 立刻落盘。
- **事件不要挂在公共的 `#view` 上**，用 `ui.js` 里的 `bindFresh(root, {...})`：
  每次渲染把内容包进一层新容器，事件挂在这层，旧容器的监听随旧 DOM 一起丢掉。
  早先图省事挂在 `#view` 上（加了个「只挂一次」的开关），结果切到别的模块后旧
  监听还在：自媒体和今日计划的表单 id 都叫 `add-form`，提交其中一个，另一个
  模块的处理函数也会跟着跑、去读不存在的字段，控制台刷出一堆 TypeError。
- **输入框自动保存要挂两个事件**：打字走 `input`（`touch(false, true)` 静默保存，
  只写数据不重画，光标才不会跳），离开输入框走 `change`（正常保存 + 重画，
  顺便刷新下面的列表）。只挂 `change` 的话，用户没离开输入框就关窗口会丢字。
  例外：数字类的「保留份数」只挂 `change`，因为敲到一半（比如想打 12，
  先出现 1）就去清理备份是破坏性的。

## 3. 运行与技术约束

- 运行时：Python 3.14（python.org 正式安装版），只用标准库。
  **注意：不能用 `D:\msys64\ucrt64\bin\python.exe`**，原因见下面 3.1。
  `启动.cmd` 自己会挑一个能用的 Python，不用手填路径。
- 浏览器：Edge（本机已装）。
- 服务只监听 `127.0.0.1`，端口从 8765 开始；万一 8765 被占用就依次试
  8766、8767……最多试 12 个。局域网和外网都访问不到。
- 界面零外链：不引用任何 CDN、在线字体、在线图标，断网也能正常打开。
- 前端不引框架：原生 HTML + CSS + JS（个人自用规模，框架只会增加维护负担）。
- 关掉黑窗口 = 程序停止；此时数据早已落盘，下次双击继续。

### 3.1 本机实测结论（第 1 步验收时发现）

- **这台电脑的「智能应用控制」（Smart App Control）是开启状态**
  （注册表 `HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy` 的
  `VerifiedAndReputablePolicyState = 1`）。
- MSYS2 那份 Python（`D:\msys64\ucrt64\bin\python.exe`）本身能启动，但它的
  `.pyd` 扩展文件没有数字签名，被系统策略拦下，连 `import struct` 都失败，
  自然也就 `import http.server` 不了 —— 原来打算拿它当运行时的方案作废。
- 可用的替代：python.org 正式安装版（有签名，实测通过）。本机有两份：
  `%LOCALAPPDATA%\Programs\Python\Python314\python.exe`（默认）和
  `...\Python312\python.exe`。
- `启动.cmd` 因此不写死路径，而是按顺序试：用户目录下的 python.org 安装 →
  Program Files → PATH 里的 python → 最后才试 msys2 那份；每个候选都先跑一次
  `import http.server, json, mimetypes, webbrowser, urllib.request`，
  真能导入才采用。
- `启动.cmd` 里的 `chcp 65001` 不能删：脚本要启动的文件名「服务.py」是中文，
  批处理文件按 UTF-8 保存，必须让控制台切到 UTF-8，cmd 才能正确读到中文名。

## 4. 数据怎么存

- 全部数据放一个 JSON 文件：`数据\数据.json`。
- 写入策略：先写临时文件、再替换（原子写），避免写一半断电把文件弄坏。
- 自动备份：每天首次打开时复制一份到 `数据\备份\YYYY-MM-DD.json`，保留最近 14 份。
- 设置页提供：导出备份 / 导入恢复 / 打开数据文件夹 / 清空数据（二次确认）。

### 4.1 接口一览（本机服务）

| 方法 | 地址 | 干什么 |
| --- | --- | --- |
| GET | `/api/health` | 服务信息：数据文件位置与大小、备份目录、导出目录 |
| GET | `/api/data` | 取整份数据 |
| POST | `/api/data` | 整份写回（日常唯一写入口） |
| GET | `/api/backups` | 备份文件列表（名字、大小、时间、类型） |
| POST | `/api/backup` | 立刻备份一份，名字形如 `手动-2026-10-06-155720.json` |
| POST | `/api/export` | 导出到 `数据\导出\备份-时间.json` |
| POST | `/api/import` | 用传上来的 JSON 覆盖数据，覆盖前自动存 `导入前-*.json` |
| POST | `/api/clear` | 清空数据，清空前自动存 `清空前-*.json` |
| POST | `/api/open-folder` | 在资源管理器里打开数据 / 备份 / 导出文件夹 |

两条踩过的坑，改代码时别踩回去：

1. **POST 处理函数必须先把请求体读干净再干活。** HTTP/1.1 是长连接，留在
   缓冲区里的字节会被当成下一个请求的开头，于是下一个请求莫名收到 400 和
   一张 HTML 错误页（第 3 步踩过一次：点「立即备份一次」后备份列表就报错）。
2. **保留份数按文件修改时间排序。** 备份要用 `shutil.copyfile` 而不是 `copy2`，
   否则备份文件会继承数据文件的时间，排序和显示都会乱。

### 5.1 tasks 的实际字段（第 2 步已落地）

上面那张表是「概念」，真正写进 `数据.json` 的是这些键：

| 键 | 类型 | 说明 |
| --- | --- | --- |
| `id` | 字符串 | 唯一标识，浏览器生成（`crypto.randomUUID`） |
| `date` | `"YYYY-MM-DD"` | 归属哪一天；今日计划里的任务就是今天 |
| `text` | 字符串 | 内容 |
| `time` | `"HH:MM"` 或 `""` | 时间点，可空；空的排在有的后面 |
| `category` | `工作` / `生活` / `运动` / `其他` | 固定四类 |
| `done` | `true` / `false` | 是否完成 |
| `note` | 字符串 | 备注 |
| `belong` | 字符串 | 归属模块，今日计划固定用 `"plan"` |
| `createdAt` | ISO 时间 | 创建时间，同一时间点的排序依据 |
| `doneAt` | ISO 时间或 `null` | 完成时间 |

前端约定：任何修改都「改内存 → 叫一声 `touch()` → 自动写回整份 JSON」。
增删改这类明确动作立刻落盘，勾选和连续输入走 400ms 防抖。

数据文件里除业务字段外，还有几个系统键：

| 键 | 说明 |
| --- | --- |
| `version` | 数据格式版本，写死的 1；服务端靠它判断「这是不是本程序的数据」 |
| `rev` | 修订号，每写一次加一；两个窗口互相覆盖就靠它挡住 |
| `updatedAt` | 最后一次写入时间 |
| `trash` | 回收站，见第 11 节；最多 200 条 |

## 8. 两个注意事项

- D 盘是固定盘，比 U 盘稳；但仍建议偶尔把导出文件放到别的地方（比如网盘或另一块盘）。

  真想把数据放到别处，设环境变量 `XIAOLI_DATA_DIR` 指过去就行。

### 11.1 回收站（不会再删了就没了）

- 所有模块的删除都改成「挪进回收站」：记录存进 `trash` 数组，附上来自哪张表、

### 11.2 两个窗口不再互相覆盖

双击两次启动文件会开两个标签页，两边各拿一份数据，早先后保存的会把先保存的顶掉。

- 数据里加了 `rev`（修订号），每写一次加一；页面读取时是多少，写回来就必须是多少，
  对不上服务端回 409 并拒收，页面自动重新载入并提示。
- 保存成功后用浏览器自带的 `BroadcastChannel` 通知其它窗口；
  其它窗口没有未保存改动就自动同步，有未保存改动就提示「刷新一下更稳妥」。

### 11.3 重要备份不会被自动清理

- 备份列表每条多了「长期保留」按钮，标了之后文件名加 `保留-` 前缀，
  自动清理时跳过它，再点一下取消。

### 11.4 运行日志

- 关键事件写进 `数据\日志\运行.log`：启动、停止、每日/手动备份、导出、导入、
  清空、被拒绝的写入、备份标记。**不记每次普通保存**，免得刷屏。
- 超过 1MB 自动轮换成 `运行.log.1`。

### 11.5 写接口只认本机页面

- 别的网站在你浏览器里也能往 `127.0.0.1` 发请求。现在写接口会看 `Origin`，
  不是 127.0.0.1 / localhost 的一律 403；本机脚本（curl 等）没有 Origin，放行。

### 11.6 数据位置可指定 + 一键自检

- 设环境变量 `XIAOLI_DATA_DIR` 可以把数据放到别的盘；`XIAOLI_PORT` 或
  `--port 8899` 可以换端口。
- 新增 [自检.cmd](../自检.cmd)（背后是 [tests/自检.py](../tests/自检.py)）：
  在临时目录里自己起一个服务跑 23 项检查——接口、修订号、来源校验、备份、

## 13. 月历（2026-10-06）

  - 计划发布的，可以点「标记已发布」——按**你正在看的那一天**记为发布日，

## 15. 四套外观（皮肤，2026-10-06）

参考木子工作台的三套 appearance（Liquid Glass / Notion 笔记 / Neo-Brutalism，
它用 `data-appearance` 覆盖一整套 token）。小李照这个思路做了**皮肤**：

```
data-skin   = glass | default | notebook | neo   ← 长什么样
data-theme  = light | dark                       ← 亮还是暗（已经是「算完」的结果）
settings.themeMode = light | dark | system       ← 明暗是怎么定的（2026-10-07 加）
```

两个维度**互相独立**，4 × 2 = 8 种组合。切换只改 CSS 变量，不碰任何数据和接口；
皮肤存在 `settings.skin`，刷新、重启都还在。**没设置过就是「液态玻璃」**。

`themeMode` 是「策略」，`data-theme` 是「结果」：选浅色 / 深色就固定住，
选 `system` 就用 `window.matchMedia('(prefers-color-scheme: dark)')` 读系统偏好，
并挂上 `change` 监听——改电脑的明暗，App 立刻跟着变（从后台回来、睡眠唤醒后再补读一次）。
读不到这个特性的极老浏览器按浅色兜底。老的 `settings.theme` 继续留一份「当前实际明暗」，
老数据文件也读得懂；老文件里没有 `themeMode` 时，按 `theme` 迁一次并补进内存，
下次一保存就自动写上新字段。

| 皮肤 | 定位 | 关键做法 |
| --- | --- | --- |
| 液态玻璃（默认） | macOS Tahoe 风，通透磨砂、悬浮分层 | 纯 CSS 渐变壁纸 + `backdrop-filter` 磨砂 + 半透白底 + 细白高光边 + 18px 统一圆角 |
| 极简 | 柔和圆角、轻阴影 | 大卡片 16px 圆角，一档轻阴影，靛蓝主色 |
| 笔记 | 紧凑画布、纯平表面、低饱和标记 | 圆角 3px、无阴影、发丝线、墨色主色（#37352f）、标签变成小方块、卡片内边距收紧 |
| 粗野 | 多色印刷、硬边框、机械反馈 | 直角、2px 硬边框、`4px 4px 0` 硬投影、珊瑚红主色、按下时整体位移 3px（像真的按下去） |

### 15.0 液态玻璃细说

玻璃要好看，**前提是有东西可透**——铺在纯色上磨砂是看不出效果的。所以：

1. **壁纸**：`html` 上铺四团柔和光斑 + 一条斜向渐变的底色，纯 CSS 画的，
   零图片零外链。深色模式换成一整套深蓝紫的夜景色。
2. **分层悬浮**：`body` 加 10px 内边距和间隙，顶栏 / 侧栏 / 状态栏从「贴边通栏」
   改成**独立的圆角玻璃面板**——这是 macOS 那种「一个个窗口浮着」的关键。
3. **磨砂**：`backdrop-filter: blur(22px) saturate(170%)`，只加在卡片、面板、
   对话框这些「大面」上；按钮、标签这类小东西只用半透明底色，省性能。
4. **边缘与深度**：1px 半透明白边模拟玻璃边缘反光，阴影是
   `0 8px 30px rgba(15,23,42,.12)` 再加一道内阴影模拟顶部高光。
5. **列表分隔线**：玻璃上白线会糊成一片，所以单独抽了 `--divider`，
   玻璃皮肤里它比面板边更淡（浅色下是 8% 的黑）。
6. **两种自动降级**：老浏览器不支持 `backdrop-filter` 时（`@supports not`），
   自动换成「稍微不透明的半透卡片」；系统开了「减少透明度」
   （`prefers-reduced-transparency`）就彻底换成不透明，跟 macOS 一个脾气。
7. **动效**：0.2s 匀速的 hover / 按压，卡片悬浮上浮 2px、阴影散开，
   按钮按下缩到 97%。

### 15.1 怎么实现的

- `style.css` 顶部是一整套 CSS 变量（颜色、圆角、边框粗细、阴影、字体）。
  皮肤就是**换这一套变量的值**，不在每个组件上写第二遍样式。
- 为此把边框统一成了 `var(--bw) solid var(--line)`——粗野风把 `--bw` 调成 2px，
  笔记风保持 1px 发丝线，同一行代码两种情况都对。
- 顶栏 / 侧栏 / 状态栏用 `--chrome` 这个变量，笔记风把它调成 #f7f7f5
  （Notion 那种「画布白、侧栏灰」的层次），其他皮肤跟卡片同色。
- 粗野风的「机械反馈」写在皮肤专属规则里：`.btn:active` 位移 + 阴影归零，
  卡片 hover 反而往外挪 2px。

### 15.2 切换入口

「数据与设置 → 外观与标语」里三张卡：每张带一个**小样**（照着那套皮肤的圆角、
边框、投影画的示意图，颜色写死，不然三张小样会长一样），下面是**浅色 / 深色 / 跟随系统**
三颗互斥的明暗按钮和一句话标语输入框（选中「跟随系统」时下面补一句小字说明，
读不到系统明暗就改成兜底提示）。换皮肤、换明暗都会弹个轻提示；
右上角的快捷按钮改成三态循环（浅色 → 深色 → 跟随系统 → 浅色），图标画的是
「点一下会变成什么」：浅色时是 🌙、深色时是 🖥、跟随系统时是 ☀️，hover 说清当前模式。

### 15.3 顺带做的两处手感

- **换页淡入**：`ui.js` 的 `markEnter()` 给刚画好的内容加 0.18s 的淡入上移。
  只在真的换页面时叫，勾选、增删这种重画不叫——否则每点一下就闪。
  跟随系统的「减少动态效果」自动关掉。
- **没有引入任何在线字体**：三套皮肤只用系统字体和形状/颜色区分，
  自检里有「界面文件没有任何外部链接」这一项，皮肤做完依然是 0 条。

## 16. 启动速度（2026-10-06 排查）

用户反馈「启动小李好慢」。先量，再改——量出来的结果很意外：

| 环节 | 修之前 | 修之后 |
| --- | --- | --- |
| 直接用 python 起服务，到端口能连 | 7584 ms | **501 ms** |
| 双击 `启动.cmd`，到端口能连 | 7746 ms | **725 ms** |
| 重复双击（服务已在跑）到自动退出 | 1884 ms | 1884 ms（其中 1.5 秒是刻意留出让你看清提示） |
| 浏览器里刷新，到首页内容出现 | 230 ms | **170 ms** |
| 单次「导入探测」的 Python 启动 | ~137 ms | 不变 |

### 16.1 慢在哪

`.cmd` 里那串「找一个能用的 Python」只花了 160 ms，不是它。真正的时间在服务自己身上：

原来的「检测是否已经有小李在跑」是用 `urllib.request.urlopen` 去问 **12 个端口**，
每个给 **0.6 秒**超时。正常机器上连一个没人监听的本地端口会「立刻被拒绝」，
所以这个检查本来应该几乎不花时间；**但要是防火墙 / 安全软件 / VPN 把连接「丢掉」
而不是「拒绝」，每个端口都会一直等到超时**——12 × 0.6 ≈ 7.2 秒，和实测的 7.5 秒对得上。

> 顺带一提：`urllib` 还会读代理环境变量，本机自检走代理也是不对的。

### 16.2 怎么改的

1. **一趟走完**（`start_server()`）：从 8765 往上，遇到是自家的服务就直接开浏览器退出，
   遇到能绑的就立刻开工——不再「先把 12 个端口挨个问一遍再回来绑端口」。
   正常情况只问 1 个端口。
2. **换 `http.client` 直连**，不走 `urllib` 那套代理逻辑。
3. **超时 0.6 秒 → 0.25 秒**：就算真碰上「丢包」型防火墙，也只多等 0.25 秒。
4. **浏览器提前开**：端口一绑好就把浏览器叫起来（0.6 秒 → 0.15 秒，并且挪到备份、
   打印之前），它加载页面的同时我们接着把剩下的事做完。
5. **静态文件可缓存**（`no-store` → `no-cache` + `Last-Modified`）：文件没变回 304，
   省掉把 20 个文件重传一遍的功夫；改了文件立刻就是新的，不会拿着旧页面发呆。
   `/api/` 那些接口仍然是不缓存的。

### 16.3 还剩什么

剩下的时间基本在浏览器自己身上：**电脑上第一次开 Edge（或当天第一次）要 2～4 秒**，
这是 Edge 冷启动，小李管不着。第二次以后双击 `启动.cmd`，服务已在运行，
它只做一件事——把浏览器叫到前台，所以会明显快很多。

## 17. 项目卡片拖拽排序（2026-10-06）

开发工作页的项目卡片支持拖着换顺序，松手即存，刷新还在。

### 17.1 用了 SortableJS（本项目唯一一个第三方文件）

在此之前这个项目是「前端零依赖」。做拖拽排序时评估了两条路：

| 方案 | 好处 | 代价 |
| --- | --- | --- |
| 原生 HTML5 拖放 | 不引任何文件 | 原生拖拽的预览和回弹很生硬，边界情况（自动滚动、跨列）要自己写一大堆 |
| **SortableJS（选定）** | 丝滑的 FLIP 动画、边界情况都处理好了、MIT 许可 | 多一个 44KB 的本地文件 |

选后者的理由：它是**本地放着的文件**，不联网、不依赖 CDN，断网照常能用；
MIT 与本项目许可兼容，许可证随文件一起放（`app/web/lib/sortable.LICENSE`）。
为了它，README 里「前端零依赖」的说法也改成了「不引框架」——不能让文档撒谎。

### 17.2 接法

- `index.html` 用普通 `<script src="lib/sortable.js">` 引入（放在模块脚本之前）。
- `dev.js` 的 `setupDragSort()`：只在**渲染出 `.proj-grid` 且卡片 ≥ 2 张**时实例化，
  离开这个页面就 `destroy()`；每次重画都重建（因为视图容器会被换掉）。
- 拖完的 `onEnd`：读 DOM 上的 `data-id` 顺序 → 就地重排 `projects` 数组 →
  `touch(true)` 整份落盘 → 弹一句「顺序已保存」。
  兜底逻辑确保**一条记录都不会丢**（没出现在 DOM 里的接在最后）。
- 关键参数 `distance: 5`：鼠标移动 5 像素以内算点击，不算拖拽——项目卡片本身是个
  链接，不加这个参数点击会被拖拽吃掉。
- 库没加载成功（比如有人删了那个文件）时 `setupDragSort()` 直接返回，
  页面一切照旧，只是拖不动。

### 17.3 实测记下来的两个坑

1. **Sortable 1.15 监听的是 PointerEvent**，不是 MouseEvent。用合成
   `new MouseEvent("mousedown")` 触发不了拖拽；要测就得用 CDP 的
   `Input.dispatchMouseEvent` 派发**受信任的**真实鼠标事件（按下 → 分十几步移动 → 松开）。
2. 拖拽的落点必须在**视口范围内**。我第一次把目标点算到视口外（x=965 > 视口宽），
   Sortable 把卡片原样放回，`onEnd` 照样触发、顺序却没变——看着"成功"其实什么都没发生。

实测结果：把第 1 张拖到最后 → 界面顺序变成 `p2 → p3 → p4 → p1`，状态栏「已保存」，
磁盘 `数据.json` 里 `projects` 数组同步变成这个顺序，刷新后仍是这个顺序；
单独点一下卡片仍然正常进入项目详情。

## 18. 自动保存的三种情况 + 未保存提醒 + 项目筛选（2026-10-06）

### 18.1 自动保存分三种，别混为一谈

| 情况 | 做法 | 例子 |
| --- | --- | --- |
| **单值字段**：一个输入框就是一条数据 | 打字走 `input` **静默保存**（只写数据不重画，光标不跳）；离开输入框再正常保存一次并刷新列表 | 快速备忘、三餐、每周训练安排、一句话标语、保留份数 |
| **行内编辑**：一整行/一个表单对应一条已有记录 | 边打字边**静默保存**（打字期间不重画，所以编辑框不会被重建）；点「保存」退出编辑态，点「取消」用**进编辑时的快照**退回去 | 项目编辑、待办编辑、问题编辑 |
| **新增表单**：填一半还不是一条记录 | **不自动存**（半截的项目会变成空记录污染列表），但**打上「有还没保存的改动」标记**，关窗口前浏览器会拦一下 | 添加项目 / 添加任务 / 添加记录 |

- 关窗口的提醒用浏览器原生 `beforeunload`：**弹窗文字由浏览器定，改不了**，
  我们能决定的只有"弹不弹"（靠 `store.dirty` 和 `store.pendingForm` 两个标记）。
- 标记是全局的：`store.js` 里监听 `main` 里的 `input`，凡是**不是**停笔即存的字段
  一律算"没保存的改动"；提交表单或点任何带 `data-act` 的按钮就清掉。
  状态栏会同步显示「⚠️ 有还没保存的改动（记得点保存）」，不用等关窗口才知道。

### 18.2 项目卡片筛选

- 开发工作页加了筛选条：关键词（匹配项目名 / 简介 / 状态）+ 状态下拉 + 「清空筛选」+
  一行「筛出 N / M 个」的计数。
- **筛选只影响显示，不动数据**；清空筛选立刻恢复全部。
- 筛选用的是"只重画卡片区"：输入关键词时不能整页重画，否则输入框会被重建、光标就丢了。

### 18.3 筛选和拖拽排序怎么共存

这是最容易出错的地方：如果直接把「拖拽后 DOM 里的 id 顺序」当成整个数组的新顺序，
**被筛掉的项目会被挤到末尾**。

正确做法是**按位置合并**：把完整数组从头遍历一遍，遇到"看得见的"就按拖后的新顺序
依次填进去，遇到"被筛掉的"原地保留。实测：4 个项目里筛出 `p1 p4` 两张，
把 p1 拖到 p4 后面 → 完整数组变成 `p4 p2 p3 p1`：
可见的两张换了位，被筛掉的 p2 p3 **一个都没动**。

### 18.4 这轮踩到的坑

**「取消」只改了内存没落盘**：行内编辑改成自动保存之后，"取消"要把记录退回编辑前的
快照，我一开始只做了 `Object.assign` 恢复内存，忘了保存——结果**界面显示退回去了，
磁盘上还留着改后的值**。修法是恢复之后补一次 `touch(true)`。
这个 bug 特别阴：屏幕上看着一切正常，只有对着 `数据.json` 才能发现。

## 19. 拖拽手感：手里那张不虚化、原位只留一条缝（2026-10-06）

### 19.1 症状与根因

第一版拖拽的观感是「**手里那张变淡、原位留着一块实心虚线占位**」，跟手机桌面那种
「拿起来的图标清清楚楚、别的位置腾空」完全相反。两个原因叠在一起：

1. **桌面浏览器默认走 HTML5 原生拖拽，跟着光标的是浏览器自己截的图**
   （天生半透明），这张图是浏览器画的，CSS 管不着——`opacity` 写了也没用。
   原来那套 `.card-ghost` 虚线样式，其实只是给"留在原位的那张"上了色，
   看起来就像一块实心占位。
2. 改成 `forceFallback: true`（让 Sortable 用自己的克隆来跟手）之后，
   拖拽**卡住不动了**。查事件才发现：页面只收到 `mousedown`，
   **一条 `mousemove` 都没有**。因为项目卡片是 `<a>` 链接，
   **浏览器默认允许原生拖拽**，一按一拖浏览器就抢先去跑原生拖拽，
   于是不再把 `mousemove` 发给页面——而 fallback 模式等的正是 `mousemove`。
   （之前用原生模式能工作，是因为 Sortable 那会儿监听的恰好是原生拖拽事件。）

### 19.2 改法

| 地方 | 做法 |
| --- | --- |
| HTML | 项目卡片加 `draggable="false"`，掐掉浏览器的原生拖拽 |
| Sortable | `forceFallback: true` + `fallbackOnBody: true`（克隆挂在 body 上，不被容器裁掉） |
| 跟手那张 | `.card-drag` / `.card-chosen`：`opacity: 1 !important` + `scale(1.04)` + 深阴影 + 高 z-index |
| 原位占位 | `.card-ghost`：`opacity: 0`，用**透明边框**而不是 `border: none`——去掉边框盒子会矮 2px，松手时会跳一下 |
| 动画 | 拖拽中的三张关掉我们自己的 `transition`，让位动画交给 Sortable 的 `animation: 180` |

### 19.3 实测（拖拽进行中读计算样式）

```
跟手那张   opacity: 1   transform: scale(1.04) + 位移   z-index: 100000   挂在 body 上 ✓
原位占位   opacity: 0   （只剩一条缝）✓
```

落位后顺序照常保存、没有残留的拖拽类、单击卡片仍然正常进入项目详情、
控制台 0 报错、自检 21 项全过。

### 19.4 补充：跟手那张的类名与两个细节

- 跟手的克隆类名从 `card-drag` 改成 **`card-follow`**（更直白），
  `dragClass` 和 `fallbackClass` 都指向它。
- 给跟手那张加 **`pointer-events: none`**：它贴在光标下面，
  不掐掉鼠标事件的话会挡住底下的卡片、干扰落点判断。
- 加 `filter: "input, textarea, select"`：将来卡片里要是放了输入框，
  从输入框上按住不会触发拖拽。
- 跟手那张**没有**写死 `border-radius: 18px`——四套皮肤的圆角不一样，
  克隆会继承卡片自己的圆角，写死反而会让笔记/粗野皮肤走样。

### 19.5 「保存失败：Failed to fetch」是什么意思

这个提示的含义很窄：**请求根本没拿到响应**。小李的写接口出错时会返回 JSON
（比如"数据格式不对"），提示里会带那句话；只有连不上才会显示 `Failed to fetch`。
所以它出现的原因通常是这两种：

1. **黑窗口被关掉了**（程序已停），而浏览器页面还开着 → 之后的每次保存都失败；
2. **服务重启后换了端口**（8765 被别的程序占了，起在 8766），
   而浏览器里那个页面还指着旧地址。

判断与恢复：看状态栏是不是红字；回黑窗口确认它还在；实在不确定就刷新页面
（刷新会重新读一遍数据）。页面上的改动不会因为这次失败而消失——
`store.dirty` 还留着，下一次操作会重试保存。

## 20. 演示数据，和「两个副本同时开着」那个坑（2026-10-07）

用户反馈「开发版看不出效果」。查出来是两件事叠在一起，都修了。

### 20.1 为什么在开发版里看不到新界面

**根因一：端口上那个不是「这一份」。** 启动时会问 8765「你有小李在跑吗」，
只要名字对就认定「我已经在运行」，于是打开浏览器指向它、自己退出。可是
日常在用的那一份常年开着，问到的其实是**它**——于是你在开发版里双击
`启动.cmd`，浏览器打开的是另一份的旧界面。

修法：`running_instance()` 除了看名字，还要看**数据目录对不对得上**
（看 `same_copy()`）。不是自己这一份的，就往后试下一个端口。

**根因二：Windows 上 `SO_REUSEADDR` 的语义不一样。** Python 的 HTTPServer
默认 `allow_reuse_address = 1`。在 Linux 上它只是「重启时不等旧连接散掉」；
在 Windows 上它的意思是**「这个端口被别人占着也让你绑」**。所以只修根因一
还不够：开发版会「成功」绑上 8765——但这个 socket 收不到任何连接，浏览器
还是连到老的那个，界面照旧是旧的，而且一点报错都没有（这次就被它骗了
一轮：进程活着、没在监听、也不退出）。

修法：`XiaoLiServer` 里 Windows 上 `allow_reuse_address = False`，再加一道
`SO_EXCLUSIVEADDRUSE`。被占的端口老实报错，启动逻辑自然往下试 8766、8767……

实测（日常那份占着 8765 时启动开发版）：

| 端口 | 数据文件 | style.css | 学习记录 |
| --- | --- | --- | --- |
| 8765 日常版 | `D:\小李\数据\数据.json` | 39926 字节（旧） | 0 |
| 8766 开发版 | `D:\自用APP管理\数据\数据.json` | 47405 字节（新） | 24 |

### 20.2 演示数据（`演示数据.cmd`）

> 2026-10-07 补：用户明确说「演示数据不同步」——`同步到小李.cmd` 因此多了一条
> 排除规则（`tools\` 整个目录 + `演示数据.cmd`）。这套工具只服务开发版，
> 日常在用的那份里不该有它，免得手一滑把真实数据换成演示数据。
> 已经同步过去的两个文件当天就删掉了，重新同步也不会再回来（实测复制 0 个文件）。

开发版常年在改，数据是空的，界面看着「没效果」。所以加了个工具：

- `演示数据.cmd`：双击出菜单——1 载入 / 2 还原 / 3 看现状 / 4 载入到
  「现在开着的那个小李」；也可以直接带参数用，比如
  `演示数据.cmd --action status`、`--data-dir "D:\小李\数据"`。
- `tools/演示数据.py`：本体。样例数据**全部按「今天」算**，所以什么时候跑
  都是当下这个月铺满记录，九张模块卡片也都有数。
- 默认只动**这份代码自己的** `数据\`，日常在用的那份不动；也不会被同步过去
  （见本节开头的排除规则）。

安全约定（演示数据可以随便玩，真实数据不行）：

1. 载入前先把现在这份存成 `备份\保留-演示前-<时间>.json`。「保留-」前缀 =
   自动清理会跳过它，界面上也标着「长期保留」，所以它不会被 14 份的规则挤掉。
2. 现在这份是空骨架（一条记录都没有）就不存——没东西可丢。
3. 有东西、又不是上一次的演示数据时，先问一句，输入「演示」才继续，
   直接回车就取消。
4. 写的时候如果那份小李正开着，就走它的 `/api/data` 接口写：修订号由服务端
   推进，不会留下「页面手里那个号跟磁盘对不上」的麻烦。开的是别的副本就
   直接原子替换文件。

`服务.py` 的 `backup_kind()` 顺手加了一条 `演示前-`，这样备份列表里显示的
是「演示前」而不是笼统的「每日」。

## 21. 记账（第 10 个模块，2026-10-07）

用户要求加「记账」。完整设计见 `docs/superpowers/specs/2026-10-07-记账-design.md`，
一步步的实施计划见 `docs/superpowers/plans/2026-10-07-记账.md`；这一节只记结论。

### 21.1 v1 做到什么

记一笔（支出 / 收入）、月历上每天显示收支金额、本月概览 + **月度总预算**、
分类占比环形图、当日明细（可编辑 / 删除）、一小份账户列表，以及首页卡片、
全局搜索、月历上的支出圆点这三处联动。

**2026-10-07 追加**：账户余额也做进 v1 了（用户当天要求）。规矩是这样：

- **余额 = 期初余额 + 该账户的收入 − 该账户的支出**，每次读的时候实时算，**不存字段**
  （存了就会跟流水对不上，账目才是唯一的可信来源）。
- 期初余额在账户弹窗里填，单位还是分；**允许 0、不许负数、最多两位小数、
  上限 999,999.99**（和「记一笔」的金额同一条上限），留空按 0 存，
  改它不会动任何已有账目（老账户期初是 0，行为跟「流水净额」一样）。
- **新增 / 编辑账户都走弹窗**（2026-10-07 追加）：账户卡片标题右边的「添加账户」，
  以及每行右侧的「编辑」，打开的是同一个表单——只有两个字段：名字（必填，
  1～20 字，不能跟别的在用账户重名，重名忽略首尾空白与大小写）+ 期初余额（可留空）。
  校验不通过时错误写在字段下面、弹窗不关、「保存」是灰的；原来行内那一个输入框
  放不下两个字段，而且报错只能用会飘走的 toast 指不着字段。
- 本月概览里多一行「账户总余额」，标着「含期初」——它跟「本月结余」不是一回事
  （结余只管当月，总余额是期初 + 全部历史收支）。
- 已删除账户的净额**默认算进总余额**，并在账户卡片下面单独写一行说明，
  这样「总余额 ≠ 列表里各行相加」有据可查。

**v1 当时的「仍不做」**：转账、分类预算、80%/100% 预警、近 6 个月趋势图、
CSV 导出、按条件筛选、常用账目模板、标签（全站都还没有标签系统）。

> 2026-10-11 回填：这一串里**分类预算已经做了**（每个分类一条进度条，超了自己标红，
> 纯计算在 `app/web/finance-calc.js` 的 `categoryBudgets` / `budgetState`），
> 分类环形图、账户期初余额、债务欠款也都在。剩下没做的是：转账、预算到
> 80% / 100% 的提醒、近 6 个月趋势图、CSV 导出、按时间段 / 账户筛选、常用账目模板
> （清单和落点见 `docs/需求清单.md` 第 8 节）。

### 21.2 数据模型

`数据.json` 里新增一个 `finance` 键（模块的数据归模块，不摊成多个顶层键）：

```
finance: {
  accounts:     [ { id, name, initialBalanceCents } ],
  categories:   { expense: [8 类], income: [5 类] },
  transactions: [ { id, type, amountCents, date, category, accountId, note, createdAt } ],
  budget:       { monthlyTotalCents, categoryCents },
  transfers:    []
}
```

- **金额一律 `amountCents` 整数（分）**，换算只在 `app/web/money.js` 里做；
  界面上的短格式（月历格子）到 1000 元以上缩写成 `1.2k`，截断不四舍五入。
- `type` 只有 `expense` / `income`；转账是第二版的一张独立表，不做成第三种 type，
  这样「本月结余」「分类占比」的算法永远是干净的。
- `transfers`、`budget.categoryCents`、`initialBalanceCents` v1 先建着不用，
  第二版加功能不用迁数据。
- **删账户不删账目**：历史记录不能因为删账户就没了，那笔账的账户栏显示
  「（账户已删）」，删除确认框里写明「有 N 笔账在用这个账户」。
- 老数据没有 `finance` 键时，服务端的 `migrate()` 补一个空骨架（前端 `table()`
  认路径时也会顺手补）。

### 21.4 两条值得记住的约定

1. **月历的「看着的那个月」和「选中的那一天」是两件事**：概览、环形图、超支日
   跟着 `currentMonth()` 走，当日明细跟着选中那天走。不分开的话，翻月时左边换了、
   右边还停在原来那个月。
2. **`table()` 认带点的路径**（`table("finance.transactions")`）。回收站、全局搜索
   这些通用零件只认一个表名，打通这一层之后，嵌套的 `finance` 对它们就是透明的。

### 21.5 债务欠款子页面（2026-10-07 追加）

完整设计见 `docs/superpowers/specs/2026-10-07-债务欠款-design.md`，
实施计划见 `docs/superpowers/plans/2026-10-07-债务欠款.md`。要点：

- **做成记账里的子 Tab**（`#finance` / `#finance/debt`），不是第 11 个侧边栏入口——
  债务和账目本来就该在一个上下文里看。
- **数据结构**：顶层 `debt` 键（和 `finance` 并列），`items[]` 里是
  `{ id, name, type, totalCents, creditor, dueDate, note, status, repayments[] }`。
- **剩余不存字段**：`总额 − 已还之和` 实时算（`debt-calc.js`），和账户余额一个思路。
- **债务只认自己的还款记录**：`repayments[].txId` 只是凭证。事后把那笔账目删了或改了，
  债务不受影响，还款记录里标一句「对应账目已删除」。
- **删还款记录不回删账目**：剩余加回来、状态按剩余重算，确认框写明「剩余金额将恢复 ¥X」。
- **`status` 只有三处会写**：记还款后、删还款记录后（按剩余重算）、手动「标记已结清」
  （用在「这笔钱不用还了」，不生成任何账目）。
- **还款计入预算与分类占比**：为此给记账加了两个分类——支出「债务还款」、收入「债务收款」；
  服务端 `migrate()` 会给老数据补上这两个分类。
- 到期提醒分四档：已结清灰、7 天以上普通、**7 天内橙、已逾期红**；债务只在债务子页的
  月历上标红点，不动另外五张月历的图例。
- 顺手修了两个早就存在的 bug：玻璃皮肤下**搜索面板被内容卡片压住、点不动**
  （`.topbar` 加 `position: relative; z-index: 40`）；**弹窗里的「删除」确认框一闪就没**
  （外层弹窗多关了一次，改成 `return false` 让确认框接管）。

### 21.6 账户转账（2026-10-12 追加）

设计见 `docs/superpowers/specs/2026-10-12-账户转账-design.md`，实施计划
`docs/superpowers/plans/2026-10-12-账户转账.md`。第 21.1 节末尾那串「留第二版」的
清单里，它是第 1 项；做完这项，那一串还剩转账以外的五项（提醒 / 趋势图 / CSV /
筛选 / 模板）。

以前「记一笔」的弹窗里写着一句实话：「账户之间转钱暂时不能记，只能手动记一笔
『A 账户支出』+ 一笔『B 账户收入』」。按那句话凑合记会连带四件事：收支统计凭空
多出一进一出、分类环形图被「其他」撑大、预算和超支日被带偏、两笔之间没有任何关联
（删了一笔就永远对不上）。这一版把这件事变成一条记录：

- **单独一张 `finance.transfers` 表**（骨架里早就留着这个键，注释写着「第二版做
  账户余额、转账、分类预算时不用再迁数据」）。一条转账就是一行：
  `{ id, amountCents, date, fromAccountId, toAccountId, note, createdAt, imagePaths }`。
  这么做最大的好处是**收支统计压根看不见它** —— `monthTotals` / `categoryTotals` /
  环形图 / 预算 / 超支日 / 月历那对小字都只收 `transactions`，一行排除代码都不用写。
  另两种记法（两笔账目互认 / 给账目加第三种 `type`）都得在七八处地方各加一个
  「跳过转账」的分支，漏一处就错。
- **余额多算两项**：账户余额 = 期初 + 收入 − 支出 + 转入 − 转出
  （`accountBalanceCents` / `balanceTotals` 各多收一个 `transfers` 参数）。
  余额照旧**不落盘**、现算。「账户总余额」还包含已删账户上的净额，转账也一样：
  连着已删账户那头的钱不会因为账户删了就凭空消失。
- **两个入口**：记一笔弹窗的第三个页签（支出｜收入｜转账），和账户卡片头上的
  「转账」按钮（点开直接停在转账页签）。转账要填的只有：金额、日期、从、到、备注、
  截图；账户不够两个时写明「先加第二个账户」并拦住保存。顺手删掉了那句「暂时不能记」。
- **当日明细里单列一块**：转账画成中性的一行（`↩` + 「A → B」 + 金额），
  **不带 + / −、不进上下两个合计**；一天只有转账时也不画那对 0.00。
- **老数据**：`migrate()` 里 `transfers` 不是数组就补空数组，每行缺的字段补齐
  （金额取整、取绝对值），已有值一个都不动；导出导入带着走。
- **搜索**：`SOURCE_SPECS` 加了转账一行，备注、金额、两个账户名（回
  `finance.accounts` 现取）都能搜到，点结果回 `#finance`。
- **测试**：`tests\记账计算.test.mjs` 111 → 140 项（规整、按账户汇总、
  校验每条边界，外加一条**守恒**断言：转账不改总余额）；`自检.py` 86 → 89 项
  （往返、补空表、补字段）；新增真浏览器回归 `tests\转账.test.mjs` 42 项 ——
  记一笔转账之后两个余额各变对、**本月支出自始至终一个数没变**、明细里看得见、
  「从 = 到」当场拦下、改金额跟着改、删了回到原样。

### 21.7 CSV 导出（2026-10-13 追加）

第 21.1 节那串「留第二版」里的第 4 项。点记账页头上的「导出 CSV」→ 小弹窗问一句
「导出这个月 / 导出全部」→ 浏览器直接下载一份文件（落在你的「下载」文件夹，
不写数据目录；整份备份那条路仍然是服务端的 JSON 导出，两回事）。

- **一份文件装下账目和转账**：表头七列 —— 日期 / 类型 / 分类 / 金额 / 账户 /
  到账账户 / 备注。**金额一律正数，方向看「类型」那一列**（支出 / 收入 / 转账），
  这样 Excel 里按类型一筛就是一张表，不用猜正负号什么意思；转账那行「账户」是
  转出、「到账账户」是转入，分类留空。账户名按**现在的名字**写（改名后导出的是新名），
  账户删了写「（账户已删）」，不会甩一个认不出的 id。
- **给 Excel 准备的细节**：开头带 UTF-8 **BOM**（不然中文乱码）、行尾 `\r\n`、
  带逗号 / 引号 / 换行的格子裹引号且引号翻倍（备注是能换行写的，不裹就串列）、
  金额写成 `25.50` 这种两位小数的元、不带 `¥`（带了 Excel 会当文本）。
- **范围**：这个月按页面上正在看的那个月算；不传范围就是全部。排序：日期升序，
  同一天按记录顺序。
- **纯逻辑**在 `finance-calc.js`：`csvCell` / `financeRows` / `financeCsv` + `CSV_HEAD`
  （只拼文本，不碰浏览器）；下载是 `store.js` 的 `downloadText()` ——
  顺手把原来冲突处理里那份 Blob 下载代码收成了这一个函数，两处共用。
- **测试**：`tests\记账计算.test.mjs` 140 → 167 项（转义、表头、金额格式、账户名、
  月份范围、排序）；新增真浏览器回归 `tests\记账导出.test.mjs` 19 项 ——
  真点按钮、浏览器真下载一份文件，再逐行核对（BOM、表头、备注里的逗号引号、
  转账那两列、按月范围把上个月那笔挡在外面）。

### 21.8 预算提醒（2026-10-13 追加）

第 21.1 节那串「留第二版」里的第 2 项。档位（`budgetState` 的 `ok` / `warn` / `over`）
和进度条的黄 / 红其实早就有，缺的是**把这件事用一句话说出来**，以及首页上根本没有提醒。
这一版补的就是那句话 —— 而且只有一份定义：

`finance-calc.js` 的 `budgetNotice(state)`：**不到 80% 什么都不说**（返回 null），
80% 起说「已用 85%，快到预算了」，正好用满（100%）单独一句「已经用完了，后面花的都算超」
（用满既不是「快到了」也还没超），过了 100% 说「已超 ¥5.00」。返回
`{ level, pct, overCents, short, long }` —— `short`（「已用 85%」）给列表行，
`long`（整句）给摆得下的地方。

三处显示，都是拿这一份：

- **记账页概览**：预算条下面多一行提醒（`lv-warn` 黄 / `lv-over` 红 + 一个小图标），
  原来那句「已用 ¥85.00 / ¥100.00」不动，两个数一起看；
- **分类预算每一行**：尾巴那格从「只写百分比」变成跟着档位说
  （「已用 85%」/「超 ¥5.00」），颜色也对上；
- **首页**：财务摘要卡片多一条和债务预警同款的提醒（琥珀底 = 快到、红边 = 超了），
  文案前面加「本月预算」好和债务那条分开；点它回记账页。首页那张记账卡片的
  `extra` 一行也优先说预算（那一行只摆得下一句，债务预警在摘要卡片上照旧看得到）。

**没做**：浏览器通知 / 提醒弹窗 —— 纯本地应用窗口一关就什么都没有，这是需求清单
第 8 节写明的硬约束；「提醒」只能是打开页面时看得见的那句话。

**测试**：`tests\记账计算.test.mjs` 167 → 181 项（各档位与边界：79.99% 不提醒、
80% 提醒、100% 用满、100.5% 超支，文案里的数字和金额）；`tests\首页视图.test.mjs`
82 → 94 项（首页那句的文案 / 提示 / 与债务预警的先后）；新增真浏览器回归
`tests\预算提醒.test.mjs` 23 项 —— 85%（提醒档）和 105%（超支档）各看一遍，
记账页、分类行、首页三处都说对了、类名也对。

### 21.9 明细的时间段 / 账户筛选（2026-10-13 追加）

第 21.1 节那串「留第二版」里的第 5 项，也是 v1.5 那次留下的尾巴
（「整月账目列表、按时间段 / 账户筛仍留第二版」）。做法是**把右栏那张「当日明细」
升格成「明细」**，不新开一张卡片：

- **范围**：当天（默认，老手感不变）/ 本月 / 自定义。切到「自定义」才多出两个日期框，
  并且先把起止垫成现在看的那天，别让人对着两个空框发呆。**「本月」就是一直缺的
  整月账目列表**，标题跟着变成「本月账目」，每行前面补上日期（看一段时间的列表
  不写日期没法读）。
- **账户**：全部 / 某个账户。转账跟账户的关系是「两头任一边是这个账户都算」——
  钱从它出或进它都关它的事。
- **合计**跟列表走：加减号后面是「下面这几笔」，分类下拉也照旧（在筛出来的这批里再分）。
- 筛选**只作用于这张卡片**：概览、环形图、月历照旧看整月，免得四个地方互相牵。
- **纯逻辑**在 `finance-calc.js`：`LEDGER_SCOPES` / `ledgerRange` / `rangeTotals` /
  `ledgerOf`。`ledgerRange` 把条件归一成「一段时间 + 一个账户」，顺手处理三种边界：
  起止填反了自动换过来、只填一头另一头补上、两头都空当回「当天」（别一不小心
  把整本账倒出来）。
- **一个只有真浏览器才抓得到的坑**：`ledgerOf` 一开始忘了把归一后的 `scope` 一起
  返回，于是列表筛对了、标题和头上那句说明却还按「当天」画 —— 纯逻辑那几条断言
  （行、合计、条数）全都过。补上 `scope` 之后两处才对上；单测里也加了一条
  「归一后的范围也带出来」盯着它。
- **测试**：`tests\记账计算.test.mjs` 181 → 206 项（三种范围、填反 / 单头 / 双空、
  账户筛选、转账两头认、合计）；新增真浏览器回归 `tests\账目筛选.test.mjs` 37 项 ——
  默认当天、切本月（上个月那笔不进来、合计对得上、每行带日期）、只看微信 / 银行卡、
  自定义时间段、起止填反自动换、空的一段给空状态。

### 21.10 常用账目模板（2026-10-13 追加）

第 21.1 节那串「留第二版」里的最后一项（趋势图之外的）。每天中午那笔、每月那笔
房租、每月那笔工资，记一次要填五样东西；模板就是把「填好的那一次」存下来，
下次点一下就填好，只剩按保存。

- **数据**：`finance.templates: [{ id, type, category, amountCents, accountId, note }]`，
  最多 8 个（`TEMPLATE_LIMIT`）。**只存这五个字段**：图片不存（每次截图都不一样）、
  日期不存（用哪天的就是哪天的）；**转账不做模板**（它没有分类，形状也对不上）。
- **存**：在「记一笔」弹窗里多一颗「存成模板」把当前填好的存下来 —— 弹窗**不关**，
  接着保存这一笔。同一笔（类型 + 分类 + 金额 + 备注都一样）提示「已经有了」不重复加；
  存满 8 个提示先删一个（不自动挤掉旧的，免得悄悄丢东西）。
- **用**：记账页头下面多一条「常用」胶囊行（**一个模板都没有时整条不出现**），
  点胶囊就打开「记一笔」并填好金额 / 分类 / 账户 / 备注；胶囊尾巴的 × 删掉它
  （确认框里写明「已经记下的账一笔都不动」）。
- **它是配置、不是记录**：不进全局搜索、不进明细列表、不参与任何统计。
- **老数据**：`default_finance()` 里加了 `"templates": []`，服务端那句「缺键就补骨架」
  会把老数据自动补上；行内容交给前端 `normalizeTemplate` 兜底（手改坏了也不会崩）。
- **测试**：`tests\记账计算.test.mjs` 206 → 231 项（规整、读列表、显示名、去重、
  限量、传空）；`自检.py` 89 → 90 项（老数据补 `templates`）；新增真浏览器回归
  `tests\记账模板.test.mjs` 29 项 —— 存成模板（弹窗不关、数据里多一个、日期没进去）、

### 21.11 近 6 个月趋势图（2026-10-13 追加）

第 21.1 节那串「留第二版」的最后一项。这一节落地之后，**那六件事就齐了**
（转账 21.6 / CSV 21.7 / 预算提醒 21.8 / 时间段与账户筛选 21.9 / 模板 21.10 /
趋势图 21.11）。

记账页一直是「一个月一个月」的：月历按月翻、概览和环形图只看当前那个月，于是
「这半年花得是多是少」只能一个月一个月翻着记、自己在脑子里比。这张图就是把
**最近 6 个月并排摆着**：

- **画柱状，不画折线**。月份是离散的、这张图要回答的是「哪个月高」，柱子比折线
  直观；某个月没花钱就是一根零高柱，缺不缺一眼看得出；数字直接标在柱子上
  （`fmtMoneyShort`，1.2k 这种短格式），不用悬停就能读。自媒体的「近 30 天」那张
  仍旧是折线 —— 那是每天一个点、要看走势，两种场景不一样。
- **放左栏、环形图下面**（右栏固定 320px 塞六根太挤）。环形图横向看「这个月花在
  哪几类」，趋势图纵向看「这半年花得怎么样」，凑成一屏全貌。窄屏两栏并一栏时
  它自然落到下面，不用额外适配。
- **支出 / 收入两头切换**（和环形图那对页签同一套样式与交互），不并成两条线 ——
  房租那个月的支出可能是收入的十倍，同一个坐标轴会把另一条压成直线。
- **手写内联 SVG**：和环形图、自媒体曲线一个路子，零依赖、颜色走 CSS 变量
  （支出 `var(--err)`、收入 `var(--ok)`）。
- **当月那根画实一点**，并且图下明说一句「…是到 10-13 为止的数，这个月还没过完」，
  免得看着像掉下来了。
- **空数据**：六个月一笔都没有就给一句空状态，不画一张空图。
- **数据全现算**（不落盘、不加字段），口径走现成的 `monthTotals` —— 图上和概览上
  的数永远同一个来源。纯逻辑三个函数在 `finance-calc.js`：`lastMonths`（往回数
  n 个月、跨年接得上）、`monthTrend`（每月的数 + 柱高比例，全 0 时不除零）、
  `trendSummary`（合计与月均）。

**这一版没做**：点柱子跳到那个月（要牵动 `selected` / 月历 / 明细范围三处状态）、
更长的区间、和明细筛选联动、导出图片。

**测试**：`tests\记账计算.test.mjs` 231 → 250 项（跨年、比例归一、全 0 不除零、
月均）；新增真浏览器回归 `tests\记账趋势.test.mjs` 27 项 —— 六根柱子的高度与金额、
三根零高柱、悬停里的完整金额、切收入换色换数、只有一个月有数照样画、
一笔没有时给空状态。

## 23. 自媒体改版（2026-10-07）

用户给了两版需求稿，核心是「现在只有选题待办，看不出运营成果」。完整设计见
`docs/superpowers/specs/2026-10-07-自媒体改版-design.md`，实施计划见
`docs/superpowers/plans/2026-10-07-自媒体改版.md`；这一节只记结论。

### 23.1 页面结构（`#media`，从上到下）

页头（+「账号管理」按钮）→ ① 账号卡片横排 → ② 数据概览（可折叠：六个汇总数 +
近 30 天趋势图 + 爆款 TOP3）→ ③ 月历排期（平台筛选、平台色圆点、格子里的标题截断、
已发布划掉）→ ④ 选中日期的当天安排 → ⑤ 选题 & 作品列表（五条状态流水线 + 已废弃折叠）。

- 需求稿里「顶部运营总览」和「数据统计看板」是同一批数字，**合并成一张**：
  同一屏出现两组「总粉丝 / 总浏览」只会互相削弱可信度。
- 账号卡片放在最前面：没账号时汇总全是 0，先看到「还没有自媒体账号，点右上角
  账号管理添加」比先看一堆 0 更自然。

### 23.2 数据模型（两个新的顶层键）

```
mediaAccounts: [ { id, name, platform, intro, baseFollowers, targetFollowers, note, createdAt } ]
mediaFollowers: [ { id, accountId, date, count } ]          ← 粉丝快照，同账号同一天只留一条
contents: [ { …, accountId, platform, status, planDate, publishDate, link,
              views, likes, comments, collects, fansGain, note, createdAt } ]
```

- **账号和作品都是顶层键，没包成 `media{}`**：开发工作就是 `projects` / `issues` /
  `progress` 三个平级顶层键；`contents` 被日历、搜索、首页、服务端、自检、演示数据
  六处引用，搬进 `media{}` 只换来一次迁移风险。
- 平台是固定清单里的一个词（B站 / 小红书 / 抖音 / 公众号 / 知乎 / 视频号 / 其他），
  存的是文本；`accountId` 是绑定关系，账号删了作品还在，显示「账号已删」。
- 状态：`想法 → 撰写中 → 剪辑中 → 待发布 → 已发布`，另有 `废弃`（归档，默认不显示）。
  老数据的「写作中」由服务端 `migrate()` 改成「撰写中」。

### 23.3 粉丝口径（这次最容易做错的地方）

**当前粉丝 = 最近一条快照 + 该快照之后发布作品的「单作品涨粉」之和**；
一条快照都没有时 = 初始粉丝 + 该账号所有已发布作品的涨粉。

- 用户在账号卡片上手动改「当前粉丝」，写的是**今天的快照**，不是在账号上存一个数字。
  这样手动校正和自动累加永远不打架，趋势曲线也有了真实锚点。
- 作品和快照同一天时算快照已经包含它（严格晚于才累加），不会同一天算两遍。
- 「本周涨粉」= 本周 vs 上周（周一算一周的开头），环比只在真有上周数据时才给百分比；
  上周是 0 就说「上周没有涨粉」，没有上周记录就说「上周没有记录」。
- 爆款：**同账号**已发布且填了播放的作品 ≥3 条时才算，≥2 倍小爆款、≥3 倍大爆款
  （样本太少时标出来的「爆款」没有说服力）。活跃度按最近发布距今天数分四档。

### 23.4 拖拽排期（没走 SortableJS）

作品卡可以拖到**日历格子**或**下面那张「当天」卡**上，放开就写进计划发布日期。

项目卡片那套 SortableJS 在这里不合适，原因是实测出来的：它跨列表拖拽是
「指针一进格子就先把卡片塞进去」，而日历格子又小又密（一次 42 个实例），
手指一抖落错天之后还会立刻重画，连改都改不了；从列表拖到日历要跨大半屏，
它的自动滚动在这种场景下也不稳。所以这里用浏览器自带的原生拖拽：落点由
`drop` 事件决定（松手那一下才算数），跨屏时的滚动浏览器自己会做。

**列表内拖拽排序没做**：列表始终按「计划时间 / 创建时间」排序，拖出来的顺序
下一次重画就会被排回去——让人以为拖成功了，比没有这个功能更糟。想换顺序用
列表上方那个「排序方式」下拉。

### 23.5 首页卡片与联动

首页自媒体卡片（简洁与完整模式同一个数据源）：

```
main : 总粉 1.26w ｜ 本周 +326
sub  : 总播放 48.6w ｜ 待发布 3 条
extra: 本周已发 2 条 · 爆款 1 条      （没爆款就不写「爆款 0 条」）
```

其它联动：全局搜索能搜作品标题 / 备注 / 平台 / 账号名；点账号卡片跳到
`#media/<账号 id>`，列表按那个账号筛；算数的部分全在 `app/web/media-calc.js`
（纯函数，`node tests\自媒体计算.test.mjs` 直接跑，116 条断言）。

### 23.7 平台清单可以自己编辑（2026-10-13 追加）

23.6 那串待办里的第 5 项（另外几项还没做）。

那个平台清单原来写死在 `media-calc.js` 的 `PLATFORMS` 里（七项：B站 / 小红书 /
抖音 / 公众号 / 知乎 / 视频号 / 其他），代码注释里早就留着一句「存的还是文本，
所以以后想改可编辑也不用迁数据」—— 这一版就是兑现它：

- **清单存 `settings.mediaPlatforms`**（没设过就用默认那七项，所以老数据一个字节
  不用动）。`PLATFORMS` 那份仍旧在，改成明确的**默认**清单；
  新加的 `platformsOf(data)` 负责「实际用哪一份」。
- **入口**：自媒体页头上多一颗「平台」按钮，点开一个小弹窗：列出当前清单、
  每行一个「删掉」、下面一个输入框 + 「加进清单」。**弹窗里明说一句**：
  改它只改下拉里有哪些可选，**已经记下的账号和作品一个字都不动**（它们存的是
  平台名本身）—— 这也是这一版不动用户数据的原因。
- **规矩**：1～12 个、每个名字 1～12 个字、重名（忽略大小写）不加，都当场说一句；
  **最后一个不让删**（下拉不能是空的，那颗删除按钮直接灰掉）。
- **删掉某个平台之后，用它建的账号照样编辑得了**：账号弹窗的平台下拉会把
  那个已经不在清单里的平台名摆在第一项并选中（和记账「账户已删」一个做法）——
  不然一打开弹窗下拉就跳到别的平台上，一保存就把账号悄悄改了。
- **纯逻辑**在 `media-calc.js`：`normalizePlatforms` / `platformsOf` / `addPlatform` /
  `removePlatform` + 两个上限常量；名字的 slug 与配色沿用 `platformSlug`，
  认不出的平台照旧走 `other` 那一档色，所以新加的平台不会没颜色。
- **测试**：`tests\自媒体计算.test.mjs` 116 → 141 项（洗清单、去重、上限、
  加 / 删的状态、删过头不让删）；新增真浏览器回归 `tests\自媒体平台.test.mjs` 25 项
  —— 默认七项、加一个（落盘 + 列表 + 下拉）、重名 / 空名 / 太长都拦下、
  删平台后**账号与作品一个字不动**、那个账号照样能编辑且下拉仍选中原平台、
  只剩一个时删除按钮变灰。

### 23.8 快照「用上一条的数字」（2026-10-13 追加）

需求清单第 8 节第 6 条里那个附加想法：**粉丝快照支持复制上一条、只改粉丝数字**。

「记粉丝」弹窗本来就把粉丝数预填成「按初始粉丝 + 作品涨粉估算到今天」的那个数，
多数时候直接确认就行。但有时想的是「在昨天那个数上改几十」—— 估算数里带着作品的
涨粉，跟昨天记下的那只差一截，来回对不上。所以这一版在弹窗里加了一行：

```
上一条：2026-10-12 · 1.2k 粉  [用它]
```

点「用它」就把**上一条记过的那个数**垫进输入框、并全选 —— 你直接打新数字就行
（敲一个字是替换，不是往后追加）。默认值那套行为一个字没动：估算仍然预填，
两者分得开，想要哪个自己挑。**没记过快照的账号不显示这一行**（没上一条可复制）。

纯逻辑是 `media-calc.js` 的 `lastSnapshotOf(snapshots, accountId)`：按日期取这个账号
最近的一条（不看数组顺序），没日期的那条不算，数字取整、负数当 0。

**测试**：`tests\自媒体计算.test.mjs` 141 → 149 项（取最近那条、别的账号不算、
没记过给 null、没日期的不算、负数归 0）；新增真浏览器回归 `tests\自媒体快照.test.mjs`
19 项 —— 上一条那行写着日期与粉丝数、默认仍是估算数（两者分得开）、点「用它」
垫进 1260 且全选（真敲一个数字验的是替换）、改成 1350 记下、再打开时上一条
就是刚记的那条、没记过的账号不显示那一行。

### 23.10 首页「待发布」提醒（2026-10-13 追加）

23.6 那串待办里的第 3 项。

首页那张自媒体卡片原来只在 `sub` 里写「待发布 N 条」—— 而**简洁模式（默认视图）
只画卡片正面那一行**，`sub` / `extra` 根本不显示，所以「有几条排期到了」这件事
在默认视图里是看不见的。这一版给卡片加了一行提醒，**简洁和完整两种模式都画**：

- **说什么**：只数「状态是待发布、没归档、**而且填了排期日**」的作品（没排期的
  还没到提醒的时候，已发布 / 废弃的不算），按最要紧的一档说一句话：
  - 排期**过了**（planDate < 今天）→ 红边：「有 2 条排期过了还没发」
  - 排期**就是今天** → 琥珀色：「今天该发 1 条」
  - **7 天内**要发 → 琥珀色：「本周还有 3 条要发」
  一档都没有（都还早）就整行不出现，不占地方。鼠标移上去写着最紧那条的
  《标题》与原定日期；卡片本身就是链接，点一下回自媒体页去处理。
- **实现**：`home-view.js` 的 `pendingNoticeOf(data, today)`（纯函数，形状照
  `debtWarningOf` 那个老规矩来：`level` / `count` / `text` / `tip`），
  `summaryOf("media")` 把它挂在卡片上，`modCard` 照 `card.alert` 画那一行
  （`.mod-alert`，颜色跟首页那两条预警同一套：红边 / 琥珀底）。
  卡片的 hover 提示也把这句话排在最前面。
- **测试**：`tests\首页视图.test.mjs` 94 → 115 项（三档各自的文案与条数、没排期 /
  已发布 / 废弃都不算、四档混着来时先说最要紧的那档、卡片上带得出 `alert`）；
  新增真浏览器回归 `tests\首页待发布.test.mjs` 13 项 —— 默认简洁视图里那行真画出来、
  红边是哪一档、悬停写着哪条、点卡片跳 `#media`，以及三种档位切换与「都不占地方」。

### 23.11 粉丝快照「补几天」（2026-10-13 追加）

23.6 那串待办里的第 4 项。前几天忘了记，现在从平台后台翻出数字来一次补上。

单个账号卡片上原来只有「记粉丝」（记今天一条）。这一版在它旁边加了「补几天」，
打开是一个多行文本框：

```
2026-10-08
2026-10-09
2026-10-10 1200
…
```

- **日期替你预填好**：最近 7 天里**还没记过**的那几天各一行（记过的再列出来等于
  让人以为漏了；想改某一天还是去「记粉丝」或直接写那天）。你只填数字。
- **一行一天**：`日期 粉丝数`（空格 / 逗号 / Tab 分开都行）。**只写日期没写数字的行
  跳过**（预填的日期本来就等着你挑着填），所以用不上的行留着不管也没事。
  同一天写两遍后写的算数；同一天已经记过的**覆盖那一条**，不堆两条。
  带千分位的 `1,200` 也认（从后台复制的数字常带逗号）。
- **当场拦住三种毛病**：日期写不成 `2026-10-10` 这样、日期不存在（`2026-13-45`）、
  **是以后的日期**（快照只能补到今天）—— 报出「第几行、什么问题」，改好才让存，
  不半截存进去让人以为都记上了。
- **底下实时预览**：`会记 2 天（2026-10-12 ~ 2026-10-13），跳过 5 行没填的` ——
  存之前先看得见会动哪几天。
- **纯逻辑**在 `media-calc.js`：`recentDays` / `parseSnapshotLines` /
  `applySnapshots`（合并只动这个账号，别的账号同一天也一个字不动；返回新数组）。
- **测试**：`tests\自媒体计算.test.mjs` 170 → 198 项（解析的四种毛病、千分位、
  同天两遍、跨月往回数、合并的新增 / 覆盖 / 不碰别人）；新增真浏览器回归
  `tests\自媒体补录.test.mjs` 29 项 —— 预填 7 行且第二次打开只剩 5 行、
  预览的条数与跳过数、乱写与未来日期当场报错并拦住保存、覆盖已记那天。

### 23.12 素材库（2026-10-14 追加）

23.6 那串待办里的最后一项，原文写作「素材关联笔记模块」。**做法上先拍了一件事**：
那句话有两种读法 ——（A）自媒体里的素材库；（B）先做全站「笔记」模块再让素材关联它
（那是需求清单第 4 节里明写着「还没做」的那件事，量大得多）。这一版按 A 做：
用途很具体（做一条作品时，脚本 / 封面 / 参考链接得有个地方放、还能跟这条作品对上），
而且不动全站结构。真要做 B，那是一条独立的线，做完之后这张素材表照样用得上。

- **数据模型**：新表 `mediaAssets`：
  `{ id, title, kind: "image"|"link", path, url, note, createdAt }`；
  **关联存在作品那一侧**（`contents[].assetIds`）——日常动作是「做这条作品 → 挑素材」，
  作品是主动方；素材页那句「用在 N 条作品上」由作品侧现算（和「进度不另存」一个哲学）。
  代价是**删素材要摘引用**：抽成纯函数 `unlinkAsset()`，单测盯着。
- **只收两种素材**：图片走现成的附件组件、存新目录 `attachments/media_asset/`
  （白名单两边各加一项）；链接就是一段 URL（必须以 http 开头）。
  剧本 .docx / 视频 .mp4 这类**不收** —— 附件组件只认图片，本地小服务也没有通用的
  文件存储与预览；先放链接、或者手动放进数据目录。
- **界面**：自媒体页多了「素材」子 Tab（`#media/assets`，和 `#media/<账号 id>` 那个
  子地址不撞）；素材一行一份（缩略图 / 链接小标记 + 标题 + 链接 + 说明 + 用在几条作品上），
  行尾编辑与删除；添加 / 编辑弹窗里类型二选一。**作品弹窗里多一格「素材」**
  可以勾（勾上就是这条作品用它），旁边一颗「＋ 新建素材」直接叠一个弹窗建完回来
  （弹窗栈管这个），作品行上多一个「素材 N」小标记。
- **搜索**：`SOURCE_SPECS` 加一行素材（标题 / 说明 / 链接都进匹配；
  **图片路径本身不搜** —— 搜一个附件文件名没意义）。
- **测试**：`tests\自媒体计算.test.mjs` 198 → 219 项（规整、用在几条作品上、
  认不出的 id 跳过、摘引用不动别的）；`自检.py` 90 → 92 项（新键与新字段的迁移）；
  新增真浏览器回归 `tests\自媒体素材.test.mjs` 32 项 —— 子页切得过去、链接素材能建、
  **图片素材真上传**（CDP 塞文件，落到 `attachments/media_asset/`）、勾到作品上、
  行上「素材 1」、素材页「用在 1 条作品上」、删素材（确认框写明几条在用）之后
  作品还在且引用被摘掉。这一轮它抓出两个真 bug，见下面那段。

> **这一版修掉的两个真 bug**（都是写真浏览器回归时才露头的）：
> ① 素材弹窗保存后 `dlg.close()` 抛错 —— `openAction(act, dlg)` 的第二个参数是
> 弹窗**根元素**、不是 `{el, close}`，写错了就「存是存进去了，但弹窗不关、页面不重画」；
> ② 删素材时把 `assetsOf()` 给的**规整副本**交给了 `moveToTrash` ——
> 它按下标从原表里摘，副本不在表里，于是「删了但没真删」。两处都是「数据看着对、
> 界面不对」的毛病，纯逻辑单测永远看不见。

## 24. 图片附件（记账 / bug 登记 / 笔记共用，2026-10-07）

### 24.1 一个文件最好复制，所以图片不进 JSON

给「记一笔」和 bug 登记加了可选的图片备注。核心约定只有一条：
**图片独立存在本地文件夹里，`数据.json` 只存相对路径。**

```
数据/
  数据.json          主数据：finance.transactions[].imagePaths / issues[].imagePaths
  attachments/       图片本身（跟着数据目录走，备份就是整个 数据 目录复制走）
    finance/         记账
    buglog/          bug 登记
    note/            笔记（组件已支持，模块还没做）
```

文件名统一是 `yyyyMMdd_随机串.扩展名`（例 `20261007_ab12cd34.jpg`，只收
png / jpg / webp）。这个规则不只是为了好看：服务端 `attach_parse()` 拿它当白名单，
外面递进来的路径必须长成这样才认，`attachments/finance/../../数据.json` 一律 403。

需求文档原本写的是「在程序根目录建 `attachments/`」，实际放在**数据目录**下面：
`同步到小李.cmd` 和 `.gitignore` 本来就把 `数据\` 排除在外（图片不会跟着代码同步走），
备份与 `XIAOLI_DATA_DIR` 换盘也自动带上图片。相对路径的写法没变，
真要挪回程序根目录只改服务端 `ATTACH_DIR` 一个常量。

### 24.2 服务端

| 接口 | 干什么 |
| --- | --- |
| `GET /attachments/<模块>/<文件名>` | 发图；先过白名单，`..` 403 |
| `POST /api/attachment` | 收一张（JSON + base64），落盘，返回该存进 JSON 的相对路径 |
| `POST /api/attachment-delete` | 删几张，返回 `deleted / missing / refused` |

`/api/health` 顺带报 `attachDir / attachCount / attachBytes`（设置页显示占用），
`/api/open-folder` 多认一个 `attach`。写图片和写 `数据.json` 一个规矩：
先 `.tmp` 再 `os.replace`。

### 24.3 前端两个文件

- `app/web/attachment-calc.js`：**纯逻辑**，Node 直接单测（97 条断言）。
  设置规整、挑文件、`fitEdge` / `decideEncode`（要不要缩、要不要重编码、
  输出什么格式）、命名、路径白名单、查看器翻页、体积显示。
- `app/web/attachment.js`：附件区（选图 / 预览 / 单张移除）、只读缩略图行
  `thumbsHtml()`、全屏查看 `openViewer()`、写盘 / 删盘、全局代理。

### 24.4 四条值得记住的口径

1. **保存才写盘**：挑进来的图先在内存里（blob + `URL.createObjectURL` 预览），
   点「保存」时才 POST 落盘，紧接着才写 JSON。点「取消」一个字节都不留。
2. **压缩卡在压完之后**：长边超档位（默认 1920）→ 缩；单张超 1.5MB → 重新编码；
   两条都不占 → 原样存（真截图基本都走这条）。10MB 这条线卡的是**存下来的大小**，
   所以 12MB 的手机照片照样收；挑进来就超 30MB 才直接拒。
   png 重画完还超 2MB 的话，再压一版 jpg 比一比，谁小用谁。
3. **回收站不动图片**：记录进回收站，图片一个都不删；「彻底删除」/「清空回收站」
   才看设置里那个开关（默认**保留**）。删文件前会扫一遍整份数据，
   还有别人在引用就不删。
4. **图片丢了不算坏**：路径在、文件被手动删了，缩略图变成虚线占位「图片丢失」，
   全屏查看里也写一句，条目本身照常显示 —— 靠 `img` 的 `error` 事件兜。

### 24.5 弹窗长高那件事

附件区挂进「记一笔」之后弹窗能超过窗口高度，实测 764px 的窗口里弹窗有 902px，
底下的「保存」被顶到屏幕外点不着。`.dlg` 因此改成 `flex` 竖排 + `max-height`，
只让中间的 `.dlg-form` 滚，标题和按钮始终看得见。这是四套皮肤共用的弹窗，
以后哪个弹窗内容再长也不会踩同一个坑。

拖拽上传、图上写字、批量导出、首页卡片上的图片小图标，以及「自定义附件文件夹路径」
（要换地方现在用 `XIAOLI_DATA_DIR` 把整个数据目录挪走，附件跟着走）。

## 28. 列表里的备注不再被压成一字一行，换行也照原样（2026-10-07）

### 28.1 现象

两处能看见：

- **记账 → 当日明细**：右栏那张卡片只有 270px 宽，一行里还塞着分类图标、
  备注、账户名、金额、编辑/删除五个东西。1080p 开满时实测备注那一格被压成
  **0px 宽、336px 高、14 行** —— 备注「DeepSeek-Token」就是一个字一行的竖排。
- **学习工作 → 学习记录**：窗口在 920px 左右时，标题「第三章」只剩 5px 宽、
  备注「记了两句想抄下来的话」22px 宽，一行被撑到 564px 高。

同一个页面上，「备注里敲的回车」也**看不见**：
`第一行\n第二行` 在列表上显示成「第一行 第二行」。

### 28.2 两个原因

1. **一行被挤爆**（竖排的真正原因）。`.task` / `.item` 是 `display:flex` 但
   `flex-wrap:nowrap`，`.i-title` / `.i-note` / `.t-text` / `.t-note`
   又都写着 `min-width:0`。一行里控件一多（比如学习记录那行有：日期 + 学了什么 +
   对象 + 待复习 + 时长 + 备注 + 三个按钮），「不会缩」的那几个加起来就超出一行的宽度，
   于是会缩的正文和备注被压到只剩一个字宽；中文又允许在任意两个字之间断行，
   看起来就成了竖排。所以这不是「没处理 `\n`」，是布局问题 ——
   一段根本没有换行的备注（`DeepSeek-Token` 就是），照样会竖排。
   `数据.json` 里也查过：整份数据里没有任何一个备注字段带换行，
   更不存在「每个字之间一个 `\n`」那种写法。
2. **换行没显示**：列表上的备注是普通元素，`white-space` 默认 `normal`，
   记录里存的 `\n` 会被 HTML 当普通空白折掉。

### 28.3 怎么改（只动 CSS，`app/web/style.css`）

- `.task` / `.item` / `.timeline li` 加 `flex-wrap: wrap`：挤不下就**折行**，
  而不是把字压扁；同时给正文 / 标题 8em、备注 6em 的宽度下限（`min-width`），
  折到第二行之后也是能读的一整段。
- `.t-note` / `.i-note` / `.tl-text` / `.fin-row .i-title` 加
  `white-space: pre-line`：认 `\n`，但不像 `pre` 那样留一串空格。
  这里**没有**把 `\n` 换成 `<br>` 再塞 `innerHTML`，所以不牵扯转义和注入；
  和「问题详情」`.issue-desc` 用的是同一个口径。

数据这一侧一个字没改：`applyValues()` 一直是只 `trim()` 两头，
中间的换行原样写进 JSON，保存时也不会额外补 `\n`；
弹窗回填是把原始字符串放进 `<textarea>`（textarea 本来就读得懂 `\n`），
不用转 `<br>`。

### 28.4 效果

「记账 → 当日明细」那一行（1080p 开满、右栏 270px 宽，自己那条记录）：

| | 改之前 | 改之后 |
| --- | --- | --- |
| 备注列宽 | 0px（一字一行，336px 高 14 行） | 150px（24px 高，一行读完） |
| 那一行的高度 | 356px | 81px |

920px 窗口下「学习记录」那五行的实测（演示数据）：

| | 改之前 | 改之后 |
| --- | --- | --- |
| 标题列宽 | 7～14px（一字一行） | 207～223px |
| 备注列宽 | 16～34px（一字一行） | 200px |
| 单行高度 | 127～564px | 77～119px |
| 整张卡片高 | 1523px | 544px |

按同一个口径把十个模块 × 1280 / 1100 / 920 / 820 四档窗口扫了一遍：
没有竖排，也没有横向溢出（`scrollWidth` 都等于 `clientWidth`）；
1280px 下逐页对比改前改后的每一行高度，**完全一致** ——
宽窗口本来就不挤，加了折行也不会平白多出一行。

### 28.5 顺带：记账的备注改成多行（2026-10-07）

「记一笔」的备注原来是一行输入框（`maxlength=60`）：一天记好几笔，
备注就只能挤成「午饭 黄焖鸡 28 地铁 5 水果 12.8」这样一串，回头自己都认不出。
换成 3 行的多行框（`maxlength=200`）：

- 回车在 `textarea` 里就是换行 —— 弹窗那段「回车 = 保存」只认 `INPUT`
  （`finance.js` 的 keydown），所以敲回车不会把表单提交掉；
- 编辑时把原始字符串直接放回 `<textarea>`（它天生读得懂 `\n`），
  支出 / 收入来回切换也会把已经写好的备注一起带过去（那段重画表单的代码
  本来就把 `#tx-note` 的值捞出来再塞回去）；
- 列表上不用另做处理：28.3 节那条 `white-space: pre-line` 已经把换行铺开了。

没动的：债务欠款的备注还是单行（它压根不在列表上露面，多行没处显示），
账户备注、其它模块的备注也都照旧。

## 29. 模块目标：健身 / 学习 / 饮食（2026-10-07）

设计见 `docs/superpowers/specs/2026-10-07-模块目标-design.md`，
实施计划见 `docs/superpowers/plans/2026-10-07-模块目标.md`。

### 29.1 为什么加

健身 / 学习 / 饮食这三个模块原来只有「记录」：能打卡、能记时长、能记三餐，
但「我要练成什么样、一周练几次」「每天学两小时」「一天 8 杯水」这些**目标**
没地方写，写了也没人盯着。这次给每个模块加一条**模块级目标**：
带周期和起止日期，能按一句人话规则自动往「今日计划」生成待办，并且能看进度。

### 29.2 两个概念分开

| | 模块目标 | 待办任务（`tasks`） |
| --- | --- | --- |
| 是什么 | 模块级配置，长期的 | 单次执行项 |
| 存哪 | `data.moduleGoals`（按模块 id 分桶，每桶一个数组） | `data.tasks` |
| 谁产生 | 你在模块页设置 | 手动加，或目标按规则自动生成 |

一个模块可以有**多条**目标（比如健身同时有「减脂」和「力量增肌」），
所以每桶是数组；每条目标都带 `moduleId`，跟原方案里那份字段表一致。

### 29.3 数据字段

```json
"moduleGoals": {
  "fitness": [{
    "id": "8f2c…", "moduleId": "fitness", "moduleName": "健身计划",
    "mainTarget": "3 个月减重 8kg，每周力量 3 次、有氧 2 次",
    "cycle": "月度", "startDate": "2026-10-07", "endDate": "2027-01-07",
    "dailyRule": "每周一、三、五力量训练；周二、四有氧",
    "remark": "训练后记录体重、感受",
    "isActive": true, "autoTask": true, "lastRun": "2026-10-07"
  }]
}
```

- `cycle`：每日 / 每周 / 月度 / 自定义起止日期。
- `isActive`：目标开关；`autoTask`：自动生成任务开关。**两个都开才会生成**
  （定稿里既有 `isActive` 那句，又有「自动生成任务」那个开关，两个都留着）。
- `lastRun`：上一次对表的日期 —— 同一天不重复生成。

自动生成的待办就是在 `tasks` 里多三个字段：
`sourceModule`（哪个模块）、`goalId`（哪条目标）、`genKey`（目标 + 日期 + 第几条规则，
防重复）。这三个字段不进表单，所以你在今日计划里改正文、勾完成、删掉，
都不会把来源标记弄丢。

### 29.4 规则怎么认（一句人话 → 待办）

按分号 / 句号 / 换行切开，逐条认：`周一` / `星期一` / `礼拜天` / `周1` /
`每周一三五` / `周一和周三` 认星期几；`每天` `每日` `天天` 认每天；
`每月 1 号` 认每月几号；**什么都没写**就按目标周期兜底（每日 → 每天，
每周 → 开始日期那天起每周，月度 → 开始日期那个号）。任务文字是规则里剩下的那半句，
顺手去掉「自动生成 / 到今日计划 / 待办」和 `【】` 标记。

### 29.5 界面

- 三个模块页**日历之上**一张「🎯 当前模块目标」卡片：目标、周期 + 起止、
  两个开关的状态标签、进度条、`已完成 3 / 12 健身 · 25%`，
  下面一行「编辑目标 / 查看目标进度 / 删除」；点「查看目标进度」就地展开
  本周完成 + 这条目标生成过的待办（最多 8 条）。
- 新增 / 编辑共用 `openItemDialog("moduleGoal")`，弹窗里九个字段：
  所属模块（只读）、核心目标、周期、开始 / 结束日期、自动任务规则、备注、
  启用目标、自动生成任务。这个弹窗没有图片区 —— `item-dialog.js` 里
  加了「没有 `upload` 就不装配件区」这条。
- 「今日计划」顶部多一条 `🎯 今天的模块目标：健身：力量训练 ｜ 学习：晚 7 点-9 点学习`
  （今天没有目标要做就整条不渲染），自动生成的待办行上多一个只读来源标签
  「健身目标任务」。

### 29.6 和原有待办的分界

项目里的待办（`belong: "dev:<项目 id>"`）**仍然只属于项目，不出现在今日计划**，
这条老规矩一个字没改。目标生成的待办是另一条线：`belong: "goal"`，
出现在今日计划、删的是它自己。

**删目标只删这条配置**，已经生成的待办一条不动（也就不进回收站，
删除确认里把这句话写清楚）。

### 29.7 老数据

`default_data()` 里加 `moduleGoals: {}`；`migrate()` 补这个键、
把（万一手写成）数组的形状按 `moduleId` 归成桶、逐条补齐缺的字段 ——
已有的字段一个都不动，没这个键的老数据读出来就是空的，页面显示「还没有设置目标」。

### 29.8 验收

- `python tests\自检.py`：60 → **65 项**全过（多 5 项走的是 `moduleGoals`）。
- `node tests\目标计算.test.mjs`：**140 项**（新写的纯逻辑单测）。
- `node tests\表单计算.test.mjs`：137 → **171 项**（多了 `moduleGoal` 的断言）。
- 其余 7 个单测照旧全过。

## 30. 开发工作的待办 / 问题可以归档了（2026-10-08）

### 30.1 要解决的事

「开发工作」里一个项目用久了，**做完的待办、修好的 bug 一直挂在列表上**：
列表越拉越长，真正要看的没几条，翻起来累。想要的不是删掉它们 ——
历史要留着复盘、追溯 —— 而是**从主列表挪出去，需要的时候还能看见、还能拿回来**。

所以这一版只做一件事：给待办和问题各加一个「归档」，归档的收进**右侧的归档抽屉**，
主列表只放没归档的。

### 30.2 归档不是删除

| | 删除 | 归档 |
| --- | --- | --- |
| 数据 | 挪进回收站，彻底删除就真没了 | **只改两个字段，一个字节都不删** |
| 主列表 | 没了 | 没了（这就是目的） |
| 找回来 | 数据与设置 → 回收站 | 归档抽屉里点「恢复」，或编辑弹窗里「取消归档」 |
| 导出备份 | —— | 归档条目**照常一起导出**，U 盘备份不丢历史 |

### 30.3 数据字段（老数据零成本）

待办（`tasks` 里 `belong: "dev:<项目 id>"` 的那些）和问题（`issues`）各加两个：

```json
{ "isArchived": false, "archivedAt": "" }
```

- `isArchived` 缺字段的老记录**一律当没归档**（`archivedOf()` 只认真正的布尔 `true`），
  所以不用写迁移脚本；`migrate()` 里顺手 `setdefault` 一下，老数据一保存就带上这两个字段。
- `archivedAt` 是「归档那一刻」的本地时间文本（`2026-10-08 08:23`），
  抽屉那一行、编辑弹窗里都显示它。

### 30.4 主卡片只留活跃条目，归档全在右侧抽屉里

两张卡片（待办 / 问题）右上角各一个一模一样的**「查看归档」**入口（有归档时带个数字角标），
点开的是**同一个右侧抽屉**，只是默认停在哪个标签不一样：点待办卡片的入口停在
「待办归档」，点问题卡片的停在「Bug 归档」。

抽屉里（从上到下）：

- 标题 + 项目名 + 关闭（点遮罩、按 Esc 也能关；弹窗或全屏看图压在上面时，Esc 先关它们）；
- 标签切换「待办归档 / Bug 归档」，每个标签带条数；
- 搜索框（标题 / 描述 / 备注 / 关联模块都搜）+ 优先级下拉 + 归档日期范围 + 清空筛选；
- 筛选结果上方一条批量条：全选、已选几条、批量恢复、批量删除（没勾东西时两个按钮是灰的）；
- 一条条归档记录：勾选框、优先级、标题、来源（bug 显示关联模块，待办显示备注）、
  「归档于 2026-10-08 08:23」、恢复、删除。整行透明度 0.68，一眼看得出是历史。

主卡片里**没有**归档折叠区，也**没有**归档筛选下拉：

| 卡片 | 主列表 | 归档 |
| --- | --- | --- |
| 待办 | 只有没归档的，顶上「全部 / 未完成 / 已完成」只筛这些 | 侧边抽屉「待办归档」标签 |
| 问题 / bug | 只有没归档的，筛选栏还是状态 / 优先级 / 关联模块 | 侧边抽屉「Bug 归档」标签 |

条目的「归档」按钮出现的时机：待办是**勾完完成**才出现，bug 是**已修复 / 已关闭**才出现。
想归档一条还没做完的待办，走编辑弹窗里那个「归档」（30.7）。

抽屉里那个「删除」和别处一个规矩：**先移进回收站**，不是永久删除 ——
这套 App 里没有「点了就找不回来」的按钮，「数据与设置 → 回收站」还捞得回来。

### 30.5 统计、搜索、联动

- 待办卡片的「未完成 N ｜ 已完成 N」、问题卡片的「未解决 / 进行中 / 已修复」、
  项目卡片上「待办 N 条 · 未解决 bug N 条」**都不算归档条目**；
  要看全量得显式传 `issueStats(list, { includeArchived: true })`（只有单测用得上）。
- 全局搜索默认**不搜归档**（归档了就是不想它再冒出来），搜索面板底部多一个
  「包含归档记录」，勾上立刻重搜一次 —— 也就是「要不要连抽屉里那些一起搜」。
- 项目待办本来就不进「今日计划」（`belong` 是 `dev:<id>`、`date` 为空），
  归档之后更不会 —— 归档不牵扯今日计划，这条老规矩没动。

### 30.6 自动归档开关（默认关）

「数据与设置」多一张「归档」卡片，两个开关存在 `settings` 里（和明暗、首页视图一样

## 31. 记账分类：前端兜底 + 当日明细按分类筛（2026-10-08）

### 31.1 那次「弹窗里没有分类」其实是数据没补上

用户报「记一笔弹窗缺少分类选择控件」。查下来：**控件一直在** —— `txFormHtml()`
里那排 `.fin-cats` Emoji 按钮，切支出 / 收入会换另一套。空的是**分类列表本身**：
它来自数据文件的 `finance.categories`，而用户那份 `数据.json` 里根本没有这个键
（只有 `accounts / budget / transactions`）。

根因是**服务端进程没重启**：那个进程从 2026-10-06 22:44 起一直开着，内存里跑的是
当时那版 `服务.py`，缺「给老数据补 `finance.categories`」这段迁移；而 `app/web/`
下的 JS 是每次请求现从磁盘读的，于是**界面是新的、数据是旧的**。两下一错位，
前端 `(f.categories || {})[type] || []` 拿到空数组，那排按钮就渲染成了一个空网格
（`.fin-cats` 是 grid，没有子元素时高度是 0，看上去就是「分类」两个字下面什么都没有）。

重启那个黑窗口即可恢复 —— 现在的 `migrate()` 会补上 9 个支出 / 6 个收入分类。
这一节做的是把它变成**不会再发生**：前端自己也留一份兜底，不指望服务端。

### 31.2 前端兜底分类（`DEFAULT_CATEGORIES` + `ensureCategories()`）

- `finance-calc.js` 里加一份 `DEFAULT_CATEGORIES`（支出 9 / 收入 6），
  内容必须与服务端 `default_finance()` + `DEBT_CATEGORIES` **一模一样**。
- `ensureCategories(finance)` 在记账页渲染前跑一次，**只补空的那一边**：
  整块 `categories` 缺失、或某一边不是数组 / 是空数组时才填默认值；
  已经有一串分类就一个都不动 —— 将来做「自定义分类」时，用户删掉的分类
  不该被这里复活。
- 真补过才 `touch(true, true)`（**静默**落盘：只是补个键，不值当重画整页）；
  没补过第二次返回 `false`，不会反复写盘。
- 两边一致这件事交给自检看着：`tests\自检.py` 里有一条
  「前端兜底分类跟服务端骨架一模一样」，从 `finance-calc.js` 里抠出那份默认值，
  和 `/api/data` 返回的 `finance.categories` 逐项比对，走岔了直接报红。

### 31.3 当日明细按分类筛

右栏「当日明细」卡片头上多一个分类下拉（`#day-cat`）。规矩：

- **当天有两个以上分类时才露出来** —— 一天只有一类，筛选没有意义；
- 选项 = 「全部分类」+ **这天真有的分类**（按当天条目的先后去重），
  不把一整张分类表铺开；
- 下面「- 支出 / + 收入」那两个数**跟着筛选走**（不是整天那个数），
  旁边补一句「餐饮 · 3 笔」，免得筛完看着数字对不上；
- **换一天、或刚记完一笔，筛选自动回到「全部」** —— 刚记的那笔要是被筛选
  挡在外面，会以为没存上；
- 改筛选只重画这一张卡（`redrawDay()`），不整页重画：整页重画会把下拉本身
  换掉，焦点和展开状态都丢。`#day-cat` 进了 `store.js` 的 `AUTOSAVE_FIELDS`，
  筛一下不会被算成「有还没保存的改动」；
- 纯逻辑 `dayCategories()` / `filterByCategory()` 放在 `finance-calc.js`，
  配了单测（它们不碰 DOM，能在 Node 里一条条断言）。

**仍然不做**：整月账目列表、按时间段 / 账户筛（还是第二版第 5 条）。

## 33. 游戏娱乐：日期区间框不再空着（2026-10-08）

### 33.1 起因

游玩记录卡片里「翻历史」那两个日期框，打开页面时是一个空的 `yyyy/mm/dd`
占位（中文 Chrome 里显示「年/月/日」），看着像坏了 —— 既不像「今天」，
也看不出当前在筛哪一段。要做的是**只改初始值和显示**，日期弹窗那套交互一个字不动。

### 33.2 一条规矩：框里永远是「当前真正在生效的那个范围」

不是把两个框填上今天就完事 —— 那样「看记录」「清除筛选」「翻日期」几条路走下来
又会空回去，或者框里写着今天、列表里却全是上个月。所以按下面几条走：

- **没在筛**（在看某一天）：两个框显示**那一天**。首次进页面就是今天，
  默认查询也就是「今天当天」这条老规矩。
- **在筛**：显示真实的起止日期。
- **只按游戏名筛**（点清单里的「看记录」，或者在名字框里打字）：区间本来没有，
  现在**坐实成这批记录实际覆盖的那几天**（最早、最晚）。结果一条不多一条不少，
  但框里看得见真实日期，也不会出现「框里写今天、列表里却有上个月」。
  一条带日期的记录都没有（老数据或手写数据）就不坐实，框里老老实实留空。
- **用户手动改一头**：另一头如果还空着，就按它当时显示的日期坐实，然后重画。
  框里显示的必须就是筛的条件，不然两边对不上。
- 「清除筛选」「回到今天」「前一天 / 后一天」都会回到「看某一天」，
  两个框跟着变成那一天 —— 框里不会再出现空的占位。

### 33.3 「开始不能晚于结束」

改「起」改到比「止」还晚时，**把另一端一起带过去**（让「止」跟着走），
而不是把用户刚填的值换到另一个框里 —— 那样一眼看不出自己填的跑哪去了，
也容易筛出个自己没想要的范围。反方向同理。这样任何一次改动之后，
区间都是一个合法范围，不会静悄悄筛出空列表。

### 33.4 框外多了一句「筛选区间」

只在翻历史时出现，例如 `筛选区间：2026/10/01 ~ 2026/10/08`：
两端同一天就写一天；只填了一头写「从…起 / 到…为止」；一天都没填
（只按名字筛、且这款游戏没有带日期的记录）写「不限日期」。

给人看的日期一律 `yyyy/mm/dd`，和顶上那个日期控件显示的一致；框的 `value`
仍然是 `yyyy-mm-dd`（浏览器原生日期控件只认这个格式，斜杠只在提示文字里用）。
日期一律走**本地时间**，不用 `toISOString()`，夜里零点附近不会差一天 ——
这一条和记账弹窗、`todayStr()` / `shiftDate()` 是同一套。

  1px 半透明白高光边 + 一点内高光 + 外弱阴影，悬停颜色加深。
  不再按容器各写一份；唯一的例外是弹窗那块还留着「滚动条贴卡片边」的负边距。
- **颜色全走变量**：`--sb-thumb` / `--sb-thumb-hover` / `--sb-edge` / `--sb-shadow`，
  四套皮肤 × 明暗各自配。**极简 / 液态玻璃**共用一套浅蓝灰（深色下换淡蓝白）；
  **笔记**换成暖灰、去掉阴影（那套本来就是暖色纯平表面）；**粗野**用墨色实心、
  没有高光和阴影 —— 硬套蓝灰在这两套里会很怪。
- Firefox 不认 `::-webkit-scrollbar`，所以仍旧只在
  `@supports not selector(::-webkit-scrollbar)` 里写 `scrollbar-width: thin` +
  `scrollbar-color`。**Chromium 这边一旦写那两条，上面那套胶囊就整个失效** ——
  这条坑第 32 节记过，这版照样绕开。

### 34.4 顺带实测否掉的两种写法

- **`opacity` + `transition` 做「平时藏起来、鼠标靠近才出现」不成立**：
  `::-webkit-scrollbar-thumb { opacity: 0 }` 浏览器**认这条声明**
  （计算样式读出来是 `0`），但**画的时候完全不理会** —— 实测滑块照样满色画出来。
- 想隐藏 / 显示只能**换背景色**：默认 `transparent`、`容器:hover` 时给颜色。
  实测默认透明时滑块整条真的不见了。这版没这么做 —— 用户最后定的表里要的是
  「一直在、只是很轻」，而且真藏起来反而看不出下面还有内容可以滚。

## 35. 弹窗里 Ctrl+V 直接贴截图（2026-10-08）

### 35.1 起因：一份「另起一套」的方案

需求是这样：截图工具（Win+Shift+S）截完，图就在剪贴板里；打开弹窗直接按
Ctrl+V 就收进去，不用先另存成文件、再点「选择文件」去挑。用户贴过来的那份方案
把 HTML / CSS / JS 都写全了，自带一个 `attachModule`、一个 `/api/upload-image`、
一套 `.attach-drop-zone` 样式。

没照抄。第 24 节那套附件组件（`attachment.js` + `attachment-calc.js`）已经在
记账 / bug 登记 / 六个表单弹窗上跑了，另起一套等于把命名规则、压缩口径、
路径校验、「点取消一个字节都不落盘」这些规矩各维护两份。所以只把那份方案要的
**交互**接进现有组件：服务端一个字节没改（还是 `/api/attachment` + base64），
CSS 也没另开一套（沿用 `.attach-*` 那几个类）。

### 35.2 怎么接的

- **挑图的逻辑进 `attachment-calc.js`**（不碰 DOM，能单测）：
  `clipboardImages(items)` 从剪贴板那一串 `DataTransferItem` 里挑出 png / jpg / webp
  （`kind === "file"` 才算文件，`"string"` 是文字；取不到 `File` 的失效 item 跳过，
  传进来是啥都行，一律不抛错）；`clipboardHasText(items)` 判断这次粘贴里
  是不是还夹着文字。
- **`document` 上一个 paste 监听**（`installPasteHandler()`，和看图那套代理一样
  自己挂自己，`attachment.js` 一加载就有）：倒着找 `.dlg-backdrop` → 里面那个
  `.attach`，再回 `mounted` 那张表拿状态，把图交给 `absorbFiles()`。
- **两条路共用一份规则**：`absorbFiles(entry, files)` 就是从原来 `input.onchange`
  里那段抽出来的 —— 查类型 / 查大小 → `prepareImage()` 压一轮 → 进预览列表。
  「点按钮选文件」和「Ctrl+V 贴图」走同一个函数，以后改规则只改一处。
- **两条克制的规矩**：
  1. 只认**当前那个弹窗里的附件区** —— 页面正文、搜索框里按 Ctrl+V 一切照旧；
     全屏看图那层（`.viewer-backdrop`）盖在上面时也不抢。
  2. 剪贴板里**同时夹着文字**就不抢这次粘贴（从 Excel、网页上复制的常常是
     图文一起，文字该照常落进输入框）。截图只有图片，不受这条影响。
- **界面上的提示**：按钮右边加一句「或在弹窗里按 Ctrl+V 贴截图」（`<kbd>` 样式，
  跟着皮肤走），底下那行说明也改成「截图（Win+Shift+S）之后直接按 Ctrl+V
  就贴进来了」；真收下图时附件区轻轻闪一下（0.4s，`prefers-reduced-motion`
  下不动）。

### 35.3 实测（无头 Edge + CDP，独立数据目录）

`XIAOLI_DATA_DIR` 指到一个临时目录（绝不去碰真实数据），在真浏览器里造真的
`ClipboardEvent`（`DataTransfer` + `File`），走一遍「今日计划 → 添加任务 →
贴两张截图 → 保存」，**20 条断言全过**：

| 看什么 | 结果 |
| --- | --- |
| 弹窗里挂上附件区、提示语里有 Ctrl+V | ✅ |
| 贴一张截图 → 缩略图出现、角标变「已选 1 张」 | ✅ |
| 收下图片时 `preventDefault`（不让它再落进输入框） | ✅ |
| 图文一起（Excel / 网页那种）不抢粘贴 | ✅ |
| 再贴一张累加 → 「已选 2 张」 | ✅ |

### 35.4 顺带修掉的一处老毛病

`mountAttach()` 里的 `paint()` 和 `onChange` 闭包捕获的是**挂载那一刻**传进来的
`state` / `options`；同一个 host 再挂一次（换一版 state）时，重画出来的还是旧数据。
这次把状态收进一个 `entry` 对象，事件、重画、回调都读 `entry.state` / `entry.options`。

## 36. 待办跨模块联动：今日计划 ↔ 首页总览 ↔ 各模块任务（2026-10-08）

### 36.1 起因：一份「另建一套任务表」的方案

需求是这样：给每条任务加 `belongModule` / `isTodayPlan` / `priority` / `status`
几个字段，今日计划按 `isTodayPlan = true` 筛，各模块卡片上加「加入今日计划」勾选框，
再写一组 `updateTaskStatus()` / `toggleTaskInTodayPlan()` / `renderAllViews()`。
方案里还提到「笔记」和「记账」两个模块的任务。

这条**思路**（一份原始数据、一处修改全局同步）本来就是这个项目的做法，所以照做；
但方案设想的「另起一套字段 + 一套重绘函数」不能照抄，原因有两条：

1. **数据结构这里已经有了**。任务全在 `tasks` 一张表里，靠 `belong` 分家：
   `plan`（今日计划自己的）、`dev:<项目 id>`（开发工作挂在项目上的待办）、
   `goal`（模块目标自动生成的）。再加一个 `belongModule` / `status` 字段，
   等于给同一件事起两个名字，旧数据还要搬一次。所以只补真正缺的那一个字段
   `isTodayPlan`，其余沿用：`done` 就是状态、`priority` 早就有了、
   `belong` 就是归属。
2. **`renderAllViews()` 不需要**。界面同一时刻只挂一个视图，`store.js` 的
   `touch(true)` 会广播给外壳重画当前页面；首页、今日计划、原模块本来就都从
   `tasks` 现读现画，所以「一处修改，全局同步」是免费拿到的。

至于「笔记 / 记账」：这个项目里没有笔记模块，记账也没有任务列表，
真正有跨模块待办的只有**开发工作挂在项目上的待办**（外加模块目标生成的、
游戏娱乐顺手加的那两条）。所以这一版就把开发待办接进今日计划，
字段和函数都留在能复用的地方，以后真有笔记模块，加一条 `belong` 就行。

### 36.2 怎么接的

- **纯逻辑进 `task-calc.js`**（不碰 DOM、不吃 store，能单测）：
  `inTodayPlan(row, today)` 说了算「今天该不该出现」；`taskOwnerOf(row)` 分
  「自己的 / 外来的」；`taskSourceLabel(row)` 出来源标签；`planTasksOf()` 筛加排；
  `planStatsOf()` 算顶部那几个数。三个页面共用同一份判断，不可能出现
  「今日计划里有、首页没有」。
- **改动只有一个入口 `task-actions.js`**：`updateTaskStatus(id, done)` 和
  `toggleTaskInTodayPlan(id, isAdd, today)`。今日计划、首页、月历、开发工作四处
  的勾选框全都调它俩，`done` / `doneAt` 的写法只有一份实现
  （`markTaskDone`，开发工作「勾完成就自动归档」那条路复用它）。
- **「加入今日计划」= 盖上今天的日期**：`isTodayPlan = true` 之外还写了
  `date = today`。这样月历、「昨天没做完的」「全部挪到今天」这些现成的口径
  一个字不用改就认得它；移出时把日期清空、开关关掉，任务本身留在项目里。
- **删除只能在原模块**：`belong = "dev:*"` 的待办在今日计划 / 首页 / 月历里
  不画删除按钮，给的是「移出今日计划」和「回项目」；删的项目里删。
- **界面**：优先级胶囊（高红 / 中橙 / 低绿，磨砂半透，和「模块目标」那几个
  小标签一套）、来源标签（开发待办用浅灰磨砂，`健身目标任务` / `游戏娱乐`
  沿用原来的强调色）、今日计划顶部一排「未完成 / 已完成 / 完成百分比」加一条
  细进度条、开发待办的弹窗里补了「优先级」（以前只有项目待办能标）。

## 37. 首页今日进度 · 目标总览 · 今日计划分组与多类型进度（2026-10-09）

第 29 节的模块目标只做到「模块页那张卡 + 今日计划顶部一条摘要」。这一次把
「今天的进度」提到**首页**和**今日计划**两处，并且把进度从「数条数」升级成
**按类型 / 目标值算、可超额**。三块界面共用同一份数据、同一套现算逻辑。

### 37.1 三块界面

- **首页 · 各模块今日进度**：完整模式摆在「今日待办」上方、直接可见；简洁模式
  收进「其他模块」折叠面板，展开才现读现画（省首页性能）。健身 / 学习 / 饮食 /
  开发工作 / 游戏娱乐各一行，单行 `图标 + 模块名 ─ 进度条 ─ [− 值/目标 单位 +]`。
  点整行（不是点加减按钮）跳 `#plan/mod-<模块>`，今日计划会滚到那一组。
- **首页 · 目标总览**：每条模块目标一行（读 `moduleGoals` + `tasks` 现算，
  和模块页那张目标卡一个口径），只读，点一下回对应模块页。
- **今日计划 · 两张独立滚动的玻璃卡片**：上「昨天及更早没做完的」、下
  「今天的任务」，各自 `max-height: 320px` 内部滚动、标题栏在滚动区之上固定不动，
  条目少时自动收缩、互不带动。今天的任务按模块分组，组头
  `模块名 ─ 进度条 ─ [− 值/目标 单位 +]`，点模块名可折叠 / 展开这一组；
  不属于模块的自己排一列。顶部一条全局细进度条按 `<80 蓝 / 80–99 黄 / ≥100 绿`。

### 37.2 进度怎么算（一致性）

- **只读不存**：进度 = 今天这一组待办里**已完成条目的 `value` 之和 ÷ 目标**。
  `currentValue` 从不落盘、永远现算 —— 首页、今日计划、勾选框三处不可能对不上。
- **多类型**：每个模块可配 `settings.dailyTargets.<模块> = { type, targetValue, unit, step }`
  （数量 / 时长、目标值、单位、单步增量）。没配就走老口径：目标 = 今天计划了几条、
  单位「项」。配置从首页卡片 / 今日计划卡片头的「今日目标」弹窗改，存进 `settings`，
  和皮肤、首页视图一样跟着数据文件走。
- **每条待办的贡献**：`task.value`（可选）。没写就按类型兜底：数量记 1、时长记一个步长。
- **超额**：`current > target` 时进度条满格绿色、数字绿色 + 「超额」小标，文字保留真实数字。
- **加减按钮**：`+` **追加一条 `done=true` 的「快速记录」条目**（value = 步长），
  `−` 撤掉最后一条这种快速记录（没有就取消勾选最后一条完成的）。**不改数字**，
  最小值 0、不会为负。
- **跨天**：今天这列按 `date === 今天` 取，昨天没做完的自动落到逾期卡，历史一个字不动
  —— 不需要额外的重置定时器。

### 37.3 实测与测试

| 看什么 | 结果 |
| --- | --- |
| 学习配成 时长 / 目标 120 / 分钟 / 步长 30 | ✅ 显示 `120/120 分钟`，绿档 |
| 点 `+` | ✅ 追加一条 `快速记录 +30分钟`（已完成），显示 `150/120 分钟` + 「超额」 |
| 点 `−` | ✅ 撤掉那条快速记录，回到 `120/120 分钟`；再点不会变负 |

| 逾期卡 / 今日卡 | ✅ 各自内部滚动，标题固定；没有逾期时显示「暂无逾期任务 🎉」 |

纯逻辑落在 `task-calc.js`（`moduleKeyOf` / `groupPlanTasks` / `dailyTargetsOf` /

## 38. 全站标签系统（2026-10-11）

设计文档在 `docs/superpowers/specs/2026-10-11-标签系统-design.md`，实施计划分两份

### 38.1 一句话

给任意一条记录贴几个自己起的词，然后按这个词把**全站**的记录一次捞出来。

以前每类记录只能按它自己写死的字段归类（待办是「工作 / 生活 / 运动 / 其他」，记账有
收支分类，自媒体有平台…），跨模块没法归堆：「这周要盯的三件事」散在待办、问题、作品
三张表里，除了记住它们叫什么，没有别的办法一起找出来。

### 38.2 标签就是记录上的一个字符串数组

```jsonc
{
  "id": "demo-t13",
  "text": "把月历的氛围底再调淡一点",
  "category": "工作",          // 原来的固定分类照旧，标签是它旁边多出来的一层
  "tags": ["工作", "本周"],     // 新增
  "imagePaths": []
}
```

**不做顶层标签表、不存 id**。理由：`数据.json` 是你自己打开看得见、也允许自己改的
（README 里写明「数据是看得见摸得着的文件」），可读性比「规范化」值钱 —— `["t3"]`
这种东西认不出是什么；而「改一个标签名全站一起改」这一版根本没有使用场景。
真要做，后面加一张「名字 → 颜色 / 备注」的表就够，数据不用重迁。

**颜色不存**：`tagColor(name)` 把名字哈希到 8 档固定调色板（色值沿用全站那套分类色），
同一个名字在任何模块、任何页面永远同色。贴一个新标签不用先建标签、不用选颜色。

**上限**：单个标签 24 个字、一条记录 8 个（`TAG_MAX_CHARS` / `TAG_LIMIT`，
只有 `tag-calc.js` 一处定义）；输入框里超了**当场提示**，保存时 `validate` 再拦一道，
不静默丢。顺序不排 —— 你自己写的顺序就是你心里的重次。

### 38.3 哪里能填、哪里看得见

- **能填**：统一弹窗里的 9 种表单 —— 今日计划、开发待办、项目、学习记录、学习对象、
  训练打卡、游戏、游玩记录、模块目标。字段表里是一种新的 `kind: "tags"`：一行文本
  （记录里是数组、框里是「工作、本周」，两个方向的换算各只有一处），候选是**全站
  已经用过的标签**（打开弹窗时现算，不落盘），下面一行实时显示收成了哪几枚胶囊。
  回车仍然是「保存」，和其它输入框一个规矩。
- **看得见**：今日计划、首页今日待办、开发工作项目详情、学习对象与学习记录、
  训练打卡、游玩记录与游戏清单。超过 3 个就先画 3 个，剩下的收成 `+N`（title 里是全的）。
- **搜得到**：标签进了搜索池的匹配字段，敲「工作」能把贴了它的记录捞出来，
  卡片正文显示命中的那个标签。
- **跨模块地看**：搜索面板顶上那行标签（`allTags()` 现算，只数没归档的），
  点一下就列出全站带它的记录，还能和关键词叠加；输入框空着时面板只摆这行标签。

## 39. 重复任务与子任务（2026-10-14）

### 39.1 一句话

给「今日计划」的待办补上两件天天遇到的事：**一条待办底下能挂子任务清单**（勾选父子联动，
行上一枚 `2/5` 点开就地勾），**「每周一、三、五」这种重复规则到日子自动生成当天的待办**
（规则本身不占某一天）。来源：`需求清单.md` 第 8 节第 7 条（通用模块）里的第 4 项。

### 39.2 子任务：记录上的一个数组，进度不落盘

待办（`tasks` 里的记录）多一个 `subtasks` 数组，每条 `{ id, text, done }`：

- **只有一层**（子任务不能再挂子任务），一条最多 30 条（上限 `SUBTASK_LIMIT` 只在
  `task-calc.js` 定义一份，表单校验和界面上限都读它）。
- **进度不落盘**：`2/5` 每次现算（`subtaskProgress`），和「今日进度不另存」一个哲学。
- **父子勾选联动**（两个方向都做，规则简单好预期）：
  - 勾上父任务 → 子任务全部跟着勾上；取消父任务 → 全部取消（发生在 `markTaskDone`）；
  - 子任务全勾上 → 父任务自动勾上；再取消任意一条 → 父任务跟着取消（发生在
    `setSubtaskDone`，它只写父任务那一格，不反过来铺给整份清单）。
  两个入口都在 `task-actions.js`，所以今日计划 / 首页 / 项目详情三处的表现天然一致。
- **界面上是一枚共用零件**：`ui.js` 的 `subtaskBadge(task)` 画出「`2/5` 胶囊 + 藏在同一个
  `li` 里的清单」，三处列表各加两行（一行标记、一行事件），逻辑不各写一遍；
  展开 / 收起靠 `li` 上的 `.sub-open`，事件走 `handleSubtaskClick` / `handleSubtaskChange`。
- 弹窗里那块清单的**值就是一条隐藏 input 里的 JSON**：读值、校验、写回还是走表单那一套
  （`kind: "subtasks"`），所以「回车加下一条」得拦一下（`stopPropagation`），
  不然回车会被弹窗那层当成「保存」。
- 项目详情画的是 `normalizeTodo` 出来的**展示副本**，副本也得带上清单（重新捏一份，
  副本不该反过来改到数据那条），行上那枚胶囊才画得出来。

### 39.3 重复任务：规则是一条记录，生成出来的是另一条

规则 = `tasks` 里 `repeat` 有内容、**且不占某一天**（`date` 空）的那条记录，
另带 `repeatUntil`（重复到哪天，留空就一直重复）和 `lastRun`（今天对过表了没有）。
生成出来的「实例」还是一条普通待办，多两个来源标记：

| 字段 | 是什么 |
| --- | --- |
| `genKey` | `repeat:<规则 id>:<日期>`，防重复生成 |
| `repeatId` | 从哪条规则来的（行上挂「重复任务」来源标记） |

生成机制**整套沿用模块目标那套**（第 29 节）：一句人话规则的解析 / 匹配 / 预览直接用
`goal-calc.js` 的 `parseRule` / `clauseMatches` / `previewDays` / `ruleSummary`，不另写一套；
`planRepeatTasks` 返回的 `{ newTasks, markRun }` 和 `planGoalTasks` 一个形状；
`repeat.js` 的 `syncRepeatTasks` 就是照 `goals.js` 的 `syncGoalTasks` 抄的（同样用
「静默保存」`touch(true, true)`，因为在渲染过程中调，不能让重画把正在挂事件的 DOM 换掉）。

两道闸：

1. **`genKey`** —— 同一条规则同一天只生成一次；
2. **`rule.lastRun`** —— 今天已经对过表就不再补，所以**你自己删掉的那条不会被加回来**。

另外两条口径：**不预生成未来**（只补今天，不然第一次打开会冒出一堆过去的日子）；
规则只认 `repeatUntil`，没有开始日期（它天生「一直有效」，也不会给过去补生成）。

实例**继承** `text` / `time` / `category` / `priority` / `note` / `tags`，子任务清单抄一份
过来（勾选从零开始，今天的勾不带到明天那条）；**不继承图片** —— 两边共用同一个文件路径的话，
删掉今天这条就可能把规则那张图也一起清掉（附件清理是按路径走的）。

### 39.4 界面：卡片在今日计划页

今日计划页多一张可折叠的「重复任务（N 条）」卡片（`repeat.js` 的 `repeatCardHtml`）：
一条规则一行（正文 ｜ 人话规则 ｜ 「下次：10-16」 ｜ 编辑 / 删除），头上有「添加重复任务」。
折叠状态只记在内存里（和「查看目标进度」一个做法）。

规则**不复用 `todayPlan` 那个表单类型**，而是新加一个 `repeatRule`：「同一套弹窗机制、
同一张 `tasks` 表、和今日计划几乎一样的字段」，但它不占日期 —— 硬塞进今日计划那套字段里
会出现「既有日期又有重复」的四不像。规则**不给图片区**（实例不继承图片，规则自己存图没地方用，
也就不用多开一个附件目录）。「重复」那一格是一个新控件 `kind: "rule"`：一句人话文本框
＋下面一行实时预览（`bindRulePreview`），顺手把「这句话里没写出哪几天」当场说出来
（保存时 `validate` 还会再拦一道：`repeat` 必填，且通篇没有时间词的过不了）。

删规则只删这条配置：确认框写明「已经生成的那几条待办留在今日计划里，不会跟着消失」
（和删模块目标一个口径）。

### 39.5 搜索与统计

- 搜索池里 `tasks` 那一条的 `fields` 多了 `"repeat"` 和子任务文字（`subtaskTextOf`）：
  搜「每周一」找得到规则，搜「换跑鞋」带得出挂它的那条父任务。
- **统计不动**：重复任务只按生成出来的实例参与统计（生成几条算几条）；
  规则本身不是待办，不占今日计划、不进「未完成」的计数。

### 39.6 老数据与兜底

`服务.py` 只补不改：`tasks` 逐条补 `repeat` / `repeatUntil` / `lastRun`（空串）和
`subtasks`（数组，逐条补 `id` / `text` / `done`，缺 id 的当场发一个 `st-` + 8 位十六进制 ——
列表上那个勾选框要靠 id 认人）。`genKey` / `repeatId` **不在这儿补**
（补了反而让老数据看着像生成物）。

### 39.7 纯逻辑与测试

纯逻辑在 `task-calc.js`：`isRepeatRule` / `repeatRulesOf` / `repeatDueOn` / `genKeyOf` /
`addDays` / `nextRepeatDay` / `planRepeatTasks`（重复那半），`subTasksOf` /
`subtaskProgress` / `setSubtasksDone` / `subtaskTextOf` / `SUBTASK_LIMIT`（子任务那半）。

新增两份真浏览器回归（同一套无头 Edge + CDP 脚手架，临时数据目录、跑完自清）：

- `tests\子任务.test.mjs`（30 项）：弹窗里回车加两条（**不触发保存**）→ 行上 `0/2` →
  点开就地展开（`getComputedStyle` 确认真看得见）→ 勾一条 `1/2` 且父任务没完成 →
  两条都勾上父任务自动完成 → 取消一条父任务跟着取消 → 勾父任务两条一起勾上 →
  首页和项目详情那两处也带同一枚胶囊；
- `tests\重复任务.test.mjs`（32 项）：建一条「每天」的规则（跑测试那天是星期几不确定，
  不用「每周一、三、五」去赌）→ 卡片里列出它、写着「下次：…」→ 今天那条自动生成、
  挂着「重复任务」标记 → 再进页面不多生成 → 勾上再进来还是勾着的 →
  删掉那条、重进也不会自己回来（`lastRun` 生效）→ 规则带子任务时生成物也带着清单 →
  删规则时确认框写明生成的待办留着、规则进回收站而不是被抹掉。

已有的几份跟着加断言：`待办联动` 到 141 项、`表单计算` 到 290 项（`repeatRule` 这个类型、
`rule` 与 `subtasks` 两种控件）、`开发计算` 到 106 项（展示副本带清单）、`搜索` 到 113 项；
`自检.py` 92 → 95 项。

## 40. 数据图表（2026-10-14）

### 40.1 一句话

给两张「看数字看不出门道」的地方补上图：**游戏娱乐的游玩统计**（TOP 排行加横条 +

先数了一遍已有的：记账那边**已经有**当月分类环形图（21 节）和近 6 个月柱状趋势图

### 40.2 为什么单独开 `chart-calc.js`

三张图要的是同一批东西：月份序列、条长比例、柱状几何、热力分档。摆在各自的页面里就是
抄三遍、还各写各的测试；放进纯逻辑模块之后 `node tests\图表计算.test.mjs` 能一条条断言
（和记账、待办那几个计算模块一个路数）。拼 HTML / SVG 的活也在这儿 —— 页面只管把结果
塞进 DOM、挂事件，所以它**自带一份本地 `esc`**，理由和 `item-form.js` 那份一样：
`store.js` 的 `esc` 会碰 `window`，纯模块 `import` 不了。

| 函数 | 干什么 |
| --- | --- |
| `lastMonths(month, count)` | 「2026-10」往回数 → 升序那几个月（含当月、跨年接得上）—— **从 `finance-calc.js` 搬来** |
| `barRatioOf` / `barRowsOf` | 条长比例（不除零、不出负）；给一组记录各补一个 `ratio` |
| `trendBars` | 柱状图的几何：每根柱的 x / 宽 / 高 / 顶 |
| `heatGrid` / `heatLevelOf` | 近 N 周的格子（按列返回，一周一列）；金额分档（0 元固定 0 档） |
| `barFillHtml` / `trendChartHtml` / `heatmapHtml` | 三个拼装函数：行背景横条、整段柱状 SVG、整块热力网格 |

`lastMonths` **搬**过去之后，`finance-calc.js` 那儿改成
`export { lastMonths } from "./chart-calc.js";` —— `finance.js` 和
`tests\记账趋势.test.mjs` 一个字都不用改。日期小工具借现成的（`weekStartOf` 从
`goal-calc.js`、`addDays` 从 `task-calc.js`），没有再抄第四份。

### 40.3 游戏娱乐：两张图

### 40.4 记账：支出日历

左栏第四张卡：**近 26 周 × 7 天**（周一起，最后一列是本周），一格一天，颜色按当天支出
分五档（0 元最浅），悬停给「日期 · 支出 ¥x」，今天那格描个边；卡片头上写着
「近 26 周共 ¥… · 最凶的一天 ¥…（日期）」。

- **只算支出**：图上要读的是「哪天花得凶」，收入混进来会把颜色搅乱（收入有月历和环形图）。
- 数据走 `finance-calc.js` 新加的 `dayExpenseMap(transactions)`（跨月，所以不能用按月切片的

## 42. 热量营养计算与菜谱库（2026-10-14）

### 42.1 一句话

饮食模块原来只能记「吃了什么」（四餐各一个文字框 + 水杯数），答不了「今天吃了多少热量、
蛋白够不够、是不是又超了」。这一轮把两件事一起做了：**菜谱库**（一样东西每份多少营养）
和**热量营养计算**（每餐挑一下、填份数，今日热量与三大营养素自动出来，能配每日目标）。

### 42.2 数据：两个形状，条目存的是「每份的快照」

```jsonc
// 新表：菜谱库 data.foods —— 一样东西「每份」多少
{ "id": "f-1", "name": "米饭", "unit": "碗",
  "kcal": 200, "protein": 4, "fat": 0.5, "carb": 44, "tags": ["主食"], "note": "" }

// 每餐挂一份清单：meals[].items —— 这一餐吃了哪样、几份
{ "id": "mi-1", "slot": "breakfast", "foodId": "f-1", "name": "米饭",
  "unit": "碗", "amount": 1.5,
  "kcal": 200, "protein": 4, "fat": 0.5, "carb": 44 }
```

条目里的营养是**每 1 份的快照**，不是「这一条一共多少」。两条理由：

- 份数随时能改（1 碗 → 1.5 碗），营养跟着走，不用重算数据；
- **改菜谱不会动摇历史账** —— 今天把「米饭 / 碗」从 200 改成 230 千卡，上个月的记录还是
  按当时那个数算的（删菜谱也一样：已经记过的条目不受影响）。

`slot` 固定是 `breakfast` / `lunch` / `dinner` / `snack`（页面上叫早 / 午 / 晚 / 加餐），
认不出的一律算加餐 —— 老数据、手改过的都不丢。

### 42.3 纯逻辑：`app/web/diet-calc.js`（新）

饮食这一块原来没有纯逻辑模块（几个小函数散在页面里），这一轮建起来：
`normalizeFood` / `normalizeMealItem` / `itemsOfSlot` / `nutritionOf` / `dayNutritionOf` /
`dayKcalSeries` / `nutritionTargetOf` / `kcalStateOf`。

两条口径值得记一笔：

- **先按原值相加、最后再四舍五入**（一条条先取整再加，误差会攒起来）；
- 份数没填按 1 份算，写成 0 / 负数就当 0（那一条不贡献热量）。

`kcalStateOf` 的档位：没设目标 → `none`（只报数、不画进度条）；不到 80% → `low`；
80% 到 100% → `good`；超了 → `over`（页面标红）。`percent` 不封顶，好知道超了多少。

### 42.4 界面

- **每餐那一行多一段清单**：文字输入框照旧（「随手写一句」留着），下面挂该餐的条目
  （`米饭 1.5 碗 · 300 千卡`）+ 行尾那个「＋ 加一样」。

  **每日目标就在这张卡上填**（四个输入框，离开输入框自动保存进 `settings.nutritionTarget`）、
  近 7 天热量柱状图（复用 `chart-calc.js` 的 `trendChartHtml`）。
  为什么目标不用弹窗：饮食页本来就是「输入框直接改、离开就存」的风格。

- **两个新表单类型**：`food`（名称 / 每份是 / 四格营养 / 标签 / 备注）与 `mealItem`
  （哪一餐 / 份数 / 名称 / 单位 / 四格营养 / 标签）。

### 42.5 两个小机制

1. **`bindAutoFill`（`item-dialog.js` 里第 4 个 bind*）**：字段声明 `autoFill: "foods"`，
   弹窗的 `ctx.autoFill.foods` 是「名字 → 每份营养」；名字一换就把后面几格填上
   （只在名字真的变了时带一次，用户接下来自己改的数不会被覆盖）。
   这是「选了菜谱自动带出营养」那一步的实现。
2. **`mealItem` 不进顶层表**：`table: ""`，落盘走 `persist` 钩子（挂到 `ctx.meal.items`）、
   删除走 `trashPlan.apply`（从那一餐里摘掉，不进回收站）。
   顺手修了一处老毛病：`trashPlan` 原来只把「几张表」传下去、**没传 ctx**，
   所以拿不到 `ctx.meal`（`表单计算` 里那条 `apply` 断言抓出来的）。

## 43. 笔记模块（富文本 / Markdown）（2026-10-14）

### 43.1 一句话

新增**第 11 个模块「笔记」**：一篇一篇的 Markdown 笔记，能贴图、贴标签、全文搜到；
左边列表、右边写，右上角「预览」看渲染结果。背景：第 4 节那句「笔记模块本身还没做，
组件已经按三个模块复用写好」—— 附件组件当初就是为它预留的（目录 `note` 一直在白名单里）。

### 43.2 「富文本 / Markdown 双模式」怎么落地

需求原文是个「/」，两种读法都成立。这一版选 Markdown，理由：

- 真富文本（所见即所得）要处理选区、粘贴、撤销栈、光标位置，成本是这一整轮的几倍；
- 一旦存成 HTML，数据和源码就不再一一对应（备份、diff、搜索、手改都变难）。

「双模式」按**同一份内容的两种看法**落地：左边写（textarea 里就是 Markdown 源码），
右边看（实时渲染），右上角一个「预览」开关并排打开 / 收起（窄屏落到下面）。
存进数据的只有 `body` 那一段**纯文本**。

### 43.3 数据

新表 `data.notes`：`{ id, title, body, tags, imagePaths, createdAt, updatedAt }`。
`body` 是 Markdown 源码；图片走现成的附件组件，目录用早就预留的 `note`
（所以这一轮**没动附件白名单那三处**）；删了进回收站，不做归档。

### 43.4 渲染器：`app/web/markdown.js`

零外链、不装依赖，所以自己写：纯函数 `renderMarkdown(text)`，`node tests\Markdown.test.mjs`
56 项断言。支持的语法：六种标题、粗体 / 斜体 / 删除线、行内代码、``` 围栏代码块、
无序 / 有序列表、引用、分割线、链接与图片、空行分段与单回车换行。

**三条安全规矩**（这一条最要紧，顺序不能反）：

1. **先转义再插标签** —— 整段文字先过一遍 `& < > "`，之后插入的都是我们自己生成的标签；
   所以笔记里写 `script` 标签只会原样显示成文字；
2. **地址白名单** —— 只认 http / https、页内锚点（`#`）、本地附件（`attachments/…`），
   其它一律不生成 `<a>`（`javascript:` 那种就这么被挡住的），原样当文字显示；
3. 生成的标签都带自己的 class（`md-h1` / `md-p` / `md-code`…），样式全在 `style.css` 里。

### 43.5 界面：`#note`

- **左：列表**（按 `updatedAt` 倒序，显示标题 / 正文第一行 + 摘要 + 标签胶囊），
  上面一个筛选框（标题 / 正文 / 标签就地筛，只重画那一列，不冲掉正在打字的内容）。
- **右：编辑器**（标题、正文 textarea（等宽）、标签、图片区、预览开关、删除），
  没选中时给一句「选一条，或者新建一条」。
- **就地保存**：打字时静默保存（`touch(false, true)`：写数据、不重画，光标不跳），
  离开输入框时正常保存并重画（列表的标题 / 摘要 / 排序跟着变）。不开弹窗 —— 弹窗是给
  「填几条字段」用的，写长文该像本地编辑器。
- **图片**：贴图后出现「保存图片（N 张还没存）」按钮（图还只是内存里的 blob）；
  离开输入框时也会顺手存掉。附件组件的 `onChange` 会带出这个按钮、并在撤掉已存的图时
  立刻写回记录。
- 地址支持 `#note/<id>`：从搜索点过来直接打开那一条。

所见即所得编辑器、Markdown **表格**（手写表格很难受，渲染器也还要多一块）、

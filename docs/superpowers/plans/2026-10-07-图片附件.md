# 图片附件 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement
> this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 给「记一笔」和 bug 登记加上可选的图片备注 —— 图片独立存在本地
`数据\attachments\` 里，`数据.json` 只存相对路径，同一套组件三个模块复用。

**Architecture:** 纯逻辑抽成 `app/web/attachment-calc.js`（Node 直接单测），
DOM 部分放 `app/web/attachment.js`（附件区 / 缩略图 / 全屏查看）。
服务端在 `app/服务.py` 里加「收一张、删几张、把图发出去」三个口子，
图片一律先过长成 `yyyyMMdd_随机.扩展名` 的白名单校验。记账和 bug 登记各接一处。

**Tech Stack:** 原生 HTML + CSS + ES 模块（无框架、无构建、零外链）；
浏览器原生 `<input type="file">` + canvas 压缩 + `URL.createObjectURL` 预览；
Python 标准库小服务（JSON + base64，不碰 multipart）；Node 跑纯逻辑单测。

**Spec:** `docs/superpowers/specs/2026-10-07-图片附件-design.md`（实施前先读一遍）

## Global Constraints

- **零外链**：`.html` / `.css` / `.js` 里不能出现 `http(s)://`，`tests/自检.py` 的
  `check_no_external()` 会扫。
- **不装依赖**：只跑 Python 标准库 + 本机 Node v24，不建 `node_modules`。
- **事件不挂公共 `#view`**：一律 `bindFresh(root, { click, submit, change, input })`。
- **改动即保存**：明确动作 `touch(true)`；连续输入 `touch(false, true)`；
  只挂 `change`/`input` 的新控件要加进 `store.js` 的 `AUTOSAVE_FIELDS`。
- **删除一律先进回收站**：`moveToTrash(表名, 行, 显示文字)`；图片只在
  「彻底删除」那一步才可能跟着删。
- **颜色只用 CSS 变量**，四套皮肤 × 明暗都不能出横向溢出。
- **注释和提交信息用中文**，说清「为什么」。
- 每个任务结束时工作区要能跑：`python tests\自检.py` 全过、控制台 0 条 error / warning。
- **写盘顺序**：图片先落盘，`数据.json` 后落盘；「取消」时一个字节都不能留下。

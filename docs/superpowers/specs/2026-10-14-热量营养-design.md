## 1. 现状与缺口

饮食模块现在只有：四餐各一个**文字输入框**（早/午/晚/加餐）、喝水杯数、一张月历、
最近 7 天的回顾、外加模块目标那张卡。也就是说它记的是「吃了什么」，
**答不了「今天吃了多少热量、蛋白质够不够、是不是又超了」** —— 而这正是饮食这件事
最需要看的数。

同时，每天重复吃的东西（鸡蛋、牛奶、米饭、常点的那几样）现在每次都得重打一遍字，
顺手补一句热量的话还得自己记着每样的数 —— 所以**菜谱库**和热量计算是同一件事的两半：
库里存「一样东西每份多少热量 / 蛋白 / 脂肪 / 碳水」，每餐从库里挑、填份数，热量自己就出来了。

## 2. 数据

### 2.1 新表：菜谱库 `data.foods`

```jsonc
{
  "id": "f-1",
  "name": "米饭",
  "unit": "碗",          // 「每什么」：碗 / 个 / 杯 / 100 克 / 份（自由文本，页面上一行里显示）
  "kcal": 200,           // 每一份的热量（千卡）
  "protein": 4,          // 每一份的蛋白质（克）
  "fat": 0.5,            // 脂肪（克）
  "carb": 44,            // 碳水（克）
  "tags": ["主食"],
  "note": ""
}
```

营养四格都**允许留空**（记个热量也能用），留空就是 0；「一样东西只知道热量」是最常见的情况。

### 2.2 每餐挂一份清单：`meals[].items`

一天的饮食还是 `meals` 表里一条（`date` + 四餐文字，一个字不动），多挂一个数组：

```jsonc
{
  "id": "m-1", "date": "2026-10-14",
  "breakfast": "鸡蛋 + 牛奶", "lunch": "", "dinner": "", "snack": "",
  "items": [
    { "id": "mi-1", "slot": "breakfast", "foodId": "f-1", "name": "米饭",
      "unit": "碗", "amount": 1.5,
      "kcal": 200, "protein": 4, "fat": 0.5, "carb": 44 }
  ]
}
```

**关键一条：条目里存的是「每 1 份」的营养快照**，不是「这一条一共多少」。两条理由：

- 份数随时能改（1 碗 → 1.5 碗），营养跟着走，不用重算数据；
- **改菜谱不会动摇历史账** —— 今天把「米饭 / 碗」从 200 改成 230 千卡，
  上个月的记录还是按当时那个数算的。

`amount` 允许小数（0.5 碗饭、1.5 勺油），汇总时乘上去再四舍五入到整数。
`foodId` 可以空（临时吃的东西，手填一个名字就行），这时候它就只是一条独立的记录。

## 3. 纯逻辑：`app/web/diet-calc.js`（新）

饮食这一块一直没有单独的纯逻辑模块（页面里散着几个小函数），这一轮把它建起来 ——
热量这块最容易算错，得能一条条断言。

| 函数 | 干什么 |
| --- | --- |
| `normalizeFood(row)` | 补齐一条菜谱的形状（数字转数字、缺的补 0 / 空串） |
| `normalizeMealItem(row)` | 补齐一条「吃了什么」（`slot` 认不出就归到加餐） |
| `itemsOfSlot(meal, slot)` | 这一餐的条目（`meal` 可能是 null） |
| `nutritionOf(items)` | 按份数换算求和 → `{ kcal, protein, fat, carb }`（整数） |
| `dayNutritionOf(meals, date)` | 那一天的合计（四餐加起来） |
| `dayKcalSeries(meals, dates)` | 这几天每天的热量 + `ratio`（给柱状图，和 `gameMonthTrend` 一个形状） |
| `kcalStateOf(total, target)` | 热量档位：`{ level, percent, diff, over }` |

口径：

- 四餐的键固定是 `breakfast` / `lunch` / `dinner` / `snack`，页面上叫早 / 午 / 晚 / 加餐；
  `slot` 认不出（老数据、手改过）一律算加餐，**不丢数据**。
- 汇总**按 `slot` 过滤**：一天的合计 = 四餐的条目相加，所以挂在加餐上的也不会漏。
- **份数没填 → 按 1 份算**（「一份」是最常用的默认）；写成了 0 或负数就当 0（那一条不贡献热量）。
  营养四格允许是小数（0.5 克脂肪很正常），汇总时先按原值相加、最后再四舍五入到整数。
- `kcalStateOf` 的档位：没设目标 → `none`；不到 80% → `low`；80% 到 100% → `good`；
  超了 → `over`（页面标红）。和记账预算、模块目标那套 `barLevelOf` 一个思路，
  只是阈值不同（热量是「别超」）。`percent` 不封顶，好让「超了多少」有数可查。

## 4. 界面

### 4.1 饮食页（`#diet`）多加两块

1. **每餐那一行挂上清单**：文字输入框照旧（「吃了什么」还是能随手写一句），
   下面多一段该餐的条目：`米饭 1.5 碗 · 300 千卡`，行尾可改可删；
   行头一个「＋ 加一样」→ 弹窗（见 4.3）。
2. **今日营养卡**（放在「今天吃了什么」下面）：
   - 热量：`已吃 1,850 / 目标 2,000 千卡`，进度条 + 一句差值（「还差 150」/「超了 120」），
     超了标红；
   - 三大营养素三格：蛋白 / 脂肪 / 碳水（有目标就画进度，没有就只报数）；
   - **每日目标就在这张卡上填**（热量 / 蛋白 / 脂肪 / 碳水四个输入框，离开输入框自动保存）。
     为什么不用弹窗：饮食页本来就是「输入框直接改、离开就存」的风格，多一个弹窗反而不顺手；
   - 近 7 天热量柱状图（复用 `chart-calc.js` 的 `trendChartHtml`）。

水杯数和「最近几天」保持原样；月历照旧标「这天有记录」。

### 4.2 菜谱库子页（`#diet/foods`）

照开发工作那套子 Tab（`今天吃了什么` / `菜谱库`）：菜谱库页 = 一行一样
（名称、每份营养、标签、编辑 / 删除），头上「＋ 加一样」。就是自媒体素材库那个形状。

### 4.3 弹窗：`food` 与 `mealItem`

两个新表单类型（`item-form.js`）：

| 类型 | 字段 |
| --- | --- |
| `food` | 名称（必填）、每份是（`unit`，比如「碗」）、热量、蛋白、脂肪、碳水、标签、备注 |
| `mealItem` | 餐次（下拉：早 / 午 / 晚 / 加餐）、名称（`combo`：菜谱库里有就选、没有就手打）、份数、每份热量 / 蛋白 / 脂肪 / 碳水 |

`mealItem` 里「名称」那一格**选到库里有的名字就自动带出后面几格**（营养 + 单位），
手打的新名字就自己填。这是 `item-dialog.js` 里新加的一个小机制 `bindAutoFill`：
字段声明 `autoFill: "foods"`，弹窗的 `ctx.autoFill` 里按名字给一份资料，
输入框一变就去查、查到就填（填完还能自己改）。

## 5. 搜索

搜索池加「菜谱」一条（表 `foods`，匹配名称 / 单位 / 备注，跳 `#diet/foods`）；
饮食记录那条 spec 的匹配字段加上条目的名字（搜「米饭」能带出那天）。

## 6. 明确不做

- **不做每 100 克的份量换算**：菜谱按「每份」记（1 碗 / 1 个 / 100 克都能写在 `unit` 里），
  要做「称了 137 克再按 100 克折算」是另一个量级的事（还得有食物成分大表）。
- 不内置食物成分数据库（几百上千条那种）：个人用不上，而且没法联网更新；
  自己常吃的几十样录一遍就够了。
- 不做营养建议 / 配餐推荐 / 体重目标联动、不做导出、不做按周月的营养报表。
- **不改四餐那四个文字输入框**：那句「随手写一句」是有用的，留着。

## 8. 需要拍板的几件事

1. **每日目标就在饮食页上填输入框**（我按这个写）；备选是单独一个「营养目标设置」弹窗。
2. **条目存「每份的快照」**（我按这个写，改菜谱不动历史账）；备选是只存 `foodId`、
   每次现查菜谱（那改菜谱就会改历史）。
3. **只算热量也能用**（蛋白 / 脂肪 / 碳水可以全空）；要不要把三大营养素做成必填？
   我按「都选填」写。
4. **一天还是 `meals` 一条**（四餐文字 + `items` 挂在一起），不新开一张「饮食条目表」——
   我按这个写，理由是「一天一条」这个形状已经在用了（月历、最近几天、首页摘要都认它）。

## 10. 执行时和设计不同的地方（实现完回填）

1. `mealItem` 多带了一格**标签**。原因：`tests\表单计算.test.mjs` 里有一条从标签那一轮
   留下来的护栏 ——「每个弹窗类型都要挂标签字段」。一条吃的贴个「外卖 / 聚餐」也确实有用，
   所以顺着加上了（`normalizeMealItem` 也跟着带上 `tags`，营养换算不看它）。
2. `trashPlan(type, row, 几张表)` 加了第 4 个参数 `ctx` —— 原来只把「几张表」传下去，
   `mealItem` 的删除计划拿不到 `ctx.meal`，`apply()` 就成了空转。这条是
   `tests\表单计算.test.mjs` 里那句「apply 把它从那一餐里摘掉」抓出来的
   （真浏览器那边同理）。属修老毛病，不是新设计。
3. 菜谱库子页第一版忘了 `bindFresh`（那一页上所有按钮都点不动），
   `tests\饮食热量.test.mjs` 当场就红 —— 这条写进「真浏览器回归值得留着」的又一个例子里。

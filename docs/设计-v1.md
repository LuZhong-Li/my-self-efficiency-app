## 1. 已确认的决策

- 软件名：**小李**（2026-10-06 定的；界面标题、浏览器标签页、黑窗口标题都用它）。
- 开源之后可以分两个目录：**日常在用的那一份带着自己的数据**，
  **仓库放在另一个文件夹**，只用来开发和推送；两边靠 `同步到小李.cmd` 同步代码。
- 单人自用；只在本机浏览器里运行；不登录、不联网、不上云、不做手机端、不部署。
- 程序和数据放在同一个目录里；放哪个盘、叫什么名字都行，代码不认死路径。
- 打开方式（方案 A）：双击 `启动.cmd` → 本机小服务起在 127.0.0.1 → 浏览器自动打开界面。
- 数据存成文件，不装数据库；这个文件可以随时复制走。
- v1 = 十个模块各做「最小可用的那个场景功能」，清单见 `需求清单.md` 第 3 节。
- 报价单不做。~~记账、预算不做~~ —— **2026-10-07 改了**：用户要求把「记账」加成
  第 10 个模块（v1 含月度总预算），见第 21 节；账户余额、转账、分类预算、

### 2.1 前端约定（第 5 步起）

- 一个模块一个文件：`app/web/<模块>.js`，导出 `render<模块>(root)`；
  公共小零件（区块标题、标签、下拉选项）放在 `ui.js`。
- 地址用哈希路由：`#dev` 是项目列表，`#dev/<项目id>` 是项目详情，
  刷新后还能停在同一个项目里。
- **项目待办就存在 tasks 表里**：`belong` 写成 `dev:<项目id>`、`date` 留空。
  今日计划和首页只认 `date` 有值的任务，所以它们不会混进来（改这两处的
  筛选条件时要记得带上 `date` 非空判断）。
- 行内编辑：每个模块自己记一个「正在编辑谁」，改完 `touch(true)` 立刻落盘。
- **事件不要挂在公共的 `#view` 上**，用 `ui.js` 里的 `bindFresh(root, {...})`：
  每次渲染把内容包进一层新容器，事件挂在这层，旧容器的监听随旧 DOM 一起丢掉。
  早先图省事挂在 `#view` 上（加了个「只挂一次」的开关），结果切到别的模块后旧
  监听还在：自媒体和今日计划的表单 id 都叫 `add-form`，提交其中一个，另一个
  模块的处理函数也会跟着跑、去读不存在的字段，控制台刷出一堆 TypeError。
- **输入框自动保存要挂两个事件**：打字走 `input`（`touch(false, true)` 静默保存，
  只写数据不重画，光标才不会跳），离开输入框走 `change`（正常保存 + 重画，
  顺便刷新下面的列表）。只挂 `change` 的话，用户没离开输入框就关窗口会丢字。
  例外：数字类的「保留份数」只挂 `change`，因为敲到一半（比如想打 12，
  先出现 1）就去清理备份是破坏性的。

## 3. 运行与技术约束

- 运行时：Python 3.14（python.org 正式安装版），只用标准库。
  **注意：不能用 `D:\msys64\ucrt64\bin\python.exe`**，原因见下面 3.1。
  `启动.cmd` 自己会挑一个能用的 Python，不用手填路径。
- 浏览器：Edge（本机已装）。
- 服务只监听 `127.0.0.1`，端口从 8765 开始；万一 8765 被占用就依次试
  8766、8767……最多试 12 个。局域网和外网都访问不到。
- 界面零外链：不引用任何 CDN、在线字体、在线图标，断网也能正常打开。
- 前端不引框架：原生 HTML + CSS + JS（个人自用规模，框架只会增加维护负担）。
- 关掉黑窗口 = 程序停止；此时数据早已落盘，下次双击继续。

### 3.1 本机实测结论（第 1 步验收时发现）

- **这台电脑的「智能应用控制」（Smart App Control）是开启状态**
  （注册表 `HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy` 的
  `VerifiedAndReputablePolicyState = 1`）。
- MSYS2 那份 Python（`D:\msys64\ucrt64\bin\python.exe`）本身能启动，但它的
  `.pyd` 扩展文件没有数字签名，被系统策略拦下，连 `import struct` 都失败，
  自然也就 `import http.server` 不了 —— 原来打算拿它当运行时的方案作废。
- 可用的替代：python.org 正式安装版（有签名，实测通过）。本机有两份：
  `%LOCALAPPDATA%\Programs\Python\Python314\python.exe`（默认）和
  `...\Python312\python.exe`。
- `启动.cmd` 因此不写死路径，而是按顺序试：用户目录下的 python.org 安装 →
  Program Files → PATH 里的 python → 最后才试 msys2 那份；每个候选都先跑一次
  `import http.server, json, mimetypes, webbrowser, urllib.request`，
  真能导入才采用。
- `启动.cmd` 里的 `chcp 65001` 不能删：脚本要启动的文件名「服务.py」是中文，
  批处理文件按 UTF-8 保存，必须让控制台切到 UTF-8，cmd 才能正确读到中文名。

## 4. 数据怎么存

- 全部数据放一个 JSON 文件：`数据\数据.json`。
- 写入策略：先写临时文件、再替换（原子写），避免写一半断电把文件弄坏。
- 自动备份：每天首次打开时复制一份到 `数据\备份\YYYY-MM-DD.json`，保留最近 14 份。
- 设置页提供：导出备份 / 导入恢复 / 打开数据文件夹 / 清空数据（二次确认）。

### 4.1 接口一览（本机服务）

| 方法 | 地址 | 干什么 |
| --- | --- | --- |
| GET | `/api/health` | 服务信息：数据文件位置与大小、备份目录、导出目录 |
| GET | `/api/data` | 取整份数据 |
| POST | `/api/data` | 整份写回（日常唯一写入口） |
| GET | `/api/backups` | 备份文件列表（名字、大小、时间、类型） |
| POST | `/api/backup` | 立刻备份一份，名字形如 `手动-2026-10-06-155720.json` |
| POST | `/api/export` | 导出到 `数据\导出\备份-时间.json` |
| POST | `/api/import` | 用传上来的 JSON 覆盖数据，覆盖前自动存 `导入前-*.json` |
| POST | `/api/clear` | 清空数据，清空前自动存 `清空前-*.json` |
| POST | `/api/open-folder` | 在资源管理器里打开数据 / 备份 / 导出文件夹 |

两条踩过的坑，改代码时别踩回去：

1. **POST 处理函数必须先把请求体读干净再干活。** HTTP/1.1 是长连接，留在
   缓冲区里的字节会被当成下一个请求的开头，于是下一个请求莫名收到 400 和
   一张 HTML 错误页（第 3 步踩过一次：点「立即备份一次」后备份列表就报错）。
2. **保留份数按文件修改时间排序。** 备份要用 `shutil.copyfile` 而不是 `copy2`，
   否则备份文件会继承数据文件的时间，排序和显示都会乱。

### 5.1 tasks 的实际字段（第 2 步已落地）

上面那张表是「概念」，真正写进 `数据.json` 的是这些键：

| 键 | 类型 | 说明 |
| --- | --- | --- |
| `id` | 字符串 | 唯一标识，浏览器生成（`crypto.randomUUID`） |
| `date` | `"YYYY-MM-DD"` | 归属哪一天；今日计划里的任务就是今天 |
| `text` | 字符串 | 内容 |
| `time` | `"HH:MM"` 或 `""` | 时间点，可空；空的排在有的后面 |
| `category` | `工作` / `生活` / `运动` / `其他` | 固定四类 |
| `done` | `true` / `false` | 是否完成 |
| `note` | 字符串 | 备注 |
| `belong` | 字符串 | 归属模块，今日计划固定用 `"plan"` |
| `createdAt` | ISO 时间 | 创建时间，同一时间点的排序依据 |
| `doneAt` | ISO 时间或 `null` | 完成时间 |

前端约定：任何修改都「改内存 → 叫一声 `touch()` → 自动写回整份 JSON」。
增删改这类明确动作立刻落盘，勾选和连续输入走 400ms 防抖。

数据文件里除业务字段外，还有几个系统键：

| 键 | 说明 |
| --- | --- |
| `version` | 数据格式版本，写死的 1；服务端靠它判断「这是不是本程序的数据」 |
| `rev` | 修订号，每写一次加一；两个窗口互相覆盖就靠它挡住 |
| `updatedAt` | 最后一次写入时间 |
| `trash` | 回收站，见第 11 节；最多 200 条 |

## 8. 两个注意事项

- D 盘是固定盘，比 U 盘稳；但仍建议偶尔把导出文件放到别的地方（比如网盘或另一块盘）。
- 项目不认死路径：程序走到哪，数据和备份就跟到哪（`服务.py` 按自己的位置推断）。
  真想把数据放到别处，设环境变量 `XIAOLI_DATA_DIR` 指过去就行。

- 所有模块的删除都改成「挪进回收站」：记录存进 `trash` 数组，附上来自哪张表、

### 11.2 两个窗口不再互相覆盖

双击两次启动文件会开两个标签页，两边各拿一份数据，早先后保存的会把先保存的顶掉。

- 数据里加了 `rev`（修订号），每写一次加一；页面读取时是多少，写回来就必须是多少，
  对不上服务端回 409 并拒收，页面自动重新载入并提示。
- 保存成功后用浏览器自带的 `BroadcastChannel` 通知其它窗口；
  其它窗口没有未保存改动就自动同步，有未保存改动就提示「刷新一下更稳妥」。

### 11.3 重要备份不会被自动清理

- 备份列表每条多了「长期保留」按钮，标了之后文件名加 `保留-` 前缀，
  自动清理时跳过它，再点一下取消。

### 11.4 运行日志

- 关键事件写进 `数据\日志\运行.log`：启动、停止、每日/手动备份、导出、导入、
  清空、被拒绝的写入、备份标记。**不记每次普通保存**，免得刷屏。
- 超过 1MB 自动轮换成 `运行.log.1`。

### 11.5 写接口只认本机页面

- 别的网站在你浏览器里也能往 `127.0.0.1` 发请求。现在写接口会看 `Origin`，
  不是 127.0.0.1 / localhost 的一律 403；本机脚本（curl 等）没有 Origin，放行。

### 11.6 数据位置可指定 + 一键自检

- 设环境变量 `XIAOLI_DATA_DIR` 可以把数据放到别的盘；`XIAOLI_PORT` 或
  `--port 8899` 可以换端口。
- 新增 [自检.cmd](../自检.cmd)（背后是 [tests/自检.py](../tests/自检.py)）：
  在临时目录里自己起一个服务跑 23 项检查——接口、修订号、来源校验、备份、

## 13. 月历（2026-10-06）

- 选中那天的卡片列出当天排期，每条显示平台和状态：
  - 计划发布的，可以点「标记已发布」——按**你正在看的那一天**记为发布日，

## 15. 四套外观（皮肤，2026-10-06）

参考木子工作台的三套 appearance（Liquid Glass / Notion 笔记 / Neo-Brutalism，
它用 `data-appearance` 覆盖一整套 token）。小李照这个思路做了**皮肤**：

```
data-skin   = glass | default | notebook | neo   ← 长什么样
data-theme  = light | dark                       ← 亮还是暗（已经是「算完」的结果）
settings.themeMode = light | dark | system       ← 明暗是怎么定的（2026-10-07 加）
```

两个维度**互相独立**，4 × 2 = 8 种组合。切换只改 CSS 变量，不碰任何数据和接口；
皮肤存在 `settings.skin`，刷新、重启都还在。**没设置过就是「液态玻璃」**。

`themeMode` 是「策略」，`data-theme` 是「结果」：选浅色 / 深色就固定住，
选 `system` 就用 `window.matchMedia('(prefers-color-scheme: dark)')` 读系统偏好，
并挂上 `change` 监听——改电脑的明暗，App 立刻跟着变（从后台回来、睡眠唤醒后再补读一次）。
读不到这个特性的极老浏览器按浅色兜底。老的 `settings.theme` 继续留一份「当前实际明暗」，
老数据文件也读得懂；老文件里没有 `themeMode` 时，按 `theme` 迁一次并补进内存，
下次一保存就自动写上新字段。

| 皮肤 | 定位 | 关键做法 |
| --- | --- | --- |
| 液态玻璃（默认） | macOS Tahoe 风，通透磨砂、悬浮分层 | 纯 CSS 渐变壁纸 + `backdrop-filter` 磨砂 + 半透白底 + 细白高光边 + 18px 统一圆角 |
| 极简 | 柔和圆角、轻阴影 | 大卡片 16px 圆角，一档轻阴影，靛蓝主色 |
| 笔记 | 紧凑画布、纯平表面、低饱和标记 | 圆角 3px、无阴影、发丝线、墨色主色（#37352f）、标签变成小方块、卡片内边距收紧 |
| 粗野 | 多色印刷、硬边框、机械反馈 | 直角、2px 硬边框、`4px 4px 0` 硬投影、珊瑚红主色、按下时整体位移 3px（像真的按下去） |

### 15.0 液态玻璃细说

玻璃要好看，**前提是有东西可透**——铺在纯色上磨砂是看不出效果的。所以：

1. **壁纸**：`html` 上铺四团柔和光斑 + 一条斜向渐变的底色，纯 CSS 画的，
   零图片零外链。深色模式换成一整套深蓝紫的夜景色。
2. **分层悬浮**：`body` 加 10px 内边距和间隙，顶栏 / 侧栏 / 状态栏从「贴边通栏」
   改成**独立的圆角玻璃面板**——这是 macOS 那种「一个个窗口浮着」的关键。
3. **磨砂**：`backdrop-filter: blur(22px) saturate(170%)`，只加在卡片、面板、
   对话框这些「大面」上；按钮、标签这类小东西只用半透明底色，省性能。
4. **边缘与深度**：1px 半透明白边模拟玻璃边缘反光，阴影是
   `0 8px 30px rgba(15,23,42,.12)` 再加一道内阴影模拟顶部高光。
5. **列表分隔线**：玻璃上白线会糊成一片，所以单独抽了 `--divider`，
   玻璃皮肤里它比面板边更淡（浅色下是 8% 的黑）。
6. **两种自动降级**：老浏览器不支持 `backdrop-filter` 时（`@supports not`），
   自动换成「稍微不透明的半透卡片」；系统开了「减少透明度」
   （`prefers-reduced-transparency`）就彻底换成不透明，跟 macOS 一个脾气。
7. **动效**：0.2s 匀速的 hover / 按压，卡片悬浮上浮 2px、阴影散开，
   按钮按下缩到 97%。

### 15.1 怎么实现的

- `style.css` 顶部是一整套 CSS 变量（颜色、圆角、边框粗细、阴影、字体）。
  皮肤就是**换这一套变量的值**，不在每个组件上写第二遍样式。
- 为此把边框统一成了 `var(--bw) solid var(--line)`——粗野风把 `--bw` 调成 2px，
  笔记风保持 1px 发丝线，同一行代码两种情况都对。
- 顶栏 / 侧栏 / 状态栏用 `--chrome` 这个变量，笔记风把它调成 #f7f7f5
  （Notion 那种「画布白、侧栏灰」的层次），其他皮肤跟卡片同色。
- 粗野风的「机械反馈」写在皮肤专属规则里：`.btn:active` 位移 + 阴影归零，
  卡片 hover 反而往外挪 2px。

### 15.2 切换入口

「数据与设置 → 外观与标语」里三张卡：每张带一个**小样**（照着那套皮肤的圆角、
边框、投影画的示意图，颜色写死，不然三张小样会长一样），下面是**浅色 / 深色 / 跟随系统**
三颗互斥的明暗按钮和一句话标语输入框（选中「跟随系统」时下面补一句小字说明，
读不到系统明暗就改成兜底提示）。换皮肤、换明暗都会弹个轻提示；
右上角的快捷按钮改成三态循环（浅色 → 深色 → 跟随系统 → 浅色），图标画的是
「点一下会变成什么」：浅色时是 🌙、深色时是 🖥、跟随系统时是 ☀️，hover 说清当前模式。

### 15.3 顺带做的两处手感

- **换页淡入**：`ui.js` 的 `markEnter()` 给刚画好的内容加 0.18s 的淡入上移。
  只在真的换页面时叫，勾选、增删这种重画不叫——否则每点一下就闪。
  跟随系统的「减少动态效果」自动关掉。
- **没有引入任何在线字体**：三套皮肤只用系统字体和形状/颜色区分，
  自检里有「界面文件没有任何外部链接」这一项，皮肤做完依然是 0 条。

## 16. 启动速度（2026-10-06 排查）

用户反馈「启动小李好慢」。先量，再改——量出来的结果很意外：

| 环节 | 修之前 | 修之后 |
| --- | --- | --- |
| 直接用 python 起服务，到端口能连 | 7584 ms | **501 ms** |
| 双击 `启动.cmd`，到端口能连 | 7746 ms | **725 ms** |
| 重复双击（服务已在跑）到自动退出 | 1884 ms | 1884 ms（其中 1.5 秒是刻意留出让你看清提示） |
| 浏览器里刷新，到首页内容出现 | 230 ms | **170 ms** |
| 单次「导入探测」的 Python 启动 | ~137 ms | 不变 |

### 16.1 慢在哪

`.cmd` 里那串「找一个能用的 Python」只花了 160 ms，不是它。真正的时间在服务自己身上：

原来的「检测是否已经有小李在跑」是用 `urllib.request.urlopen` 去问 **12 个端口**，
每个给 **0.6 秒**超时。正常机器上连一个没人监听的本地端口会「立刻被拒绝」，
所以这个检查本来应该几乎不花时间；**但要是防火墙 / 安全软件 / VPN 把连接「丢掉」
而不是「拒绝」，每个端口都会一直等到超时**——12 × 0.6 ≈ 7.2 秒，和实测的 7.5 秒对得上。

> 顺带一提：`urllib` 还会读代理环境变量，本机自检走代理也是不对的。

### 16.2 怎么改的

1. **一趟走完**（`start_server()`）：从 8765 往上，遇到是自家的服务就直接开浏览器退出，
   遇到能绑的就立刻开工——不再「先把 12 个端口挨个问一遍再回来绑端口」。
   正常情况只问 1 个端口。
2. **换 `http.client` 直连**，不走 `urllib` 那套代理逻辑。
3. **超时 0.6 秒 → 0.25 秒**：就算真碰上「丢包」型防火墙，也只多等 0.25 秒。
4. **浏览器提前开**：端口一绑好就把浏览器叫起来（0.6 秒 → 0.15 秒，并且挪到备份、
   打印之前），它加载页面的同时我们接着把剩下的事做完。
5. **静态文件可缓存**（`no-store` → `no-cache` + `Last-Modified`）：文件没变回 304，
   省掉把 20 个文件重传一遍的功夫；改了文件立刻就是新的，不会拿着旧页面发呆。
   `/api/` 那些接口仍然是不缓存的。

### 16.3 还剩什么

剩下的时间基本在浏览器自己身上：**电脑上第一次开 Edge（或当天第一次）要 2～4 秒**，
这是 Edge 冷启动，小李管不着。第二次以后双击 `启动.cmd`，服务已在运行，
它只做一件事——把浏览器叫到前台，所以会明显快很多。

## 17. 项目卡片拖拽排序（2026-10-06）

开发工作页的项目卡片支持拖着换顺序，松手即存，刷新还在。

### 17.1 用了 SortableJS（本项目唯一一个第三方文件）

在此之前这个项目是「前端零依赖」。做拖拽排序时评估了两条路：

| 方案 | 好处 | 代价 |
| --- | --- | --- |
| 原生 HTML5 拖放 | 不引任何文件 | 原生拖拽的预览和回弹很生硬，边界情况（自动滚动、跨列）要自己写一大堆 |
| **SortableJS（选定）** | 丝滑的 FLIP 动画、边界情况都处理好了、MIT 许可 | 多一个 44KB 的本地文件 |

选后者的理由：它是**本地放着的文件**，不联网、不依赖 CDN，断网照常能用；
MIT 与本项目许可兼容，许可证随文件一起放（`app/web/lib/sortable.LICENSE`）。
为了它，README 里「前端零依赖」的说法也改成了「不引框架」——不能让文档撒谎。

### 17.2 接法

- `index.html` 用普通 `<script src="lib/sortable.js">` 引入（放在模块脚本之前）。
- `dev.js` 的 `setupDragSort()`：只在**渲染出 `.proj-grid` 且卡片 ≥ 2 张**时实例化，
  离开这个页面就 `destroy()`；每次重画都重建（因为视图容器会被换掉）。
- 拖完的 `onEnd`：读 DOM 上的 `data-id` 顺序 → 就地重排 `projects` 数组 →
  `touch(true)` 整份落盘 → 弹一句「顺序已保存」。
  兜底逻辑确保**一条记录都不会丢**（没出现在 DOM 里的接在最后）。
- 关键参数 `distance: 5`：鼠标移动 5 像素以内算点击，不算拖拽——项目卡片本身是个
  链接，不加这个参数点击会被拖拽吃掉。
- 库没加载成功（比如有人删了那个文件）时 `setupDragSort()` 直接返回，
  页面一切照旧，只是拖不动。

### 17.3 实测记下来的两个坑

1. **Sortable 1.15 监听的是 PointerEvent**，不是 MouseEvent。用合成
   `new MouseEvent("mousedown")` 触发不了拖拽；要测就得用 CDP 的
   `Input.dispatchMouseEvent` 派发**受信任的**真实鼠标事件（按下 → 分十几步移动 → 松开）。
2. 拖拽的落点必须在**视口范围内**。我第一次把目标点算到视口外（x=965 > 视口宽），
   Sortable 把卡片原样放回，`onEnd` 照样触发、顺序却没变——看着"成功"其实什么都没发生。

实测结果：把第 1 张拖到最后 → 界面顺序变成 `p2 → p3 → p4 → p1`，状态栏「已保存」，
磁盘 `数据.json` 里 `projects` 数组同步变成这个顺序，刷新后仍是这个顺序；
单独点一下卡片仍然正常进入项目详情。

## 18. 自动保存的三种情况 + 未保存提醒 + 项目筛选（2026-10-06）

### 18.1 自动保存分三种，别混为一谈

| 情况 | 做法 | 例子 |
| --- | --- | --- |
| **单值字段**：一个输入框就是一条数据 | 打字走 `input` **静默保存**（只写数据不重画，光标不跳）；离开输入框再正常保存一次并刷新列表 | 快速备忘、三餐、每周训练安排、一句话标语、保留份数 |
| **行内编辑**：一整行/一个表单对应一条已有记录 | 边打字边**静默保存**（打字期间不重画，所以编辑框不会被重建）；点「保存」退出编辑态，点「取消」用**进编辑时的快照**退回去 | 项目编辑、待办编辑、问题编辑 |
| **新增表单**：填一半还不是一条记录 | **不自动存**（半截的项目会变成空记录污染列表），但**打上「有还没保存的改动」标记**，关窗口前浏览器会拦一下 | 添加项目 / 添加任务 / 添加记录 |

- 关窗口的提醒用浏览器原生 `beforeunload`：**弹窗文字由浏览器定，改不了**，
  我们能决定的只有"弹不弹"（靠 `store.dirty` 和 `store.pendingForm` 两个标记）。
- 标记是全局的：`store.js` 里监听 `main` 里的 `input`，凡是**不是**停笔即存的字段
  一律算"没保存的改动"；提交表单或点任何带 `data-act` 的按钮就清掉。
  状态栏会同步显示「⚠️ 有还没保存的改动（记得点保存）」，不用等关窗口才知道。

### 18.2 项目卡片筛选

- 开发工作页加了筛选条：关键词（匹配项目名 / 简介 / 状态）+ 状态下拉 + 「清空筛选」+
  一行「筛出 N / M 个」的计数。
- **筛选只影响显示，不动数据**；清空筛选立刻恢复全部。
- 筛选用的是"只重画卡片区"：输入关键词时不能整页重画，否则输入框会被重建、光标就丢了。

### 18.3 筛选和拖拽排序怎么共存

这是最容易出错的地方：如果直接把「拖拽后 DOM 里的 id 顺序」当成整个数组的新顺序，
**被筛掉的项目会被挤到末尾**。

正确做法是**按位置合并**：把完整数组从头遍历一遍，遇到"看得见的"就按拖后的新顺序
依次填进去，遇到"被筛掉的"原地保留。实测：4 个项目里筛出 `p1 p4` 两张，
把 p1 拖到 p4 后面 → 完整数组变成 `p4 p2 p3 p1`：
可见的两张换了位，被筛掉的 p2 p3 **一个都没动**。

### 18.4 这轮踩到的坑

**「取消」只改了内存没落盘**：行内编辑改成自动保存之后，"取消"要把记录退回编辑前的
快照，我一开始只做了 `Object.assign` 恢复内存，忘了保存——结果**界面显示退回去了，
磁盘上还留着改后的值**。修法是恢复之后补一次 `touch(true)`。
这个 bug 特别阴：屏幕上看着一切正常，只有对着 `数据.json` 才能发现。

## 19. 拖拽手感：手里那张不虚化、原位只留一条缝（2026-10-06）

### 19.1 症状与根因

第一版拖拽的观感是「**手里那张变淡、原位留着一块实心虚线占位**」，跟手机桌面那种
「拿起来的图标清清楚楚、别的位置腾空」完全相反。两个原因叠在一起：

1. **桌面浏览器默认走 HTML5 原生拖拽，跟着光标的是浏览器自己截的图**
   （天生半透明），这张图是浏览器画的，CSS 管不着——`opacity` 写了也没用。
   原来那套 `.card-ghost` 虚线样式，其实只是给"留在原位的那张"上了色，
   看起来就像一块实心占位。
2. 改成 `forceFallback: true`（让 Sortable 用自己的克隆来跟手）之后，
   拖拽**卡住不动了**。查事件才发现：页面只收到 `mousedown`，
   **一条 `mousemove` 都没有**。因为项目卡片是 `<a>` 链接，
   **浏览器默认允许原生拖拽**，一按一拖浏览器就抢先去跑原生拖拽，
   于是不再把 `mousemove` 发给页面——而 fallback 模式等的正是 `mousemove`。
   （之前用原生模式能工作，是因为 Sortable 那会儿监听的恰好是原生拖拽事件。）

### 19.2 改法

| 地方 | 做法 |
| --- | --- |
| HTML | 项目卡片加 `draggable="false"`，掐掉浏览器的原生拖拽 |
| Sortable | `forceFallback: true` + `fallbackOnBody: true`（克隆挂在 body 上，不被容器裁掉） |
| 跟手那张 | `.card-drag` / `.card-chosen`：`opacity: 1 !important` + `scale(1.04)` + 深阴影 + 高 z-index |
| 原位占位 | `.card-ghost`：`opacity: 0`，用**透明边框**而不是 `border: none`——去掉边框盒子会矮 2px，松手时会跳一下 |
| 动画 | 拖拽中的三张关掉我们自己的 `transition`，让位动画交给 Sortable 的 `animation: 180` |

### 19.3 实测（拖拽进行中读计算样式）

```
跟手那张   opacity: 1   transform: scale(1.04) + 位移   z-index: 100000   挂在 body 上 ✓
原位占位   opacity: 0   （只剩一条缝）✓
```

落位后顺序照常保存、没有残留的拖拽类、单击卡片仍然正常进入项目详情、
控制台 0 报错、自检 21 项全过。

### 19.4 补充：跟手那张的类名与两个细节

- 跟手的克隆类名从 `card-drag` 改成 **`card-follow`**（更直白），
  `dragClass` 和 `fallbackClass` 都指向它。
- 给跟手那张加 **`pointer-events: none`**：它贴在光标下面，
  不掐掉鼠标事件的话会挡住底下的卡片、干扰落点判断。
- 加 `filter: "input, textarea, select"`：将来卡片里要是放了输入框，
  从输入框上按住不会触发拖拽。
- 跟手那张**没有**写死 `border-radius: 18px`——四套皮肤的圆角不一样，
  克隆会继承卡片自己的圆角，写死反而会让笔记/粗野皮肤走样。

### 19.5 「保存失败：Failed to fetch」是什么意思

这个提示的含义很窄：**请求根本没拿到响应**。小李的写接口出错时会返回 JSON
（比如"数据格式不对"），提示里会带那句话；只有连不上才会显示 `Failed to fetch`。
所以它出现的原因通常是这两种：

1. **黑窗口被关掉了**（程序已停），而浏览器页面还开着 → 之后的每次保存都失败；
2. **服务重启后换了端口**（8765 被别的程序占了，起在 8766），
   而浏览器里那个页面还指着旧地址。

判断与恢复：看状态栏是不是红字；回黑窗口确认它还在；实在不确定就刷新页面
（刷新会重新读一遍数据）。页面上的改动不会因为这次失败而消失——
`store.dirty` 还留着，下一次操作会重试保存。

## 20. 演示数据，和「两个副本同时开着」那个坑（2026-10-07）

用户反馈「开发版看不出效果」。查出来是两件事叠在一起，都修了。

### 20.1 为什么在开发版里看不到新界面

**根因一：端口上那个不是「这一份」。** 启动时会问 8765「你有小李在跑吗」，
只要名字对就认定「我已经在运行」，于是打开浏览器指向它、自己退出。可是
日常在用的那一份常年开着，问到的其实是**它**——于是你在开发版里双击
`启动.cmd`，浏览器打开的是另一份的旧界面。

修法：`running_instance()` 除了看名字，还要看**数据目录对不对得上**
（看 `same_copy()`）。不是自己这一份的，就往后试下一个端口。

**根因二：Windows 上 `SO_REUSEADDR` 的语义不一样。** Python 的 HTTPServer
默认 `allow_reuse_address = 1`。在 Linux 上它只是「重启时不等旧连接散掉」；
在 Windows 上它的意思是**「这个端口被别人占着也让你绑」**。所以只修根因一
还不够：开发版会「成功」绑上 8765——但这个 socket 收不到任何连接，浏览器
还是连到老的那个，界面照旧是旧的，而且一点报错都没有（这次就被它骗了
一轮：进程活着、没在监听、也不退出）。

修法：`XiaoLiServer` 里 Windows 上 `allow_reuse_address = False`，再加一道
`SO_EXCLUSIVEADDRUSE`。被占的端口老实报错，启动逻辑自然往下试 8766、8767……

实测（日常那份占着 8765 时启动开发版）：

| 端口 | 数据文件 | style.css | 学习记录 |
| --- | --- | --- | --- |
| 8765 日常版 | `D:\小李\数据\数据.json` | 39926 字节（旧） | 0 |
| 8766 开发版 | `D:\自用APP管理\数据\数据.json` | 47405 字节（新） | 24 |

### 20.2 演示数据（`演示数据.cmd`）

> 2026-10-07 补：用户明确说「演示数据不同步」——`同步到小李.cmd` 因此多了一条
> 排除规则（`tools\` 整个目录 + `演示数据.cmd`）。这套工具只服务开发版，
> 日常在用的那份里不该有它，免得手一滑把真实数据换成演示数据。
> 已经同步过去的两个文件当天就删掉了，重新同步也不会再回来（实测复制 0 个文件）。

开发版常年在改，数据是空的，界面看着「没效果」。所以加了个工具：

- `演示数据.cmd`：双击出菜单——1 载入 / 2 还原 / 3 看现状 / 4 载入到
  「现在开着的那个小李」；也可以直接带参数用，比如
  `演示数据.cmd --action status`、`--data-dir "D:\小李\数据"`。
- `tools/演示数据.py`：本体。样例数据**全部按「今天」算**，所以什么时候跑
  都是当下这个月铺满记录，九张模块卡片也都有数。
- 默认只动**这份代码自己的** `数据\`，日常在用的那份不动；也不会被同步过去
  （见本节开头的排除规则）。

安全约定（演示数据可以随便玩，真实数据不行）：

1. 载入前先把现在这份存成 `备份\保留-演示前-<时间>.json`。「保留-」前缀 =
   自动清理会跳过它，界面上也标着「长期保留」，所以它不会被 14 份的规则挤掉。
2. 现在这份是空骨架（一条记录都没有）就不存——没东西可丢。
3. 有东西、又不是上一次的演示数据时，先问一句，输入「演示」才继续，
   直接回车就取消。
4. 写的时候如果那份小李正开着，就走它的 `/api/data` 接口写：修订号由服务端
   推进，不会留下「页面手里那个号跟磁盘对不上」的麻烦。开的是别的副本就
   直接原子替换文件。

`服务.py` 的 `backup_kind()` 顺手加了一条 `演示前-`，这样备份列表里显示的
是「演示前」而不是笼统的「每日」。

## 21. 记账（第 10 个模块，2026-10-07）

用户要求加「记账」。完整设计见 `docs/superpowers/specs/2026-10-07-记账-design.md`，
一步步的实施计划见 `docs/superpowers/plans/2026-10-07-记账.md`；这一节只记结论。

### 21.1 v1 做到什么

记一笔（支出 / 收入）、月历上每天显示收支金额、本月概览 + **月度总预算**、
分类占比环形图、当日明细（可编辑 / 删除）、一小份账户列表，以及首页卡片、
全局搜索、月历上的支出圆点这三处联动。

**2026-10-07 追加**：账户余额也做进 v1 了（用户当天要求）。规矩是这样：

- **余额 = 期初余额 + 该账户的收入 − 该账户的支出**，每次读的时候实时算，**不存字段**
  （存了就会跟流水对不上，账目才是唯一的可信来源）。
- 期初余额在账户弹窗里填，单位还是分；**允许 0、不许负数、最多两位小数、
  上限 999,999.99**（和「记一笔」的金额同一条上限），留空按 0 存，
  改它不会动任何已有账目（老账户期初是 0，行为跟「流水净额」一样）。
- **新增 / 编辑账户都走弹窗**（2026-10-07 追加）：账户卡片标题右边的「添加账户」，
  以及每行右侧的「编辑」，打开的是同一个表单——只有两个字段：名字（必填，
  1～20 字，不能跟别的在用账户重名，重名忽略首尾空白与大小写）+ 期初余额（可留空）。
  校验不通过时错误写在字段下面、弹窗不关、「保存」是灰的；原来行内那一个输入框
  放不下两个字段，而且报错只能用会飘走的 toast 指不着字段。
- 本月概览里多一行「账户总余额」，标着「含期初」——它跟「本月结余」不是一回事
  （结余只管当月，总余额是期初 + 全部历史收支）。
- 已删除账户的净额**默认算进总余额**，并在账户卡片下面单独写一行说明，
  这样「总余额 ≠ 列表里各行相加」有据可查。

**v1 仍不做**（留第二版）：转账、分类预算、80%/100% 预警、
近 6 个月趋势图、CSV 导出、按条件筛选、常用账目模板、标签（全站都还没有标签系统）。

### 21.2 数据模型

`数据.json` 里新增一个 `finance` 键（模块的数据归模块，不摊成多个顶层键）：

```
finance: {
  accounts:     [ { id, name, initialBalanceCents } ],
  categories:   { expense: [8 类], income: [5 类] },
  transactions: [ { id, type, amountCents, date, category, accountId, note, createdAt } ],
  budget:       { monthlyTotalCents, categoryCents },
  transfers:    []
}
```

- **金额一律 `amountCents` 整数（分）**，换算只在 `app/web/money.js` 里做；
  界面上的短格式（月历格子）到 1000 元以上缩写成 `1.2k`，截断不四舍五入。
- `type` 只有 `expense` / `income`；转账是第二版的一张独立表，不做成第三种 type，
  这样「本月结余」「分类占比」的算法永远是干净的。
- `transfers`、`budget.categoryCents`、`initialBalanceCents` v1 先建着不用，
  第二版加功能不用迁数据。
- **删账户不删账目**：历史记录不能因为删账户就没了，那笔账的账户栏显示
  「（账户已删）」，删除确认框里写明「有 N 笔账在用这个账户」。
- 老数据没有 `finance` 键时，服务端的 `migrate()` 补一个空骨架（前端 `table()`
  认路径时也会顺手补）。

### 21.3 页面与文件

路由 `#finance`，侧边栏第 10 项。页面是**双栏**（方案乙）：左栏月历 + 分类环形图，
右栏 320px 放本月概览 / 当日明细 / 账户。内容是区窄于 1100px（和首页看板同一档）
时塌成一列。

| 文件 | 干什么 |
| --- | --- |
| `app/web/money.js` | 分 ↔ 元换算、金额格式化（纯函数，无依赖） |
| `app/web/finance-calc.js` | 月度/按天/分类汇总、预算档位、超支日（纯函数） |
| `app/web/finance.js` | 页面 + 弹窗表单 + 环形图 |
| `tests/记账计算.test.mjs` | 上面两个纯模块的单元测试，`node tests\记账计算.test.mjs` 跑（93 条断言） |
| `app/web/dialog.js` | 加了一个通用弹窗 `openDialog`（原来只有确认框和轻提示） |
| `app/web/calendar.js` | 多了一个可选的 `dayExtraOf` 钩子（不传就和原来一模一样），并导出 `currentMonth()` / `showMonth()` |

### 21.4 两条值得记住的约定

1. **月历的「看着的那个月」和「选中的那一天」是两件事**：概览、环形图、超支日
   跟着 `currentMonth()` 走，当日明细跟着选中那天走。不分开的话，翻月时左边换了、
   右边还停在原来那个月。
2. **`table()` 认带点的路径**（`table("finance.transactions")`）。回收站、全局搜索
   这些通用零件只认一个表名，打通这一层之后，嵌套的 `finance` 对它们就是透明的。

### 21.5 债务欠款子页面（2026-10-07 追加）

完整设计见 `docs/superpowers/specs/2026-10-07-债务欠款-design.md`，
实施计划见 `docs/superpowers/plans/2026-10-07-债务欠款.md`。要点：

- **做成记账里的子 Tab**（`#finance` / `#finance/debt`），不是第 11 个侧边栏入口——
  债务和账目本来就该在一个上下文里看。
- **数据结构**：顶层 `debt` 键（和 `finance` 并列），`items[]` 里是
  `{ id, name, type, totalCents, creditor, dueDate, note, status, repayments[] }`。
- **剩余不存字段**：`总额 − 已还之和` 实时算（`debt-calc.js`），和账户余额一个思路。
- **债务只认自己的还款记录**：`repayments[].txId` 只是凭证。事后把那笔账目删了或改了，
  债务不受影响，还款记录里标一句「对应账目已删除」。
- **删还款记录不回删账目**：剩余加回来、状态按剩余重算，确认框写明「剩余金额将恢复 ¥X」。
- **`status` 只有三处会写**：记还款后、删还款记录后（按剩余重算）、手动「标记已结清」
  （用在「这笔钱不用还了」，不生成任何账目）。
- **还款计入预算与分类占比**：为此给记账加了两个分类——支出「债务还款」、收入「债务收款」；
  服务端 `migrate()` 会给老数据补上这两个分类。
- 到期提醒分四档：已结清灰、7 天以上普通、**7 天内橙、已逾期红**；债务只在债务子页的
  月历上标红点，不动另外五张月历的图例。
- 顺手修了两个早就存在的 bug：玻璃皮肤下**搜索面板被内容卡片压住、点不动**
  （`.topbar` 加 `position: relative; z-index: 40`）；**弹窗里的「删除」确认框一闪就没**
  （外层弹窗多关了一次，改成 `return false` 让确认框接管）。

## 23. 自媒体改版（2026-10-07）

用户给了两版需求稿，核心是「现在只有选题待办，看不出运营成果」。完整设计见
`docs/superpowers/specs/2026-10-07-自媒体改版-design.md`，实施计划见
`docs/superpowers/plans/2026-10-07-自媒体改版.md`；这一节只记结论。

### 23.1 页面结构（`#media`，从上到下）

页头（+「账号管理」按钮）→ ① 账号卡片横排 → ② 数据概览（可折叠：六个汇总数 +
近 30 天趋势图 + 爆款 TOP3）→ ③ 月历排期（平台筛选、平台色圆点、格子里的标题截断、
已发布划掉）→ ④ 选中日期的当天安排 → ⑤ 选题 & 作品列表（五条状态流水线 + 已废弃折叠）。

- 需求稿里「顶部运营总览」和「数据统计看板」是同一批数字，**合并成一张**：
  同一屏出现两组「总粉丝 / 总浏览」只会互相削弱可信度。
- 账号卡片放在最前面：没账号时汇总全是 0，先看到「还没有自媒体账号，点右上角
  账号管理添加」比先看一堆 0 更自然。

### 23.2 数据模型（两个新的顶层键）

```
mediaAccounts: [ { id, name, platform, intro, baseFollowers, targetFollowers, note, createdAt } ]
mediaFollowers: [ { id, accountId, date, count } ]          ← 粉丝快照，同账号同一天只留一条
contents: [ { …, accountId, platform, status, planDate, publishDate, link,
              views, likes, comments, collects, fansGain, note, createdAt } ]
```

- **账号和作品都是顶层键，没包成 `media{}`**：开发工作就是 `projects` / `issues` /
  `progress` 三个平级顶层键；`contents` 被日历、搜索、首页、服务端、自检、演示数据
  六处引用，搬进 `media{}` 只换来一次迁移风险。
- 平台是固定清单里的一个词（B站 / 小红书 / 抖音 / 公众号 / 知乎 / 视频号 / 其他），
  存的是文本；`accountId` 是绑定关系，账号删了作品还在，显示「账号已删」。
- 状态：`想法 → 撰写中 → 剪辑中 → 待发布 → 已发布`，另有 `废弃`（归档，默认不显示）。
  老数据的「写作中」由服务端 `migrate()` 改成「撰写中」。

### 23.3 粉丝口径（这次最容易做错的地方）

**当前粉丝 = 最近一条快照 + 该快照之后发布作品的「单作品涨粉」之和**；
一条快照都没有时 = 初始粉丝 + 该账号所有已发布作品的涨粉。

- 用户在账号卡片上手动改「当前粉丝」，写的是**今天的快照**，不是在账号上存一个数字。
  这样手动校正和自动累加永远不打架，趋势曲线也有了真实锚点。
- 作品和快照同一天时算快照已经包含它（严格晚于才累加），不会同一天算两遍。
- 「本周涨粉」= 本周 vs 上周（周一算一周的开头），环比只在真有上周数据时才给百分比；
  上周是 0 就说「上周没有涨粉」，没有上周记录就说「上周没有记录」。
- 爆款：**同账号**已发布且填了播放的作品 ≥3 条时才算，≥2 倍小爆款、≥3 倍大爆款
  （样本太少时标出来的「爆款」没有说服力）。活跃度按最近发布距今天数分四档。

### 23.4 拖拽排期（没走 SortableJS）

作品卡可以拖到**日历格子**或**下面那张「当天」卡**上，放开就写进计划发布日期。

项目卡片那套 SortableJS 在这里不合适，原因是实测出来的：它跨列表拖拽是
「指针一进格子就先把卡片塞进去」，而日历格子又小又密（一次 42 个实例），
手指一抖落错天之后还会立刻重画，连改都改不了；从列表拖到日历要跨大半屏，
它的自动滚动在这种场景下也不稳。所以这里用浏览器自带的原生拖拽：落点由
`drop` 事件决定（松手那一下才算数），跨屏时的滚动浏览器自己会做。

**列表内拖拽排序没做**：列表始终按「计划时间 / 创建时间」排序，拖出来的顺序
下一次重画就会被排回去——让人以为拖成功了，比没有这个功能更糟。想换顺序用
列表上方那个「排序方式」下拉。

### 23.5 首页卡片与联动

首页自媒体卡片（简洁与完整模式同一个数据源）：

```
main : 总粉 1.26w ｜ 本周 +326
sub  : 总播放 48.6w ｜ 待发布 3 条
extra: 本周已发 2 条 · 爆款 1 条      （没爆款就不写「爆款 0 条」）
```

其它联动：全局搜索能搜作品标题 / 备注 / 平台 / 账号名；点账号卡片跳到
`#media/<账号 id>`，列表按那个账号筛；算数的部分全在 `app/web/media-calc.js`
（纯函数，`node tests\自媒体计算.test.mjs` 直接跑，116 条断言）。

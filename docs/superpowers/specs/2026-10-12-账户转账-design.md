# 账户转账：两个账户之间挪钱（设计）

版本 v1 · 2026-10-12 · 对应实现：待定（本文档是设计，代码还没写）
（预计落在 `app/web/finance-calc.js`、`app/web/finance.js`、`app/web/store.js`、
`app/web/search-calc.js`、`app/服务.py`）

来源：`docs/需求清单.md` 第 8 节第 5 条（记账第二版）里的第 1 项。

## 1. 想解决什么

「记一笔」弹窗里现在写着这么一句（`app/web/finance.js` 第 510 行，且这句是**代码里
自己承认的**）：

> 账户之间转钱暂时不能记，只能手动记一笔「A 账户支出」+ 一笔「B 账户收入」。

按那句话凑合记，会连带出四个麻烦：

1. **收支统计被凭空放大**：从微信转 1000 到银行卡，本月「支出 +1000 / 收入 +1000」，
   可一分钱都没花也没挣；
2. **分类环形图被污染**：得给这笔编一个分类（「其他」），于是「其他」永远最大；
3. **预算 / 超支被带偏**：这笔算进月度支出，可能当场把预算顶到 100%、把那天标成超支日；
4. **两笔之间没有任何关联**：删了一笔忘了另一笔，两个账户的余额就永远对不上，
   而且事后根本看不出「这两笔其实是一件事」。

转账要做的就一件事：**在一处记一次，钱从 A 到 B，账户余额跟着变，收支统计一点都不动。**

## 2. 三种记法，为什么选第一种

| 记法 | 长什么样 | 好处 | 代价 |
| --- | --- | --- | --- |
| **① 独立一张 `finance.transfers` 表**（推荐） | `{ fromAccountId, toAccountId, amountCents, date, note }` | 收支统计天然不受影响（它只认 `transactions`）；余额是「加一份转入、减一份转出」；删除就是删一行，不会只删一半 | 余额计算要认识这张表（一处改动）；明细、搜索要各自多认一行 |
| ② 两笔 `transactions` 用一个 `transferId` 互认 | 一笔支出 + 一笔收入，靠 id 串起来 | 不改余额公式 | 统计、环形图、预算、月历**每一处**都得记得排除带 `transferId` 的；删除要成对（漏一处就出脏数据）；用户手改数据时极易只删一半 |
| ③ 给 `transactions` 加第三种 `type: "transfer"` | 一张表里三种类型 | 不用新表 | 全站所有只认 `expense` / `income` 的地方（`monthTotals` / `categoryTotals` / 环形图 / 预算 / 超支日 / 债务联动 / 搜索）都得逐个加分支 —— 漏一个就出错，且转账没有分类、没有单一账户，字段形状本来就不一样 |

**选 ①。** 还有一条现成的理由：**这个键骨架里早就留好了** ——
`服务.py` 的 `default_finance()` 里写着
「`transfers` / `budget.categoryCents` / `accounts[].initialBalanceCents` 这个版本
先建着不用——第二版做账户余额、转账、分类预算时不用再迁数据」。
账户余额、分类预算这两项都已经按这个约定做完了，转账是最后一项。

## 3. 数据模型（写进 `数据\数据.json` 的 `finance.transfers`）

```jsonc
{
  "id": "demo-tf1",
  "amountCents": 100000,          // 整数分，和账目一个规矩（换算只走 money.js）
  "date": "2026-10-12",
  "fromAccountId": "demo-a1",     // 从哪个账户出
  "toAccountId": "demo-a2",       // 进哪个账户
  "note": "还信用卡",
  "createdAt": "2026-10-12T09:00:00.000Z",
  "imagePaths": []
}
```

- **只存账户 id，不存账户名**：账户改名之后这条转账的名字跟着变（和账目一个规矩）。
- **一条转账就是一行**，不做「成对的两行」——它们本来讲的就是一件事。
- 字段与 `transactions` 尽量对齐（`amountCents` / `date` / `note` / `createdAt` /
  `imagePaths`），这样导出、搜索、回收站这些通用零件不用为它单开一套。

## 4. 余额口径（这一版唯一要动的算法）

现在（`finance-calc.js` 的 `accountBalanceCents`）：

```
账户余额 = 期初 + 该账户的收入 − 该账户的支出
```

改成：

```
账户余额 = 期初 + 该账户的收入 − 该账户的支出 + 转入该账户的 − 从该账户转出的
```

- `accountBalanceCents(account, transactions, transfers)` 与
  `balanceTotals(accounts, transactions, transfers)` 各多收一个参数（默认 `[]`），
  老调用点不传也不会炸。
- **余额依旧不落盘**，还是现算：账目 + 转账是唯一可信来源，存了就会跟流水对不上
  （这条规矩不动）。
- 「账户总余额」的口径不变：还包含已删除账户的净额；转账在已删账户上
  （转出方或转入方任一已删）也照样算进总余额 —— 不然删个账户余额就凭空变了。

**收支统计一律不看 `transfers`**（这是选①换来的好处，不是要写的代码）：
`monthTotals` / `categoryTotals` / `overDays` / 月历那对小字 / 环形图 /
预算进度，签名都只收 `transactions`，转账那张表它们根本看不见。

## 5. 界面

### 5.1 入口：记一笔弹窗里加第三个页签

「记一笔」顶上现在是 `支出 | 收入` 两个页签（`txFormHtml`），加第三个：

```
[ 支出 ] [ 收入 ] [ 转账 ]
```

选「转账」时，弹窗里换成转账该有的字段（分类格子那一块整个收起来）：

| 字段 | 控件 | 校验 |
| --- | --- | --- |
| 金额 | 和现在同一个金额输入框（`¥` + `0.00`） | 必填、＞0、最多两位小数、上限 999,999.99（和记一笔同一套） |
| 日期 | 日期框，默认「正在看的那一天」 | 必填（和记一笔一致） |
| 从 | 账户下拉，排除「到」已经选了的那个 | 必选 |
| 到 | 账户下拉，排除「从」已经选了的那个 | 必选 |
| 备注 | 多行文本框（可以写「还信用卡」） | 可不填，同 200 字上限 |
| 图片附件 | 沿用现成那块（`attachments/finance/`） | 与账目一样 |

**账户不足两个**：转账这件事至少要有两个账户才成立。页面上只有一个（或零个）账户时，
「转账」页签照旧点得开，但弹窗里写一句「先在账户卡片上加第二个账户」并禁用保存 ——
比点开一个空下拉、保存时再报错要清楚。

**顺手把那句「账户之间转钱暂时不能记…」删掉**（`finance.js` 第 510 行）——
这一版它就是过期的了。

另外在**账户卡片头上**加一个次要样式的「转账」按钮（`card-tools` 里，
「添加账户」旁边）：站在账户列表前想转钱是最自然的时机，点了直接开弹窗、
停在「转账」页签上。两个入口开的是同一个弹窗。

### 5.2 当日明细里看得见

转完账得能看见、能改、能删，不然记了像没记。当日的明细列表把当天的转账**并进来**，
画成中性的一行：

```
↩  还信用卡                                    微信 → 银行卡        ¥1000.00      [编辑] [删除]
```

- 图标/配色跟支出（红）收入（绿）都不撞 —— 它是一个「搬东西」的动作，不是花销；
- 金额**不带 + / − 号**，也不进那一行「−¥xx / +¥xx」的合计（合计还是只算收支）；
- 账户那一格写成「A → B」（账户已删就写「（账户已删）」）；
- 标题用备注；没写备注就写「微信 → 银行卡」；
- 编辑 / 删除走同一个弹窗和回收站（删除确认文案：「这条转账会放进回收站」）。

### 5.3 月历上不标

月历格子里那对小字是「当天收支」，转账不算收支，所以格子里不出现它 —— 保持不动。

## 6. 明确不进这些地方

- 月度 / 当日收支统计、分类环形图、分类预算与超支日、日均那几处 → 一个都不进；
- 月历上的收支小字 → 不进；
- 债务模块 → 不联动（还信用卡是转账，和「债务欠款」是两回事，别互相自动生成）；
- 标签 → 这一版不带（记账「记一笔」也还没接，第二版统一接记账这几处入口时一起做）。

## 7. 删除 / 编辑 / 回收站

- 编辑、删除都复用「记一笔」那个弹窗（`openTxDialog` 认转账这种形态）；
- 删除走 `moveToTrash("finance.transfers", row, label)`；
- `store.js` 的 `TRASH_TABLE_LABEL` 补一项 `"finance.transfers": "转账"`，
  回收站里那一行才显示得对（`table("finance.transfers")` 已经按点号路径取表，不用改）。

## 8. 老数据与兜底

- `transfers: []` 这个键 v1 就在骨架里，所以**大多数数据文件里它已经是一个空数组**；
- 但更老的、或者手改过的数据可能没有它 → `服务.py` 的 `migrate()` 里补：
  不是数组就给 `[]`；数组里每一行缺字段的（`amountCents` / `date` /
  `fromAccountId` / `toAccountId` / `note` / `createdAt` / `imagePaths`）按账目那套补齐，
  **一条都不丢、已有值不动**；
- 前端读转账一律走一个 `normalizeTransfer(row)`（`finance-calc.js`），
  金额取整、账户 id 去空白、日期当字符串 —— 手改坏了也不至于把余额算崩。

## 9. 搜索

`search-calc.js` 的 `SOURCE_SPECS` 加一行：表 `finance.transfers`、模块 `finance`、
标签「转账」、标题 = 备注（没写就拿「A → B」拼）、字段 = 备注 / 日期 / 金额 /
两个账户名（账户名要回 `finance.accounts` 里现取，和「粉丝快照回账号表取平台名」
一个做法）。这样搜「还信用卡」「微信」都能捞到这条转账，点结果回记账页。

## 10. 纯逻辑与测试

纯逻辑（`finance-calc.js`，`node tests\记账计算.test.mjs` 直接跑）：

| 函数 | 干什么 |
| --- | --- |
| `normalizeTransfer(row)` | 一条转账读出来规整：金额取整、id 去空白、缺字段补默认 |
| `transfersOfAccount(transfers, accountId)` | 这个账户的转入 / 转出 / 净额 |
| `validateTransferInput({ amount, date, fromAccountId, toAccountId, accounts })` | 校验，返回 `{ ok, cents, fromErr, toErr, amountErr, dateErr }`（和账户表单同一个形状：错误写在字段下面） |
| `accountBalanceCents` / `balanceTotals`（改） | 多收一个 `transfers` 参数 |

测试：

- `tests\记账计算.test.mjs`：余额含转账（转入 / 转出 / 两边都算在总余额里）、
  收支统计**不含**转账、校验每条边界（转给自己、金额 0 / 负数 / 三位小数 / 超上限、
  缺账户、缺日期）、一条已删账户上的转账不影响别人；
- `tests\自检.py`：老数据补 `transfers` 与行内字段；导出导入往返带着转账走；
- 真浏览器回归 `tests\转账.test.mjs`（照 `标签弹窗.test.mjs` 那套无头 Edge 脚手架）：
  记一笔 → 切到「转账」→ 选从/到、填金额 → 保存 → **两个账户的余额各变对**、
  **本月收支一个数都没变**、当日明细里出现那一行（不带 + / −）、
  编辑金额后余额跟着改、删除后余额回到原样、全程 0 条 JS 报错。

## 11. 这一版不做

- 转账模板（「固定每周转 X 到 Y」）→ 第 6 项「常用账目模板」那一版一起做；
- 按时间段 / 账户筛转账 → 第 5 项那一版；
- CSV 导出转账 → 第 4 项那一版（导出时**别漏了这张表**，写在这儿备忘）；
- 转账手续费（要收手续费的场景：想记两笔就行）；
- 多币种、汇率；
- 自动对账 / 提醒（纯本地应用，做不了后台常驻提醒 —— 见需求清单第 8 节那条硬约束）。

## 12. 需要你拍板的几件事

1. **入口**：我按「记一笔弹窗加第三个页签 + 账户卡片头上一个转账按钮」写。
   也可以只留弹窗里的页签（少一个入口少一处维护），或者只留账户那边的按钮。
2. **图片附件**：转账要不要也能贴截图（比如转账成功的截图）？我倾向**要** ——
   弹窗里那块附件区本来就在，去掉反而要多写一段分支。
3. **当日明细里显示转账**：我倾向**显示**（记了看不见最难受）。
   也可以只在账户余额里体现、明细列表保持只有收支。
4. **转账能不能贴标签**：我倾向这一版**不带**（和「记一笔」保持一致，等第二版
   统一接记账那几处入口时一起做）。

# 开发工作「添加项目」弹窗化 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement
> this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 开发工作页顶上那行「添加项目」输入框搬进弹窗（新增 / 编辑复用），
接上图片附件，补上详细描述和预计结束日期两个字段。

**Architecture:** 不新增文件 —— 直接往第 26 节那套里加一个类型：
`item-form.js` 的 `FORMS` 加 `devProject`，页面侧调 `openItemDialog("devProject", …)`，
删除走共用的 `trashItem()`。服务端只加图片目录和字段迁移。

**Tech Stack:** 原生 HTML + CSS + ES 模块（无框架、无构建、零外链）；
Python 标准库小服务；Node 跑纯逻辑单测。

**Spec:** `docs/superpowers/specs/2026-10-07-项目弹窗-design.md`

## Global Constraints

- **零外链**、**不装依赖**、**事件不挂公共 `#view`**（同前几次）。
- **只做加法**：项目的老字段 `intro` / `startDate` 名字不动，老数据零成本。
- **图片先落盘、JSON 后落盘**；「取消」时一个字节都不留。
- **删除先进回收站**，连带规则只有一处实现（`trashPlan` + `trashItem`）。
- **注释和提交信息用中文**，说清「为什么」。

## 自查记录

- **覆盖检查**：spec §1 数据（Task 1）、§2 弹窗（Task 1 + 2）、§3 页面（Task 3）、
  §4 不做的三项没碰。
- **类型一致**：`devProject` 完全走第 26 节那套，没有为它开特例；
  唯一的特例是「删除后跳回列表」，用 `onDeleted` 回调而不是改通用层。
- **实测发现并修掉的两个**：
  1. 删除确认的提示语把类型写死了（删项目会说“它的 N 条学习记录”），
     改成读 `spec.extraNote`。
  2. 删掉正在看的那个项目之后，地址还停在 `#dev/<已删的 id>`；
     加了 `onDeleted` 把它拉回 `#dev`。

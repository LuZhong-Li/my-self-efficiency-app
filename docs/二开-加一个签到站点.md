# 二开：给小李加一个签到站点

> 2026-11-04。这份写给想加站点的人——包括三个月后忘了细节的我自己。

## 一句话

在你的数据集目录里建一个 `签到站点\` 文件夹，往里放一个 JSON，刷新页面就能用。
**不用改代码，不用重启，不用会 Python。**

放在哪：

```
D:\小李\数据\<数据集名>\签到站点\我的站点.json
```

界面上点「打开站点文件夹」会直接开到这里。放进去之后点「重新读一遍」。

---

## 一、先搞清楚一件事

签到接口**没有公开的**。你要做的是：在浏览器或客户端里登录，按 F12，
找到那个「签到」按钮点下去时发的请求，然后把它的地址、参数、返回结构抄进 JSON。

所以顺序永远是：

1. 先用浏览器打开那个网站，**手动签到一次**（确认这站真有签到、你账号真能领）
2. F12 → 网络（Network）→ 清空 → 点签到
3. 找到那个请求 → 看「请求标头」和「响应」
4. 抄成 JSON

**第 1 步不能跳过。** TRAE 就是个教训：代码里接口写得明明白白，但服务端开关没开，
照样签不了。先确认手动能签，再谈自动化。

## 二、最小可用例子

假设你查到的接口长这样：

- 查状态：`POST https://example.com/api/checkin/status`，返回 `{"data":{"checked":false,"streak":3}}`
- 签到：`POST https://example.com/api/checkin/claim`，返回 `{"data":{"credit":50}}`
- 鉴权：请求头 `Authorization: Bearer <token>`

那你的 JSON 就是：

```json
{
  "schema": 1,
  "id": "example",
  "name": "示例站",
  "auth": { "type": "bearer" },
  "status": {
    "url": "https://example.com/api/checkin/status",
    "method": "POST",
    "body": {},
    "extract": {
      "checked": "data.checked",
      "streak": "data.streak"
    }
  },
  "checkin": {
    "url": "https://example.com/api/checkin/claim",
    "method": "POST",
    "body": {},
    "extract": { "credit": "data.credit" }
  }
}
```

存成 `签到站点\example.json`，刷新，卡片里就多一行「示例站」。
点「填凭证」把 token 粘进去，就能签了。

## 三、字段逐个说

### 顶层

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `schema` | 否 | 格式版本，不写默认 1。**这个版本只认 1** |
| `id` | 是 | 唯一标识，字母数字下划线连字符，1~40 字。凭证按这个存，**改了 id 等于之前的凭证作废** |
| `name` | 是 | 显示名，最多 24 字 |
| `homepage` | 否 | 网址，只给人看，不参与请求 |
| `enabled` | 否 | 写 `false` 就暂时不跑这个站点，不用删文件 |
| `token` | 否 | 一段说明文字，告诉用户去哪找凭证。会显示在填凭证的地方 |
| `auth` | 否 | 鉴权头怎么写，见下 |
| `vars` | 否 | 额外需要用户填的变量，见下 |
| `status` | **是** | 查状态怎么发 |
| `checkin` | 否 | 签到怎么发。不写就只能查状态不能签 |

### auth：鉴权头

| type | 效果 |
| --- | --- |
| `bearer`（默认） | `Authorization: Bearer <token>` |
| `header` | 自定义头名，要配 `header` 和 `prefix` |
| `cookie` | `Cookie: <token>`（token 里自己写全 `name=value; name2=value2`） |
| `none` | 不带头 |

`header` 类型的例子：

```json
"auth": { "type": "header", "header": "X-Token", "prefix": "" }
```

会发 `X-Token: <token>`。前缀 `prefix` 想加什么都行，比如 `"Cloud-IDE-JWT "`。

### status / checkin：怎么发请求

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `url` | — | **必填，只允许 https**，不能指向本机或内网 |
| `method` | `POST` | GET / POST / PUT / PATCH |
| `body` | `{}` | 请求体，JSON 对象。GET 时忽略 |
| `headers` | `{}` | 额外请求头。值里可以用 `{{变量}}` |
| `extract` | `{}` | 从返回里取哪些字段，见下 |

### extract：从返回里取字段

值是一个**路径**，用点号分隔，可以穿数组下标：`data.list.0.name`。

能取的标准字段：

| 字段 | 含义 | 取不到时 |
| --- | --- | --- |
| `checked` | **今天签没签**（最重要） | 当成没签 |
| `streak` | 连续天数 | 0 |
| `credit` | 每天能领多少 | 0 |
| `today_credit` | 今天领了多少 | 0 |
| `total` | 总积分 | 不显示 |
| `week` | 本周七天，数组，`true` 表示那天签了 | 不画格子 |
| `week_days` | 本周签了几天 | 0 |
| `activity_name` | 活动名，比如「Buddy加油站」 | 不显示 |
| `error_code` | 业务错误码，非 0 视为失败 | 不检查 |
| `error_msg` | 错误话 | 用 `msg` |

**每个字段都可以写成一串候选路径**，前一个取不到就用下一个。站点改版时多写几个能少挂几次：

```json
"extract": {
  "checked": ["data.today_checked_in", "data.checked", "checked"]
}
```

`error_code` 特别说一下：很多站的返回是 `{"code":0,"data":{...}}`，`code` 非 0 就是失败。
写上这个，失败时能拿到服务端自己的错误话，比「取不到字段」好查得多。

### vars：额外变量

有些站除 token 外还要别的，比如设备号：

```json
"vars": {
  "device_id": { "required": true, "hint": "在浏览器 localStorage 里找 deviceId" }
}
```

`required: true` 的变量没填，界面上会显示「还没填凭证」并且不让签。
界面上会给它一个输入框。

变量在 `body` 和 `headers` 里用 `{{变量名}}` 引用：

```json
"body": { "deviceId": "{{device_id}}", "platform": "web" }
```

## 四、几条安全规矩

这些是硬性的，写到一半会被拦：

1. **只能用 https**。http 直接拒。
2. **不能指向本机或内网**。`127.0.0.1`、`localhost`、`192.168.x.x`、`10.x.x.x`、
   `*.local` 全部拒。
   理由很实在：站点定义是用户从别处抄来的文件，要是能写内网地址，
   那这个文件就成了内网探测工具。
3. **凭证不进 `数据.json`**。存在 `数据\签到凭证.json`，所以备份、导出、整份搬走
   都不会把凭证带走。这是故意的。

## 五、JSON 表达不了的怎么办

遇到这几种，JSON 就没法写了：

- 请求要**签名**（有 `sign` / `timestamp` / `nonce` 这类参数，算法是代码）
- 返回要**解密**
- 签到前要**先调几个接口**拿临时凭证
- 鉴权不是简单的头，要走 Cookie 交换或 OAuth

那就写 Python。在 `app\签到.py` 的 `PYTHON_SITES` 里加一项：

```python
def _my_site_status(data_dir: str) -> dict:
    """返回和 JSON 站点一样的结构。"""
    values = (get_site_cred(data_dir, "my_site").get("values") or {})
    token = values.get("token") or ""
    if not token:
        raise CheckinError("还没填 Token")

    # 想发什么请求都行，用 http_json 能省掉错误处理
    r = http_json("https://example.com/api/status",
                  method="POST", body={},
                  headers={"Authorization": "Bearer " + token})

    return {
        "checked": bool(r.get("data", {}).get("checked")),
        "streak": as_int(r.get("data", {}).get("streak")),
        "dailyCredit": 50,
        "total": r.get("data", {}).get("total"),
        "week": [],
        "tokenExpires": token_expiry(token)[1],
    }


def _my_site_checkin(data_dir: str) -> dict:
    """签到。返回 skipped / credit / streak / total / message。"""
    ...


PYTHON_SITES["my_site"] = {
    "status": _my_site_status,
    "checkin": _my_site_checkin,
}
```

在 `PYTHON_SITES` 里的站点会**覆盖**同名的 JSON 定义。
界面上完全看不出区别——它一样会出现在列表里，一样能查能签。

内置的 WorkBuddy 就是用这个格式写的（在 `_builtin_sites()` 里），
想抄现成的看那个。

## 五之二、连 Python 也发不出去怎么办：让浏览器去跑

有一种情况 Python 也救不了：**接口要浏览器现场算的签名**。

即梦（`jimeng`）就是。它的 `user_credit` 要带 `x-secsdk-web-signature` 这个头，
签名由字节的 secsdk JSSDK 在页面里算出来。实测：**同一个接口、同一份 Cookie、
同一时刻**，Python 直接 POST 返回 `{"ret":"1014","errmsg":"system busy"}`，
页面自己发就 `ret:0` 成功。差别只在有没有那份签名。这种签名没法用 Python 复刻。

判断方法很简单：**打开 F12，看那个请求有没有 `sign` / `signature` / `x-*-signature`
这类头，而它的值每次刷新都变**——基本就是这类。

### 解法：起一次无头浏览器，只听不请求

`app\签到_浏览器.py` 提供了现成的 `visit_site()`：

```python
from 签到_浏览器 import visit_site

URL = "https://example.com/home"
# 想捞哪些接口的响应（按 URL 片段匹配）
WANT = ["/api/credit", "/api/credit_history"]

def _pick(bodies):
    """bodies: {去掉 query 的完整 URL: 响应文本}，返回要展示的数据。"""
    ...

def _my_site_status(data_dir: str) -> dict:
    return visit_site(data_dir, "my_site", URL, WANT, _pick)
```

它负责：

1. 起系统自带的 Edge（`--headless=new`），用 `<数据集>\浏览器配置\<站点id>\` 那份配置
2. **先开空白页、挂好 CDP 监听、再导航**——顺序很重要，
   反过来的话页面可能在你挂上监听之前就把请求发完了（这个坑即梦踩过）
3. 把页面**自己发的**响应捞回来（你不发任何请求，所以不会触发多余业务逻辑）
4. `finally` 里杀整个进程树，不留后台进程

> ⚠️ **别自己 fetch。** 从 CDP 注入 `fetch(...)` 发的请求**没有签名**，
> 一定会被风控拦下（即梦返回 1014）。只能听页面自己发的。

### 登录态

这类站点没有 Token 可填，凭证是**一份登录过的浏览器配置**：

- 站点定义里写 `"auth": {"type": "none"}`
- 界面会自动把「填 Token」换成「打开浏览器登录」（`POST /api/checkin-login`）
- 用户登一次，之后长期复用
- 配置目录约 650 MB，**不进 `数据.json`、不进备份导出、不进 git**，
  但**等同账号登录态**，要提醒用户别拷给别人

### 别做的事

即梦的 JS bundle 里搜得到 `credit_receive` 这个接口，看着像「领取」。
**但我没有调它**——任务面板返回空，看不出它是不是给每日积分用的，
贸然调用有重复领取的风险。页面自己发什么就让它发什么，我们只读。
照这个原则：**能不动就不动，只读不写。**

## 六、调试技巧

**先用 GET 试试是不是 401。** 拿不到真实 token 时，用一个乱编的 token 打接口：

- 返回 **401** → 地址对，就是没登录，继续抄结构
- 返回 **404** → 地址错，或者这个域名不承接这个接口
- 返回 **200** 但内容是 HTML → 地址其实是网页，不是 API

⚠️ 注意 401 **只证明前缀存在，不证明端点对**。WorkBuddy 那会儿就栽过：
`/billing/meter/xxx` 随便编一个也回 401。所以一定要拿真实请求对照。

**看界面的报错。** 错误话是分好的：

| 看到 | 意思 |
| --- | --- |
| 登录凭证失效了（401） | token 过期或粘错 |
| 服务器拒绝了请求（403） | 账号、地区或风控限制 |
| 服务器返回的不是 JSON | 地址打到网页上了 |
| 连不上服务器 | 网络或域名问题 |
| 还缺凭证：xxx | 有必填变量没填 |
| 定义有问题：xxx | JSON 本身写错了，按提示改 |

**验证凭证没被带进数据文件。** 存完凭证，打开 `数据.json` 搜你的 token 前 20 位，
应该搜不到。搜得到就是 bug，赶紧报。

## 七、加完站点记得做这几件事

1. **自己先手动签一次**，确认这站真有活动、你账号真能领。
   TRAE 就是这么被排除的——接口在，活动没开。
2. 用小李签一次，然后**去网站上确认真的签上了**。别只信界面。
3. 如果站点要求每天固定时间，去 Windows 计划任务里看一眼时间对不对
   （现在那个任务叫「自动签到」，每天 9:00）。**小李本身不定时**，
   它只在开着的时候才签。

## 八、贡献回来

你写好的站点 JSON，可以提到项目里让大家用：

- 放到 `docs\站点示例\` 下面，命名成 `站点id.json`
- **凭证绝对不能提交**（`数据\` 和 `签到凭证.json` 都在 .gitignore 里，但别赌）
- 浏览器型站点额外注意：`数据\<数据集>\浏览器配置\` 里是你的**登录 Cookie**，
  尤其别拷出去、别截图发人
- 在文件里用 `_说明` 之类的下划线字段写点背景：
  哪年哪月验证的、从哪个页面抄的、有什么坑

下划线开头的字段会被忽略，随便写注释。

## 1. 想解决什么

两件在待办里天天遇到、现在都只能凑合的事：

1. **重复任务**：「每周一、三、五跑步」「每月 1 号交房租」这类事，现在每次都得手打一条，
   打完还得自己记得下周再来一遍。模块目标里其实已经有一模一样的需求和实现
   （「自动生成任务规则」+ 进今日计划时补当天那条），但那是**模块级**的：一个模块一条目标，
   管不了「这条具体的待办每周重复」。
2. **子任务**：一条大待办（「把工作台改版做完」）底下其实是几件小事，现在只能全塞进备注里，
   既勾不了、也看不出做到哪一步了。

## 2. 重复任务：规则是一条记录，生成出来的是另一条

### 2.1 数据

待办（`tasks` 里的记录）多两个字段：

```jsonc
{
  "id": "t-rule-1",
  "text": "跑步 5 公里",
  "date": "",                    // 规则本身不占某一天
  "repeat": "每周一、三、五",     // 一句人话规则（和模块目标同一套解析器）
  "repeatUntil": "",             // 可选：到这天为止
  "lastRun": "",                 // 今天对过表了（你自己删掉的那条不再补回来）
  "priority": "中",              // 规则上带这些，生成出来的实例继承
  "category": "运动",
  "subtasks": [],                // 见第 3 节（可选，规则也能带清单）
  "belong": "plan",
  "isArchived": false
}
```

生成出来的「实例」还是 `tasks` 里的一条普通待办，只是多了几个来源标记：

```jsonc
{
  "id": "t-9f",
  "text": "跑步 5 公里",
  "date": "2026-10-14",                      // 就是「今天」那条，照常勾、照常改
  "genKey": "repeat:t-rule-1:2026-10-14",    // 防重复 + 知道它是哪天生成的
  "repeatId": "t-rule-1",                    // 从哪条规则来的（行上给个小标记）
  "belong": "plan"
}
```

### 2.2 怎么生成（整套沿用模块目标那套）

- 进「今日计划」时对一遍表：`syncRepeatTasks(today)`，骨架照 `goals.js` 的
   `syncGoalTasks()`（新开一个 `app/web/repeat.js` 放这套，不往 plan.js 里堆）；
   纯逻辑在 `task-calc.js`（`planRepeatTasks(rules, tasks, today)`），
  返回 `{ newTasks, markRun }` —— 和 `planGoalTasks` 一个形状。
- **防重复靠 `genKey`**：`repeat:<规则 id>:<日期>`。已经有一条就不再加。
- **你自己删掉的那条不补回来**（就是 `lastRun` 的语义，规则上记 `lastRun: <date>`）；
  想当天再来一条就手动加，或者去规则那儿改。
- **不预生成未来**：只补今天。历史一条不留空壳（不然第一次打开会冒出一堆过去的日子）。
- 规则只认 `repeatUntil`（「重复到哪天」，留空就一直重复）—— 规则上没有开始日期：
  它天生就是「一直有效」，不会给过去的日子补生成（只补今天，见上一条）。
- 规则的解析 / 匹配 / 人话预览**直接用现成的**：`goal-calc.js` 的 `parseRule()` /
  `clauseMatches()` / `previewDays()` / `ruleSummary()`。**不另写一套。**

### 2.2.1 生成出来的实例，哪些继承、哪些不继承

- 继承：`text` / `time` / `category` / `priority` / `note` / `tags`；
  子任务清单**复制一份过去**（各自的勾选独立，今天勾了不影响明天那条）。
- 不继承：**图片**。实例的 `imagePaths` 一律从空开始 —— 两边共用同一个文件路径的话，
  删掉今天这条就可能把规则那张图也清掉（附件清理是按路径走的）。

### 2.3 规则在界面上放哪儿

规则本身不占某一天（`date` 空），所以它不会出现在今日计划的待办列里。
今日计划页加一张**可折叠的卡片「重复任务（N 条）」**：

- 每条一行：`跑步 5 公里` ｜ `每周一、三、五` ｜ 「下次：10-16」 ｜ 行尾「编辑 / 删除」；
- 头上一个「添加重复任务」→ **同一套弹窗机制**（`item-form.js` 里新加一个表单类型
  `repeatRule`：同一张 `tasks` 表、同一种弹窗、和今日计划几乎一样的字段，只多一格「重复」）。
  不直接复用 `todayPlan` 那个类型：规则不占日期，硬塞进「今日计划」那套字段里
  会出现「既有日期又有重复」的四不像（见第 4 节）；
- 折叠状态记在内存里（不进数据文件，和「查看目标进度」一个做法）；
- 删规则：确认框写明「已经生成的那几条待办留着，不会跟着消失」（和删模块目标一个口径）。

规则**不给图片区**：实例不继承图片（见 2.2.1），规则自己存图没地方用，
也没必要为它多开一个附件目录。

## 3. 子任务：一条待办下面挂几件小事

### 3.1 数据与口径

```jsonc
{ "id": "t-3", "text": "把工作台改版做完",
  "subtasks": [
    { "id": "st-1", "text": "改侧栏", "done": true },
    { "id": "st-2", "text": "改首页卡片", "done": false }
  ] }
```

- **只有一层**（子任务不能再挂子任务）。一条待办最多 30 条。
- **进度不落盘**：`2/5` 现算（`subtaskProgress(task) -> { done, total, percent }`），
  和「今日进度不另存」一个哲学。
- **父子勾选联动**（两个方向都做，规则简单好预期）：
  - 勾上父任务 → 子任务全部跟着勾上；取消父任务 → 全部取消；
  - 子任务全勾上 → 父任务自动勾上；再取消任意一条 → 父任务跟着取消。
  - 联动集中在 `task-actions.js` 的 `updateTaskStatus()` 一处（待办状态的唯一入口），
    所以今日计划、首页、项目详情三处的表现天然一致。

### 3.2 界面

- **弹窗里**（`item-form.js` 的字段表加一种 `kind: "subtasks"`）：一行一个输入框 + 「加」，
  已加的每条前面一个勾选框、行尾一个删除；回车 = 加下一条（不触发「回车保存」，
  和备注那种多行输入一个规矩）。
- **列表行上**：有子任务就在时间旁边画一枚小胶囊 `2/5`（全做完那一档变浅灰）；
  点它就地展开那一行看清单，每条也能勾（不弹窗）。
- 今日计划、首页、项目详情共用同一份渲染零件 —— 标记画在 `ui.js` 的
  `subtaskBadge(task)`（和 `priorityChip` / `sourceTag` / `tagChips` 摆一起），
  事件交给 `task-actions.js` 的 `handleSubtaskChange` / `handleSubtaskClick`。
  三处各只加两行（一行标记、一行事件），逻辑不各写一遍。

## 4. 两个功能怎么拼在一起

- 规则也可以带子任务：生成实例时**把清单复制一份过去**（各自的勾选独立，
  今天勾了不影响明天那条）。
- 重复任务的实例照样能编辑（改时间、改文字、加子任务）—— 改的是**那一天那一条**，
  不动规则；想改以后每次都这样，去规则那儿改。这一点在弹窗里写一句说明，
  免得改完下一天发现「没生效」。
- 「重复」那一格是一个新控件 `kind: "rule"`：一句人话文本框（占位提示
  「比如：每周一、三、五」）＋ 下面一行实时预览（`ruleSummary`，`bindRulePreview`）。
  模块目标那个弹窗里的 `dailyRule` 其实**没有**实时预览，所以这一格是新加的，
  顺带把「这句话里没写出哪几天」当场说出来（不等到保存才报错）。
  这一格是必填：空着、或者通篇没有时间词（比如只写「跑步」），都过不了校验。

## 5. 搜索、导出、统计

- 搜索池：`tasks` 那条 spec 的 `fields` 加 `repeat`（搜「每周」找得到规则）和
  **子任务的文字**（取值函数把 `subtasks[].text` 拼起来，搜「改侧栏」能带出父任务）。
- 统计不动：重复任务只按它生成出来的实例参与统计（生成几条算几条）；
  规则本身不是待办，不占今日计划、不进「未完成」的计数。

## 6. 这一版明确不做

- 嵌套子任务、子任务拖拽排序、子任务单独设时间 / 优先级。
- 重复任务的「跳过这一次」「提前生成到未来几天」「按上次完成时间顺延（完成后 3 天再来）」。
- 图形化的重复规则编辑器 —— 就写一句人话（「每周一、三、五」），和模块目标一个体验。
- 通知 / 提醒（纯本地应用做不了后台提醒，见需求清单第 8 节那条硬约束）。

## 7. 纯逻辑与测试

| 函数（`task-calc.js`） | 干什么 |
| --- | --- |
| `isRepeatRule(task)` | 这条是不是规则（`repeat` 非空、没归档、且 `date` 为空） |
| `repeatRulesOf(tasks)` | 所有生效中的规则 |
| `repeatDueOn(rule, date)` | 这一天是不是这条规则的日子（`repeatUntil` 之后一律不算） |
| `genKeyOf(rule, date)` | `repeat:<规则 id>:<日期>` 这个防重键 |
| `planRepeatTasks(rules, tasks, today)` | 今天该生成哪几条、哪些规则该记 `lastRun`（照 `planGoalTasks` 的形状） |
| `nextRepeatDay(rule, today)` | 「下次：10-16」那个日期（从明天往后找最近一天，最多找 400 天；`repeatUntil` 到了就没有） |
| `addDays(date, n)` | 日期加减（跨月跨年靠 `Date` 自己算，不走 UTC） |
| `subTasksOf(task)` | 这条待办的子任务清单（不是数组 / 缺字段就当空的） |
| `subtaskProgress(task)` | `{ done, total, percent }` |
| `setSubtasksDone(task, done)` | 父任务勾选时把清单整体勾上 / 取消（返回新清单，不改传进来的） |
| `subtaskTextOf(task)` | 子任务的文字拼成一段（进搜索池用） |

测试：

- `tests\待办联动.test.mjs`：上面几个函数（含跨月跨年找「下次」、`repeatUntil` 到了就停、
  已经生成过的不重复生成、`lastRun` 当天不补、子任务进度与联动、传 null 不炸）；
- `tests\表单计算.test.mjs`：`repeatRule` 这个类型（字段齐全、必填、`rule` 与 `subtasks`
  两种控件读写成 JSON / 数组、上限 30 条、规则那句话的校验）；
- `tests\自检.py`：老数据补 `subtasks` / `repeat` / `repeatUntil` / `lastRun` 四个字段
  （子任务逐条补 `id` / `text` / `done`）；
- 新增真浏览器回归 `tests\重复任务.test.mjs`：建一条「每天」的规则 →
  今日计划那列出现今天这条（带「重复任务」小标记）→ 再进一次页面不会多生成一条 →
  勾上它再进来还是只有一条 → 把它删掉、重进也不会自己回来（`lastRun` 生效）→
  规则卡片上写着「下次：…」；
- 新增真浏览器回归 `tests\子任务.test.mjs`：弹窗里加两条（回车加、不触发保存）→
  行上出现 `0/2` → 点开就地展开 → 勾一条变 `1/2` 且父任务还没完成 →
  两条都勾上父任务自动完成 → 取消一条父任务跟着取消 → 勾父任务两条都跟着勾上 →
  首页那条也带同一枚胶囊。

## 8. 需要你拍板的几件事

1. **勾选联动的方向**：我按「勾父任务 → 子任务全勾；子任务全勾 → 父任务自动勾；
   取消任意一条子任务 → 父任务跟着取消」写。**「子任务全勾时父任务自动完成」**
   是这一节最值得你点头或否掉的一条（有人喜欢自己最后按那一下）。
2. **规则卡片放今日计划页**（我推荐，它跟待办是一件事），还是收进「数据与设置」？
3. **规则上要不要带优先级 / 分类 / 子任务**：我按「都带，生成时继承」写；
   嫌复杂可以只留文字 + 规则。
4. **子任务上限 30 条**：够不够？

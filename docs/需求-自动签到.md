# 自动签到：需求

> 2026-11-03。按你的决定定：**先做独立脚本验证**，凭证**Cookie 和账号密码两种都提供**。
> 调研结论见 `调研-自动签到.md`。

## 1. 一句话目标

写一个**独立的小脚本**，每天自动去 WorkBuddy（以及后面要加的 TRAE 等站点）签到领积分。
**先不进小李**，跑通、跑稳了再谈整合。

## 2. 为什么先独立、不进小李

小李现在的定位是「单机 · 离线 · 不发网络请求 · 不用登录」。上一轮为适配包破例开了 GitHub 一个口子，还严格限定成「只有点按钮才联网」。

自动签到是**性质不同**的东西：

- 要**长期保存你的登录凭证**（这是小李从来没有过的）；
- 要**每天自动联网**（这和小李「断网也能用」的承诺直接冲突）。

**所以先在独立脚本里验证。** 如果验证下来这条路走得通、你也确实想每天用，再单独讨论怎么整合。
整合的两种可能（**现在不选，留到验证之后再定**）：

- **隔离式**：小李只显示签到结果，凭证和签到动作留在脚本里，小李不碰凭证；
- **一体式**：小李自己存凭证、自己签。功能完整，但会破坏离线承诺，需要你明确接受。

## 4. 关键设计决定

### 4.1 凭证怎么存

**存在脚本目录下的 `凭证.json`，并默认加进 `.gitignore`。**

- 绝不写进 `数据/`（那个目录会被同步到网盘、会进备份）
- 文件权限尽量收紧（Windows 上没法像 Linux 那样 chmod 600，至少不进仓库）
- 支持从环境变量读 Cookie（给不想落盘的人留条路）

结构大概是：

```json
{
  "workbuddy": {
    "method": "cookie",
    "cookie": "...",
    "savedAt": "2026-11-03 20:00:00"
  }
}
```

密码方式的话字段换成 `username` / `password`。**两种都存的情况，Cookie 优先用，失效了才回落到密码。**

### 4.2 站点差异怎么隔离

虽然这期只做一个站，但**结构上要能扩展**，否则加第二个站就得重写。

每个站点一个「适配」文件，只描述三件事：

1. **怎么判断今天签没签**（查哪个接口、看什么字段）
2. **怎么签**（请求哪个地址、什么方法、带什么头）
3. **怎么判断结果**（看响应里什么算成功）

字段名和判定逻辑写死在各站点的适配里，公共流程（读凭证、重试、写日志、报错）抽出来共用。

### 4.3 「签没签」的判断依据

**绝不能只靠脚本自己记「我今天签过了」**。因为：

- 你手动在客户端签了，脚本不知道；
- 脚本以为签了，其实请求失败了。

所以每次运行都**先查一次真实状态**，已经在今天签过了就跳过。这个「查状态」的接口通常是现成的（客户端要显示签到状态就得调它）。

如果实在查不到状态接口，退而求其次：**每天用同一个请求**，让服务端自己判断重复（大部分签到接口是幂等的，签过了会返回「已签到」）。但这是兜底，不是首选。

### 4.4 定时策略

用 **Windows 计划任务**，每天固定时间跑一次。

- 建议时间：**早上开机后**（比如 9:00），失败还能当天手动补一次
- 任务要配「错过时间后尽快补跑」（StartWhenAvailable），避免那天没开机就漏了
- 脚本自身**不常驻**，跑完就退出

### 4.5 失败怎么处理

| 情况 | 处理 |
| --- | --- |
| Cookie 过期 | 明确提示「凭证过期了，需要重新获取」并给出获取步骤；有密码就自动用密码重新登录 |
| 网络失败 | 重试 2~3 次，间隔递增；仍失败就记日志 |
| 接口变了（返回结构对不上） | 报「接口可能改版了」，**不要猜**，宁可报错也别误判成成功 |
| 需要验证码 | 直接报「需要人工处理」，不做自动过验证码 |

### 5.1 唯一还缺的：Bearer Token

现在只剩「怎么拿到那个 Token」这一个未知。两条路，都做：

**路 A：手动贴 Token（先做这个，也够用）**

你从网页版或客户端把当前 Token 复制出来，填进脚本的配置文件。取法：

- 打开 `www.workbuddy.cn` 并登录
- 按 `F12` → **Network** 面板 → 刷新页面
- 随便点一个发往 `copilot.tencent.com` 的请求
- 在 **Request Headers** 里找 `Authorization: Bearer eyJ...`，复制 `Bearer ` 后面那一整串

Token 一般几天到几周过期，过期了重贴一次。

**路 B：账号密码自动登录（后做）**

脚本自己调登录接口换 Token。难点是登录接口大概率有验证码或滑块，
**遇到就停下来让你手动过一次**，我不做自动破解验证码。

### 5.2 你可以什么都不用给我

真要用的时候，Token 你自己填进配置文件，**不必发给我**。
你要是想让我先验证接口通不通，也可以只贴前 20 个字符，我判断格式即可。

### 阶段 1 ✅ 单站点脚本

| 文件 | 作用 |
| --- | --- |
| `签到.py` | 主流程：查状态 → 已签跳过 → 未签才签 → 复核 |
| `抓Token.py` | 从客户端 CDP 调试端口读 Token，验证后存盘 |

关键设计（对应 §4 的要求）：

- **先查真实状态**，不靠自己记 —— 实测中「今天已签」正确跳过

- **凭证失效单独提示**「重新运行 抓Token.cmd」，不和网络错误混为一谈（已测）
- **失败返回非 0 退出码**，便于外部感知

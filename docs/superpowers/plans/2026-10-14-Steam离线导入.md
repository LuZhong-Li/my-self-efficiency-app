# Steam 离线导入（CSV）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 游戏娱乐页多一个「导入记录」：选一份本地 CSV（游戏名/时长/日期/备注），先看解析预览，确认后写进现有 `gameRecords`；全程不联网。

**Architecture:** 「读 CSV」这个纯函数加在现有的 `csv.js`（和写 CSV 的 `csvCell` / `csvText` 对称）；认出「一条条游玩记录」的活加在 `game-calc.js`（`parsePlayCsv` / `dupeOf`）；界面就是 `game.js` 里一个弹窗 —— 本地 `FileReader` 读文本，解析纯逻辑跑一遍，**预览由解析结果渲染**，确认后 `table("gameRecords").push(...)`。字段和表全用现成的，所以服务端不用改、不用迁移。

**Tech Stack:** 原生 HTML/CSS/ES 模块（无框架、无构建、零外链）；测试用 Node 22+ 内置 `fetch` / `WebSocket` 直连 CDP 驱动无头 Edge（选文件用 `DOM.setFileInputFiles`）。

**Spec:** `docs/superpowers/specs/2026-10-14-Steam离线导入-design.md`（列名清单、时长的几种写法、跳过口径都在那一份里，实施时对着它写）

## Global Constraints

- **零外链 / 不联网**：任何 `.html` / `.css` / `.js` 里不许出现 `http://` 或 `https://` 字面量（自检会扫）；导入只读本地文件，**不发任何请求**。
- **一个任务一个提交**，commit message 用中文；直接提交到 `main`。
- 注释用中文，写「为什么这么写」。
- 每改完一处至少跑：`node tests\<相关>.test.mjs` 和 `& "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" tests\自检.py`。
- 测试断言写错就改测试，不改实现。
- 落库形状必须和手动记的那条**一模一样**（否则统计 / 图表 / 搜索会认不出来）。
- 真浏览器测试里 `ev()` 里只放一行字符串（用 `+` 拼）。

# 小李 · 第 10 个模块「记账」设计（v1 / MVP）

2026-10-07。本文说「这一个版本做什么、长什么样、怎么算」，不写实施步骤
（实施步骤见后续的 plan 文档）。定稿后按本文动代码。

## 0. 背景与这个版本的边界

`docs/需求清单.md` 第 4 节当初写的是「哪天要管钱，告诉我**另加一个最小版本**」。
2026-10-07 用户要求把「记账」加成第 10 个模块。

**这个版本做（MVP）：**

1. 记一笔（支出 / 收入）
2. 月视图日历 + 当日明细
3. 本月概览（支出 / 收入 / 结余）+ 月度总预算进度条
4. 分类环形图
5. 编辑 / 删除
6. 首页摘要卡片
7. 小账户列表（能加、能改名、能删）

**这个版本不做（放第二版）：** 账户余额、转账、分类预算、80%/100% 预算预警、
近 6 个月趋势图、CSV 导出、按条件筛选、常用账目模板、标签。

**一次到位的部分：** 账户、转账、预算的数据结构这个版本就建全，第二版加功能
不用迁移数据。

## 1. 已定的决定（逐条有出处）

| 决定 | 选择 | 为什么 |
| --- | --- | --- |
| 范围 | MVP 六项 + 账户列表 | 用户 2026-10-07 选 A |
| 预算 | 只做「月度总预算」+ 进度条 | 用户选 A2；分类预算与预警留第二版 |
| 超支日 | 当月**累计**已超预算之后、当天仍有支出的日子，格子加红边框 | A2 里的定义，比「当天花得多就算超支」更像提醒 |
| 账户 | 一个可增删改名的小列表，记一笔时下拉选 | 用户选 B2；预置账户里没有银行卡，写死会堵死 |
| 账户余额 | 这个版本不显示 | 余额要等期初余额 + 转账，属第二版 |
| 金额 | 以**分**存整数（`amountCents`） | 定下来就不用再迁移；避免小数误差 |
| 页面布局 | 方案乙：左日历 + 右（概览 / 明细 / 账户），饼图在左栏日历下方 | 用户选乙 |
| 分类 | 8 类支出 + 5 类收入，这个版本固定 | 但存成数据，第二版可以做成可编辑 |
| 标签 | 不做 | 全站没有标签系统，「复用」无处可复用 |
| 侧边栏图标 | 手写 SVG（硬币） | 另外九个模块全是 SVG，混一个 emoji 会突兀 |
| 分类图标 | Emoji（🍜🚌🛒📚🎮🏠💊📦 / 收入 5 个） | 系统自带、不联网，属页面内容不是界面零件 |
| 图表 | 手写 SVG 环形图，不引图表库 | 项目零外链零框架；`需求清单.md` 第 4 节原本也把图表排除在外 |

## 2. 数据模型

`数据.json` 里新增一个 `finance` 键（嵌在一个键里，不摊成多个顶层键；
`store.js` 的 `table()` 因此要能认路径，见 §7）。

```json
"finance": {
  "accounts": [
    { "id": "…", "name": "微信", "initialBalanceCents": 0 }
  ],
  "categories": {
    "expense": ["餐饮", "交通", "购物", "学习", "娱乐", "住房", "医疗", "其他"],
    "income":  ["工资", "兼职", "红包", "退款", "其他"]
  },
  "transactions": [
    {
      "id": "…",
      "type": "expense",
      "amountCents": 2550,
      "date": "2026-10-07",
      "category": "餐饮",
      "accountId": "…",
      "note": "午饭 黄焖鸡",
      "createdAt": "2026-10-07 12:30"
    }
  ],
  "budget": { "monthlyTotalCents": 0, "categoryCents": {} },
  "transfers": []
}
```

约定：

- **`amountCents` 是正整数，单位分。** 界面、统计、输入解析一律用
  `app/web/money.js` 里的换算函数，不在别处手写 `* 100` / `/ 100`。
- `type` 只有 `"expense"` / `"income"`。**转账不是第三种 type**：第二版用
  `transfers` 这张独立的表，这样「本月结余」「分类占比」的算法永远干净。
- `id` 用项目现成的 `uid()`（随机串），不用 `tx-001` 这种手写序号——
  以后合并两份数据不会撞号。
- `date` 用本地日期 `YYYY-MM-DD`；`createdAt` 用本地时间文本，和别的表一致
  （不要用 `toISOString`，那是 UTC，晚上会差一天）。
- `transfers`、`budget.categoryCents`、`initialBalanceCents` 这个版本先建着
  不用，是给第二版留的位置。

**删账户不删账目。** 账户被删后，引用它的账目原样保留，那一笔的账户栏显示
「（账户已删）」；删除确认框里写明「有 N 笔账在用这个账户」。历史记录不能
因为删账户就没了。编辑那笔账时，账户下拉里会补一个「（账户已删）」选项，
只有原本就是它的那笔才出现——用户自己改成别的账户，它自然就修正了。

## 3. 页面结构

路由 `#finance`，侧边栏第 10 项「记账」。

```
页头：记账（一句话说明）                      [+ 记一笔]
┌──────────────────────────┬──────────────────┐
│ 月历卡片                  │ 本月概览          │
│  ‹  2026年10月  回到今天  │  支出 / 收入 / 结余 │
│  周一起，7 列             │  预算进度条        │
│  每格：日期               ├──────────────────┤
│    -25.50（红）           │ 当日明细           │
│    +3,000（绿）           │  每笔一行：         │
├──────────────────────────┤  图标 备注 金额     │
│ 分类环形图 + 图例          ├──────────────────┤
│                          │ 账户（加 / 改名 / 删）│
└──────────────────────────┴──────────────────┘
```

- **左栏**：月历卡片（复用全站共用的 `monthGridHtml`）、分类环形图卡片。
- **右栏 320px**：本月概览、当日明细、账户，三张卡竖着排。
- 饼图放左栏是因为它宽，环形图加图例正好铺开；右栏 320px 给概览、明细、
  账户这类窄内容。
- 点某天 → 右栏「当日明细」跟着切（和今日计划页、学习页同一个手感）。
  日历自己的 `‹` `›` 和「回到今天」留在卡片里，行为不变。
- 页面打开时默认选中今天；点过别的日子之后，「回到今天」把它复位。
- **当日明细一行 = 分类 Emoji + 备注 + 金额**：备注为空时显示分类名；
  账户名以更小更淡的字缀在备注后面；备注超长用省略号。
  排序按 `createdAt` 升序（当天从早到晚），同一时间按记入顺序。
- 每月累计超预算之后、还有支出的那些天，格子加红边框
  （`.cal-cell.over`，颜色用 `--err`）。
- 格子里的金额到 1000 元以上时缩写成 `1.2k`，否则显示原数（两位小数）。

### 3.1 尺寸与断点（量过实际宽度才定的）

用户这台机器上窗口 1159px 时，内容区实测只有 **830px**。

- 右栏 **320px**，左栏拿剩下的约 500px，7 列每格约 68px——放得下
  「日期 + 红支出 + 绿收入」三行小字。
- **塌陷阈值用项目现有的 `@media (max-width: 1100px)` 这一档**（和首页看板
  同一档，视口宽度，不是内容区宽度）。它是视口宽度：视口 1100px 时内容区
  约 770px，两栏最挤时每格约 63px——还能看；再窄就落成一列，
  顺序：日历 → 概览 → 明细 → 账户 → 饼图。
- 也就是说视口 1101–1150px 是两栏最挤的一段（每格 63–70px），可接受。

## 4. 记一笔（弹窗表单）

这是项目里**第一个表单弹窗**（现在只有确认框和轻提示）。

做法：在 `dialog.js` 里加一个和 `askConfirm` 同族的通用弹窗
`openDialog({ title, body, actions })`，共用现有的 `.dlg-backdrop` / `.dlg`
样式与行为（Esc 关、点遮罩关、Tab 在按钮间绕圈、同时只留一个），四套皮肤
和深浅两色自动都覆盖。记账页把表单塞进 `body`。

字段与顺序：

| 字段 | 控件 | 默认与校验 |
| --- | --- | --- |
| 类型 | 支出 / 收入 两个 Tab | 默认「支出」 |
| 金额 | 大字号输入，只收数字和一个小数点 | 必填、> 0、最多两位小数、≤ 999999.99 元 |
| 日期 | 日期选择器 | 默认今天，或日历上正选中的那天 |
| 分类 | Emoji 图标网格（支出 8 / 收入 5） | 默认「其他」，点中高亮 |
| 账户 | 下拉（来自账户列表） | 默认第一个账户；账户列表为空时允许留空 |
| 备注 | 文本 | 可空，最多 60 字 |

行为：

- 打开即聚焦金额；回车保存；Esc 关闭。
- 保存：金额换算成分 → 入 `finance.transactions` → `touch(true)` 立刻落盘 →
  `toast("已记一笔 ¥25.50")` → 日历格子和右栏立刻重画。
- **编辑**：点明细里的某一笔 → 同一个弹窗，字段填好，标题变「改一笔」，
  按钮多一个「删除」（二次确认 → 挪进回收站）。
- 金额不合法（空、0、超过上限、小数位超过两位）时不保存，在弹窗里提示一句。
- 常用账目模板不做（第二版）。

## 5. 分类环形图

- 手写 SVG：本月支出按分类占比画环形图（`<circle>` + `stroke-dasharray`
  或多段 `<path>` 扇形），不引任何图表库。
- 图例：分类 Emoji、名称、金额、占比、一条细比例条。
- 点图例里的某一类 → 卡片下方展开「这个分类本月共 N 笔」的明细
  （日期 / 备注 / 金额），再点收起。
- 本月没有支出时用项目现成的 `emptyState`。
- 只有支出参与占比；收入不画进这张图（收入分类少、金额集中，画出来没什么信息）。

## 6. 本月概览卡片

- 三个数：本月支出、本月收入、结余（**结余 = 本月收入 − 本月支出**，
  正数绿、负数红）。
- 预算进度条：`已用 ¥1,234 / ¥2,000`；进度条颜色按用量变
  （< 80% 正常、≥ 80% 黄、> 100% 红）。
- 预算输入框就在这张卡片里，走 `change`（离开输入框才存），理由和
  「保留份数」一样——数字敲到一半不该生效；同时把 `#budget-input` 加进
  `store.js` 的 `AUTOSAVE_FIELDS`，免得打字时弹「有还没保存的改动」。
- 预算为 0 时不画进度条，改成一句「还没设本月预算」+ 输入框。

### 7.1 数据兼容

- 老的 `数据.json` 没有 `finance` 键：`服务.py` 的 `default_data()` 管新建，
  老文件靠 `migrate()` 补一个空骨架；前端 `table()` 认路径时也顺手补。
  两边都做，谁先碰到都能补上。
- 导出 / 导入 / 清空是整份文件操作，`finance` 自动跟着走，不用单独改。
- 回收站：账目和账户都走
  `moveToTrash("finance.transactions" / "finance.accounts", …)`，
  「数据与设置 → 回收站」里能还原。

## 8. 测试与验收

**自动**：`自检.cmd` 原本 21 项全过，再加两条 finance 检查。

**手工（在开发版 8766 上做，配演示数据）：**

1. 记一笔支出、一笔收入 → 日历格子当天立刻出现红 / 绿金额，右栏明细多两条。
2. 点日历上别的日子 → 右栏明细跟着切；翻月、「回到今天」都正常。
3. 编辑一笔（改金额和分类）→ 概览和饼图跟着变；删除一笔 → 回收站里能还原。
4. 设一个月度预算，花到 80% 以上、再花超 → 进度条黄 → 红；超预算之后有支出的
   日子出现红边框。
5. 饼图点某个分类 → 展开该分类本月明细；本月没支出时是空状态。
6. 账户加一个「银行卡」、改个名；删一个还有账目的账户 → 确认框写明有多少笔，
   删完账目还在、账户栏显示「（账户已删）」。
7. 首页卡片显示「今日支出 / 本月结余」；全局搜索搜备注能搜到账目并跳过去。
8. 今日计划页的月历上，有账的那天多一个圆点（图例里叫「支出」）。
9. 窗口拉窄到 1100px 以下 → 双栏塌成一列，顺序正确。
10. 四套皮肤 × 深浅两色各看一眼，不破相；控制台 0 条 error / warning。

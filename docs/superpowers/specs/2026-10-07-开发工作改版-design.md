# 开发工作改版：bug 记录 + 项目进展（2026-10-07）

## 要解决的问题

「开发工作」里的两个板块都是半成品：

- **问题 / bug** 只有一行标题 + 优先级 + 状态两个下拉。真出问题的时候要写复现步骤、
  预期行为、实际现象、贴一张报错截图 —— 一行输入框一个都放不下，于是要么不记，
  要么记一句「xx 有问题」，过两天自己都看不懂。
- **最近进展** 只能记一句话，改了进度顺手截的图没地方放，也没法回头补/改。

这次把两块补齐，图片能力直接用记账那套附件组件（第 24 节），一行都不重写。

## 一、数据

### 1.1 bug 条目（`issues[]`）

```
id, projectId, title          原有
severity                      原有（界面上叫「优先级」，字段名不搬，老数据零成本）
status                        状态词扩过一次，见下
desc                          新的：详细描述（复现步骤 / 预期 / 实际，多行）
module                        新的：关联模块（这个 bug 是 App 哪个模块的问题）
imagePaths                    新的：截图，存 attachments/buglog/
createdAt / fixedAt           新的：创建时间、修复时间（自动记，用来算迭代周期）
```

状态从「待处理 / 处理中 / 已解决 / 已关闭」改成
**「待处理 / 进行中 / 已复现 / 已修复 / 已关闭」**：

- `处理中` → `进行中`、`已解决` → `已修复`（只是改名，语义没变）；
- 中间补的 `已复现` = 复现出来了但还没动手。

只有 `已修复 / 已关闭` 算「结」。**「已解决」这个老名字一直认**，
所以数据文件还没保存过、或者有人手工改回去，口径都不会错。

### 1.2 项目进展（`progress[]`）

```
id, projectId, date, text     原有（内容字段还叫 text，没跟着文档里的 content 改名）
imagePaths                    新的：截图 / 设计稿，存 attachments/progress/
```

### 1.3 老数据怎么迁

两层：

1. 服务端 `migrate()`：给每一条 bug 补 `desc / module / createdAt / fixedAt / imagePaths`，
   把 `处理中` / `已解决` 改成新名字；给每条进展补 `imagePaths`。
2. 前端 `dev-calc.js` 的 `normalizeIssue()`：展示和筛选时再兜一层 ——
   缺字段给默认值（模块默认「通用」），老状态名照样算对。

所以页面永远只看一套口径，一处都不用判空。

## 二、界面

### 2.1 问题 / bug 卡片

```
问题 / bug        未解决 4 · 进行中 2 · 已修复 1      [＋ 记一个问题]
[全部状态 ▾] [全部优先级 ▾] [全部模块 ▾] [清空筛选]
┌──────────────────────────────────────────────┐
│ [中] 切模块时输入框焦点丢了  🖼  [进行中]  标记已修复 编辑 删除 │
└──────────────────────────────────────────────┘
```

- 统计三个数：未解决（= 待处理 + 进行中 + 已复现）、进行中、已修复；
- 筛选只影响显示，不动数据；筛没结果时给空状态 + 「清空筛选」；
- 行首是优先级标签，标题后面的 🖼 是**有截图才显示**的图片标记。

### 2.2 点条目展开详情

点一行（不是点它右边那几个按钮）就在它下面展开一块：

```
复现步骤：
1. 在「今日计划」里点开一条待办
2. 不点保存，直接切到别的模块
3. 再切回来，刚才打的字没了

关联模块  通用
记录于    2026-10-03 10:20
修复于    —
[缩略图] [缩略图]
```

详情是列表里紧跟的第二个 `<li>`，不是弹窗：一次能扫好几条，而且不用来回开关。
描述用 `white-space: pre-line` 渲染，换行照原样保留。截图点开就是全屏查看器
（和记账用的是同一个）。

### 2.3 记一个问题 / 改一个问题（弹窗）

原来的行内一行输入框换成弹窗，字段：标题、优先级、状态、关联模块、
详细描述（多行）、图片附件区。规矩和「记一笔」完全一致：

- Esc 关、点遮罩关、Tab 在弹窗里绕圈、回车保存（描述框里回车是换行）；
- 图片点「保存」才写进 `数据\attachments\buglog\`，点「取消」一个字节都不留；
- 编辑时多一个「删除」，进回收站；彻底删除时按设置决定要不要连图片一起删。
- 状态改成「已修复」时自动写上 `fixedAt`，退回去就清掉；展开详情里能看到
  「迭代周期 N 天」。

### 2.4 最近进展

- 「＋ 记一笔进展」→ 弹窗：日期、内容（多行）、图片附件；
- 列表行有图才可点开，点开在下面铺一行缩略图；没图的行点不动（不装作能展开）；
- 「编辑」能改文字、增删图片（同一套弹窗）。

## 三、搜索

全局搜索的 bug 条目从「只搜标题」扩成「标题 + 详细描述 + 关联模块」。
图片本身不参与搜索（文件里的内容搜不了），但条目照样搜得到。

## 四、这一版没做

原需求里标 P1 的四条：bug 条目拖拽排序、按模块单独做统计、每周解决数量的简易燃尽图、
拖拽 / 粘贴图片直接上传。

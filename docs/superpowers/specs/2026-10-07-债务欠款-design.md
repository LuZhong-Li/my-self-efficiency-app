# 小李 · 记账里的「债务欠款」子页面设计（v1）

2026-10-07。本文说「这一版做什么、长什么样、怎么算」，不写实施步骤
（实施步骤见后续的 plan 文档）。定稿后按本文动代码。

## 0. 背景与这个版本的边界

用户在记账模块之后要求加「债务欠款」。定的做法是**做成记账模块里的子页面**，
不单独占侧边栏——债务和账目本来就该在一个上下文里看，侧边栏也不用从 10 项挤到 11 项。

**这个版本做：**

1. 记账页顶部加子 Tab：`账目记录` / `债务欠款`（后者带未结清笔数角标）
2. 债务的增 / 改 / 删（删除进回收站）
3. 债务列表、债务总览（我欠 / 别人欠我 / 净负债 / 近 30 天到期）
4. **记录还款 → 自动生成一笔账目**（我还款＝支出，别人还我＝收入）
5. 还款历史与「删掉某条还款记录」（剩余金额跟着加回来，但不动那笔账目）
6. 债务子页面的月历：到期日标红
7. 首页一句话提醒（只在这几天内到期或已逾期时才出现）

**这个版本不做：** 利率计算、分期计划、自动提醒推送、按币种记账、
债务和账户之间的「预扣」、把债务利息滚进总额。

## 1. 已定的决定（逐条有出处）

| 决定 | 选择 | 为什么 |
| --- | --- | --- |
| 入口 | 记账模块里的子 Tab，不占侧边栏 | 用户 2026-10-07 指定 |
| 剩余金额 | **不存字段**，实时算 `总额 − 已还之和` | 和账户余额一个思路：存了就会和记录漂开 |
| 还了账之后删那笔账目 | **债务不受影响**（还款记录里留 `txId` 当凭证，标一句「对应账目已删」） | 用户选 A：两边各自都说得通，不用处理一堆边界 |
| 删还款记录 | 剩余加回来，**不回删账目**；确认框写明「剩余金额将恢复 ¥XXX」 | 用户补的边界：账目是独立财务记录 |
| 结清状态 | **存 `status`**，三处会写它：记还款后重算、删还款记录后重算、手动「标记已结清（不用还了）」 | 用户选 B：「对方说不用还了」这种情况一定要有个入口 |
| 还款算不算支出 | **算**，并且给支出加一个「债务还款」分类（收入加「债务收款」） | 还款是真钱出去了；单独分类才能看出「这个月还债花了多少」 |
| 债务数据放哪 | 顶层 `debt` 键，和 `finance` 并列 | 用户给的结构；`store.js` 的 `table()` 认路径，回收站/搜索照样能用 |

### 1.1 我替你定的几处（不对就说，改起来都不大）

1. **子 Tab 用现有那套手写 SVG 图标，不用 emoji**：侧边栏十个模块全是 SVG，
   两个子 Tab 单独用 📊 / 💳 会像两个世界。分类图标那种「页面内容」继续用 emoji。
2. **子 Tab 走哈希路由**（`#finance` / `#finance/debt`）：不是纯前端 state。
   好处是刷新、从首页点进来、搜索跳转都能落在对的那个 Tab 上。
3. **状态颜色分四档**：已结清＝灰、待还（7 天以上）＝普通、7 天内到期＝橙、已逾期＝红。
   你原来写的是三档，我把「逾期」单列——它还差 7 天的能提醒，过了日子的更该催。
4. **超额还款挡掉**：还款金额不得超过剩余，提示「最多还能还 ¥1,200.00」。
   这样剩余不会变成负数，界面不用处理「已结清但还倒欠」这种状态。
5. **状态重算的一条后果**（写在这儿免得以后觉得是 bug）：手动「标记已结清」之后，
   如果又去删了某条还款记录，状态会按剩余重算回「待还」。理由是「你刚动过还款记录，
   状态按记录重算」，比多存一个「手动结清标记」简单，也和「不存冗余字段」这个原则一致。
6. **债务只在债务子页面的月历上标红**，不动「今日计划/自媒体/健身/饮食/学习」那五张
   月历的图例（它们的圆点种类已经够多了；首页那一行提醒足够让你知道有事）。

## 2. 数据模型

`数据.json` 里新增一个顶层 `debt` 键（和 `finance` 并列）：

```json
"debt": {
  "items": [
    {
      "id": "…",
      "name": "花呗",
      "type": "oweOthers",
      "totalCents": 350000,
      "creditor": "支付宝",
      "dueDate": "2026-10-20",
      "note": "每月20号还款",
      "status": "pending",
      "repayments": [
        { "date": "2026-09-20", "amountCents": 230000, "txId": "…" }
      ]
    }
  ]
}
```

- `type`：`oweOthers`（我欠别人）/ `othersOweMe`（别人欠我）。
- `totalCents`：整数分（和记账一样，金额只用「分」存）。
- **`remainCents` 不存**：`剩余 = totalCents − sum(repayments.amountCents)`，
  由一个纯函数算（`debt-calc.js`），像 `accountBalanceCents()` 那样。
- `status`：`"pending"` / `"done"`。写入点只有三处（§1）。
- `repayments[].txId`：**可空**。空 = 这条还款没有对应账目（比如你自己在别处记的）；
  有值但找不到那笔账目 = 界面上标一句「对应账目已删」。
- 时间都用本地日期 `YYYY-MM-DD`（不要 `toISOString`，那是 UTC，晚上会差一天）。

### 2.1 分类里加两个

`finance.categories.expense` 末尾加 **「债务还款」**、`income` 末尾加 **「债务收款」**。
图标沿用 emoji：💳 还款 / 💰 收款。服务端的 `migrate()` 要给老数据补上这两个
（缺了就追加，已经有了就不动）。

## 3. 子 Tab 与页面结构

记账页页头下面加一行子 Tab：

```
💰 记账  ……说明……                                  [+ 记一笔]
[ 账目记录 ]  [ 债务欠款 (3) ]        ← 括号里是未结清笔数，0 笔时不显示
```

### 3.1 债务子页面（和账目记录同款双栏）

```
┌──────────────────────────┬──────────────────┐
│ 月历卡片                  │ 债务总览          │
│  有到期的那天标红点，      │  我欠别人合计      │
│  格子里写「到期 ¥350」     │  别人欠我合计      │
│                          │  净负债            │
│                          │  近 30 天到期提醒  │
│                          ├──────────────────┤
│                          │ 债务列表          │
│                          │  每行：名称/类型   │
│                          │  剩余·到期日·状态  │
│                          │  [编辑][记录还款]  │
│                          │  [结清]           │
│                          │  └ 已结清（折叠）  │
└──────────────────────────┴──────────────────┘
```

- 双栏尺寸和塌陷规则**和记账页共用同一套**（右栏 320px，窄于 1100px 塌成一列）。
- 月历复用 `monthGridHtml`：`marksOf` 给出到期日的红点（本地 `kinds: [["debt", "到期"]]`，
  **不改** `ALL_KINDS`，所以别处的图例一动不动），`dayExtraOf` 在格子里写「到期 ¥350.00」。
  只标**未结清**债务的到期日。
- 状态与颜色：已结清灰、7 天以上普通、7 天内橙、已逾期红（逾期＝`dueDate` 早于今天且未结清）。

### 3.2 总览卡片上的三个数

- 我欠别人合计（红）＝ 所有 `oweOthers` 未结清的剩余之和
- 别人欠我合计（绿）＝ 所有 `othersOweMe` 未结清的剩余之和
- 净负债（红）＝ 我欠 − 别人欠我（负数就写「净债权」，绿色）
- 近 30 天到期：列出 `dueDate` 在 30 天内的未结清债务，写成
  `花呗 ¥1,200.00 · 10月20日`，逾期的那条前面加「已逾期」。

## 4. 记录还款（和记账的联动）

点某笔债务的「记录还款」，弹窗里四个字段：

| 字段 | 说明 |
| --- | --- |
| 还款金额 | 默认填剩余全额；必须 > 0 且 ≤ 剩余 |
| 日期 | 默认今天 |
| 账户 | 我欠别人 → 「从哪个账户还」；别人欠我 → 「收到哪个账户」 |
| 备注 | 可空，默认填成 `${债务名}还款` |

保存时依次做三件事（一个动作，一起落盘）：

1. `repayments.push({ date, amountCents, txId })`
2. 在 `finance.transactions` 里**新增一笔账目**：
   - `oweOthers` → `type: "expense"`，分类「债务还款」
   - `othersOweMe` → `type: "income"`，分类「债务收款」
   - 带上选的账户、日期、备注；把新账目的 id 回填进 `txId`
3. 重算状态：剩余 ≤ 0 → `status = "done"`

保存后：债务行、总览、月历、账目页、首页卡片一起刷新，并 `toast("已还 ¥350.00，已记一笔支出")`。

### 4.1 三条边界（都在用户确认过的口径里）

- **删掉那笔账目 → 债务不动**：还款历史里给那条标一句「对应账目已删除」。
- **删掉还款记录 → 剩余加回来，账目不动**：确认框写「删除这笔还款记录？剩余金额将恢复 ¥1,200.00」。
- **手动结清**：债务行上的「结清」按钮，二次确认「标记为已结清（不用还了）？」；
  结清后再点变成「恢复待还」。这一条**不生成任何账目**（本来就没钱流动）。

**还款历史在哪儿看**：债务行的「编辑」弹窗下半部分是还款记录列表，每条一行
——`2026-09-20 还了 ¥2,300.00`，右边一个「删除」；`txId` 有值但账目找不到时，
那一行下面加一句灰字「对应账目已删除」。列表为空时写「还没还过」。

## 7. 测试与验收

**自动**：`node tests\债务计算.test.mjs`（剩余、合计、逾期判断、状态分组等纯逻辑）；
`python tests\自检.py`（骨架、清空、导出导入带着 `debt` 走）。

**手工（开发版 8766，配演示数据）：**

1. 记账页出现两个子 Tab；债务那个角标显示未结清笔数；点它切到债务页，刷新还在债务页。
2. 加一笔「我欠别人」（花呗 ¥3,500、本月 20 号到期）→ 列表出现，总览的「我欠」跟着变。
3. 「记录还款」¥350、选微信 → 债务剩余变 ¥3,150；**账目页多一笔支出**（分类「债务还款」、账户微信、备注「花呗还款」）；微信余额跟着少 ¥350。
4. 一直还到剩余 0 → 自动变「已结清」并折叠；删除其中一条还款记录 → 剩余加回来、状态回到「待还」、确认框写明恢复多少；那笔账目**还在**。
5. 去账目页删掉还款生成的那笔支出 → 债务不变，还款历史里标「对应账目已删除」。
6. 「别人欠我」：记录收款 → 生成一笔**收入**（分类「债务收款」），账户余额增加。
7. 到期日当天：债务页月历上那天有红点、格子里写「到期 ¥350.00」；7 天内到期的行是橙色、逾期的是红色。
8. 首页记账卡片：没有近期到期时不显示那一行；把某笔的到期日改到明天 → 那一行出现。
9. 全局搜索搜债务名 → 结果标签是「债务」，点进去落在债务子页。
10. 删除一笔债务 → 回收站里能找到、能还原。
11. 四套皮肤 × 深浅两色看一眼，不破相；控制台 0 条 error / warning。

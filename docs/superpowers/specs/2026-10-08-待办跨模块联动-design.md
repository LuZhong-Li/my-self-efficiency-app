# 待办跨模块联动：今日计划 ↔ 首页总览 ↔ 各模块任务（设计）

版本 v1.4 · 2026-10-08 · 对应实现：`app/web/task-calc.js`、`app/web/task-actions.js`、
`plan.js` / `home.js` / `dev.js` / `calendar.js`、`item-form.js` 的 `todayPlan` 与
`devTodo`

## 1. 核心原则

**任务只有一份原始数据，不做多份拷贝。**

「今日计划」「首页总览」「开发工作里的项目待办」读的都是同一张 `tasks` 表里
**同一条记录**：一处打勾，另外两处跟着变；不需要任何同步代码，也不可能出现
「这边做完了那边还亮着」的不一致。

怎么区分一条任务从哪来，用的是已经存在的 `belong` 字段：

| `belong` | 谁的任务 | 在哪看得见 |
| --- | --- | --- |
| `plan` | 今日计划自己的（含游戏娱乐顺手加的） | 今日计划 / 首页 / 月历 |
| `dev:<项目 id>` | 开发工作挂在某个项目上的待办 | 项目详情；**勾了「今日计划」之后**才同时进今日计划与首页 |
| `goal` | 模块目标按规则自动生成的 | 今日计划 / 首页（行上带「健身目标任务」这类来源标签） |

## 2. 数据结构（写进 `数据\数据.json`）

这次只给任务加两个字段，其余一个字都没动（老数据由 `服务.py` 读出来自动补齐）：

```jsonc
{
  "id": "demo-t13",
  "date": "2026-10-08",      // 「加入今日计划」时盖成今天；移出时清空
  "text": "把月历的氛围底再调淡一点",
  "done": false,             // 完成状态只有一个来源：就是这条记录本身
  "doneAt": null,
  "priority": "中",           // 高 / 中 / 低 / ""（不标）——今日计划与开发待办共用
  "isTodayPlan": true,       // 新增：跨模块那个「加入今日计划」开关
  "belong": "dev:demo-p1",   // 原模块：决定它能在哪儿删
  "isArchived": false,       // 归档的不占今日计划与首页
  "note": "顺手改的，不着急",
  "imagePaths": []
}
```

- `isTodayPlan`：开关。勾选 → 同时出现在【今日计划】与【首页总览】；
  取消 → 两边都不再显示，**任务本身留在原模块**，一个字节都不删。
- `date`：今天计划要看的就这一天。加入今日计划时盖成今天，移出时清空。
  这么做的好处是月历、「昨天没做完的」这些现成的口径不用改就认得它。
- `done` / `doneAt`：状态唯一源，只在原始记录上改。

## 3. 各页面渲染规则

### 今日计划

- 画哪几条：`task-calc.js` 的 `planTasksOf(tasks, today)` —— 日期是今天的，
  加上 `isTodayPlan` 标着的；归档的不算。
- 顶部统计：`未完成 N ｜ 已完成 M ｜ 完成 X%` + 一条细进度条，每次改动自动重算。
- 每行：优先级胶囊（高 / 中 / 低）+ 来源标签（`开发待办` / `健身目标任务` / `游戏娱乐`）。
- 操作：
  - 勾复选框 → `updateTaskStatus(id, done)`：写状态、落盘、重画；
  - `移出今日计划`（只对外来的待办）→ `toggleTaskInTodayPlan(id, false)`；
  - `编辑` → 开发待办开的是**它自己那个弹窗**（带优先级），其余开今日计划弹窗；
  - `删除` **只对今日计划自己的任务出现**，外来的换成「回项目」链接。

### 首页总览

- 「今日待办」与进度用同一套口径（`home-view.js` 的 `todayTasks` → `inTodayPlan`），
  所以今日计划里有什么，首页就有什么，百分比也对得上。
- 行上同样显示优先级与来源标签。

### 开发工作（各业务模块这一侧）

- 项目详情里每条待办尾部多一个「今日计划」勾选框：勾上 = 加入，取消 = 移出。
- 在本模块勾完成，首页与今日计划同步更新（走同一个 `updateTaskStatus`）。
- 归档的待办不占今日计划与首页（`inTodayPlan` 里挡掉），归档区照旧。

## 4. 事件联动（JS 核心）

```js
// task-actions.js —— 一处修改，全局生效的两个入口
export function updateTaskStatus(taskId, done) {
  const task = findTask(taskId);
  if (!task) return null;
  markTaskDone(task, done);   // done + doneAt 只有这一份实现
  touch(true);                // 落盘 + 通知界面重画当前页面
  return task;
}

export function toggleTaskInTodayPlan(taskId, isAdd, today) {
  const task = findTask(taskId);
  if (!task) return null;
  if (isAdd) { task.isTodayPlan = true; task.date = today || todayStr(); }
  else { task.isTodayPlan = false; task.date = ""; }
  touch(true);
  return task;
}
```

`touch(true)` 会广播给整个界面；页面同一时刻只挂一个视图，重画当前页面就等于
「首页 / 今日计划 / 各模块一次性刷新」——不需要额外的 `renderAllViews()`。

## 5. UI 细节

- 优先级胶囊：高（红）/ 中（橙）/ 低（绿），磨砂半透，和「模块目标」那几个小标签一套。
- 来源标签：`健身目标任务` / `游戏娱乐` 沿用原来的强调色胶囊；`开发待办` 用浅灰磨砂，
  一眼能分出「这条是从项目里拉过来的」。
- 统计数字实时联动，改完立刻重算，不用刷新。

## 6. 边界规则

1. **删除**：必须在原模块删。今日计划 / 首页 / 月历对 `belong = "dev:*"` 的任务
   不提供删除按钮，只给「移出今日计划」和「回项目」。
2. **归档**：`isArchived` 为真的任务不在首页、今日计划、月历出现，归档区照旧能看能恢复。
3. **不重复**：同一条任务只渲染一次 —— 判定「今天该不该出现」只在一个函数里
   （`inTodayPlan`），三个页面共用。
4. **落盘**：每次修改都走 `touch(true)`，复用原来的「先写临时文件再整体替换」防损坏逻辑。

## 7. 测试

- `node tests\待办联动.test.mjs`：33 项，覆盖优先级分档、归属判定、
  「今天要不要出现」（含归档 / 昨天 / 兜底三条边界）、来源标签、排序与统计。
- `python tests\自检.py`：老任务补齐 `isTodayPlan` 的迁移检查。
- 浏览器里实际点过一遍：开发工作勾「今日计划」→ 今日计划与首页都出现（带来源标签）
  → 在首页勾完成 → 回开发工作看，项目统计与那一条都变成已完成 →
  今日计划里点「编辑」打开的是原模块那个带优先级的弹窗 → 移出后两边同时消失。

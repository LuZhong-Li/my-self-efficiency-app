# 自媒体「素材库」：素材收进来、关联到作品（设计）

版本 v1 · 2026-10-14 · 对应实现：待定（本文档是设计，代码还没写）

来源：`docs/需求清单.md` 第 8 节第 6 条（自媒体第二版）里的最后一项，
原文写作「素材关联笔记模块」。

## 1. 先要拍板的一件事：这句话怎么理解

原文那句「素材关联笔记模块」有两种读法，**选哪一种，工作量差好几倍**：

| 读法 | 要做的事 | 量 |
| --- | --- | --- |
| **A. 自媒体里的素材库**（本设计按这个写） | 自媒体页多一个「素材」子页：把脚本 / 封面 / 参考链接收进来（图片 + 链接两种），每条带一句说明，**关联到作品**（一条作品用哪几份素材） | 一块新子页 + 一张新表 + 作品弹窗里勾一下 |
| B. 先做全站「笔记」模块，再让素材关联它 | 新建第 11 个模块（笔记本体、富文本 / Markdown、笔记与各模块的关联……）——这是 `需求清单.md` 第 4 节里写着「还没做」的那件事 | 一个新模块，比这一条大得多 |

**我按 A 写。** 理由：这一项是挂在「自媒体第二版」下面的，用途很具体 —— 做一条作品时，
脚本、封面、参考链接得有个地方放、还能跟这条作品对上；A 能做到这件事，而且不动全站结构。
真要做 B（通用的笔记模块），那是另一条独立的线（需求清单第 7 条也列着「笔记富文本 /
Markdown」），做完之后素材再关联笔记也不迟 —— 到时候这张素材表照样用得上。

> 这一条写在最前面：**如果你要的是 B，先告诉我**，这份设计就要重写（改成笔记模块的设计）。

## 2. 现在缺什么

- 自媒体到今天为止**一处也不能挂图片**：`media.js` 里没有任何 `imagePaths` / 附件组件
  （记账、bug、六模块表单都有，唯独作品、账号没有）。封面、脚本截图没处放。
- 参考链接只能塞进「备注」那一格，和别的字混在一起，发的时候找不到。
- 现成能用的零件其实不少：图片附件组件（`attachment.js` / `attachment-calc.js`，
  上传 / 预览 / 删除 / 全屏查看都齐）、`openDialog`、`moveToTrash`、`search-calc`
  的搜索池、以及记账那边「子页 + 子 Tab」的现成做法（`#finance/debt`）。

## 3. 数据模型

新增一张顶层表（和 `contents` / `mediaAccounts` 并列）：

```jsonc
mediaAssets: [
  {
    "id": "asset-1",
    "title": "封面：这期讲标签系统",
    "kind": "image",          // image | link
    "path": "attachments/media_asset/20261014_ab12cd.png",  // kind=image 时用
    "url": "",                // kind=link 时用
    "note": "B 站竖版封面，改过两版",   // 一句说明（就是原文说的「笔记」）
    "createdAt": "2026-10-14 10:00"
  }
]
```

**关联存在作品那一侧**：`contents[].assetIds: ["asset-1", …]`。

- 为什么放作品侧：日常动作是「做这条作品 → 挑素材」，作品是主动方；素材库里那句
  「用在 2 条作品上」由作品侧现算（和「进度不另存」一个哲学，不会有第二份真相）。
- 代价是**删素材时要摘引用**：删一份素材，得把它从各作品的 `assetIds` 里摘掉 ——
  这件事抽成一个纯函数（第 6 节），单测盯住，别让作品留着一个指向不存在素材的 id。

**素材只收两种**（见第 7 节「不做」）：

- `image`：走现成的附件组件，存进新目录 `attachments/media_asset/`
  （`attachment-calc.js` 的 `ATTACH_MODULES` 与 `服务.py` 的 `ATTACH_MODULES` 各加一项，
  `MODULE_LABEL` 配一个中文名「自媒体素材」）。
- `link`：一段 URL 文本（参考链接、别人的视频、素材站页面）。

## 4. 界面

### 4.1 素材库：自媒体页的子页（`#media/assets`）

照记账「账目记录 / 债务欠款」那对子 Tab 的做法，在自媒体页的子 Tab 里加第三个
「素材」（`#media/assets`）：

- 卡片列表：每行写 **标题 + 类型小标签 +（图片给一张小缩略图 / 链接给可点的链接）+
  一句说明 + 用在 N 条作品上**，行尾是「编辑 / 删除」（鼠标移上去才露出来，和别处一致）。
- 头上一个「添加素材」按钮 → 弹窗：类型（图片 / 链接）二选一、标题（必填）、
  图片（选文件 / Ctrl+V 粘贴，复用附件组件）或链接（必填、以 http 开头才收）、
  一句说明（选填）。
- 空状态：「还没有素材」「把脚本、封面、参考链接收进来，做作品的时候直接挑」。

### 4.2 作品弹窗里勾素材

作品弹窗（`openWorkDialog`）里加一格「素材」：把素材库里现有素材列成一行可勾的
小胶囊（勾上 = 这条作品用它），下面一个「新建素材」的链接直接开那个弹窗、建完回来
接着勾（省得关掉重开）。**一条素材可以被多条作品勾**（同一张封面用在 B 站和公众号）。

作品列表的行上：有素材就画一个小标记（`素材 2`），没有就不画 —— 和现在「有图才画图标记」
一个规矩。点开作品看详情时，素材以缩略图 / 链接列出来。

### 4.3 删除的连带关系

- **删素材**：确认框里写明「有 2 条作品在用，删掉之后它们的素材里也会少这一份」，
  确认后从各作品摘掉引用（作品本身不动），走回收站。
- **删作品**：素材本身留着（别的作品可能还在用），只是那条引用没了。
- 回收站里素材显示成「自媒体素材」（`TRASH_TABLE_LABEL` 加一项）。

## 5. 搜索

`search-calc.js` 的 `SOURCE_SPECS` 加一行：表 `mediaAssets`、模块 `media`、
标签「素材」、标题 = 标题、字段 = 标题 / 说明 / 链接。这样搜素材名或链接能直接找到它，
点结果回自媒体页。**不进**搜索结果的是图片路径本身（搜文件名没意义）。

## 6. 纯逻辑与测试

纯逻辑放 `media-calc.js`（它已经管着自媒体的账号 / 作品 / 粉丝口径）：

| 函数 | 干什么 |
| --- | --- |
| `normalizeAsset(row)` | 一条素材读出来规整：类型只认 image / link、标题去空白、说明去空白 |
| `assetsOf(data)` | 素材列表（老数据没这个键就是空的，手改坏了也当空） |
| `assetUsage(assets, contents)` | 每份素材被几条作品用着（作品侧 `assetIds` 现算） |
| `unlinkAsset(contents, assetId)` | 删素材时把引用从各作品摘掉（返回新数组，不改传进来的） |

测试：

- `tests\自媒体计算.test.mjs`：上面四个函数（含老数据、手改坏的、一条被多条引用、
  摘引用之后别的引用不动）；
- `tests\自检.py`：老数据补 `mediaAssets: []` 与 `contents[].assetIds: []` 两条
  （服务端那句「缺键就补骨架」管前者，行内字段由 migrate 补后者）；
- 新增真浏览器回归 `tests\自媒体素材.test.mjs`：建一份图片素材 + 一份链接素材 →
  作品弹窗里勾上 → 作品行上出现「素材 2」→ 素材页那句「用在 1 条作品上」→
  删掉一份素材 → 作品那边引用跟着没了、另一份还在 → 全程 0 条 JS 报错。

## 7. 这一版明确不做

- **不做全站笔记模块**（第 1 节的读法 B），也不做富文本 / Markdown。
- **不收图片以外的文件**（剧本 .docx、视频 .mp4）：附件组件只认图片，本地小服务也没有
  通用的文件存储与预览。想收这类，先放链接、或者手动放进数据目录。
- 不联网：**不做**「粘一个链接自动抓标题 / 封面」（纯本地应用，不联网是硬规矩）。
- 不给素材贴全站标签（记账「记一笔」也还没接标签，等第二版统一接）。
- 不做素材的分组 / 文件夹 / 版本管理（「封面 v2」这种就再建一条，说明里写清）。
- 不做素材的批量导入导出（作品 CSV 那一版没带素材，这里也不加；真要导出，附件目录本身
  就是文件，复制走即可）。

## 8. 需要你拍板的几件事

1. **第 1 节的读法**：按 A（自媒体素材库）做，还是你其实要 B（全站笔记模块）？
2. **关联方向**：作品里勾素材（我推荐，见第 3 节），还是素材里勾作品？
3. **图片存哪**：新开 `attachments/media_asset/`（我推荐，职责清楚），
   还是复用现成的 `attachments/note/`（那个目录本来给笔记模块留的，现在没人用）？
4. **素材要不要能被「详情」看到**：我按「作品弹窗里勾 + 行上小标记 + 详情列出」写；
   嫌多可以只留弹窗勾选那一处。

## 9. 实施顺序（给后面的实施计划用）

1. `media-calc.js` 四个纯函数 + 单测（TDD，先红后绿）。
2. `服务.py` 与 `自检.py`：新键与新字段的迁移、附件新目录白名单、回收站标签。
3. 素材子页（`#media/assets` 的 Tab、列表、添加 / 编辑 / 删除弹窗）。
4. 作品弹窗里勾素材 + 作品行上的小标记 + 删除时的引用摘除。
5. `search-calc.js` 加一行来源 + 单测。
6. 真浏览器回归 `tests\自媒体素材.test.mjs`；文档回填（设计文档补一节、
   `需求清单.md` 第 8 节第 6 条标完成、变更记录、README 的测试清单）。

## 1. 三条主线

### 1.1 桌面化（D-1 ~ D-5）—— `app\服务.py` + `启动.cmd`

服务层加的是一条**可选外壳**，服务本身还是标准库 `http.server`，一行没换成框架：

| 函数 | 干什么 |
| --- | --- |
| `desktop_requested()` | `--desktop` 或 `XIAOLI_DESKTOP=1` → 要开窗口；带 `--no-browser` 一律当没要过 |
| `desktop_available()` | `try: import webview` 探个路，失败就是 False |
| `desktop_mode()` | 上面两个都成立才为真 —— **回退判断就在这一句里** |
| `run_desktop(httpd, port)` | `serve_forever` 挪到后台线程，主线程跑 pywebview 消息循环；窗口关掉先 `shutdown()` 再 `server_close()` |

几个踩过才知道的细节：

1. **`icon` 是 `webview.start()` 的参数，不是 `create_window()` 的。** 按调研文档
   那种写法会当场抛 `TypeError: unexpected keyword argument 'icon'`，
   然后被回退逻辑吃掉、静默变回浏览器模式 —— 第一版就是这么跑起来的
   （好在 `日志\console.log` 把原文记下来了，这正是日志重定向的价值）。
2. **收尾顺序**：先 `server_close()` 再让 `serve_forever` 自己结束，accept 那边会抛
   一段套接字报错（日志里多一段 Traceback）。改成 `shutdown()` → `server_close()`，
   并在服务线程里只吞 `OSError`。
3. **`--no-browser` 的语义没变**：它还是「一个界面都不开」。桌面模式也归它管 ——
   49 个测试文件全部走这条路连端口，服务层必须保持无 GUI 可跑。
4. 回退是**两级**的：`import webview` 失败 → 不开窗口；`run_desktop()` 中途抛异常
   （WebView2 坏了之类）→ 把窗口关掉、退回浏览器模式，进程继续服务。

### 1.2 消灭黑窗口（D-1）—— `启动.cmd` + `启动-调试.cmd`

`启动.cmd` 原来只探「有没有能用的 Python」。现在探到之后再问两件事，
四档各自落到该落的跑法：

| 有 pywebview | 有 pythonw.exe | 怎么跑 |
| --- | --- | --- |
| 有 | 有 | `start "" pythonw.exe 服务.py --desktop` —— 双击后只有小李窗口，没有控制台 |
| 有 | 没有 | `python.exe 服务.py --desktop` —— 窗口 + 控制台（控制台就是「关掉程序」的开关） |
| 没有 | 有 | `python.exe 服务.py` —— **故意不用 pythonw**：没有窗口又没有控制台，用户就没处关程序了 |
| 没有 | 没有 | 同上 |

第三档是这一轮唯一一处**和计划文档不一样**的地方（见第 4 节）。

无控制台时（pythonw 下 `sys.stdout is None`），`redirect_console()` 把 `print`
接进一个 `FileStream`，追加到 `数据\默认\日志\console.log`：写一次加一次锁
（关窗时服务线程和主线程都会写）、每次写完关文件（被强杀也已经落盘）、
超 512 KB 轮换成 `.log.1`。带控制台的调试入口不受影响 —— 它有 stdout，这段直接不生效。

### 1.3 界面质感（U-1 ~ U-5）—— `app\web\style.css`

**只增不改**：全部追加在文件末尾的 `2026-10-15 设计感升级` 区块里，
老规则一条没删、一条没改。确需覆盖的用更高优先级选择器压过去，
每条都写了为什么；真出问题可以整块删掉回退。

1. **设计令牌**：`--bg-grad`、`--glass-bg / --glass-blur / --glass-line`、`--shadow-2`、
   `--dur-s/m/l` + `--ease`、11 个 `--m-*`；深色块里给每个令牌一组更亮的版本。
2. **背景与外壳**：body 换成柔和渐变；极简皮肤（没挂 `data-skin`）的顶栏 / 侧栏 /
   状态栏做成半透明磨砂 + 高光描边。这里有个坑：顶栏一旦有 `backdrop-filter`
   就成了层叠上下文，里面的搜索面板（z-index 30）会被卡片压住、看得见点不动 ——
   玻璃皮肤 1993 行踩过同一个坑，照它的办法提 z-index。
3. **卡片**：双档阴影 + hover 抬升（笔记 / 粗野各按自己的脾气来，不做悬浮）。
4. **11 个模块主题色**：侧栏图标方块 + 选中项、首页模块卡片左侧色条与图标色、
   页头图标、空状态标记、全局搜索结果标签。**认模块靠现成的 `href="#模块id"` 和
   `.side-item.active`，一条 DOM 都没动、一个 class 都没加。**
5. **动效**：弹窗进场（0.96→1 + 淡入）、搜索面板下落进场、按钮按压，
   页面切换沿用原来的 `fadeUp`；全部收进 `prefers-reduced-motion: reduce`。
6. **聚焦环 / 等宽数字 / 空状态**：统一 `:focus-visible`（输入框仍走它自己那圈外发光，
   避免两道框）；卡片里的数字 `tabular-nums`；空状态标记改成模块色淡底 + 虚线外圈。

## 2. 模块色是怎么定的（这一轮最费斟酌的一块）

**为什么不是随手挑 11 个好看的色**：这些颜色会被当**文字**用（侧栏选中项的名字、
全局搜索结果标签），所以既要「一眼分得开」，又要过对比度。

两条规则：

1. **按色相摊开，20°~40° 一档。** 第一版沿用了计划文档给的那组色值，走查时当场被
   看出问题：开发（橙）和健身（琥珀）基本同色，学习（青绿）/ 记账（绿）/ 饮食（黄绿）
   三个绿挤在一起分不开。现在色相是：
   开发 22° · 健身 41° · 饮食 74° · 记账 145° · 学习 174° · 笔记 211° ·
   设置 217°（低饱和灰蓝）· 首页 225° · 计划 258° · 游戏 288° · 自媒体 331°。
   首页那个就是品牌蓝 `#3b66d9`，按约定不动。
2. **过对比度算式。** 浅色那组压到白底 ≥ 4.6:1、深色那组压到深色面板 ≥ 5.8:1。
   走查时健身那档只有 2.59:1，是全场唯一低于「图形下限 3:1」的，所以整组重压了一遍。
   色相一个没动，只是整体压深 / 提亮。

**深色下为什么另配一组**：同一批色在深底上会糊成一团，所以深色块里换成更亮的一档、
色相一一对应 —— 同一个模块在两个主题下仍然是「同一个人」。

**页头 / 空状态怎么知道自己在哪个模块**：模块页里没有「我是谁」的标记，但侧栏上有
（`.side-item[href="#finance"].active`）。用 `html:has(.side-item[…].active)` 把 `--m`
提到 `html` 这一层，页面里的元素就都继承到当前模块的颜色。浏览器不认 `:has()` 时
整段自动失效，退回中性色，不会把页面弄坏。

## 4. 和计划文档的偏差（逐条）

1. **`--no-browser` 也管桌面模式。** 计划里没写这一条。不这么定的话，测试和调试就没法
   在「不开任何界面」的前提下起服务，而服务层必须保持无 GUI 可跑。
2. **pythonw 只在「有 pywebview」时才用。** 计划写的是「探测到 `%PY%` 就优先用 pythonw
   跑 --desktop」。真按那样写，没装 pywebview 的机器上会得到一个**没有窗口、也没有
   控制台**的后台进程 —— 用户只能去任务管理器关它。现在没 pywebview 就退回
   `python.exe`（有控制台 = 有关掉的开关）。
3. **弹窗只做进场动效，没做「关闭反向」。** 关闭是 `dialog.js` 里立刻摘节点，
   要做退场得改那段收尾时序，会牵动弹窗栈那 54 项回归测试；收益（一次 180ms 的淡出）
   不值这个风险。CSS 注释里写明了。
4. **没有为「顶栏 / 侧栏玻璃质感」新增令牌。** 玻璃皮肤本来就有 `--card / --chrome`
   半透明 + `blur(22px)` + 白高光边，这块本来就是它的强项；真正缺的是**极简皮肤**
   和**模块主题色**，所以玻璃那套保持原样、只补缺的。
5. **主题色落在 `--m` 这一个变量上**，而不是每个模块铺一遍规则：少写十倍，
   将来加模块只要补一行。
6. **多花了一次 `import webview` 探测**（约 0.3s），换来的是「不会静默留一个关不掉的
   后台进程」。

## 5. 已知限制

- **原生窗口不进 CDP 测试。** pywebview 的窗口不是网页，没有可连的调试端口，
  自动化测不了它的渲染。兜底两条：回退逻辑有测试（`桌面回退.test.mjs`），
  窗口本身靠人工验收（双击、关窗、任务管理器）。
- **关窗后 `netstat` 可能还有几条 TIME_WAIT**，那是 WebView2 与本地端口之间的客户端
  连接在系统里等超时，不是监听残留；`LISTENING` 一条都没有。
- **无控制台模式下，启动期以外的报错也只有日志。** 要实时看，用 `启动-调试.cmd`。
- **走查截图的色彩判断有分辨率上限。** 联络表缩到每格 620px 宽之后，侧栏那些 8~10px
  的图标方块，看图只能给出「色族」级别的判读。颜色分离度最终是靠
  `getComputedStyle` + 对比度算式定的，不是靠看图。
- **必须先装 pywebview 才有桌面窗口**（`python -m pip install pywebview`）。
  没装不影响使用，只是走浏览器模式。

## 6. 想回退怎么办

- **只回退观感**：把 `style.css` 末尾 `2026-10-15 设计感升级` 那一整块删掉即可，
  前面 4044 行是老样子，一行没动过。
- **只回退桌面窗口**：删掉 `启动.cmd` 里那两层探测（回到只跑 `python.exe`）就行 ——
  服务层不传 `--desktop` 就是老行为。
- **只回退桌面模式本身**：`python -m pip uninstall pywebview`，
  双击自动回到浏览器模式，别的什么都不用改。

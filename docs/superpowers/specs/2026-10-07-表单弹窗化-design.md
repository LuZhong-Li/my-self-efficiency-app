# 六个模块的录入表单改成弹窗（2026-10-07）

## 要解决的问题

「今日计划」「开发待办」「学习记录」「学习对象」「训练打卡」「游戏」这六处，
录入一直是**卡片顶上平铺一行输入框**。一行里塞四五个控件，能写下的东西就那么点：
多行备注写不了、图片没地方放，手机 / 窄窗口下还会挤成一团。

这次把它们统一改成：**卡片上只留一个蓝色添加按钮，点开弹窗填，保存写回 JSON**；
编辑复用同一个弹窗回填。「记一笔」和「记一个问题」早就是这个样子了，改完之后
全 App 的录入范式统一，图片附件那一套（第 24 节）也能直接接上。

## 一、数据

只做加法，老记录一个字段都不动：

```
tasks[]         += imagePaths（今日计划的任务 / 开发待办共用）、priority（开发待办才有）
studies[]       += imagePaths
subjects[]      += imagePaths
workoutLogs[]   += imagePaths
games[]         += imagePaths
```

服务端 `migrate()` 给老记录补空数组 / 空串；页面只读得到一套口径。
图片按模块分格存，一个模块一个文件夹：

| 模块 | 图片目录 |
| --- | --- |
| 今日计划 | `attachments/today_plan/` |
| 开发待办 | `attachments/dev_todo/` |
| 学习记录 | `attachments/study_record/` |
| 学习对象 | `attachments/study_item/` |
| 训练打卡 | `attachments/fitness/` |
| 游戏 | `attachments/game/` |

`ATTACH_MODULES` 现在有 10 个（还有记账 finance、bug 登记 buglog、项目进展 progress、
给笔记留的 note），服务端和前端各一份，加模块要同时改。

## 二、怎么做到「六个模块共用一套」

新加两个文件，把「弹窗」拆成能复用的两半：

### 2.1 `app/web/item-form.js`（纯逻辑，能被 Node 直接单测）

**字段写成一张表**。六个弹窗的区别只有「有哪些字段、存哪张表、图片放哪个目录」，
所以一张表加几个通用函数就够了：

```js
FORMS.game = {
  table: "games",
  upload: "game",
  titleNew: "新增游戏", titleEdit: "改这条游戏",
  hint: "想玩的、在玩的、通关的都记一下。",
  fields: [
    { name: "name", label: "游戏名称", kind: "text", required: true, maxlength: 80 },
    { name: "platform", label: "平台", kind: "select", list: GAME_PLATFORMS, half: true },
    { name: "status", label: "状态", kind: "select", list: GAME_STATUSES, half: true },
    { name: "hours", label: "游玩时长（小时）", kind: "number", min: 0, step: 1 },
    { name: "progress", label: "进度备注", kind: "textarea", rows: 3 },
  ],
  label: (row) => row.name,          // 删除确认里显示的名字
  create: (ctx) => ({ id: ctx.uid(), name: "", platform: "PC", status: "想玩", hours: 0, progress: "" }),
};
```

函数只有这么几个，全是纯的：

| 函数 | 干什么 |
| --- | --- |
| `formHtml(type, values, ctx)` | 把字段表画成 HTML；连续两个 `half` 字段并排一行 |
| `defaultsOf` / `valuesOf` | 新增时的初始值 / 编辑时按老记录回填 |
| `readValues(type, get)` | 从表单读值（`get(name)` 由调用方给，方便单测） |
| `validate(type, values)` | 必填 + 「这几项至少写一个」 |
| `applyValues(type, row, values)` | 写回记录：数字转数字、文本去空白，别的字段一个不动 |
| `newRow(type, values, ctx)` | 新增：`create()` 捏空壳 + 写表单值 + `imagePaths: []` |
| `trashPlan(type, row, rows)` | 删除要动哪几张表（学习对象要连学习记录一起），**纯描述**，执行交给上面那层 |

### 2.2 `app/web/item-dialog.js`（DOM 层）

`openItemDialog(type, row, options)` —— 六个模块都调它，传类型和记录就行。
它负责：摆弹窗、挂附件区、**先写图片再动 JSON**、删除确认、回车保存、
关窗时把预览地址还回去。图片那一套直接用 `attachment.js`，一行没重写。

## 三、六个弹窗各有什么字段

| 模块 | 类型 | 字段 |
| --- | --- | --- |
| 今日计划 | `todayPlan` | 任务（必填）、计划时间、分类、备注（多行）、图片 |
| 开发待办 | `devTodo` | 要做什么（必填）、优先级（不标/高/中/低）、备注（多行）、图片 |
| 学习记录 | `studyRecord` | 日期（必填）、学习对象（下拉，接学习对象列表）、时长、学了什么、心得（多行）、图片 |
| 学习对象 | `studyItem` | 名称（必填）、类型（书/课程/视频/技能/其它）、作者平台、备注（多行）、图片 |
| 训练打卡 | `fitness` | 打卡日期（必填）、训练内容（多行，必填）、备注（多行）、图片 |
| 游戏 | `game` | 游戏名（必填）、平台、状态、游玩时长、进度备注（多行）、图片 |

几个统一的小规矩：

- 校验不过**留在弹窗里**、用 toast 说清是哪个字段（「任务」不能是空的）；
- 多行字段是 textarea，里面回车是换行；文本框 / 下拉里回车 = 保存；
- Esc 关、点遮罩关、Tab 在弹窗里绕圈（`openDialog` 本来就管）；
- 「取消」时图片一个字节都不落盘（挑中的图只在内存里）；
- 编辑时多一个「删除」，进回收站；图片要不要跟着删看「数据与设置」里那个开关。

## 四、列表这边动了什么

- 卡片顶上的输入行没了，换成卡片头右上角的蓝色按钮（今日计划是「添加任务」，
  开发待办是「添加待办」，学习记录是「记一条」，学习对象是「添加」，
  训练打卡是「记一次」，游戏是「添加游戏」）；
- 列表本身没动，只是**有图片的条目多一个小图片标记**（`attachment.js` 的
  `imgBadge()`，六个模块共用一个，提示语和样子才一致）；
- 编辑按钮从「行内展开输入框」改成打开同一个弹窗回填；
- 健身页的「体重记录」「每周训练安排」不在这次范围内，保持原样（一个仍是行内表单，
  一个是停笔即存）。

## 五、这一版没做（原需求里的 P1）

弹窗里拖拽 / 粘贴图片、弹窗快捷键（除了已有的回车保存和 Esc 关闭）、
列表点开变成详情面板看完整备注和图片。

另外「开发工作 → 问题 / bug」「最近进展」「记账」「债务」这几处的弹窗本来就已经是
弹窗了，这次**没有**把它们迁到 `openItemDialog` 上（它们各有各的特殊逻辑：
状态联动修复时间、还款记录、预算分类…），但外观和交互规则完全一致。

## 六、验证

- `node tests\表单计算.test.mjs`：**110 项**。字段表本身（每个类型的图片目录都在
  白名单里、目录互不重复、必填字段就那几个）、下拉选项（含动态的「学习对象」）、
  画表单（并排、值回填、**转义** —— 游戏名里塞 `<script>` 不会变成标签）、
  初始值（新增默认 / 编辑回填 / 数字 0 当没填）、读值、校验（必填 + 至少写一项）、
  写回（trim、数字、不动别的字段、NaN 变 0）、新增（belong / date / reviewed 这些
  不在表单里的字段对不对）、删除计划（删学习对象要连记录一起走）。
- `python tests\自检.py`：49 → **57 项**（六个新图片目录各存一次、老的任务 /
  学习 / 对象 / 打卡 / 游戏读出来都补上了 `imagePaths`、老任务补 `priority`）。
- 浏览器里手工走了一遍：六个页面都没有平铺输入行了、六种弹窗都能开 / 填 / 存 /
  编辑回填 / 取消不留痕 / 空值被拦；游戏那条从「添加图片备注」真选了一张图存进
  `attachments/game/`，列表上出现「带 1 张图」的小标记；粗野 + 深色皮肤下弹窗
  没有横向溢出、控制台 0 报错。

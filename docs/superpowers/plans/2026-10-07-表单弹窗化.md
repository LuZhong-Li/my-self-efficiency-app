# 表单弹窗化 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement
> this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 今日计划、开发待办、学习记录、学习对象、训练打卡、游戏六处，
把卡片顶上的平铺输入行拿掉，改成「一个添加按钮 + 弹窗」，编辑复用同一个弹窗，
并且都接上图片附件。

**Architecture:** 新增 `item-form.js`（纯逻辑：六个模块的字段表 + 画 / 读 / 校验 / 写回）
和 `item-dialog.js`（DOM：`openItemDialog(type, row)` 一个入口，六个模块共用）。
图片沿用 `attachment.js`，一行没改。服务端只加图片目录白名单和字段迁移。

**Tech Stack:** 原生 HTML + CSS + ES 模块（无框架、无构建、零外链）；
弹窗用现成的 `openDialog`；Python 标准库小服务；Node 跑纯逻辑单测。

**Spec:** `docs/superpowers/specs/2026-10-07-表单弹窗化-design.md`

## Global Constraints

- **零外链**：`.html` / `.css` / `.js` 里不能出现 `http(s)://`（`tests/自检.py` 会扫）。
- **不装依赖**：Python 标准库 + 本机 Node v24，不建 `node_modules`。
- **事件不挂公共 `#view`**：一律 `bindFresh(root, { click, submit, change, input })`。
- **图片先落盘、JSON 后落盘**；「取消」时一个字节都不留。
- **只做加法**：老记录字段一个都不改；`severity`、`text`、`note` 这些老字段名不动。
- **删除先进回收站**；图片只在「彻底删除」时按设置决定跟不跟着删。
- **注释和提交信息用中文**，说清「为什么」。
- 每个任务结束时：`python tests\自检.py` 全过、控制台 0 条 error / warning。

## 自查记录

- **覆盖检查**：spec §1 数据（Task 2）、§2 共用组件（Task 1 + 3）、§3 六个弹窗的字段
  （Task 1 的字段表）、§4 列表改动（Task 4）、§5 不做的三条明确没碰。
- **类型一致**：字段的 name 就是记录上的字段名（`text` / `note` / `severity` 这些老名字
  一个没改），所以 `applyValues` 不需要一层映射。
- **踩到的两个坑**：
  1. 「从某一天点添加」的日期没预填 —— `ctx.date` 只喂给了 `create()`，
     没喂给表单默认值。改成 `seed.date = options.date` 之后才对。
  2. 训练打卡的「记一次」按钮在卡片头上、没有 `data-id`，一开始写在
     `if (!row) return` 后面，永远走不到；挪到找行之前。

# 游戏娱乐 · 游玩记录与游玩统计（设计）

版本 v1.3 · 2026-10-07 · 对应实现：`app/web/game.js`、`app/web/game-calc.js`、
`item-form.js` 的 `gamePlayRecord`、`gameRecords` 数据表

## 1. 为什么要改

游戏娱乐原来只有一张「游戏清单」：游戏名、平台、状态（想玩 / 在玩 / 已通关 / 弃坑）、
进度备注，外加一个手填的「游玩时长」。用下来两个问题：

1. **记不住过程**：今天玩了什么、玩了多久、玩得怎么样，清单里放不下；
2. **累计时长要手填**：得自己去算「42 + 2」，填错了也没人发现，慢慢就懒得填了。

这次在不破坏清单的前提下加两块：**游玩记录**（玩一次记一条）和**游玩统计**
（今日 / 本周 / 本月 / 全年 + 玩得最多的 TOP3）。清单上那个「累计 X 小时」改成
从游玩记录自动加出来，不再手填。

## 3. 数据结构（写进 `数据\数据.json`，老数据兼容）

```jsonc
"gameRecords": [
  {
    "id": "8b2cf9bb-…",              // uid
    "gameId": "demo-j1",             // 清单里那款游戏的 id；临时玩的可留空
    "gameName": "塞尔达传说：王国之泪",   // 名字始终存一份（清单删了也看得出玩的什么）
    "playDate": "2026-10-07",
    "durationMin": 120,              // 统一按分钟存，展示时换算成 2 小时
    "remark": "主线第三章，打完一个神庙",
    "createAt": "2026-10-07T20:10:00",
    "imagePaths": []                 // 图片备注，和别的模块一套（attachments/game_record/）
  }
],
"games": [ /* 原有字段一个字都没动，包含老的手填 hours */ ]
```

老数据兼容（`服务.py` 的 `migrate()`）：

- 没有 `gameRecords` 这个键 → 补一个空数组；
- 有的逐条补齐 `id / gameId / gameName / playDate / durationMin / remark / createAt /
  imagePaths`，一条都不丢；
- `games` 里的 `hours`（老的手填时长）**一个字都不动**，并且继续算进「累计时长」，
  这样以前记过的 42 小时不会凭空消失；想清掉就在游戏弹窗里把它填 0。

## 4. 录入弹窗（type = `gamePlayRecord`）

复用全局那套液态玻璃弹窗（`item-dialog.js` + `item-form.js` 的字段表），
和「修改待办」长得一模一样：Esc 关、点遮罩关、回车保存、Tab 在弹窗里绕圈，
图片点「保存」才落盘、点「取消」不留渣。

| 字段 | 控件 | 说明 |
| --- | --- | --- |
| 游戏名称 | 下拉 + 手打（`<input list>` + `<datalist>`） | 选项是清单里的游戏（在玩的排前面）；清单里没有的直接打名字，`gameId` 留空 |
| 游玩日期 | 日期选择器 | 默认今天；从某一天点「添加」时预填那一天 |
| 游玩时长 | 数字框 + 单位下拉（分钟 / 小时） | 落盘只有 `durationMin` 一个字段；2 小时 = 120 |
| 备注 | 多行 textarea | 对局感受、关卡进度 |
| 图片备注 | 附件区（多张 / 预览 / 单张移除 / 点开看大图） | 存进 `数据\attachments\game_record\` |

底部按钮：编辑时是 **删除 ｜ 取消 ｜ 保存**，新增时是 **取消 ｜ 保存**。
删除走回收站（表名 `gameRecords`，回收站里显示成「游玩记录」）。

游戏清单那个弹窗（type = `game`）做了三处小改动：

1. 原来那个「游玩时长（小时）」改名叫「原有手填时长（小时）」，说明里写清
   「累计时长以后由游玩记录自动算，这一格是老数据兼容，可以清 0」；
2. 新增「每月目标（小时）」（可选，给单款游戏设本月打算玩多久）；
3. 新增「通关日期」，**只在状态选到「已通关」时才露出来**
   （字段表里写 `showWhen: { field: "status", equals: "已通关" }`，
   `item-dialog.js` 挂一个 change 监听做显隐，不用重画弹窗）。

图片备注（存档截图）还是原来那套附件组件，没有变化。

## 5. 计算口径（`game-calc.js`，全是纯函数）

- **累计时长（一款游戏）** = 它的游玩记录求和 + 老数据里手填的 `hours`（×60 分钟）；
  认游戏先认 `gameId`，没绑定就按 `gameName` 相等来对。
- **今日 / 本周 / 本月 / 全年**：按 `playDate` 落段，本周从**周一**算起
  （和首页、模块目标一个算法）；没写日期的记录只进「累计」，不掺进任何一段。
- **TOP3**：清单里每款游戏各算一次累计，没绑定清单的临时记录按名字聚一聚，
  一起排序取前三（只有老手填、一条记录都没有的游戏也会上榜，行上标「原有手填」）。
- **筛选**：按游戏名（模糊）+ 日期范围，只影响显示，不动数据；点清单或排行里的
  「看记录」会把游戏名填进筛选框，等于「看这款的全部历史」。
- **时长显示**：120 → `2 小时`，90 → `1 小时 30 分钟`，45 → `45 分钟`，0 → `—`；
  统计格子里的主数字用 `2.5 小时` 这种紧凑写法，下面补一行准确的 `150 分钟`。

## 6. 几个顺手的小功能

- **快速计时**：点「开始计时」开始跑表（`sessionStorage` 记着，切模块回来还在走），
  「停止并记录」把计出来的分钟数填进新增弹窗，确认一下就能存。
- **拖拽排序**：游戏清单的四行可以拖（和项目卡片同一个 SortableJS、同一套观感），
  组内换位置，拖到别的分组就是换状态（会 toast 一句「移到『已通关』」）。
  顺序按页面上的顺序写回 `games` 数组整份落盘。
- **每月目标提醒**：给单款游戏设了「每月目标」时，统计卡片底部会提示本月
  超了目标的游戏（比如「塞尔达 已玩 6 小时（目标 5 小时）」）；
  一个都没超就不显示这一行。清单行上也能看到「目标 X 小时/月」和「通关 日期」。
- **跨模块联动（可关）**：今日计划那张卡右上角有个开关「显示今日游玩」，
  开着的时候，今日计划顶上会有一条「🎮 今日游玩：… · 共 2 小时」，
  带一个「加一条『玩游戏放松』」（存下来会挂「游戏娱乐」的来源标签，
  和模块目标生成的待办一个待遇）和一个跳到游戏娱乐的链接。开关存
  `settings.planShowGame`。
- **别处也能看到**：全局搜索能搜到游玩记录（游戏名 / 备注 / 日期）；
  今日计划的月历视图里，某天的详情会多一段「游玩」。

## 9. 精简需求（可直接放进 canvas）

游戏娱乐模块优化：保留原有游戏清单（在玩、想玩、已通关、弃坑，四个分组一个字不动）；
页面上方新增「游玩记录卡片」与「游玩统计卡片」。新增游玩记录弹窗，记录游戏名称
（下拉 + 手打）、游玩日期、时长（分钟 / 小时）、备注与截图；游玩记录弹窗复用全局
液态玻璃样式与组件，数据写进 `数据\数据.json` 里新增的 `gameRecords` 数组
（一条 = 哪天玩了哪款游戏、多久、什么感受）。游玩时长自动汇总：统计卡片给出
今日 / 本周 / 本月 / 全年总时长与玩得最多的 TOP3；游戏清单里每款游戏的「累计时长」
由这些记录自动求和，不再手填（老数据里手填的时长继续算进去，不会丢）。
支持按游戏名 / 日期范围翻游玩历史，点清单里的游戏可筛出它的全部记录；
清单支持拖拽排序与换分组；可开启跨模块联动，在今日计划里看到今天的游玩记录、
并一键把「玩游戏放松」加成待办（带「游戏娱乐」来源标签）。游戏清单弹窗补上
「每月目标（小时）」与「通关日期」（通关日期只在状态 = 已通关时出现），
本月超了目标的游戏会在统计卡片上提醒一句。

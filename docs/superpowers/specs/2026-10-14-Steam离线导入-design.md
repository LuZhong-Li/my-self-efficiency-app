# Steam 离线导入（CSV）（设计）

版本 v1 · 2026-10-14 · 对应实现：待定（本文档是设计，代码还没写）
（预计落在 `app/web/csv.js`、`app/web/game-calc.js`、`app/web/game.js`、`app/web/style.css`）

来源：`docs/需求清单.md` 第 8 节第 7 条里的「Steam 同步」，
落地方案见同一份文档第 9.2 节（**原「联网拉接口」方案废弃**）。

## 1. 为什么是这个做法

原方案（拉 Steam Web API + OAuth 登录 + 定时同步）三条都撞本 App 的定位：
**不主动联网、没有登录、数据只在本机**。所以改成**离线手动导入**：
用户自己在别处（Steam 客户端 / 第三方站点）导出游玩记录 CSV，在本 App 里**选本地文件**导入；
解析全程只在本地内存里做，**一个网络请求都不发**。

明写在界面上的限制：**不会自动更新** —— 想更新就再导出一份、再导一遍。

## 2. 用户看到的样子

游戏娱乐页头上「导入记录」（在「添加记录」旁边）→ 弹窗：

1. 一段说明：「选一份本地 CSV（游戏名 / 时长 / 日期 / 备注 四列，列名认得常见的几种）。
   **不会联网**；重复导入同一份会重复记账，导入前会先给你看一眼。」
2. 一个「选择文件」按钮（`<input type="file" accept=".csv,text/csv">`，浏览器本地读）。
3. 选完立刻给**解析预览**：
   - `认出来 12 行 · 跳过 2 行（第 5、9 行：没写游戏名 / 时长认不出）`；
   - 一个表格预览前 5 行：游戏名 / 日期 / 时长（换算成「1 小时 30 分钟」） / 备注；
   - 和现有记录重了的：`其中 3 行和现有记录一模一样（同游戏 + 同日期 + 同时长），会跳过`；
   - 一行都认不出来时，把最可能的毛病说出来（比如「没找到时长那一列」）。
4. 「导入 N 条」按钮（N = 0 时是灰的）。导完 toast + 重画 —— 统计、TOP 排行、
   图表、搜索**自动都跟着变**（因为写的就是现有那张 `gameRecords` 表）。

## 3. 数据落点：现有 `gameRecords`

一条导入的记录和「手动记一条游玩记录」**形状完全一样**：

```jsonc
{ "id": "…", "gameId": "g1", "gameName": "只狼", "playDate": "2026-10-14",
  "durationMin": 90, "remark": "", "tags": [], "imagePaths": [], "createAt": "…" }
```

- `gameId` 用现成的 `linkGameId(名字, 清单)` 按名字绑 —— 名字和游戏清单里某款对得上就绑上，
  统计里就归到那款游戏头上；对不上就是「没绑清单的临时记录」（现有逻辑照旧认）。
- 所以**不用改服务端、不用迁移**：字段和表都是现成的。
- 截图那一栏留空（CSV 里没有图），要补图回头在记录上编辑。

## 4. 解析：两个纯函数

### 4.1 `csv.js` 加一个「读」：`parseCsvText(text)`

现有的 `csvCell` / `csvText` 是**写**；导入要**读**，对称地加一个：

- 认逗号 / 分号 / 制表符分隔（各家导出的不一样）；
- 处理**带引号的格子**（里面的逗号、换行、翻倍的双引号）；
- 认 CRLF / LF，开头有 UTF-8 **BOM** 就吃掉；
- 空行丢掉；返回二维数组（`string[][]`）。纯函数，可单测。

### 4.2 `game-calc.js` 加 `parsePlayCsv(text)`

把上面的二维数组认成「一条条游玩记录」，容错优先：

| 列 | 认得出这些写法 |
| --- | --- |
| 游戏名 | `游戏名` / `名称` / `Game` / `Title` / `Game Name` / `游戏` |
| 时长 | `时长` / `游玩时长` / `Time` / `Playtime` / `Minutes` / `Duration` / `Hours` |
| 日期 | `日期` / `游玩日期` / `Date` / `Play Date` / `开始日期` |
| 备注 | `备注` / `Note` / `Comment` / `Remark` / `说明` |

- 表头行**按名字认**；一个都对不上时按**位置兜底**（游戏名 / 时长 / 日期 / 备注 四列的顺序），
  并在返回值里标出「按位置认的」。
- **时长怎么读**：`1:30` / `01:30:00`（时:分[:秒]）、`12.5h` / `12.5 小时` / `1.5 hrs`、
  `90m` / `90 分钟`、纯数字按**分钟**算（本 App 那格默认单位就是分钟）。
  换算结果在预览里显示成人话，所以猜错了当场看得见。
- **日期怎么读**：`2026-10-14` / `2026/10/14` / `2026年10月14日` / `2026.10.14`；
  认不出（或者空着）就留空 —— 没日期的记录只算进「累计」，不会算错某一周。
- **跳过哪些行**：没游戏名的、时长认不出的、表头行自己。
  返回值把这些行连原因一起给出来（`{ line: 5, why: "没写游戏名" }`）。
- 返回 `{ rows, skipped, headerBy }`：
  - `rows`: `{ gameName, playDate, durationMin, remark }`；
  - `skipped`: 跳过的行（行号 + 原因）；
  - `headerBy`: `"name" | "position"`（表头是认出来的还是按位置兜底的）。

### 4.3 去重：`dupeOf(rows, existing)`

同一份导出导两遍会记两遍账，所以导入前拿现有记录比一遍：
**同游戏名 + 同日期 + 同时长**就算重复，会自动跳过（预览里报出「其中 N 行会跳过」）。
（按游戏名比而不是 `gameId`，因为清单名字可能改过。）

## 5. 明确不做

- **联网版**：拉接口、登录、定时同步 —— 一条都不做（第 1 节）。
- 不做「自动更新 / 增量同步」：导入就是一次性动作，导完不会记得你导过什么。
- 不做游戏名映射表（名字对不上就是新的一款记法，靠 `linkGameId` 按名字绑，
  绑不上就当临时记录 —— 和手动记一条的表现一致）。
- 不做 Excel（`.xlsx`）解析：零依赖手写 xlsx 不划算，CSV 够用（Excel 另存为 CSV 即可）。
- 不导入截图 / 成就 / 总时长快照：CSV 里没有，硬凑会引入假数据。

## 7. 需要拍板的几件事

1. **纯数字时长按「分钟」算**（我按这个写）；备选是弹窗里加一个「纯数字按分钟 / 小时」的选择。
2. **去重按「同游戏名 + 同日期 + 同时长」自动跳过**（我按这个写）；备选是不去重（由用户自己看着办）。
3. **列名认不出时按位置兜底**（我按这个写，并在预览里说明）；备选是直接报错让人改表头。
4. 入口放在游戏娱乐页头上（「添加记录」旁边）。

## 8. 实施顺序

3. 导入弹窗（预览 + 确认 + 落库）+ 样式；真浏览器回归 `tests\游戏导入回归.test.mjs`（先写）。

## 9. 执行时和设计不同的地方（边做边记）

1. **时长换算没有复用 `toMinutes`**：设计里写「复用现成的 `toMinutes` / `hoursOf`」，
   实际另写了 `parseDurationText`。原因是 `toMinutes(amount, unit)` 的「单位」是**另一个参数**
   （表单里是「数字 + 下拉」两格），而 CSV 一格里的单位是**跟在数字后面**的（`12.5h`），
   签名对不上、硬套会变成「先猜单位再调 toMinutes」，比直接写还绕。
   **显示**那一半仍然是共用的：预览里的时长走 `durationText`（`750` → `12 小时 30 分钟`），
   没有第二套「怎么显示时长」。
2. **Task 1 与 Task 2 合成一个提交**：`parseCsvText` 和 `parsePlayCsv` 一起才是一条完整能力，
   中间那个提交单看没意义（`parseCsvText` 除了 `parsePlayCsv` 没有别的调用方）；
   `dupeOf` 也跟着这一个提交走。
3. **多了一件设计里没写的事：编码兜底**。读文件先按 UTF-8 解，解不动退回 GBK。
   起因是中文 Windows 上 Excel「另存为 CSV」出来的是 GBK，按 UTF-8 解会整份乱码 ——
   而乱码在预览里看着像**解析器写坏了**，用户根本想不到是编码的事。
4. **按钮的状态**：设计只说「N = 0 时是灰的」；实现顺带让「还没选文件」也是灰的，
   并且点灰按钮**不写库、也不关弹窗** —— 让人还能看着预览知道为什么一条都导不了。
   文案上「不会联网」改成和全站一致的**「全程不联网」**。
5. **测试里踩的一个小坑**（和被测逻辑无关，但下次写断言会省一次返工）：
   统计那格是 `<div class="gm-stat">` 里套 `<span>本月</span>`，`textContent` 前面带着
   模板串的换行和缩进，所以 `startsWith("本月")` 找不到它 —— 断言改成 `includes` 并 `trim()`。

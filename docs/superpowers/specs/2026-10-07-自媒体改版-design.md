# 自媒体模块改版设计（账号 + 数据 + 排期）

2026-10-07。本文说「这一次改什么、数据怎么存、数字怎么算」，不写实施步骤
（步骤见 `docs/superpowers/plans/2026-10-07-自媒体改版.md`）。定稿后按本文动代码。

## 0. 背景与这次的范围

用户给了两版需求稿，核心诉求是：现在的自媒体页只是「选题待办」，**看不出运营成果**
——没有账号体系、没有粉丝/播放/点赞数据、没有成长曲线、没有内容状态流水线。

**这次做：**

1. 多平台账号管理（新增/编辑/删除，独立存储，删账号不删作品）
2. 账号总览卡片（当前粉丝、本周涨粉、总播放、待发布、活跃度、hover 详情）
3. 数据概览面板（汇总指标 + 近 30 天趋势图 + TOP3 爆款，可折叠）
4. 月历增强（平台筛选、平台色圆点、格子内标题短预览、已发布删除线）
5. 作品流水线（想法 → 撰写中 → 剪辑中 → 待发布 → 已发布，另有「废弃」归档）
6. 作品数据字段（浏览/播放、点赞、评论、收藏、单作品涨粉、链接、备注）
7. 悬停/汇总口径统一（爆款识别、账号活跃度、本周 vs 上周环比）
8. 拖拽排期（作品卡拖到日历格子 → 填计划发布日期）与列表内拖拽排序
9. 首页自媒体卡片改版（总粉 / 本周涨粉 / 总播放 / 待发布 / 本周已发）

**这次不做（P2，留位置）：** 作品数据导出、素材关联笔记模块、首页「待发布」提醒。
浏览器关闭后无法可靠提醒，这是「纯本地页面」的硬限制，全站一致。

## 1. 已定的决定（逐条有出处）

| 决定 | 选择 | 为什么 |
| --- | --- | --- |
| 数据放哪 | 新增两个顶层键 `mediaAccounts` / `mediaFollowers`，`contents` 原样保留、不搬进 `media{}` | 「开发工作」就是 `projects` / `issues` / `progress` 三个平级顶层键；`contents` 被日历、搜索、首页、服务端、自检、演示数据六处引用，搬家只换来迁移风险 |
| 粉丝口径 | **快照 + 作品涨粉**：当前粉丝 = 最近快照 + 之后发布作品的涨粉；没有快照就用「初始粉丝 + 所有作品涨粉」 | 若在账号上直接存一个数字再往上加，手动改一次就把作品统计冲掉；差额法让手动校正和自动累加永不打架 |
| 手动改粉丝 | 在账号卡片上改「当前粉丝量」时，自动写一条**今天的快照** | 用户只想改个数字，不该被迫理解内部结构；写快照顺便让趋势曲线有了真实锚点 |
| 趋势图 | 手写 SVG 折线，近 30 天，两个指标页签（粉丝 / 累计播放） | 项目零外链零框架，记账的环形图已经走了这条路 |
| 平台图标 | **首字色块**（B / 红 / 抖 / 公 / 知）+ 低饱和平台色 | 零外链没有各平台 logo；自绘品牌标志既有版权问题，四套皮肤下也不统一 |
| 页面顺序 | 账号卡片 → 数据概览（含趋势、TOP3）→ 月历 → 当天排期 → 作品列表 | 没账号时汇总全是 0，先看到「还没有账号，点右上角账号管理添加」更自然 |
| 两个看板 | 需求稿里「顶部运营总览」和「数据统计看板」是同一批数字，**合并成一张**可折叠的「数据概览」卡 | 同一屏出现两组「总粉丝 / 总浏览」互相削弱可信度 |
| 状态命名 | 老数据「写作中」由服务端迁移成「撰写中」 | 新流程要跟「剪辑中」对齐；老数据里只有这一个词会撞 |
| 编辑作品 | 行内编辑改成**弹窗表单**（复用 `openDialog`） | 字段从 6 个涨到 13 个，行内塞不下；需求稿也要求「弹窗内字段下方提示」 |
| 拖拽排期 | 用浏览器**原生拖拽**（列表行 `draggable`，格子/当天卡收 `drop`）；不做列表内排序 | 实测 SortableJS 在这种「小格子密排 + 悬停即插入」的场景里落点不可控（见 §6）；列表又始终按时间排序，拖出来的顺序会被排回去 |

## 2. 数据模型

`数据.json` 顶层新增两个键，`contents` 扩字段（老字段一个不动）。

```json
"mediaAccounts": [
  {
    "id": "…",
    "name": "B站小李",
    "platform": "B站",
    "intro": "记录一个人做产品",
    "baseFollowers": 1200,
    "targetFollowers": 5000,
    "note": "",
    "createdAt": "2026-10-07 12:00"
  }
],
"mediaFollowers": [
  { "id": "…", "accountId": "…", "date": "2026-10-07", "count": 12689 }
],
"contents": [
  {
    "id": "…",
    "title": "十月复盘",
    "accountId": "…",
    "platform": "小红书",
    "status": "待发布",
    "planDate": "2026-10-10",
    "publishDate": "",
    "link": "",
    "views": 0,
    "likes": 0,
    "comments": 0,
    "collects": 0,
    "fansGain": 0,
    "note": "",
    "createdAt": "2026-10-07 12:00"
  }
]
```

约定：

- **`platform` 是固定清单里的一个词**：`B站 / 小红书 / 抖音 / 公众号 / 知乎 / 视频号 / 其他`。
  （保留「视频号」是为了让老数据的自由文本不至于全变成「其他」。）
- **`accountId` 是绑定关系**，`platform` 是这份绑定的快照。作品卡片优先按 `accountId`
  找账号；账号被删了就退回按 `platform` 文本匹配 + 显示「账号已删」。
- **`mediaFollowers` 是快照表**，同一账号同一天只留一条（再记就覆盖那一天）。
- 数字字段统一是**整数**，缺省当 0；允许用户只填一部分（比如只填播放）。
- **删账号不删作品**：作品的 `accountId` 留着，界面显示「账号已删」。
- `id` 一律用 `uid()`；`createdAt` 用本地时间文本（不要 `toISOString`，那是 UTC）。

**老数据兼容**：`contents` 里没有 `accountId` / 数据字段的记录照常显示，
只在需要的地方给默认值（缺字段当 0、缺账号显示平台名）。

## 3. 算法（`app/web/media-calc.js`，纯函数、无依赖）

这个文件是本次改动的算账中心，全部是纯函数，用 Node 直接跑
`tests/自媒体计算.test.mjs`，不用开浏览器。**别的文件不许再自己算这些数**。

### 3.1 数字显示

```js
fmtCount(326)      -> "326"
fmtCount(6200)     -> "6.2k"      // 千元位：保留一位，截断
fmtCount(486000)   -> "48.6w"     // 万位：保留一位，截断
fmtCount(12689)    -> "1.26w"     // 万位、不足 10w 时给两位
```

截断不四舍五入：涨粉、播放都是「有多少说多少」，宁少不多。

### 3.2 粉丝：快照 + 作品涨粉

```js
// 截至 date（含）这天，这个账号有多少粉
followersAt(account, contents, snapshots, date)
  = 最近一条 date <= 那天 的快照值
    + 该快照之后（publishDate > 快照日期）发布作品的 fansGain 之和
  // 没有快照时：account.baseFollowers + 该账号所有已发布作品的 fansGain
```

「快照之后」用**严格大于**：作品和快照同一天时算快照已经包含它，避免同一天算两遍。

### 3.3 趋势

```js
followersSeries(account, contents, snapshots, today, days) // [{ date, value }]
viewsSeries(account, contents, today, days)                 // 累计播放，同构
```

粉丝曲线逐日调 `followersAt`；播放曲线是「截至那天的已发布作品的 `views` 之和」
（累计值，不是当日增量）。两条线都只画 `days` 天，日期用本地日期推，不走 UTC。

### 3.4 汇总与环比

```js
weekRangeOf(today) -> { start, end, prevStart, prevEnd }   // 周一为一周的开头
followersGain(account, contents, snapshots, from, to)      // 区间涨粉
weekGain = followersAt(today) - followersAt(weekStart 的前一天)
lastWeekGain = followersAt(weekStart-1) - followersAt(prevWeekStart-1)
growthText(weekGain, lastWeekGain) -> { text: "+326", tip: "比上周多 12%" }
```

没有上周数据时说「上周没有记录」，不编一个百分比出来。

### 3.5 爆款与活跃度

```js
isHit(views, avgViews) -> null | "small" | "big"   // ≥2 倍小爆款、≥3 倍大爆款
```

分母是**同账号已发布作品的平均播放**（只算填了播放的），作品不足 3 条或平均为 0
时不评爆款——样本太少，标了也没意义。

```js
activityOf(account, contents, today)
  -> { level: "none"|"hot"|"ok"|"slow"|"stalled", text: "高频更新"… }
```

按最近一次发布距今天数：≤7 天高频、≤14 天正常、≤30 天轻微断更、>30 天严重停更；
一条都没发过是「新号」。

### 3.6 汇总看板

```js
overviewOf(data, today) -> {
  accounts, totalFollowers, totalViews, totalLikes, totalCollects,
  weekGain, lastWeekGain, weekViews, monthPublished, hitCount,
  top: [{ id, title, views, platform, mult }]   // 按播放取前 3
}
```

全部按「所有账号 + 未绑定账号的作品」汇总——没建账号但录了作品的人也要能看到数。

## 4. 页面结构（`#media`，从上到下）

```
页头：自媒体 ｜ 选题到发布的内容流水          [⚙ 账号管理]

① 账号卡片横排（横向滚动）
   首字色块 + 账号名 + 平台
   当前粉丝 ｜ 本周 +326   ·   总播放 48.6w   ·   待发布 3 条
   hover：最近更新日期、目标粉丝进度
   点卡片 → #media/<accountId>（列表按这个账号筛）
   空状态：还没有自媒体账号，点右上角账号管理添加

② 数据概览（可折叠，默认展开）
   汇总：[累计粉丝] [累计播放] [点赞+收藏] [本周涨粉 + 环比] [本月发布] [爆款]
   趋势图：〔粉丝〕〔播放〕两个页签，近 30 天折线 + 渐变填充
   TOP3 爆款：标题 + 平台 + 播放 + 倍率，点开看详情

③ 月度日历（共用零件）
   工具条：‹ 年月 ›  回到今天   〔平台筛选 ▾〕
   格子：日期 + 平台色圆点 + 最多 2 条标题预览（6 字截断，已发布带删除线）

④ 选中日期排期卡（保留原有逻辑）
   当天的计划/发布作品列表 + 「今天排一条」快速输入

⑤ 选题 & 作品列表
   快速添加行：标题 + 账号 + 状态 + 计划日期 + 添加
   筛选项：账号/平台、状态、排序（计划时间 / 创建时间）
   五条状态流水线（想法 / 撰写中 / 剪辑中 / 待发布 / 已发布）+ 已废弃折叠区
   每条：标题 + 平台标签 + 状态标签 + 计划/实际时间 + 数据（播放/点赞/涨粉）
        + 爆款标记 + 操作（编辑 / 删除 / 废弃 / 恢复）
```

### 4.1 空状态文案（照需求稿）

- 没有账号：还没有自媒体账号，点右上角账号管理添加
- 没有作品：还没有选题，把想到的选题先记录下来
- 筛选后没结果：当前筛选条件下没有内容，更换筛选条件试试

## 5. 两个弹窗

**账号弹窗**（`openDialog`，新增/编辑复用）：账号名称（必填）、平台（下拉）、账号简介、
初始粉丝量、目标粉丝量、备注；编辑时多一个「删除」（二次确认，走回收站）。

**作品弹窗**（`openDialog`，新增/编辑复用）：标题（必填）、账号、状态、计划发布日期、
实际发布日期、作品链接、浏览/播放、点赞、评论、收藏、单作品涨粉、备注。

- 状态不是「已发布」时，实际发布日期 / 链接 / 五个数据字段**禁用**并提示
  「标记为已发布后可填」；改成「已发布」后立刻解锁（同一个弹窗里切换，不重开）。
- 校验失败在**字段下方**提示（`fin-err` 那套样式），不弹浮层。
- 保存后 `touch(true)` 落盘，日历和列表立刻重画。

## 6. 日历增强与拖拽

- 平台筛选只影响**显示**（圆点、预览文字、当天排期卡），不改数据。
- `calendar.js` 的 `dayExtraOf` 加一个可选字段：`lines[].strike`（已发布 → 删除线）。
  只加这一个字段，别的页面不传就完全和现在一样。
- 平台色圆点复用现成的 `mk-*` 机制，媒体页传 `kind` 为 `plat-<平台拼音>`。
- **拖拽排期**用浏览器原生拖拽：列表行 `draggable`，`dragstart` 把作品 id 记在
  模块变量和 `body.dataset` 上（`dataTransfer` 在「拖的是选中的文字」时会被换掉），
  落点（每个 `.cal-cell` 的 `data-day`、当天卡的 `data-drop-day`）在 `dragover`
  时 `preventDefault()` + 高亮，在 `drop` 时写 `planDate` 并重画。
- **实测过的坑**：项目卡片那套 SortableJS 是「指针一进格子就先把卡片塞进去」，
  日历格子又小又密（一次 42 个实例），落错天之后立刻重画、连改都改不了；
  而且列表和日历隔了大半屏，它的自动滚动在这种场景下不稳。所以这里不用它。
  同一个原因，**列表内拖拽排序也没做**——列表始终按「计划时间 / 创建时间」排序，
  拖出来的顺序下一次重画就被排回去，等于骗人；想换顺序用「排序方式」下拉。

## 9. 视觉规范（四套皮肤 × 明暗都不能破相）

- 一律走 CSS 变量（`--ink` / `--muted` / `--chip` / `--divider` / `--accent` / `--ok` / `--err` / `--warn`），
  圆角用 `--r-lg` / `--r-md` / `--r-sm`，阴影用 `--shadow` / `--shadow-lift`。
- 平台色是**内容色**（跟月历圆点 `mk-*` 同一性质），允许写死低饱和 hex：
  B站 `#4a90c4`、小红书 `#d9705a`、抖音 `#3c3c46`、公众号 `#4a9d7f`、
  知乎 `#5b6bd6`、视频号 `#c98a3c`、其他 `#94a3b8`。
- 状态标签：想法灰、撰写中蓝、剪辑中紫、待发布橙、已发布绿、废弃灰（划掉）。
- 爆款：暖色光晕 + 金色小标签；涨粉绿、掉粉红，箭头 `↑` `↓`。
- 数字用 `font-variant-numeric: tabular-nums`，大号加粗。

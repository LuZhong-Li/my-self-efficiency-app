## 1. 现状与缺口

2026-10-14 那轮做了「自媒体素材库」：`mediaAssets` 一张表、两种类型（图片 / 链接）、
挂在自媒体的「素材」子页上，引用关系存在作品那一侧（`contents[].assetIds`），
素材行上写着「用在 N 条作品上」。零件是齐的，问题在**范围**：

- 只有**作品**能引用素材，别的模块（记账、bug、待办、学习、健身、游戏、笔记）想挂
  一张参考图 / 一段常用文字，只能各自再传一份；
- 「用在几条作品上」这个数只数了作品，素材是不是别处也在用看不出来；
- 素材类型只有图片和链接，**一小段常用文字**（脚本模板、常用话术、一段代码）没地方放。

## 2. 数据：搬到顶层 `assets`，加一种类型

### 2.1 新家

顶层新表 `data.assets`（和 `tasks` / `notes` 一个层级），一条长这样：

```jsonc
{
  "id": "a-1",
  "title": "封面参考",
  "kind": "image",          // image | link | text
  "path": "attachments/media_asset/20261014_a1b2.png",  // 只有 image 有
  "url": "",                // 只有 link 有（一段文本，App 绝不访问它）
  "text": "",               // 只有 text 有（一小段常用文字）
  "note": "在哪找的、给谁看的",
  "tags": ["封面"],
  "createdAt": "2026-10-14T21:00:00.000Z"
}
```

### 2.2 老数据怎么搬（只补不改）

`mediaAssets` 那张表**退休**，但老数据一个字节都不能丢：

- 读的时候（`服务.py` 的 `normalize_data`）：把 `mediaAssets` 里每条**按原 id** 并进
  `assets`（`assets` 里已经有同 id 的就以 `assets` 那份为准），然后把 `mediaAssets` 清空。
  下次落盘之后，数据文件里就只剩 `assets` 了 —— 迁移是「搬家」，不是「改内容」。
- `contents[].assetIds` 里存的 id **原样不动**（id 没变，引用自然还成立）。
- 各表补一个 `assetIds: []`（能挂素材的那几张：见 3.2 的清单），老记录补空数组。

## 3. 纯逻辑：`app/web/asset-calc.js`（新）

素材现在是全站的东西了，再放在 `media-calc.js`（自媒体那个模块的纯逻辑）里名不副实。
把现有那四个函数**搬**到新文件，`media-calc.js` 那儿只留一行转出 ——
`media.js` 和 `tests\自媒体素材.test.mjs` / `tests\自媒体计算.test.mjs` 一个字都不用改
（和前面搬 `lastMonths` / 时长函数一个做法）。

| 函数 | 干什么 | 从哪来 |
| --- | --- | --- |
| `normalizeAsset(row)` | 补齐一条素材的形状（三种类型都认） | 新 |
| `assetsOf(data)` | 读出全部素材（**顶层 `assets` 为准**，老的 `mediaAssets` 也认） | 搬 + 改 |
| `assetUsage(data)` | 每条素材**被全站几处引用**（跨表数，同一处写两遍算一次） | 搬 + 改（原来只数作品） |
| `assetsOfRow(row, assets)` | 一条记录引用的那几份素材（原样按 id 查） | 搬 + 改名（原 `assetsOfContent`） |
| `unlinkAsset(data, assetId)` | 从**所有**表里摘掉这条素材的引用（删素材时用） | 搬 + 改（原来只摘作品） |
| `ASSET_TABLES` | 允许挂素材的表清单（引用计数与摘引用都照它走） | 新 |

`ASSET_TABLES`（表名 + 页面上叫什么，报「被 N 处引用」时用）：

```js
export const ASSET_TABLES = [
  ["contents", "作品"],
  ["tasks", "待办"],
  ["issues", "问题"],
  ["projects", "项目"],
  ["studies", "学习记录"],
  ["subjects", "学习对象"],
  ["workoutLogs", "训练打卡"],
  ["gameRecords", "游玩记录"],
  ["notes", "笔记"],
  ["finance.transactions", "账目"],
];
```

（`finance.transactions` 是记账那种「带点的路径」，取表用现成的 `readTable` 那套逻辑。）

## 4. 界面上怎么「引用」

### 4.1 通用素材选择器（新字段 `kind: "assets"`）

`item-form.js` 加一种字段控件 `assets`：一块可勾选的素材清单（图片给缩略图、
链接给小图标、文本片段给前面几十个字），每份一行一个勾选框；头上一个
「＋ 新建素材」（**叠开**素材弹窗，建完回来就能勾）；下面一行说明
「记录里只存素材 id，不重复存图片」。

读值 / 写回还是走表单那一套：**一条隐藏 input 里存 id 数组的 JSON**
（和子任务那个控件一个路子），`valuesOf` / `readValues` / `applyValues` /
`validate` 各加一处 —— 页面上不用管它是怎么存的。

### 4.2 挂到哪些地方

| 地方 | 怎么挂 |
| --- | --- |
| 今日计划 / 开发待办 / 学习记录 / 学习对象 / 训练打卡 / 游玩记录 / 项目 | 字段表里加一格 `{ name: "assetIds", kind: "assets" }`（七处，都是声明式一行） |
| 记账「记一笔」 | 弹窗是手写的，单独加一块素材区（照作品弹窗那套） |
| 笔记 | 就地编辑器里加一块「素材」（列着已挂的 + 一个「＋ 挑素材」） |

### 4.3 素材库页（还是 `#media/assets`）

保留在自媒体下面（它是从那儿长出来的，也省得多开一个模块），页头改叫
**「素材库」**并写一句「全应用共用」；三种类型都能建、能改、能删；
每行那句从「用在 N 条作品上」改成 **「被 N 处引用」**（跨表算，
鼠标移上去能看到分别是什么）。

## 5. 搜索

搜索池里 `mediaAssets` 那条改成 `assets`，匹配标题 / 说明 / 链接 /
**文本片段的正文**；点结果还是回 `#media/assets`。

## 6. 明确不做

- **不做行上的「素材 N」标记**（今日计划、首页、项目详情、记账… 八处渲染都要改），
  这一轮只在弹窗里看和改；真觉得需要，下一轮统一加。
- 不做「把文本片段的字面插进备注框」（那要处理光标位置，是另一种交互）；
  这一轮素材统一按**引用**理解：记录上挂 id，要看点开弹窗或去素材库。
- 素材**不会**自动跟着记录一起删（删记录不动素材），反过来删素材会从各处摘掉引用
  （和自媒体素材那一轮一个口径）。
- 不做素材分类 / 文件夹 / 批量导入。

## 7. 测试

- 新增 `tests\素材计算.test.mjs`（纯逻辑）：`normalizeAsset` 三种类型补形状、
  `assetsOf` 认顶层 `assets` 也认老的 `mediaAssets`、`assetUsage` 跨表数（同一处写两遍算一次、
  认不出的 id 不算）、`assetsOfRow` 按 id 取、`unlinkAsset` 从所有表里摘、

- 新增真浏览器回归 `tests\素材全站.test.mjs`：素材库加一份**文本片段** →

  回素材库看那句「被 1 处引用」→ 删素材 → 那条任务的 `assetIds` 被摘干净。
- 已有的：`tests\自媒体素材.test.mjs` 一个字不改就得继续绿（验证搬家的那四个函数没走味）；

  各表补 `assetIds: []`）；`tests\搜索.test.mjs` 那条 spec 的断言跟着改。

## 8. 需要拍板的几件事

1. **素材库页留在 `#media/assets`**（我按这个写）；备选是提成第 12 个顶层模块
   （入口更好找，但模块已经 11 个了）。
2. **文本片段按「引用」用**（我按这个写，记录上存 id）；备选是「插入字面文字」
   （要处理光标，见第 6 节）。
3. **删记录不动素材、删素材摘引用**（我按这个写，和自媒体那一轮一个口径）；
   备选是双向都不自动动（那会留一堆找不到的引用）。
4. 记账和笔记这两处**手写弹窗**也一起接（我按这个写）；嫌多可以先只给七处声明式字段挂上。

## 10. 执行时和设计不同的地方（边做边记）

1. **计划里说「`media-calc.js` 和它的测试一个字都不用改」不成立**：`assetsOf` /
   `assetsOfContent` 确实能转出（签名没变），但 `assetUsage` 的入参从
   「(素材数组, 作品数组)」变成「整份 data」、返回从 `{ id: 条数 }` 变成
   `{ id: { total, byTable } }`，`unlinkAsset` 从「返回新数组」变成
   「原地摘掉、返回摘了几处」—— 这两个接口是**故意改的**（要跨表），所以
   `media.js` 的两处调用点跟着改了，`tests\自媒体计算.test.mjs` 里那段素材断言
   也交接给了 `tests\素材计算.test.mjs`（那边测得更全）。
2. **先只做七处声明式字段**（记账弹窗与笔记编辑器两处手写挂载点留到下一轮），
   理由见实施计划里那条说明。
3. **一个已有的偶发**：`tests\弹窗栈.test.mjs` 在「连着跑很多浏览器测试」时会偶发
   两条失败（删掉的那条待办没落盘 / 没进回收站），单独跑和多数全量跑都是绿的。
   它和这一轮改动无关（没碰过那条链路），但记在这儿：
   下次修的时候先看那个 `for (let i = 0; i < 40; i += 1)` 的轮询循环是不是被
   前面的步骤拖到超时，以及 `store.conflict` 有没有被误置。
4. **真浏览器回归当场抓到两个纯逻辑测不到的 bug**（都记在这儿，回头写类似的「加一种枚举值」
   改动时先想一遍）：
   ① 素材弹窗切类型那一段把 kind 夹成了「link 或 image」——
   `kind = btn.dataset.kind === "link" ? "link" : "image"`，于是点了「文本片段」仍然渲染成图片那档，
   `#asset-text` 根本不存在、保存时读到 null；
   ② 改完 ① 之后还是红：`media.js` 里用了 `ASSET_KINDS` 却没 import 它，
   点击监听里抛 ReferenceError，界面表现是「点了没反应」（`ev()` 不会报错，只有页面错误列表里能看到）。
   两个都是「加一种枚举值」时最容易漏的：**枚举的每一处（渲染、判断、导入）都要一起改**。

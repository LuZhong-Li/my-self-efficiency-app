## 1. 为什么是这个做法

原方案（账号 + 密码 + 权限 + 数据隔离）和本 App 的定位直接冲突：**单机自用、没有登录**。
自用场景里加一层密码只是给自己添麻烦（安全本来就靠本地文件的权限）。

所以改成**多套数据文件**：一个数据集 = 一个文件夹，里面就是今天这一整套
（`数据.json` + `attachments\` + `备份\` + `日志\` + `导出\`）；
设置页一个下拉/列表，点一下就换用哪一份。

**同一时间只加载一份**，不做并行 —— 正好回避「两个窗口各拿一份、互相覆盖」那个老坑。

## 2. 用户看到的样子

设置页「数据放在哪」上面多一张卡片「数据集」：

```
数据集
  现在在用：默认
  ● 默认                         128 条 · 10-14 15:30   [在用]
    工作                          12 条 · 10-12 09:10   [用这份] [重命名] [导出]
  [新建数据集] [打开数据文件夹]
  一份数据一个文件夹，整份能搬走；同一时间只用一份，切换后页面会重载。
```

- 点「用这份」→ 确认框（写着「先把你现在的改动存下来，再整页重载成那一份」）→
  切换成功就 `location.reload()`。
- 「新建数据集」→ 小弹窗填名字（当场校验，见第 7 节）→ **建好不自动切过去**，
  列表里出现，你自己点「用这份」。
- 「重命名」→ 改文件夹名（当前在用的那份也能改；改完页面重载，因为状态栏和
  `health` 里的路径都变了）。
- 「导出」→ 打包成 zip，落在**你现在这份**的 `导出\` 里（「打开导出文件夹」按钮
  开的就是这个文件夹），zip 里是 `数据.json` + 图片附件那一整套。
- 状态栏那行也带上数据集名字：`数据集「工作」 · D:\…\数据\工作\数据.json` ——
  一眼看出自己正在改哪一份，这是这套功能里最要紧的一句提示。

## 3. 数据布局

```
数据\                        ← 数据根目录（新环境变量 XIAOLI_DATA_ROOT，默认就是这儿）
  当前数据集.txt             ← 就一行：现在用哪一份
  默认\                      ← 一个数据集 = 一个子文件夹，内部结构和一个字都没变
    数据.json   attachments\   备份\   日志\   导出\   数据.lock
  工作\
    数据.json   attachments\   备份\   日志\   导出\   数据.lock
```

### 3.1 老数据自动搬迁（一次性）

启动时（数据集功能开着的时候）看一眼根目录：

- `<根>\默认\数据.json` 已经在了 → 什么都不做。
- `<根>\数据.json` 不在 → 什么都不做（全新的一份，`默认\` 到时候按需建）。
- 两个条件都满足老布局 → 把根目录下**除了 `默认\` 之外的每一样**（`数据.json`、
  `attachments\`、`备份\`、`日志\`、`导出\`、`数据.lock`、`.演示数据` 这些）
  逐个搬进 `<根>\默认\`，顺手把 `当前数据集.txt` 写成 `默认`。

几条讲究：

- **同一盘内搬，是改名不是复制**，所以再大的图片附件也是秒完，不会多占一份空间。
- **内容一个字都不动**：不读、不改、不重新序列化，就是把文件/文件夹挪个位置。
  搬完 `数据.json` 的修改时间、rev、里面的每一项都和搬之前一样。
- **可回退**：一样一样地搬，中途失败也不会丢东西（没搬完的那些还在原地）；
  控制台和 `日志\运行.log` 各留一句「搬了哪几样」，想还原就照那句搬回去。
- 只在**启动时**做，不在切换时做 —— 迁移是启动路径上的事，切换路径上只认文件夹。

### 3.2 `当前数据集.txt` 为什么是纯文本

它是「读数据之前就得先知道」的那个信息，所以只能放在数据集**外面**。写成纯文本是因为：
它坏得起（读不到、写坏了、被手改成一个不存在的名字 → 一律兜回 `默认`），
也改得动（拿记事本打开就知道现在是哪一份）。换成 JSON 只会多一层解析失败的可能。

## 4. 服务端：一组路径常量变成「按当前数据集算」

今天 `DATA_DIR` / `DATA_FILE` / `BACKUP_DIR` / `EXPORT_DIR` / `LOG_DIR` / `LOG_FILE` /
`PREV_FILE` / `LOCK_FILE` / `ATTACH_DIR` 九个常量在导入时就从 `XIAOLI_DATA_DIR`
定死了，`save_data`、`load_data`、附件、备份这些地方全都是**用的时候现读**（这点很关键，
不用把它们全改成传参）。所以只要**换掉这九个全局**，整套服务就跟着换过去了。

做法是收成两个函数，启动和切换共用一条代码路径：

```python
ENV_DIR = os.environ.get("XIAOLI_DATA_DIR")        # 老变量：就是「这一份」
DATA_ROOT = os.environ.get("XIAOLI_DATA_ROOT") or os.path.join(BASE_DIR, "数据")
DATASETS_ENABLED = not ENV_DIR                     # 老变量在 → 数据集功能关掉

def derive_paths(data_dir: str) -> None:
    """九个路径全按这个目录算。启动和切换都走它，不给漏项留缝 ——
    换了一半（数据文件换了、附件目录没换）是最难查的那种错。"""

def link_dataset(name: str) -> None:
    """切到某个数据集：先写 当前数据集.txt（权威落盘），再 derive_paths。"""

def switch_dataset(name: str) -> None:
    """运行期切换。拿一次写入锁又立刻放开，等于问一句「此刻没人在写吗」——
    LOCK_FILE 马上就要指向新目录了，不摘掉就会永远留在旧目录里。"""
```

启动时：`DATASETS_ENABLED` 为真 → 迁移 → 读 `当前数据集.txt` → `derive_paths(那份)`；
为假（设了 `XIAOLI_DATA_DIR`）→ `derive_paths(那个目录)`，`当前数据集` 记为 `""`。

### 4.1 接口

| 接口 | 干什么 |
| --- | --- |
| `GET /api/health` | 多报三样：`dataset`（没开就是 `""`）、`dataRoot`、`datasetsEnabled` |
| `GET /api/datasets` | `{ok, enabled, current, root, items:[{name, current, dataFile, rev, bytes, count, counts, updatedAt, mtime}]}` |
| `POST /api/dataset-new` | `{name}` → 建文件夹 + 一份空骨架（`default_data()`），**不切换** |
| `POST /api/dataset-switch` | `{name, rev}` → 切换；`rev` 对不上给 409（见第 5 节） |
| `POST /api/dataset-rename` | `{name, to}` → 改文件夹名；改的是当前那份就顺手切过去 |
| `POST /api/dataset-export` | `{name}` → 打出 zip，落在**当前**数据集的 `导出\` |

列表里的「多少条」直接用现成的 `summarize()`（它本来就在数这几张表），
`count` 取各项之和，`counts` 给明细（悬停提示用）。读**别的**数据集时按原始 JSON 读，
不跑 `migrate()`、不写盘 —— 看一眼列表不该改动别人的数据。

### 4.2 `XIAOLI_DATA_DIR` 在的时候，功能整体关掉

那个变量的语义是「**就是这一份**」，今天 `自检.py`、45 个 `*.test.mjs`、
`演示数据.py` 全靠它。和「根目录」是两个概念，混在一起必然出歧义，所以：

- 设了它 → `datasetsEnabled: false`，`/api/datasets` 返回 `enabled: false` + 空列表；
  前端那张卡片显示一句「这次的数据目录是外面指定的（`XIAOLI_DATA_DIR`），数据集功能关着」
  + 路径 + 「打开数据文件夹」。
- 想用数据集功能又想把数据放别处 → 设 `XIAOLI_DATA_ROOT`（新变量）。

**这条是「现有 45 个测试 + 自检一行都不用改」的原因**：它们全都设了 `XIAOLI_DATA_DIR`，
于是全部落在老语义上，行为和今天一模一样。

## 5. 防串数据（本轮最要紧的一条）

场景：窗口 A 还在数据集 1 上（内存里是数据集 1 的数据，手里拿着它的 rev），
你在设置页把服务切到了数据集 2。这时候 A 再保存一次 ——
**光比 rev 是挡不住的**：两份数据的修订号完全可能正好相等（都是 12），
那样 A 的旧数据就写进数据集 2 了，这是真丢数据。

三道一起上：

1. **保存请求带上「我是哪一份」**：`POST /api/data` 加一个请求头
   `X-XiaoLi-Dataset: <名字>`，服务端和当前数据集一比，对不上直接
   409 `{conflict: true, dataset: 当前}`，一个字都不写。
   - 值要**百分号编码**（前端 `encodeURIComponent`，服务端 `urllib.parse.unquote`）：
     HTTP 头的值只能是 latin-1，中文数据集名直接塞进去，客户端那一侧连请求都发不出来
     （2026-10-14 实现时踩到，`自检.py` 里那条断言当场报的是编码错）。
   - **不带头 = 不校验**：`自检.py`、`冲突保护.test.mjs` 这些直接打接口的地方
     照旧能跑（向后兼容），页面上永远带。
   - 撞上这一条时，页面复用手上现成的冲突弹窗（`conflict.js`），
     换一句话说：「你正在用的数据集已经换成了『工作』，本窗口的改动没有保存」，
     按钮给「重载页面」。
2. **切换要求 rev 对得上**：`/api/dataset-switch` 收 `rev`，和当前数据集比，
   对不上就 409（数据已经变过了，刷新一下再切）。防的是「切走的那一刻，
   另一个窗口正存到一半」。
3. **切完整页重载**：切换成功后本窗口 `location.reload()`，
   内存里不留任何旧数据集的残留（各模块的状态、缓存、填了一半的东西全清掉）。

三层合起来的效果：**任何一处对不上，宁可停下来让人刷新，也绝不覆盖**。
和现有那句「数据层自己绝不替用户决定丢哪一份」是同一个原则。

### 6.2 卡片 `app/web/dataset.js`（新）

`datasetCardHtml()` 出那张卡片的骨架（`#ds-current` / `#ds-list` / `#ds-msg`），
`mountDataset()` 拉 `/api/datasets` 画列表并绑事件。事件钩子（测试也靠它们）：

| 钩子 | 干什么 |
| --- | --- |
| `data-ds-act="use"` + `data-ds-name` | 切过去（确认 → 存盘 → POST → reload） |
| `data-ds-act="new"` | 开小弹窗填名字（`#ds-new-name`，复用 `openDialog`） |
| `data-ds-act="rename"` + `data-ds-name` | 改名字 |
| `data-ds-act="export"` + `data-ds-name` | 打 zip |

卡片里不另设「打开文件夹」按钮：那个按钮本来就在下面「数据放在哪」那张卡片上
（`data-act="open" data-which="data"`，开的就是当前数据集目录），多放一个只会让人分不清。
数据集那张卡片只在文字里写清根目录在哪。

切换那一串按顺序做，任何一步不成就**不切**：

```
确认框（有填了一半的弹窗时，多警告一句）
  → await touch(true)  把改动存下来（撞冲突就停下，先让用户处理）
  → POST /api/dataset-switch {name, rev: store.data.rev}
  → 成功：location.reload()；失败：toast 说原因，留在原地
```

## 7. 数据集名字的规则

名字就是文件夹名，所以规则既要「取不出坏名字」，也要「说得清为什么不行」：

| 规则 | 为什么 |
| --- | --- |
| 去掉首尾空格后 1–24 个字 | 太长的名字在列表里放不下，也容易手输错 |
| 不许含 `\ / : * ? " < > \|` | Windows 文件名里不允许，含了就是建不出来 |
| 不许是 `.` / `..`，不许以 `.` 开头、以点或空格结尾 | 前两个会跑出根目录；后两个 Windows 会悄悄截掉，容易两份撞在一起 |
| 不许是 `CON` / `PRN` / `AUX` / `NUL` / `COM1-9` / `LPT1-9` | Windows 的保留设备名，建不出来 |
| 不许和已有数据集重名 | 两份数据一个名字，就没法区分了；重命名成自己 = 不改 |

首尾空格**自动去掉**（打多了不算错），其余一律拦下并说明原因，不做「悄悄改成合法名」——
悄悄改名字比报错更让人困惑。

## 8. 明确不做

- **账号 / 密码 / 登录 / 权限**：和「单机自用无登录」直接冲突（第 1 节）。
- **并行同时开两份数据**：本轮的模型就是「同一时间只加载一份」，正好避开多窗口覆盖。
- **跨机器同步 / 云盘**：那是另一个东西（要联网），不在这个 App 的定位里。
- **每份数据单独的主题 / 皮肤**：主题存在数据里，天然就跟着数据集走了，不额外做开关。
- **数据集内的子文件夹 / 分组 / 标签**：份数不会多到需要分类，YAGNI。
- **自动按日期归档数据集**：想归档就自己新建一份、把旧的那份留着不动。

3. 新建数据集不自动切过去 —— ✅ 确认。

5. 切换方式 = 运行期换数据目录 + 整页重载 —— ✅ 确认。

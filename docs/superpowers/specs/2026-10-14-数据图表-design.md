## 1. 现状与缺口

先把已经有的数一遍，免得重复劳动：

- **记账已经有**：当月分类环形图（占比 + 图例，能点开某类明细）、近 6 个月柱状趋势图
  （页签切支出 / 收入）、左栏还有一张当月月历（每格画当天支出红 / 收入绿、超支日套红圈）。
- **游戏娱乐只有数字**：今日 / 本周 / 本月 / 全年 / 累计，外加 TOP3 的**列表**和
  「本月超过目标」的一行提醒 —— 一张图都没有。谁玩得多、这段时间是不是比上个月凶，
  只能自己读数字比。
- **记账真正缺的那一张**：月历只看得见一个月，环形图只看得见当月分类，趋势图只看得见总额
  —— 「这半年哪一段花得凶、哪天漏记了」这三张图一张都答不出来。

所以这一轮做三件事：**给游戏补两张图**、**给记账补一张支出日历**、
**把画图的通用部分抽出来**（本来要抄三遍的那点几何与分档）。

## 2. 通用零件：`app/web/chart-calc.js`

为什么单独开一个文件：三张图要的是同一批东西（月份序列、条长比例、柱状几何、热力图分档），
摆在各自的页面里就是抄三遍、还各写各的测试；放进纯逻辑模块，`node tests\图表计算.test.mjs`
能一条条断言（和记账、待办那几个计算模块一个路数）。

它**自带一份本地 `esc`**，理由和 `item-form.js` 那份一样：`store.js` 的 `esc` 会碰 `window`，
纯模块 `import` 不了它；所以拼 HTML 的活放这儿，页面只管把结果塞进 DOM、挂事件。

| 函数 | 干什么 |
| --- | --- |
| `lastMonths(month, count = 6)` | `"2026-10"` 往回数 → `["2026-05" … "2026-10"]`（含当月、升序、跨年接得上）—— **从 `finance-calc.js` 搬过来** |
| `barRatioOf(value, max)` | 条长比例 0..1；`max <= 0` 或 `value <= 0` 一律给 0（不除零、不出负） |
| `barRowsOf(rows, key)` | 给一组 `{ …, [key]: 数字 }` 各补一个 `ratio`（并列第一名都给满格） |
| `trendBars(rows, box)` | 柱状图的几何：`{ width, height, gap, value(row) }` → `{ baseY, chartH, bars: [{ x, w, h, y, ratio, value }] }` |
| `heatGrid(endDate, weeks)` | 近 N 周 × 7 天的格子：按**列**返回（一周一列，周一到周日；最后一列是 `endDate` 那一周），每格 `{ date, inRange }` |
| `heatLevelOf(value, max, levels = 5)` | 金额（分）→ `0 … levels-1` 档；0 元固定 0 档，最大值落最高档，中间单调 |
| `hbarsHtml(rows, opts)` | 横条那一列（整行当背景的条形，见 3.1） |
| `trendChartHtml(rows, opts)` | 柱状图整段 SVG（柱 + 柱顶数字 + 底部月份，当月那根画实一点） |
| `heatmapHtml(cells, opts)` | 热力图整块（CSS grid，颜色分档，每格带悬停说明） |

两处**不重复造**：

- `lastMonths` 从 `finance-calc.js` **搬**过来，`finance-calc.js` 那儿改成
  `export { lastMonths } from "./chart-calc.js";` —— 这样 `tests\记账趋势.test.mjs`
  和 `finance.js` 一个字都不用改。
- 日期小工具借现成的：`weekStartOf` 从 `goal-calc.js` 借（那已经是纯函数，
  没必要再抄第三份），`addDays` 从 `task-calc.js` 借。以后要是把日期小工具收成
  一个 `date-calc.js`，那是另一轮的清理，这一轮不动。

## 3. 游戏娱乐：两张图

### 3.1 TOP 排行加横条

`statsCardHtml` 里那张 TOP3 榜单，每行加一条横条：**条长按第一名**（第一名满格，
其余按比例），铺在整行背景上（`position: absolute` + 低透明度），文字压在条上面。

为什么铺背景、不在标题下面另起一行：榜单一行本来就矮，另起一行会把三行变六行的高度，
而「谁比谁长」这件事，铺成背景一眼就出来了，鼠标移到行上还能看到完整时长（现在是 chip）。

### 3.2 近 6 个月游玩时长（柱状图）

「游玩统计」卡片末尾加一张柱状图：横轴近 6 个月（`lastMonths`），纵轴那个月的总时长。

- 口径走 `game-calc.js` 新加的 `gameMonthTrend(records, months)` → `[{ month, minutes, ratio }]`，
  和上面那排数字（`statsOf`）**同源**，永远对得上。
- 画法照记账那张（手写 SVG，不引库）：柱 + 柱顶写时长（`hoursText`）+ 底部月份，
  当月那根画实一点、别的淡一点；没记录的那个月是一根零高柱 —— 缺不缺一眼看得出。
- **不做页签**：图上只有一种口径（时长）。要看别的尺度，上面那排数字（今日 / 本周 /
  本月 / 全年 / 累计）已经在了。

## 4. 记账：支出日历（热力图）

记账左栏再加一张卡（顺序：当月月历 → 分类占比 → 近 6 个月 → **支出日历**）：
**近 26 周 × 7 天**（周一起，最后一列是本周），每格一天，颜色按当天支出分五档
（0 元最浅），悬停给「日期 · 支出 ¥x」，今天那一格描个边；标题右侧给一句
「近 26 周 · 支出 ¥合计 / 最凶的一天 ¥x」。

几条口径：

- **只算支出**。图上要读的是「哪天花得凶」，收入混进来会把颜色搅乱；收入要看有月历和环形图。
- 数据 `finance-calc.js` 新加 `dayExpenseMap(transactions)` → `{ "2026-10-14": cents }`
  （跨月，所以不能用 `monthByDay` —— 那个是按月切的）；和月历 / 明细**同一个来源**
  （都从 `transactions` 现算），所以图上的数和点开那天的明细永远一致。
- 格子**不可点**：读图就是读图，点开某天去看明细已经在旁边的月历上做了，两处能点会互相打架。
- 为什么不另外做「账户余额横条」「分类环比」：那两张是「换个角度看已经有的数」，
  支出日历是「现在答不出来的问题」。真想要，第 7 节里记着，下一轮接。

## 5. 明确不做

- **不引任何图表库**：零外链是硬约束，继续手写 SVG / CSS（记账那两张已经证明了这条路够用）。
- 折线图先不做：月份是离散的、要读的是「哪个月高」，柱状更合适。
- 图表动画、导出图片、点开全屏、跨模块大屏（首页不放图）。
- 热力图上的月份 / 周标签：26 列挤在一起，标签比格子还宽；悬停给完整日期就够。
- 游戏那张图不做「按周 / 按年」切换。

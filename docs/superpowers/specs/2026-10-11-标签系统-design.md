# 全站标签系统（设计）

版本 v1 · 2026-10-11 · 对应实现：待定（本文档是设计，代码还没写）
（预计落在 `app/web/tag-calc.js`、`app/web/item-form.js` 的字段表、
`app/web/search-calc.js` 的 `SOURCE_SPECS`、`app/服务.py` 的老数据迁移）

来源：`docs/需求清单.md` 第 8 节第 7 条的第 1 项（「全站标签系统，tags 数组，
改动最小，优先」）。

## 1. 想解决什么

现在每类记录只能按它自己的字段归类：待办有「工作 / 生活 / 运动 / 其他」四个固定分类，
记账有自己的收支分类，自媒体有平台和状态，学习有「书 / 课程 / 视频」。这些**都是各自
写死的**，跨模块没法归类 —— 「这周要盯的三件事」散在待办、问题、作品三张表里，
除了记住它们叫什么，没有别的办法一起找出来。

标签要解决的就是这件事：**给任意一条记录贴几个自己起的词，然后按这个词把全站的
记录一次捞出来。**

## 2. 三种存法，为什么选第一种

| 存法 | 长什么样 | 好处 | 代价 |
| --- | --- | --- | --- |
| **① 记录上的字符串数组**（推荐） | `"tags": ["工作", "本周"]` | 改一个字节就完事；`数据.json` 直接看得懂、手改不炸；不用迁移 | 标签没有「全局身份」，改名得逐条改；颜色只能现算 |
| ② 记录存字符串 + 顶层 `tags` 表存颜色 / 备注 | `"tags": ["工作"]` + `tags: { 工作: { color } }` | 颜色可以手动指定、能加备注 | 多一份要维护的配置；删了记录标签还在表里，得清垃圾 |
| ③ 记录存 id + 顶层标签表 | `"tags": ["t3"]` | 改名 / 改色一次到位，最「规范」 | `数据.json` 里 `["t3"]` 根本认不出是什么；老数据迁移 + 到处要 join；这一版不值得 |

**选 ①。** 理由是这个 App 的数据文件是**给用户自己看、也允许自己改**的（README 里
写明了「数据是看得见摸得着的文件」），可读性比「规范化」值钱；而且这一版要的只是
「贴得上、看得见、搜得到」，③ 换来的改名能力还没有使用场景（YAGNI）。

颜色不存：**由标签名字哈希到一组固定调色板**（8 色，详见第 6 节）。所以贴一个
新标签不用先建标签、不用选颜色，敲个字就完事；同一个名字在任何模块、任何页面
颜色都一样。

如果以后真出现了「标签得能改名、得能编成分组树」的需求，② 是在 ① 之上加一张表
就能走的下一步，数据不用重迁。

## 3. 数据模型

每张「能贴标签的表」的每条记录多一个字段（其余一个字节不动）：

```jsonc
{
  "id": "demo-t13",
  "text": "把月历的氛围底再调淡一点",
  "category": "工作",          // 原来的固定分类照旧，标签是它旁边多出来的一层
  "tags": ["工作", "本周"],     // 新增：字符串数组，按用户输入的原样存
  "imagePaths": []
}
```

写入规则（只有一份实现，在 `tag-calc.js` 里）：

- **去重**：同一个标签只留一个（比对时忽略首尾空白与大小写，存的是第一次写下的那个写法）。
- **去空**：空白、纯空格的丢掉。
- **上限**：单个标签 ≤ 24 个字，一条记录 ≤ 8 个标签。超了**截断并提示**，
  不是静默丢（和表单别的字段一样，错误写在框下面）。
- **不排序**：按用户输入顺序存 —— 他自己排的顺序就是他心里的重次。

## 4. 这一版接到哪儿（范围）

「全站」不是一次把所有页面都改完，而是**先把地基铺满，再按入口的难易分两步**。

**第一步（v1）**

1. **数据与迁移**：所有记录表都补上 `tags`（见第 8 节）。
2. **统一弹窗的录入**：`item-form.js` 的字段表里加一种 `tags` 字段，
   然后给这 9 个表单各挂一个（一次改一条，覆盖最广）：
   `todayPlan`、`devTodo`、`devProject`、`studyRecord`、`studyItem`、
   `fitness`、`game`、`gamePlayRecord`、`moduleGoal`。
3. **行上看得见**：今日计划 / 首页待办 / 开发项目详情 / 学习 / 健身 / 游戏
   这几处列表，条目上把标签画成小胶囊（沿用优先级胶囊那套磨砂样式）。
4. **搜得到**：`search-calc.js` 的 `SOURCE_SPECS` 给每张表把 `tags` 加进
   `fields`，于是搜索面板里敲标签名就能把记录捞出来（全局搜索本来就跨模块）。
5. **跨模块地看**：搜索面板顶部多一行「标签」区（现算的全站标签，点一个
   就在面板里列出带它的记录）。这是这一版真正的新能力 —— 在哪个模块都能用，
   也不用给每个列表页各加一个下拉。

**第二步（第二版再说）**

- 不走统一弹窗的那几处录入：记账「记一笔」、问题 / bug、自媒体作品、债务、
  饮食（三餐 / 饮水 / 体重）。它们是各自手写的弹窗或行内表单，得一个个接。
- **各列表页内部的按标签筛**（比如记账页只看 `#报销`）。面板里能看，先够用。
- **批量改名 / 删标签**这类「标签管理」工具。

## 5. 录入：统一弹窗里的一种新字段

字段表现在是 `{ name, label, kind: "text"|"number"|"date"|"time"|"select"|"combo"|"textarea" }`，
加一种：

```js
{ name: "tags", label: "标签", kind: "tags", maxlength: 24, max: 8,
  placeholder: "回车或逗号分开，比如：工作、本周" }
```

控件行为（`item-dialog.js` 里一处实现）：

- 一个输入框 + 已贴标签的胶囊行；敲**回车或逗号**就收成一个标签，退格删最后一个。
- 下面挂一个 `datalist`，候选是**全站现算出来的已有标签**（和 `combo` 一个套路）——
  打个「工」就把「工作」补出来，不用记着自己以前起过什么名。
- 编辑老记录时，`fromRow` 默认取 `tags`，没有就空数组。

## 6. 展示：胶囊 + 固定调色板

- 胶囊样式沿用优先级 / 来源标签那套（磨砂半透、圆角、小字号）。
- 颜色：`tagColor(name)` 把名字做一个简单哈希，落到 8 色的调色板上；
  深浅两套皮肤各有一份色值（走 CSS 变量，和分类颜色一个做法）。
  好处是不用存、不用配；代价是「工作」和「本周」可能撞色 —— 撞色不影响用，
  真要区分还能看字。
- 一行里标签排在**分类 / 优先级之后**、备注之前；超过 3 个就先画 3 个，
  剩下的收成 `+2`（鼠标移上去有 title）。

## 7. 找得到：搜索面板里那行「标签」

搜索面板（顶栏那个）现在只有「输入框 + 结果 + 包含归档记录」。加一行标签区：

- 内容：`allTags(data)` 现算 —— 扫所有表的 `tags` 去重、按用得多的排前面
  （次数一样按名字）；**不落盘**，和「进度不另存」一个哲学，不会有第二份真相。
- 点一个标签 → 面板里列出全站带这个标签的记录（复用现成的结果卡片与跳转地址：
  待办回今日计划、问题回它那个项目、作品回自媒体…）。
- 再点一下取消筛选；和关键词可以叠加（「搜到的东西里，只要 #工作 的」）。

## 8. 老数据兼容与迁移

照 `imagePaths` 那套来，在 `服务.py` 读数据时的迁移里补：

```python
# 标签（2026-10-11 加的）：老记录没有 tags，读出来补一个空数组，页面那边
# 就不用到处判空；只是补，不动任何已有字段，也不做任何清洗。
for row in <每张记录表>:
    if isinstance(row, dict) and not isinstance(row.get("tags"), list):
        row["tags"] = []
```

要覆盖的表一共 16 张：`tasks`、`projects`、`issues`、`progress`、`subjects`、
`studies`、`workoutLogs`、`weights`、`meals`、`water`、`games`、`gameRecords`、
`finance.transactions`、`debt.items`、`contents`、`mediaAccounts`。
（前 15 张和服务端 `COUNT_KEYS` 那张清单基本对得上；`progress`（最近进展）
不在那张清单里，但它也是记录表，一样补。）

- **不搬、不改、不排序**已有的标签：已经是数组的原样留着（只会补缺的那部分）。
- 数组里混进了非字符串（手改数据可能出）→ 读出来时过滤掉，不留半截字符串。
- 第二条防线：前端读表时也用 `normalizeTags()` 过一道，服务端进程是旧的也不会崩
  （v1.5 记账那次「服务端没重启」的教训，那次之后前端都留了一手）。

## 9. 纯逻辑与测试

新增 `app/web/tag-calc.js`（不碰 DOM、不改数据，和 `task-calc.js` / `search-calc.js`
一个路子）：

| 函数 | 干什么 |
| --- | --- |
| `normalizeTags(value)` | 清洗：去空、去重（忽略大小写与首尾空白）、截断到上限 |
| `parseTagInput(text)` | 把「工作, 本周， 重要」这种一串解析成数组（中英文逗号、顿号、换行都认） |
| `allTagsOf(data)` | 扫全站记录，现算标签与出现次数，按次数排 |
| `recordsWithTag(data, tag)` | 跨模块捞记录（带模块、标题、跳转地址，喂给搜索面板） |
| `tagColor(name)` | 名字 → 调色板序号（稳定、同一个名字永远同色） |

测试：

- `node tests\标签计算.test.mjs`：上面五个函数的单元测试（含大小写、空值、
  超长、超量、非字符串混入、老数据缺字段这些边界）。
- `python tests\自检.py`：加一条「老记录补 `tags`」的迁移断言（和现成的
  `imagePaths` 那条并排）。
- 浏览器回归（可选，看实现时的时间）：弹窗里贴两个标签 → 列表行上出胶囊 →
  搜索面板里点那个标签 → 全站带它的记录都出来、点一条跳到对的地方。

## 10. 这一版明确不做

- 标签的**批量改名 / 合并 / 删除**工具（改一个就得逐条改，先不做）。
- 标签的**分组 / 层级 / 层级树**（`工作/项目A` 这种斜杠写法这一版按普通字符串处理）。
- 每个列表页内部的标签下拉（只有搜索面板那一行）。
- 颜色自定义（固定调色板）。
- 给「快速备忘」和「设置」贴标签（它们不是记录）。

## 11. 需要你拍板的几件事

1. **默认范围**：先只在统一弹窗那 9 处贴（第 4 节第一步），还是记账 / 问题 /
   自媒体那几处也要在第一版就接上？（我建议先不接，等用起来再说。）
2. **每条记录的标签上限**：我按 8 个写。够不够、要不要更少？
3. **跨模块看标签的位置**：我放在**搜索面板**里（一行标签区）。也可以单独做一张
   「标签」卡片放在首页 —— 更显眼，但多一块要维护的 UI。
4. **单个标签的字数上限**：我按 24 个字。要不要更短（比如 12 个）？

# 小李 · 首页总览改版设计（双视图：简洁 / 完整）

2026-10-07。本文说「首页改成什么样、为什么这么改、边界在哪」，不写实施步骤
（实施步骤见后续的 plan 文档）。定稿后按本文动代码。

## 0. 背景与这个版本的边界

首页是十个模块里唯一一个「什么都往里放」的页面。模块从 6 个加到 10 个之后，
现在的问题是：**卡片平铺堆砌、信息密度混乱；重要信息淹没在一堆小卡片里，
一眼抓不到当日核心，次要模块抢占主视觉。**

改法的核心是**分区 + 权重分层**：首页不再把所有模块信息同等平铺，拆成
「核心区（当日必看）」+「概览卡片区（各模块摘要）」+「折叠的次要信息」，
玻璃拟态风格不变。

**这个版本做：**

1. 首页双视图：简洁（默认）/ 完整，一键切换
2. 核心区：今日进度 + 今日待办（并放大）｜财务摘要（记账 + 债务预警）并排双栏
3. 二级网格：高优先级 4 张卡片默认展示，健身 / 饮食 / 游戏娱乐收进「其他模块」折叠面板
4. 卡片文案精简：只留 1 行核心数字，次要信息进 hover 提示
5. 所有卡片都是入口，点击跳到对应模块；财务卡与债务预警分别跳到记账的两个子 Tab

**这个版本不做：** 首页自定义（拖拽排序卡片、自己选哪些卡片上首页）、模块顺序调整、
新的数据字段、新的模块、图表。

## 1. 已定的决定（逐条有出处）

| 决定 | 选择 | 为什么 |
| --- | --- | --- |
| 默认视图 | **简洁模式** | 用户定稿：日常打开先看当日状态 |
| 视图切换放在哪 | 欢迎栏右侧，和「+新建待办」并排 | 用户定稿：只首页有，其他页面不受影响 |
| 视图状态存哪 | `数据.json` 的 `settings.homeView`（`"simple"` / `"full"`） | 主题、皮肤已经存在这里（`store.js` 的 `setTheme` / `setSkin`），视图偏好跟着数据走才一致：换数据文件、两个窗口同步都不用另做一套 |
| 切换后要不要写盘 | 写（`touch(true)`） | 和主题、皮肤同一条路径，`settings` 变了就整份保存 |
| hover 提示怎么实现 | 原生 `title` 属性 | 零依赖、零 JS、四套皮肤通用；不引第三方 tooltip 库 |
| 财务卡片的定位 | 简洁模式下**核心区独占**，二级网格里不再重复放出记账卡 | 用户定稿里二级网格列了「记账」，和核心区的财务摘要说的是同一件事（今日支出 / 本月结余）。同一屏出现两次是新的冗余，和这次改版的目的相反。**这一条是本文与定稿原文的唯一分歧，见 §10** |
| 债务预警的显示条件 | 只有「已逾期或 7 天内到期」的未结清债务才显示那一行 | 用户定稿：无债务就整行不渲染，不留空白占位 |
| 债务预警文案 | 取最近到期的一笔，形如 `🔴 近 7 天待还：花呗 ¥350`；已逾期时 `🔴 已逾期：花呗 ¥350` | 复用 `debt-calc.js` 的 `upcoming()` / `dueState()` / `remainCents()`，不新写算法 |
| 「其他模块」折叠面板 | 用 `<details>` 原生折叠，默认收起 | 零 JS、键盘可用、不写状态也能记住这一次的展开；不存盘（每天打开都收着，符合「不拥挤」的初衷） |
| 待办最多列几条 | 简洁模式列前 5 条，超出在底部给「打开今日计划 →」 | 用户定稿 |
| 遗留待办提醒 | 保留，柔和高亮（`.tip` 样式） | 现有实现的黄色提示条位置和文案不动 |
| 预警配色 | 沿用 `--warn` 系，不加新的大面积重色 | 用户定稿：保持柔和玻璃风格 |
| 响应式 | 核心区两栏在窄于 1100px 时塌成一列；模块网格沿用现有三档断点 | 和记账页 `fin-layout`、首页 `mod-grid` 现有断点保持一致 |

## 2. 简洁模式（默认）页面结构，从上到下

### ① 欢迎栏

> 夜深了，小李｜把时间花在看得见的地方 　 右侧：`📋 简洁模式` / `📊 完整模式` ＋ `+新建待办`

- 去掉原来按钮上的「还有 3 条待办」这种重复信息——待办数量放到下面的进度里。
- 按钮从「还有 N 条待办」改成 `+新建待办`，仍然跳 `#plan`。
- 问候语和标语沿用现有逻辑（`greeting()` / `settings.slogan`）。

### ② 一级核心区（首屏）

并排双栏：**【今日进度 & 待办】** ｜ **【财务摘要】**

**今日进度卡片**（首页主卡片）

- 进度条 + 百分比；右侧 `已完成 n / 总数 m`、`待安排 k 条`
- 下方今日待办清单，**最多 5 条**，超出在底部给 `打开今日计划 →`
- 待办仍可直接勾选（复用现有 `data-act="toggle"` 那套）
- 昨日及更早未完成的黄色提醒条保留

**财务摘要卡片**（记账 + 债务合并，只放预警，不展开明细）

```
今日支出：¥168.80 ｜ 本月结余：¥5,874.50
🔴 已逾期：花呗 ¥350        ← 只有存在到期/逾期债务才有这一行
```

- 点卡片主体 → `#finance`（记账 · 账目记录）
- 点债务预警那一行 → `#finance/debt`（记账 · 债务欠款）
- 没有任何账目时，`今日支出` 显示 `今日暂无支出`（不写 ¥0.00 假装有数据）

### ③ 二级区域：模块卡片网格

默认展示 **3 张**高优先级卡片：自媒体、开发工作、学习工作（记账见 §1 的说明）。

卡片统一规则：**只保留 1 行核心数字，辅助信息进 hover 提示**

| 卡片 | 卡片正面 | hover 提示 |
| --- | --- | --- |
| 自媒体 | 2 条待发布 | 想法 1 · 写作中 1 · 已发布 2 |
| 开发工作 | 2 个项目进行中 | 未解决 bug 2 条 |
| 学习工作 | 本周学了 340 分钟 | 待复习 17 条 |
| 健身计划 | 本周练了 2 次 | 最近一次训练：2026-10-07 |
| 饮食计划 | 今天记了 4 餐 | 喝水 6 杯 |
| 游戏娱乐 | 在玩 1 款 | 塞尔达传说：王国之泪 |

下方折叠面板：`▾ 其他模块（健身计划、饮食计划、游戏娱乐）`，默认收起，
展开后展示剩下 3 张卡片。三个模块都没有数据时，面板整个隐藏。

### ④ 三级辅助区（页面下半部分）

1. 快速操作栏：`+新建事项 / 记备忘 / 记训练 / 记饮食 / 加内容`（保留，位置下移）
2. 快速备忘卡片（放最下方，辅助输入，不抢首屏）

## 3. 完整模式页面结构

**原来的首页布局原样保留**，只跟着改欢迎栏按钮文字：

1. 欢迎栏（问候 + 标语 + 视图切换 + `+新建待办`）
2. 今日进度条（`overview-strip` 那一条，不动）
3. 快速操作栏
4. 快速备忘
5. 今日待办卡片（不截断，按时间 / 待安排分组，和现在完全一样）
6. 模块卡片网格：7 张全部平铺（自媒体 / 开发 / 学习 / 健身 / 饮食 / 游戏 / 记账）

完整模式下**没有**独立的财务摘要卡片：债务信息回到记账卡片的 hover 提示里，
不在顶部常驻。适合周末全盘复盘。

## 4. 视图切换与持久化

- 控件：两个小按钮（复用现有 `.view-switch` / `.btn` 样式），放在欢迎栏右侧。
- 点击：写 `settings.homeView` → `touch(true)` 落盘 → 就地重画首页（不整页刷新）。
- 默认：`settings.homeView` 缺失或值不认识时按 `"simple"` 处理（和 `skinOf()` 的兜底写法一致）。
- 其他页面完全不受影响；搜索、侧边栏、状态栏都不认这个设置。
- 两个窗口同时开着时，视图切换会跟着数据同步过去（现有 `BroadcastChannel` 机制，不用额外做）。

## 5. 卡片信息精简规则

1. 卡片正面只放 **1 个核心指标**，最多两行；次要信息全部进 `title` 提示。
2. 卡片一律是入口：整张卡可点，跳到对应模块。
3. 没有数据时给一句人话（`今天还没有任务` / `今日暂无支出` / `还没有内容`），
   不显示 `0` 这种空数字，也不留空壳。
4. 现有 `SUMMARY_MODULES` 继续作为「有哪些摘要卡」的唯一清单，
   新增的只是「哪些进核心、哪些默认折叠、哪些在完整模式才出现」的归属表。

## 6. 与记账 / 债务两处的联动

| 从哪里点 | 跳到哪 | 说明 |
| --- | --- | --- |
| 财务摘要卡片主体 | `#finance` | 记账 · 账目记录 Tab |
| 财务摘要里的债务预警行 | `#finance/debt` | 记账 · 债务欠款 Tab |
| 简洁模式核心区「打开今日计划 →」 | `#plan` | 现有行为 |
| 遗留提醒条里的链接 | `#plan` | 现有行为 |

首页**不承担明细查看职责**：所有模块的明细都在各自页面里，首页只给快照和入口。
债务预警的取数完全复用 `debt-calc.js`，不在首页另写一套到期判断。

## 7. 边界与空状态

| 情况 | 表现 |
| --- | --- |
| 今天一条任务都没有 | 进度卡片走现有空状态（`emptyState`），给「加一条」按钮 |
| 今天有任务但都完成了 | 进度 100%，清单里仍是勾好的那几条 |
| 没有任何账目 | 财务摘要显示「今日暂无支出」，不显示本月结余那一列 |
| 没有到期/逾期债务 | 债务预警行整行不渲染，不留空白占位 |
| 债务已结清 | 不进预警（`isSettled()` 已经过滤） |
| 「其他模块」三张卡都没数据 | 折叠面板整个隐藏 |
| 窗口窄到 620px 以下 | 核心区、模块网格都塌成单列 |

## 9. 写进文档的取舍要点

> 首页提供【简洁 / 完整】双视图切换，默认启用简洁模式；视图选择本地持久保存。
>
> - 简洁模式：首屏优先展示今日任务进度、待办清单、财务预警；只默认加载高频模块卡片，
>   健身 / 饮食 / 游戏娱乐收纳至「其他模块」折叠面板。适合日常打开快速查看当日状态。
> - 完整模式：全部模块卡片平铺展开，保留原有首页布局，适合周期性全盘复盘。
> - 卡片设计原则：首页卡片仅展示**单条核心指标**，次要详情放入鼠标悬浮提示；
>   明细统一放在各模块内，首页仅作为仪表盘入口。
>
> 打开 App 第一屏只回答三个问题：今天任务完成多少？有没有紧急待办？
> 财务有没有到期 / 超支预警？模块越多，首页越要克制。

## 10. 唯一待确认的一条

定稿 §二-③ 写的是简洁模式二级网格默认放 4 张卡片（**自媒体、开发工作、学习工作、记账**），
但同一份定稿的 §二-② 已经把「今日支出 / 本月结余」放进了核心区的财务摘要卡片。

本文按**「记账只在核心区出现，二级网格放 3 张」**定稿，理由：同一屏重复同一个数字
与这次改版的目的（减少冗余、一眼抓到核心）相反。

如果你更想要 4 张卡（核心区只做预警、记账卡承担打开展示），说一声，改回来只动
`home-view.js` 的一张表加一条测试断言。

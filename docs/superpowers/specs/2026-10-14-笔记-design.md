## 1. 想解决什么

现在没有一个「随便记点什么」的地方。几个能写字的地方都是「给某个模块记账」用的
（待办、进展、备注、饮食那四个框），不适合放「一段长一点的文字 + 截图 + 回头能搜到」。

这一轮补上：**新的「笔记」模块** —— 一篇一篇的 Markdown 笔记，能贴图、能贴标签、
能全文搜到，写完就是一份本地的纯文本（备份、diff、搬家都简单）。

## 2. 「富文本 / Markdown 双模式」怎么落地

需求原文是个「/」—— 两种读法：**真富文本编辑器**（所见即所得）或者 **Markdown**。
这一版选后者，理由是：

- 真富文本要处理选区、粘贴、撤销栈、光标位置，成本是这一整轮的几倍；
- 而且一旦存成 HTML，数据和源码就不再一一对应了（备份、diff、搜索、手改都变难）。
  Markdown 存的是**纯文本**，`body` 里那一段就是用户打的那一段，一个字不多。

「双模式」按**同一份内容的两种看法**落地：左边写（textarea 里就是 Markdown 源码），
右边看（实时渲染出来的样子），右上角一个「预览」开关并排打开 / 收起
（窄屏时渲染结果落到下面）。所以既能「按源码写」，也能「照着样子看」。

## 3. 数据

新表 `data.notes`（顶层，和别的模块表一个待遇）：

```jsonc
{
  "id": "n-1",
  "title": "给工作台加个笔记模块",
  "body": "## 想做成什么样\n\n- 左边列表、右边写\n- **Markdown** 存纯文本\n",
  "tags": ["开发", "想法"],
  "imagePaths": ["attachments/note/20261014_a1b2.png"],
  "createdAt": "2026-10-14T21:00:00.000Z",
  "updatedAt": "2026-10-14T21:30:00.000Z"
}
```

- **`body` 就是 Markdown 源码**（纯文本），不存渲染后的 HTML。
- **图片**走现成的附件组件，目录用 `note` —— 这个目录当初做附件时就预留好了
  （`ATTACH_MODULES` 和设置页那串说明里都有它），所以这一轮**不用动白名单**。
- 不进归档：笔记删了进回收站，捞得回来（和自来水的素材 / 工时一个待遇）。
- `title` 允许空（没标题就用正文第一行当列表上的名字，还是空就叫「（空笔记）」）。

## 4. 纯逻辑：Markdown 渲染器 `app/web/markdown.js`（新）

零外链、无依赖，所以自己写一个小渲染器：**纯函数** `renderMarkdown(text) -> html`，
`node tests\Markdown.test.mjs` 能一条条断言。

支持的语法（够个人笔记用，不求全）：

| 写法 | 出什么 |
| --- | --- |
| `#` ~ `######` 行首 | 标题 h1~h6 |
| `**粗**` / `*斜*` / `~~删~~` | strong / em / del |
| `` `行内代码` `` | code |
| ``` 围栏 | 代码块（pre > code，里面的东西一律原文照排） |
| `- ` / `* ` 行首 | 无序列表 |
| `1. ` 行首 | 有序列表 |
| `> ` 行首 | 引用 |
| `---` 单独一行 | 分割线 |
| `[文字](地址)` | 链接（新窗口打开） |
| `![说明](图片地址)` | 图片 |
| 空行 / 单回车 | 空行分段，单回车在同一段里换行 |

**安全规矩（这一条最要紧）**：

1. 先把整段文字**转义**（`& < > "`），再往里插我们自己生成的标签 ——
   笔记里写 `<script>alert(1)</script>` 只会原样显示成文字；
2. 链接只认 `http://` / `https://` / `#` / 相对路径（`attachments/…`），
   `javascript:` 这类一律不认（不生成 `<a>`，原样显示成文字）；
3. 生成的每个标签都带自己的 class（`md-h1` / `md-p` / `md-code`…），样式都在 style.css 里。

## 5. 界面：`#note`

左右两栏（窄屏堆成一栏）：

- **左：笔记列表**。按 `updatedAt` 倒序，每行：标题（或正文第一行）+ 一句摘要 +
  标签胶囊 + 一点点图片标记（有图就标一下）。头上一行「＋ 新笔记」+ 搜索框
  （在列表里按标题 / 正文 / 标签就地筛，和别处的「筛选框」一个做法）。
- **右：编辑器**。标题输入框、正文 textarea（等宽字体）、标签输入框、
  图片区（拖 / 点 / Ctrl+V 粘贴，组件是现成的）、右上角「预览」开关、
  底下「删除」（进回收站）。没选中任何一条时，右边写一句「选一条，或者新建一条」。
- **就地保存**：正文和标题打字时静默保存（`touch(false, true)`，光标不跳），
  离开输入框时正常保存并刷新左边列表（标题 / 摘要 / 排序跟着变）。
  不用弹窗 —— 弹窗不适合写长文，而且这里本来就该像「本地编辑器」。
- 地址支持 `#note/<id>`：从搜索点过来直接打开那一条（`sub` 就是 id）。

## 6. 搜索

搜索池加「笔记」一条：匹配标题 / 正文 / 标签，结果卡片显示标题（没标题就第一行），
点结果回 `#note/<id>`（直接打开那一条，不是只到列表页）。

## 7. 明确不做

- **不做所见即所得编辑器**（理由见第 2 节）。
- 不做 Markdown **表格**：手写表格很难受，渲染器还要多一块；真需要时再说
  （要贴表格可以先贴成代码块或者截图）。
- 不做双向链接 `[[ ]]`、不做文件夹 / 层级、不做版本历史 / diff、不做导出 Markdown
  文件（数据本来就在 `数据.json` 里，复制得出来）。
- 不做数学公式、脚注、任务清单勾选框（笔记里想勾就写 `- [ ]`，这版不认）。
- 首页不加笔记卡片（笔记不是「每天要看的东西」）；侧边导航里有入口。
